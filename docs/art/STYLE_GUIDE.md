## 1. 픽셀 해상도 기준 (확정)

### 1-1. 핵심 수치

| 항목 | 확정값 | 근거 |
|---|---|---|
| **타일 크기** | **16x16 px** | ① CC0 에셋 생태계(Kenney, OpenGameArt 등)의 최대 규격 ② Pillow 절차 생성 비용 최소 ③ 250시간 분량 = 맵 물량이 많으므로 타일 제작비를 낮게 고정 |
| **게임 월드 내부 해상도** | **480x270 px** (2026-07-18 개정 — 해상도 전환에 맞춰 720p 기준값을 대체) | 1920x1080의 정수 1/4. 화면에 가로 **30타일** x 세로 16.875타일 표시(1-2-1절 근거표 참조) — 실시간 액션의 교전 시야(잡몹 무리 2~5마리 + 회피 공간)에 적정 |
| **카메라 줌 배율** | **x4 (Godot 4: `Camera2D.zoom = Vector2(4, 4)`)** | 480x270 → 1920x1080 정수 스케일. 비정수 줌 금지 (픽셀 왜곡). 줌 배율 자체는 720p 시절과 동일(1-2-1절) |
| **UI 렌더링** | **네이티브 1920x1080** (CanvasLayer, 줌 비적용, 2026-07-18 1280x720에서 상향) | ux-foundation.md의 HUD 좌표·글자 크기(본문 33px/보조 27px)가 네이티브 px 기준이므로, UI는 월드 줌과 분리한다 |
| **월드 1타일의 화면 크기** | 64x64 px (16 x 4배) | 참고치 |

- 텍스처 필터: **Nearest 고정** (프로젝트 설정 `default_texture_filter = Nearest`). 스프라이트의 런타임 회전·비정수 스케일 금지 (투사체 등 회전이 필수인 오브젝트만 예외 허용, vfx-artist 판단).
- 2D 픽셀 스냅 활성화 (`snap_2d_transforms_to_pixel = true`) — 적용은 tech-artist.
- combat.md의 타일 단위 수치와의 정합: 대시 3타일 = 48px(월드 좌표), 잡몹 근접 스윙 1.5타일 = 24px.

### 1-2. 스프라이트 크기 규격 (2026-07-27 개정 — 스톤샤드식 안 1, 인간형·몬스터 프레임 상향)

**개정 원칙 — "모든 인간형·잡몹 프레임을 각 축 +4px(폭 +0.25타일) 상향"**: 인간형이 16x32 → 20x36으로 각 축 +4px 커지므로, 잡몹 3종에도 **동일한 절대 증분(+4/+4)**을 적용한다. 그 결과 모든 액터가 폭 기준 정확히 +0.25타일씩만 커져 **세계·체급·인간형 대비 상대 비율이 그대로 보존**된다(비대해지지 않음, 1-2-2절 검증). 정예 이상(48x48~)·펫·오브젝트·아이콘·초상화는 본 개정 범위 밖으로 규격 불변 — 해당 자산 제작 시점에 별도 검토.

|---|---|---|---|

| 펫 | 24x24 | 약 12x14 | **변경 없음**(본 개정 범위 밖) — 몸(12x14)이 플레이어 몸(15x33)보다 확실히 작아 위계 유지 |
| **몬스터(잡몹) — 경량 체급** | **20x20** (가로 ~1.25타일 x 세로 1.25타일) | 약 18x15 | 예: **뿔토끼**(`m2-monster-spec.md` 3-1). 구 16x16 → +4/+4. combat.md 5-2-1 "경량"(넉백 저항 ×1.5)과 용어·대상 일치. 폭은 인간형과 같은 1.25타일이나 높이(20 vs 36)·형태(웅크린 소형 야수+뿔)로 실루엣 명확 구분(6-3절). **여전히 3규격 중 최소 프레임**(면적 400 < 들개 1008 < 점액 1296)이라 경량 위계 보존. 패밀리 아종은 팔레트 스왑(combat.md 9-2) |
| **몬스터(잡몹) — 표준 체급** | **36x28** (가로 2.25타일 x 세로 1.75타일) | 약 30x19 | 예: **들개 마수**(`m2-monster-spec.md` 3-2). 구 32x24 → +4/+4. combat.md 5-2-1 "표준"(넉백 저항 ×1.0)과 용어·대상 일치. 4족보행이라 인간형(20x36)보다 폭넓고 낮은 가로형 실루엣 — 실루엣만으로 인간형과 구분(6-3절) |

### 1-2-1. 스타듀밸리 대비 화면 비율 근거표 (재검토 방지용)

> **2026-07-27 갱신 주석**: 아래 표는 2026-07-18 G2-2 당시 인간형 프레임 폭을 32→16(1타일)으로 슬림화한 결정의 근거다. 2026-07-27 스톤샤드식 개정으로 인간형 폭이 **16 → 20(1.25타일)**로 조정됐으므로, 이 표의 "인간형 프레임 폭 = 1타일" 결론은 폭에 한해 **1-2-2절로 대체**된다. 단 이 표의 핵심 논리("화면 폭 점유율은 줌·해상도가 아니라 프레임 폭의 타일 환산값에만 좌우된다")는 여전히 유효하며, 20px 조정도 그 논리의 연장선이다(변경 이력 2026-07-27 G2-2 부분 되돌림 참조). 아래 표 본문은 당시 판단 근거로 원형 보존한다.

이 결정이 "줌을 낮추자"는 이전 논의를 대체하는 이유를 수치로 남긴다. 화면 폭 점유율은 타일 크기·카메라 줌이 아니라 **스프라이트 프레임 폭의 타일 환산값**에만 좌우된다 — 타일·줌이 스타듀와 이미 동일했으므로, 문제는 항상 스프라이트 쪽에 있었다.

이 표는 최초 G2-2 검증(2026-07-18 1차 개정) 당시 720p(1280x720) 기준으로 작성됐다. 같은 날 해상도가 1920x1080으로 전환(94a681d)되며 월드 내부 해상도가 320x180→480x270으로 바뀌었으므로, 아래 수치는 **1080p 기준으로 재계산**했다(2026-07-18 2차 개정). 타일 크기·줌 배율이 그대로이므로 결론(인간형 프레임 폭 = 1타일 = 스타듀와 일치)은 변하지 않는다 — 화면이 더 넓어져 표시 타일 수와 점유율 %가 달라졌을 뿐이다.

- 이 표는 향후 "화면 비율이 이상하다"는 재검토 요청이 들어왔을 때, 줌 구조부터 의심하지 말고 스프라이트 비율을 먼저 확인하도록 남겨두는 근거다.

### 1-2-2. 신규 프레임 화면 대비 근거표 (2026-07-27 스톤샤드식 개정)

### 1-2-3. 프레임 크기 결정 원칙 (2026-07-27 신설 — 유형이 늘어난 M3 이후 공통 규칙)

M2 3종(뿔토끼·들개 마수·균열 점액)은 "프레임 면적 순서 = 넉백 체급 순서"가 우연히 일치했으나, **유형(벌레·인간형·균열)이 늘어나면 이 일치를 전 종에 강제할 수 없다.** 숲거미와 임프는 둘 다 넉백 **경량**이지만, 경량 규격 20x20에 8다리 방사형 벌레와 뿔·꼬리 달린 악마를 모두 담으면 4단 램프(3-2-1절)가 뭉개지고 실루엣 구분(6-3절)이 무너진다. 따라서 아래 3원칙으로 대체한다.

1. **체급(경량/표준/중량)은 넉백 수치(`combat.md` 5-2-1)로만 표현한다.** 프레임 면적과 체급의 순서 일치 요구는 폐기한다(M2 3종 내부 기록으로만 보존).
2. **프레임 크기는 유형별 실루엣 요구가 결정하되, 두 가드레일을 절대 지킨다** — ① **인간형은 20x36 불변**(진영·유형 무관. 플레이어·NPC·인간형 적 공통, 세계 척도의 기준선) ② **잡몹 프레임 상한 36x36(2.25타일)** (디렉터 "과하게 키우지 말 것" 지시).
3. **모든 프레임 변은 4px 배수(16/20/24/28/32/36)로만 고른다** — 2026-07-27 개정의 "+4/+4 균등 증분" 규율 계승. 신규 규격이 임의 수치로 늘어나는 것을 막는다.

- 위 원칙에 따라 신규 규격을 추가할 때는 반드시 **1-2절 표에 행을 추가하고 크기 근거를 1행 이상 기록**한다(근거 없는 규격 신설 금지).

#### 3-2-1. 캐릭터·몬스터 4단 램프 규칙 (2026-07-27 신설, 스톤샤드식 볼륨감)

프레임 상향(인간형 20x36 등)으로 음영을 넣을 픽셀 공간이 늘어난 캐릭터·몬스터에 한해, 재질당 명도 단계를 **4단까지** 허용한다. 스톤샤드의 다단계 볼륨 셰이딩을 EDG32 제약 안에서 근사하는 장치다.

1. **4단 구성**: 명도 순으로 **하이라이트 1 + 기본색 + 그림자 2**, 또는 **하이라이트 2 + 기본색 + 그림자 1** — 재질당 총 4개 명도. 3단(기존)도 그대로 허용하며, 4단은 **상한이지 의무가 아니다**. 작은 프레임(뿔토끼 20x20 등)이나 좁은 재질 영역에서 4단이 뭉개지면 3단으로 절제한다(pixel-artist 판단).
2. **팔레트 확장 없음**: 4단은 반드시 **EDG32 32색 내의 인접 명도**만 조합해 만든다. 새 색을 추가하거나 중간색을 섞지 않는다(2장·2-2절 팔레트 준수 규칙 그대로). 램프 예시:
   - 피부: `#e8b796`(하이라이트) → `#e4a672`(기본) → `#d77643`(그림자1) → `#b86f50`(그림자2)
   - 강철·회청: `#c0cbdc` → `#8b9bb4` → `#5a6988` → `#3a4466`
   - 초록(야수 가죽 등): `#63c74d` → `#3e8948` → `#265c42` → `#193c3e`
   - 균열 점액: `#b55088`(발광 하이라이트) → `#68386c`(기본) → `#3e2731`(그림자1) → `#262b44`(그림자2)
3. **채도 방향 유지**(3-2 채도 규칙): 4단이 되어도 그림자 2단은 "어둡게+약간 차갑게(남색 방향)", 하이라이트는 "밝게+약간 따뜻하게"를 지킨다. 검정을 섞은 탁한 그림자 금지 — 위 램프처럼 명도가 낮아질수록 한색 계열 색상으로 넘어가게 고른다.
4. **아웃라인 불변**: 4단 램프와 무관하게 외곽선은 3-1절 그대로 1px `#181425`. 내부 선은 램프의 그림자색을 쓰고 `#181425` 남용 금지(3-1 원칙 유지).
5. **적용 대상 명확화**: 4단 허용 = 캐릭터·몬스터·펫·보스. **타일·배경 오브젝트·아이템 아이콘·UI 프레임은 3단 고정**(3-2 표). 이펙트는 6-2절 규칙(EDG32·알파만 사용)을 따르며 볼륨 셰이딩 대상이 아니다.

- **2차 전직 스킬 모션 추가 예산: +24프레임 이내 (별도 예산, 2026-07-27 신설)** — 90프레임 예산은 M1 시점에 **1차 전직 기준**으로 산정된 값이라 2차 전직(승계·신규 4스킬)의 모션이 포함돼 있지 않다. 상한 24를 두어 무제한 팽창을 막는다. 실제 배정 예: 전사 검투사 = 검투 선풍 4(1행 공용) + 처형 일격 12 = 16, 난입 강타·혈투의 함성은 재사용 0(`m3-character-art-plan.md` 5-2절).
- **재사용 판정 기준 (2026-07-27 신설)**: 신규 스킬 모션의 제작 여부는 **"실루엣이 이미 존재하는 모션과 같은가"**로 판정한다. 같으면 기존 시트 재사용(예: 돌진 = 대시 시트), 다르면 제작(예: 처형 일격의 머리 위 치켜듦). 자기 중심 360° 회전처럼 **한 애니메이션 안에서 전 방향을 지나가는 모션은 1행(방향 무관) 제작**으로 3방향분을 절감한다.
- 잡몹 1종당 기본 예산: 3방향 x (idle 4 + walk 4 + attack 5 + death 4) = **51프레임 이내**. 아종은 팔레트 스왑이므로 0.
- **잡몹 유틸/방어 블록 추가 예산: 블록 1개당 6프레임 이내 (2프레임 루프 x 3방향, 2026-07-27 신설)** — `combat.md` 9-2의 무피해 유틸/방어 블록(거미줄 조준·가드·포효 등)은 데미지 예고가 아니지만 플레이어가 읽어야 하는 상태이므로 최소 표현이 필요하다. 잡몹 1종 실질 상한 = 51 + 6 = **57프레임**(유틸 블록 1개 기준). 예: 숲거미 `_web` 6 / 무법자 `_guard` 6 / 임프 `_roar` 6.
  - **초단시간 상태의 이펙트 대체 허용**: 예고·후딜이 0.3초 이하인 상태(순간이동 소멸·등장 등)는 **`_idle` 프레임 + 알파 페이드 셰이더 + 이펙트**로 대체하고 스프라이트 신규 프레임을 만들지 않는다. 단 **상반된 두 상태(사라지는 중 ↔ 나타나는 중)가 시각적으로 구분되어야 한다** — vfx-artist 검수 항목.
- 보스: 프레임 규격 자유이나 동작당 6프레임 이내, 총 120프레임 이내 권장.

## 5. "밝음 6 : 어둠 4"의 비주얼 해석

원칙 (worldview 2.1 "낮은 밝지만, 그늘은 깊다"의 화면 번역):

1. **비율은 콘텐츠 단위로 적용한다** — 화면 전체에 회색 필터를 씌우는 방식이 아니라, "밝은 장소 6 : 어두운 장소·순간 4"로 공간과 연출을 배분한다. 도시·마을·평시 필드는 항상 밝게, 균열 지대·폐허·특정 스토리 연출만 어둡게.
2. **평시(밝음 6)**: 고채도·고명도 서브 팔레트, 하늘은 밝고 광원은 풍부하게. 일상 콘텐츠(수집, 펫, 영지, 축제)는 EDG32의 난색·원색 계열을 아끼지 않는다.
3. **어두운 순간(어둠 4)**: 다음 3가지 장치만 사용하고, 그 이상 어둡게 만들지 않는다.
   - **팔레트 축소**: 해당 씬의 타일·배경을 어둠 계열 서브 팔레트(`#262b44` `#3a4466` `#3e2731` `#68386c` 중심)로 교체. 순수 검정 화면 금지 — 가장 어두운 값은 `#181425`.
   - **라이팅 모듈레이트**: CanvasModulate를 한색(寒色)으로 — 진지한 대화·회상 `#b8c0d4`(채도 저하+한색화), 균열 지대 `#8a86a8`.
   - **광원의 고립**: 어두운 씬일수록 광원(횃불 `#f77622`, 숨결 `#2ce8f5`)을 작고 적게 두어 "그늘의 깊이"를 만든다. 어둠 속의 밝은 점 = "그럼에도 나아가는 사람들"의 시각화.
4. **금지**: 데저추레이션(흑백) 풀스크린 필터, 비네트 남용, 공포 연출 수준의 암전. 어둠 4는 "침울"이지 "호러"가 아니다.

### 6-3. 실루엣 원칙

- 같은 화면에 서는 플레이어 / 펫 / 잡몹 / NPC는 **크기 규격(1-2)과 아웃라인(3-1)만으로도 구분**되어야 한다. 색은 보조 수단 (ux 접근성: 색만으로 상태 구분 금지 원칙의 전투판).

#### 6-3-1. 인간형 적 3중 신호 의무 (2026-07-27 신설)

**인간형 적(무법자·노상강도·밀렵꾼 등)은 프레임이 플레이어와 동일한 20x36이므로 크기로 구분할 수 없다**(1-2·1-2-3절 가드레일 ①의 필연적 결과). 위 6-3절 "크기 규격과 아웃라인만으로 구분" 원칙의 **명시적 예외**로서, 아래 3중 신호를 **모두** 의무화한다 — 하나라도 빠지면 규격 위반이다.

| 신호 | 요구 |
|---|---|
| ① **실루엣 요소** | 머리 윗선에 **후드**(뾰족한 실루엣 + 목덜미로 늘어지는 천 2~3px) 등 플레이어에 없는 형태 요소 필수. 무기도 플레이어 대검(긴 직선)·활(비대칭 곡선)과 다른 형태(**단검·손도끼**처럼 짧고 굽은 것)를 쓴다 |
| ② **적 액센트색** | 어깨·허리에 **`#e43b44`(2장 "적 식별 기본색") 1~2px** 액센트 의무. **`#ff0044`는 절대 금지**(6-1 1순위 예고 전용) |
| ③ **적 UI** | 몬스터 HP 바 표시(적 공용 UI) — 색+형태 이중 신호(ux 접근성) |

**두신 규칙 (2026-07-27 신설)**: 같은 세로형 실루엣끼리는 **머리 비율로 구분**한다 — **인간형(플레이어·인간형 적) = ~3.3두신**, **소형 악마·균열 개체(임프 계열) = ~2.5두신(머리 크게)**. 이 수치를 지키지 않으면 임프가 "작은 사람"으로 보여 유형 식별이 실패한다. 가로형끼리(숲거미 ↔ 들개 마수)는 **다리 개수·몸통 높이**로 구분한다(거미 8다리 방사형·몸통 낮게 밀착 / 들개 4다리·목과 꼬리로 전후 축이 뚜렷) + 팔레트 분리(거미 = 심록·흑록, 들개 = 회청·황토).

## 7. 제작 파이프라인 규칙 (pixel-artist · tech-artist)

1. **원본 관리**: 스프라이트 시트는 PNG, 프레임은 캔버스 규격(1-2) 격자 정렬. 파일명 snake_case: 플레이어 `player_<직업>_<상태>.png`, 몬스터 `mob_<이름>_<상태>.png` (예: `player_warrior_walk.png`, `mob_outlaw_thug_attack.png`). 상태 어휘는 3-3-1절 확정 목록만 사용한다. **아종은 기반종과 공통 접두를 쓴다** — `mob_outlaw_thug` / `mob_outlaw_highwayman` / `mob_outlaw_poacher`처럼 파일명만으로 아종 관계가 읽히게 한다(2026-07-27 개정 — 구 "`_색이름` 접미" 규칙 대체).
   - **시트 레이아웃 확정**: 가로 = 프레임(열), 세로 = 방향(행). **행 0 = front(하) / 행 1 = side(측) / 행 2 = back(상)**, 좌우는 `flip_h`(실제 제작 3방향). **시트 크기 = `(프레임 수 x W) x (3 x H)`** (예: 궁수 walk = (6x20) x (3x36) = 120x108). 프레임 `(열 c, 행 r)`의 아틀라스 리전 = **`Rect2(c*W, r*H, W, H)`**. 예외는 방향 무관 1행 시트(3-3 재사용 판정 기준)뿐이며, 그 사유를 반드시 문서에 기록한다.
   - **발밑 기준점 = 캔버스 하단 중앙** 고정. **전 상태·전 프레임에서 발밑 y좌표가 동일**해야 한다(걸을 때 캐릭터가 위아래로 튀지 않도록) — 검증 항목.
   - 소싱 원본은 `godot\assets\tools\_raw_src\`에만 두고 **저장소에 커밋하지 않는다**(`ASSET_SOURCES.md` 7장 재현 절차 유지).
2. **절차 생성(Pillow) 우선 대상**: 지형 타일셋, 아이템 아이콘, 오브젝트, UI 프레임(9-slice), 이펙트 시트 — 규칙적·대량 생산에 유리한 것. **반대로 관절이 있는 몸의 자세·모션(캐릭터·몬스터 애니메이션)은 절차 생성의 구조적 약점**이다(무게 이동·예비동작·잔여동작이 좌표 규칙으로 표현되지 않는다) — 이것이 M2 전사 스프라이트 지적의 원인이었다(`m3-character-art-plan.md` 1장).
3. **CC0 소싱 우선 대상**: 캐릭터·몬스터 애니메이션 — 프레임 애니메이션은 **손그림 원본에서 자세·타이밍을 가져오는 것**이 절차 생성보다 품질이 높다. 출처·라이선스는 `godot\assets\CREDITS.md`(최소 크레딧) + `docs\art\ASSET_SOURCES.md`(전체 기록) 양쪽에 기록한다.
   - **"축소가 아니라 재작화" 원칙 (2026-07-27 신설)**: 원본 캔버스(64x64·100x100 등)를 20x36으로 단순 리샘플하면 무기·얼굴·손이 뭉개진다. **캔버스 크기가 아니라 실체(몸) 알파 bbox로 축소율 `r`을 산출**하고(목표 실체 약 15x33), `r ≥ 0.8`이면 NEAREST 축소 + 수동 정리 / `0.5 ≤ r < 0.8`이면 축소본을 초벌로만 쓰고 재작화 / `r < 0.5`면 원본을 참고 레이어로만 깔고 20x36에서 처음부터 그린다. 절차 상세는 `m3-character-art-plan.md` 4장.
   - **처리 순서 엄수**: **축소·재작화 → EDG32 재색상 → 아웃라인 보정.** 재색상을 먼저 하면 축소 보간으로 32색 밖 색이 다시 생긴다(M2에서 확인된 함정).
   - 공용 유틸 `sprite_source_common.recolor_ramp4`(휘도 5밴드 = 아웃라인 + 4단 램프)를 재사용한다.

4. **임포트**: Nearest 필터, mipmap 끄기. 공통 임포트 프리셋은 tech-artist가 구성.
5. **검증**: 커밋 전 팔레트 검증(32색 외 색 검출) + 캔버스 규격 검사 스크립트 통과 — pixel-artist가 검증 스크립트를 `tools\`에 작성해 공용화할 것. **캔버스 규격 검사값은 1-2절 표 갱신 시 함께 갱신**한다(현행 대상: 플레이어·인간형 20x36 / 뿔토끼 20x20 / 숲거미 28x24 / 임프 24x28 / 들개 마수 36x28 / 균열 점액 36x36).
