## 1. 레퍼런스의 역할

레퍼런스는 에셋·레이아웃·캐릭터를 복사하기 위한 자료가 아니다. 각 작품에서 아래 원리만 분리해 사용하며, 최종 결과는 아스터 왕국·동부 변경·계급 상승 서사에 맞는 원본 디자인으로 만든다.

| 레퍼런스 | 현재 역할 | 채택 원리 | 복사하지 않는 것 |
|---|---|---|---|
| **롬스테드** | G3 이후 **전체 아트 전환의 주 기준** | 프롭 밀도 증가, 128색 후보, 재질별 5~6단 명암, 부분 외곽선, zoom 3 비교 | 원본 에셋, 타일 패턴, 건물 배치, 화면 구도 |
| **《영주님은 방치중》** | **최종 캐릭터 리디자인** 참고 | 작은 화면에서도 읽히는 직업 실루엣, 의상 덩어리 구분, 무기 존재감, 친근한 인상 | 캐릭터 비율·복식·얼굴·무기 디자인의 직접 모사 |
| **Hearth and Hamlet** | **환경** 참고 | 아늑함, 생활 소품 군집, 촘촘하지만 길이 읽히는 마을, 자연과 건물의 부드러운 연결 | 마을 레이아웃, 건물 조합, 색 배치, 타일 구성 |
| **스톤샤드** | 아트 전환 기준에서 대체된 **결정 이력** | 현행 28×36·3.3등신·4단 명암의 근거 | 미래 룩·톤의 기준으로 사용하지 않음 |
| **스타듀밸리** | 화면 비율 검토 이력 | 16px 타일, 발밑 앵커, 상체 오버랩 비교 | 최종 화풍·캐릭터 디자인 |
| **Foozle Legend Main Character** | 픽셀 편입 반려 | 포즈·프레임 타이밍 참고 | 약 2등신 원본 픽셀 편입 |

## 2. 현재 제작 파이프라인

### 2-1. 캐릭터·무기

1. LPC 정적 레이어에서 몸·머리·의상 자세를 합성한다.
2. 실체 높이를 32~34px로 맞추고 28×36 캔버스의 발밑 하단 중앙에 정렬한다.
3. 검·활은 LPC 원본 픽셀을 그대로 축소하지 않고 최종 해상도에서 직접 그린다.
4. 각 프레임의 실제 피부 손 픽셀에 손잡이를 고정한다.
5. 팔레트·클리핑·손 접점·방향·공격 판정 시계를 검사한다.

공격 전용 64×64 투명 캔버스·8프레임은 검 베기 궤적을 담기 위한 상태별 예외다. 몸 크기와 발 위치는 28×36 기준을 유지한다. 상세 계약은 `sword-sweep-contract.md`를 따른다.

### 2-2. 환경·타일·소자산

- 현재 타일·아이콘·단순 오브젝트는 Pillow 절차 생성이 주력이다.
- 현행 동부 변경 타일은 16px·EDG32·대면적 지면 대비 규칙을 지킨다.
- 여울목 Phase C 파일럿은 기존 충돌·마커·통로를 보존하고 시각 레이어만 대표 샘플로 교체한다.
- 현재 타일 생성기를 곧바로 128색으로 바꾸지 않는다. 대표 샘플용 팔레트와 검증기가 승인된 뒤 기존 생성기를 대체하거나 병행한다.

### 2-3. 지금 고치는 것과 미루는 것

| 지금 수정 | 전체 리디자인 단계 |
|---|---|
| 걷기·공격 중 무기가 손에서 떨어짐 | 체형·두신비의 전면 변경 |
| 공격 방향과 무기 방향 불일치 | 10직업 최종 의상·실루엣 |
| 프레임 간 무기 순간이동·뒤집힘·크기 변화 | 머리카락·옷의 보조 동작 |
| 조준→사격, 준비→타격→복귀 연결 단절 | 모든 모션의 프레임 추가와 미적 완성 |
| 모션 접촉 시점과 실제 판정 불일치 | 128색·5~6단·부분 외곽선의 전체 적용 |

## 3. 생성 도구 실측 판정

| 기준 | 현행 LPC + Pillow | SpriteCook | PixelLab |
|---|---|---|---|
| 판정 | **현재 사용** | **반려** | **Phase C 조건부 후보** |
| 캐릭터 색 수 | EDG32 안 | 2,071~8,640 | 41~49 |
| 캔버스 | 28×36 중심, 공격 예외 64×64 | 72~200px 제각각 | 92×92 고정, 실체 높이 66~72px |
| 방향·애니메이션 | 3방향, 필요한 상태를 자체 매핑 | 방향 없음, 정지 1장 | 4방향, 걷기 4프레임×4방향 |
| 타일 | Pillow 16px | 단일 이미지 | 16px Wang 타일 4×4 지원 |
| 현재 위험 | 자세·모션 수작업 비용 | 픽셀아트·스케일·애니메이션 부적합 | 장비 소실, 5.5등신 출력, 서비스 약관 재확인 |

### 3-1. SpriteCook — 반려

Mini Pack 9종의 색 수가 2,071~8,640색이고 캔버스도 72~200px로 일관되지 않았다. 정지 이미지뿐이라 방향과 애니메이션 비용을 해결하지 못한다. Grass Floor의 심 없는 타일링과 Warrior 시안의 실루엣은 참고 가치만 남긴다. 원본은 `_raw_src\spritecook_trial\`에 두고 커밋하지 않는다.

### 3-2. PixelLab — 조건부 후보

PixelLab 실측 출력은 안티에일리어싱이 없고 4방향 캐릭터와 16px Wang 타일을 제공해 기술 호환성은 높다. 그러나 현재 출력은 다음 이유로 바로 편입할 수 없다.

- 요청 `size:64`에서 실제 92×92 캔버스, 실체 높이 66~72px가 나온다.
- 기본 출력은 약 5.5등신으로 현재 3.3등신과 다르다.
- 걷기 프레임에서 방패·검이 사라져 장비 연속성이 깨진다.
- 서비스 출력물 이용 조건은 실제 채택 시점에 다시 확인해야 한다.

고비용 호출인 `create_image_pro`, `create_ui_asset`, `create_8_direction_object`는 대표 샘플의 저비용 검증을 통과하기 전에 사용하지 않는다.

## 4. PixelLab·Godot 연결 규칙

### 4-1. 접속과 보안

- PixelLab MCP 주소는 `https://api.pixellab.ai/mcp`다.
- 인증 값은 Windows 사용자 환경변수 `PIXELLAB_API_KEY`로만 관리한다.
- 키를 코드·문서·커밋·`.env`에 넣지 않는다.
- 환경변수 참조가 MCP 클라이언트에서 확장되지 않으면 토큰을 복사해 설정 파일에 넣지 말고, 환경변수를 읽는 로컬 호출 스크립트로 전환한다.

### 4-2. Wang 메타데이터 — 해소됨

16개 타일을 전수 대조한 결과 `corners`가 `wang_N` 비트와 16/16 일치했고, `pattern_4x4`는 16/16 불일치했다.

- Godot 배선은 `corners`만 사용한다.
- 비트 순서는 `NW, NE, SW, SE`의 MSB 우선이며 `upper=1`이다.
- `pattern_4x4`는 무시한다.
- 검증은 `wang_N`에서 코너 비트를 복원해 `corners`와 16/16 일치하는지 확인한다.

## 5. Phase C 착수 전 검증 2건

### 5-1. 장비 프레임 연속성

현재 시험 출력은 east 4프레임 중 방패가 한 프레임에만 남고 north에서 방패·검이 사라진다. 다음 순서로 캐릭터 1종·걷기 1방향만 시험한다.

1. `mode="v3"`로 생성한다.
2. 같은 조건에서 `frame_count=8`을 시험한다.
3. 두 방법 모두 실패하면 몸과 장비를 별도 레이어로 생성·합성한다.
4. 모든 프레임에서 장비 종류·크기·손 접점·앞뒤 레이어가 유지될 때만 통과한다.

### 5-2. 3.3등신 재현

먼저 `create_character`의 `proportions`로 현재 실체 비율을 재현할 수 있는지 검증한다.

| 결과 | 처리 |
|---|---|
| 3.3등신과 장비 연속성 모두 통과 | PixelLab을 대표 샘플 도구로 채택하고 28×36 또는 새 트림 규격을 수치화한다. |
| 3.3등신 실패, 장비 연속성 통과 | 5.5등신 상향안과 PixelLab 미채택안을 비용표와 함께 디렉터에게 상정한다. 자동으로 규격을 바꾸지 않는다. |
| 장비 연속성 실패 | 캐릭터 생성 도구로 채택하지 않는다. 타일 도구만 별도 판정할 수 있다. |

5.5등신 상향은 캐릭터 PNG만의 변경이 아니다. 캔버스·콜리전·앵커·씬 offset·카메라·공격 거리 체감을 함께 재검증해야 하므로 대표 샘플 승인 없이 `STYLE_GUIDE`에 반영하지 않는다.

## 6. 대표 샘플 실행 순서

1. **G3 기준 고정**: 현재 LPC·EDG32·zoom 4 빌드의 여울목 낮/밤, 1대1 전투, 다수전 화면을 캡처한다.
2. **도구 선결 검증**: 장비 연속성과 3.3등신을 한 번의 최소 생성 실험으로 판정한다.
3. **규격 초안**: 프로젝트용 128색 팔레트, 5~6단 재질 램프, 부분 외곽선 조건을 대표 샘플 전용으로 작성한다.
4. **대표 세트 제작**: 여울목 지형 1세트, 플레이어 1직업, 근접 몬스터 1종, 원거리 몬스터 1종, 전투 FX 일부만 만든다.
5. **zoom 비교**: 같은 위치와 입력에서 zoom 4와 3을 비교한다.
6. **게이트**: 가독성, 명암, 충돌 박스 체감, 공격 거리 체감, 픽셀 밀도, 낮/밤을 함께 판정한다.
7. **승인 후 문서 전환**: `STYLE_GUIDE` 수치, `PIPELINE` 줌, 팔레트·검증기, `ASSET_SOURCES` AI 생성 항목을 한 작업 단위로 갱신한다.
8. **카테고리별 확대**: 기능 시스템 변경과 섞지 않고 아트 카테고리별로 교체한다.

### 대표 샘플 통과 기준

- 여울목이 수선 중인 생활 공간으로 읽히며 길·출입구·교전면이 먼저 보인다.
- 플레이어·적·투사체·아이템 드롭·공격 예고가 배경보다 먼저 읽힌다.
- 무기와 손, 공격 방향, 판정 시점이 현재 빌드보다 나빠지지 않는다.
- 기존 통로·충돌·스폰·퀘스트 마커가 유지된다.
- zoom 3에서 공격 사거리와 이동 속도가 잘못 느껴지지 않는다.
- 대표 샘플의 생성·후처리·검증을 같은 입력으로 재현할 수 있다.
