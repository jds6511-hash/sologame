## 1. 설계 원칙 — 강제 팝업 최소화

`ux-foundation.md` 1장 설계 원칙(전투 중 손은 항상 전투에 / 정보 위계)을 온보딩에도 그대로 적용한다. 실시간 액션 게임에서 조작을 멈추고 글을 읽게 하는 튜토리얼은 그 자체로 첫인상을 해친다 — **아래 6원칙을 모든 온보딩 요소에 강제한다.**

| # | 원칙 | 구현 방식 |
|---|---|---|
| 1 | **모달 금지** | 온보딩 힌트는 게임을 일시정지하지 않는다. 입력을 막지 않는다. "확인" 버튼이 있는 팝업창을 만들지 않는다 — 전부 HUD 위에 얹히는 반투명 오버레이다. |
| 2 | **진행 게이트는 퀘스트 목표뿐** | 힌트를 읽었는지, 힌트대로 했는지는 퀘스트 진행 조건이 아니다. 진행 조건은 오직 퀘스트 프리미티브(REACH/KILL 등)뿐이다. 플레이어가 힌트를 무시하고 자기 방식대로 이동·공격해도 막지 않는다. |
| 3 | **자동 소멸** | 힌트는 해제 조건 충족 시 0.3초 페이드아웃으로 스스로 사라진다. 닫기 버튼·키를 만들지 않는다. |
| 4 | **절제된 재노출** | 조건 미충족 시 8초 후 페이드아웃, 15초 후 재노출 — **최대 3회**까지만. 3회를 넘기면 조용히 포기한다(퀘스트 트래커 D가 계속 다음 목표를 알려주므로 힌트가 없어도 진행은 가능하다). |
| 5 | **숙련자 자동 생략** | 힌트가 뜨기 전에 플레이어가 이미 해당 조작을 스스로 수행하면 힌트 자체를 표시하지 않는다 (예: 이동 힌트가 뜨기 전에 이미 WASD를 눌렀다면 생략). |
| 6 | **1회 학습·세이브 영구 해제** | 6단계 전부 완료 시 세이브 데이터에 `tutorial_done=true` 플래그를 기록한다. 이후 같은 세이브(사망 후 재도전, 챕터 재방문 등)에서는 어떤 온보딩 힌트도 다시 뜨지 않는다. |

- **시스템 텍스트 vs 서사 대사 분리**: 본 문서의 힌트 문구("W A S D 로 이동하세요" 등)는 시스템 UI 텍스트이며, NPC 대사·퀘스트 텍스트(서사)는 narrative-designer·quest-designer 소관이다. 힌트는 대사창(S12)이 아니라 HUD 오버레이에만 나타난다 — 대화 중에는 온보딩 힌트를 띄우지 않는다(`ux-foundation.md` 4장 "모달 우선" 규칙과 동일).

## 2. 첫 10분 개요 — MQ-01~05 배치

`quest-structure.md` 3장: 1장 "모험가 패" = 여울목 부락, Lv1~4, 5퀘, 경험치 200, R1=0, "튜토리얼 겸용". 개별 퀘스트 내용은 아직 미확정(quest-designer M2+ 작업)이므로, 아래는 **온보딩 6단계를 수납하기 위한 제안 배치**다.

| 퀘스트 | 제안 내용 | 온보딩 담당 구간 | 상태 |
|---|---|---|---|
| MQ-01 | "눈을 뜨다" (가칭) — 여울목 부락 어귀에서 시작, 마을 안 NPC(선배 모험가/조합장)에게 이동해 대화 (REACH→TALK) | **1단계(이동)** | 제안 — quest-designer 확정 필요 |
| MQ-02 | "토끼몰이" (가칭) — NPC의 첫 의뢰로 마을 밖 초원(뿔토끼 서식지)에서 **뿔토끼 2마리 처치** 후 복귀 보고 (TALK→KILL→TALK, 토벌 유형 표준 패턴) | **2~6단계(기본 공격·회피·스킬·첫 처치·루팅)** 전부 | 제안 — quest-designer 확정 필요 (특히 **목표 수량 2마리** — 1마리째는 회피 학습까지 담당하고 처치를 강제하지 않으며, 2마리째에서 스킬 사용→첫 처치→루팅이 이어지도록 설계했다. 1마리 목표면 6단계 순서를 다 담을 수 없다) |
| MQ-03~05 | 이후 마을 정착·주변 탐색 서사 (내용은 quest-designer 소관, 온보딩 범위 밖) | 질주·응급 처치의 **지연 노출**(5장) | quest-designer 소관 |

- **무대 확인 필요(level-designer 연계)**: 뿔토끼 서식지가 여울목 부락에서 도보 30초 이내(가까운 거리)에 배치되어야 첫 10분 타임라인이 성립한다. `world-structure.md` 4장 뿔토끼 서식 권역 = "동부 들녘"으로 여울목과 인접 — MP-3(맵 씬 구성) 작업 시 이 근접성을 확인 요청.
- **몬스터 근거**: `m2-monster-spec.md` 3-1장이 뿔토끼를 "첫 처치·루팅 튜토리얼의 실제 대상"으로 이미 지정했고, 무리 구성 1~3마리·비어그로 공유(2-3단계에서 개별 개체로 안전하게 연습 가능)·근접 스윙 예고 0.4초(회피 학습에 적합한 가장 느슨한 예고)까지 온보딩 목적에 맞게 설계돼 있다. 본 문서는 그 스펙을 그대로 사용한다.

## 3. 조작 학습 순서 — 6단계 상세

### 공통 UI 컴포넌트: 온보딩 힌트 바 (T)

신규 HUD 요소 1개만 추가한다. 나머지는 `ux-foundation.md` 5장 기존 HUD 요소(F 스킬바, I 상호작용 프롬프트, E 알림 토스트)를 그대로 재사용한다.

```
┌────────────────────────────────────────────────────────────────┐
│           (T)┌──────────────────────────────────┐              │
│              │ ⌨  W A S D 로 이동하세요           │              │
│              └──────────────────────────────────┘              │
│                     (필드 / 전투 영역)                           │
```

| 항목 | 값 |
|---|---|
| 위치 | 상단 중앙 (340, 24) — `ux-foundation.md` HUD 요소 **H(보스 HP 바)**와 동일 좌표 재사용 |
| 크기 | 600 x 40 |
| 배경 | 검정 60% 반투명, 모서리 둥근 사각형, 테두리 없음 |
| 글자 크기 | 16px (본문 규칙 준수, `ux-foundation.md` 5-1) |
| 구성 | 좌측 아이콘(24x24, 키/입력 아이콘) + 우측 문구 |
| 좌표 충돌 검토 | H(보스 HP 바)는 보스전에만 표시되는데, 온보딩 6단계는 전부 Lv1~4(챕터 1)에서 끝나고 첫 보스(B1, 권장 Lv15)는 챕터 2 이후 — **동시 표시 시점이 존재하지 않아 좌표 재사용에 문제 없음** |
| 전환 | 페이드인 0.3초 / 페이드아웃 0.3초. 슬라이드·바운스 등 과장된 연출 없음(주의를 필요 이상으로 끌지 않음) |

### 3-1. 1단계 — 이동 (WASD)

| 항목 | 값 |
|---|---|
| 트리거 | 게임 시작(New Game) 직후, MQ-01 자동 수령 시점 |
| 노출 유예 | 즉시 판정 시작 — 힌트가 뜨기 전에 플레이어가 이미 WASD 중 하나라도 눌렀다면 힌트 자체를 생략(원칙 5) |
| 표시 위치 | T 바 |
| 문구 | `⌨ W A S D 로 이동하세요` |
| 해제 조건 | 시작 지점 기준 누적 이동 거리 3타일 이상 (방향 무관) |
| 강제성 | 없음 — 미이동 상태에서도 좌클릭·스킬 등 다른 입력은 자유 |

### 3-2. 2단계 — 기본 공격 (마우스 좌클릭)

| 항목 | 값 |
|---|---|
| 트리거 | MQ-02 수령 + 뿔토끼 서식지 진입, 뿔토끼가 처음으로 3타일 이내 근접 |
| 표시 위치 | T 바 + 뿔토끼 머리 위 월드 프롬프트(기존 HUD 요소 **I** 상호작용 프롬프트와 동일 스타일 — 월드 좌표 추종, 대상 상단) |
| 문구 | T 바: `🖱 마우스 좌클릭으로 공격하세요` / 월드 프롬프트: `[좌클릭] 공격` |
| 해제 조건 | 좌클릭 기본 공격으로 몬스터에게 유효 타격 1회 |
| 강제성 | 없음. 이 시점의 뿔토끼는 처치를 요구하지 않는다 — 몇 대 맞고 도주해도 정상(5단계에서 실제 처치) |

### 3-3. 3단계 — 회피 (Space)

뿔토끼의 두 가지 행동(도주/반격)을 그대로 이용해 **Space의 두 쓰임(거리 좁히기·공격 회피)**을 모두 자연스럽게 익히게 한다 (`m2-monster-spec.md` 3-1 상태 전이 그대로).

| 하위 계기 | 트리거 | 문구 (T 바) | 해제 조건 |
|---|---|---|---|
| (a) 추격 대시 | 뿔토끼가 [도주] 상태 진입(플레이어 인지범위 3타일 진입 직후) | `⎵ Space 로 대시해 거리를 좁히세요` | Space 입력 1회 (따라잡기 성공 여부 무관 — 입력 자체로 학습 인정) |
| (b) 반격 회피 | 뿔토끼가 도주 실패로 붙잡혀 근접 스윙(박치기) 예고 모션 시작 (0.4초 예고) | `⎵ 적이 공격을 예고하면 Space 로 피하세요` + 뿔토끼 위 짧은 경고 아이콘(0.4초, 붉은 느낌표) | 예고 시작 후 0.6초 이내 Space 입력 (실제 무적 프레임 판정 성공 여부와 무관 — 입력 자체로 학습 인정) |

- 강제성 없음: (b)에서 회피에 실패해 맞아도 뿔토끼 공격력은 15(Lv1 기준)로 페널티가 미미하다 — 실패해도 진행을 막지 않는다.
- (a)(b) 둘 다 원칙 4(절제된 재노출)를 따른다: 각 하위 계기당 최대 3회.

### 3-4. 4단계 — 스킬 (슬롯 1: 강타)

| 항목 | 값 |
|---|---|
| 트리거 | 두 번째 뿔토끼에게 기본 공격 유효 타격 2회 이상 누적 (아직 처치되지 않은 상태) |
| 표시 위치 | T 바 + 스킬 슬롯 바(기존 HUD 요소 **F**) 슬롯 1 칸에 테두리 강조(신규 UI 없음, 기존 슬롯 강조만 추가) |
| 문구 | `① 1번 키로 스킬 [강타]를 사용해보세요` |
| 해제 조건 | 슬롯 1(강타) 입력 1회 (적중 여부 무관 — 시전 자체로 학습 인정) |
| 강제성 | 없음 — 스킬을 쓰지 않고 기본 공격만으로 처치해도 무방(아래 5단계 참고) |

### 3-5. 5단계 — 첫 처치

| 항목 | 값 |
|---|---|
| 트리거 | 뿔토끼 HP 0 (2마리 중 어느 쪽이든 첫 처치 시점) |
| 표시 위치 | 기존 HUD 요소 **E**(알림 토스트, 우측 중하단) 재사용 — 신규 UI 없음 |
| 문구 | `첫 처치! 경험치 +5` (경험치 수치는 `m2-monster-spec.md` 2장 Lv1 경험치 5 그대로 인용 — 실제 노출 수치는 밸런스 조정 시 자동 반영) |
| 지속 시간 | 2초 후 자동 소멸 (다른 알림 토스트와 동일 규칙, `ux-foundation.md` 5장) |
| 강제성 | 없음. 스킬로 마무리하든 기본 공격으로 마무리하든 동일하게 발생 — **순서를 강제하는 것은 4단계까지의 힌트 노출 타이밍이지, 처치 방식 자체가 아니다.** 만약 플레이어가 4단계 힌트를 무시하고 첫 뿔토끼를 기본 공격만으로 먼저 처치해버려도 진행은 막지 않는다 — 이 경우 스킬 힌트(4단계)는 두 번째 뿔토끼에게 이월된다. |

### 3-6. 6단계 — 루팅

| 항목 | 값 |
|---|---|
| 트리거 | 뿔토끼 사망 직후, 사망 지점에 드랍 아이템 생성 (`m2-monster-spec.md` 4-1장 드랍 테이블 — 골드 100% + 재료 30% + 포션 2% 등) |
| 표시 위치 | 사망 지점 위 월드 아이콘(반짝이는 주머니, 12x12) + 근접 시 상호작용 프롬프트(기존 HUD 요소 **I**와 동일 스타일) |
| 문구 | 최초 1회만 T 바에 `F 키로 드랍 아이템을 주우세요` 병행 표시, 월드 프롬프트는 상시 `[F] 줍기` |
| 해제 조건 | F 입력으로 드랍 아이템 1회 획득 |
| 강제성 | 없음 — 줍지 않고 지나쳐도 진행 막지 않음(드랍물은 계속 필드에 남는다). 완료 시 `tutorial_done=true` 플래그 기록(1장 원칙 6) |

- **systems-dev 확인 필요**: "근접 시 F 프롬프트로 개별 루팅"은 본 문서가 제안하는 규칙이다. `combat.md` 2장 핵심 루프에는 "루팅(펫 자동 줍기)"라는 표현이 있으나, 펫은 M2 범위 밖(수집 시스템 미구현)이므로 튜토리얼 시점에는 펫이 없다. IT-3(인벤토리 최소 기능: 줍기·장착·버리기) 구현 시 실제 루팅 방식(F 프롬프트 vs 자동 획득)을 systems-dev가 확정하고, 본 문서와 다르면 이 절만 갱신 요청.

## 4. 지연 노출 — 질주·응급 처치 (5~7단계는 아니지만 챕터 1 내 노출)

`m2-warrior-skills.md` 4장의 모험가 공용 스킬 3종(강타/질주/응급 처치)은 전부 Lv1부터 사용 가능하지만, 첫 10분에 3개를 전부 가르치면 정보 과부하다. **질주·응급 처치는 첫 10분 밖(MQ-03~05 구간)에서 상황이 맞을 때 1회씩만** 가르친다 — 온보딩 6단계 완료(`tutorial_done=true`) 이후에도 이 2개는 별도 플래그(`hint_dash_done`, `hint_heal_done`)로 독립 관리한다.

| 스킬 | 트리거 (최초 1회) | 문구 (T 바) | 해제 조건 |
|---|---|---|---|
| 질주 (슬롯 2) | 퀘스트 목표 지점이 현재 위치에서 15타일 이상 떨어진 REACH 목표를 처음 수령했을 때 | `② 먼 거리는 2번 키 [질주]가 유용합니다` | 슬롯 2 입력 1회 또는 8초 후 자동 소멸(재노출 없음 — 1회성 힌트) |
| 응급 처치 (슬롯 3) | 전투 중 HP가 처음으로 50% 이하로 떨어졌을 때 | `③ HP가 낮으면 3번 키로 [응급 처치]를 사용할 수 있습니다` | 슬롯 3 입력 1회 또는 8초 후 자동 소멸(재노출 없음 — 1회성 힌트) |

- 두 힌트 모두 원칙 1~3(모달 금지·게이트 아님·자동 소멸)을 그대로 따르되, 원칙 4(절제된 재노출)는 적용하지 않는다 — 1회 노출·미반응 시 조용히 소멸하고 다시 뜨지 않는다(챕터 1 전체를 통틀어 급하지 않은 보조 정보이므로 나그다이는 것 자체가 과함).
- **quest-designer 연계 필요**: MQ-03~05 중 하나가 "먼 거리 REACH" 목표를 자연스럽게 포함하는지 확인 요청 — 없다면 질주 힌트가 챕터 1 내내 안 뜰 수 있음(치명적이지 않음: 힌트가 늦게 뜨는 것은 괜찮으나, 아예 안 뜨는 상황은 피하는 게 좋음).

## 6. 접근성

`ux-foundation.md` 6장 접근성 체크리스트를 온보딩 요소에도 동일 적용한다.

- T 바 글자 16px(본문 기준 이상), 대비 4.5:1 이상(검정 60% 배경 + 흰 텍스트로 검증 필요 — tech-artist/ui-dev 구현 시 실측).
- 키 입력 안내는 **아이콘 + 텍스트 병기** (예: ⌨ 아이콘 + "WASD" 텍스트) — 색상만으로 구분하지 않는다.
- 월드 경고 아이콘(3-3절 (b) 반격 회피)은 색(붉은색) + 형태(느낌표) 이중 신호 — `ux-foundation.md` 1장 5번 원칙 그대로.
- HUD 토글(H 키)로 HUD 전체를 끄면 온보딩 힌트(T 바 포함)도 함께 숨겨진다 — 단 언제든 H를 다시 눌러 확인 가능하므로 진행에 지장 없음.
