# 실제 월드 실행 테스트 — 입력·전투·아이템·UI

- **최종 수정일**: 2026-09-11
- **담당**: Codex
- **대상**: `0e37423` 기준 게임 구현, Godot 4.7.1 stable, Windows / NVIDIA RTX 3060 Laptop GPU.
- **의존 문서**: [기존 정밀 점검](project-audit-2026-09-11.md), [M3 게이트 체크리스트](m3-gate-checklist.md), [테스트 도구](tools/runtime_playtest_2026_09_11.gd).
- **변경 이력**:
  - 2026-09-11: 실제 월드 씬 렌더링·입력 주입·화면 확인과 전체 GUT 테스트를 실행하고 결과를 기록했다.

## 1. 범위와 판정

**이동·메뉴·전직·사망/부활은 동작하지만, 아이템 회수와 회복 제한 및 반복 타격 오류를 해결해야 한다.** 기존 자동 테스트만으로 실제 플레이 준비 완료를 판정할 수 없다.

시작 지역과 신규 적 필드의 실제 씬을 로드했다. 키 입력은 `InputEventKey`, 공격은 마우스 버튼 입력으로 주입했다. 궁수 조준은 게임 뷰포트 입력과 커서 이동을 사용했다. 화면은 Compatibility 렌더러로 저장해 확인했다. 최종 검사는 1920×1080 창이며 초기 960×540 시험에서 발생한 조준 좌표 문제는 게임 결함으로 집계하지 않는다.

전투 장소 진입은 순간이동, 상위 직업 접근은 기존 디버그 레벨 키, 사망 준비와 처치 보상 대조군은 피해 API를 사용했다. 아이템 줍기는 원본 `world_item.tscn`에 실제 포션 데이터를 넣어 플레이어 옆에 생성했다. 감지 마스크 대조군은 실행 중 테스트 아이템에만 적용했다. 게임 소스·씬·설정·밸런스·음악 파일을 수정하지 않았다.

이 검사는 입력과 시스템 연결을 확인하는 짧은 자동 실행이다. 자유 플레이의 재미, 회피의 체감 난이도, 1→10레벨 소요 시간, 장시간 안정성, 소리, 저장/로드는 판정하지 않았다. 오디오는 Dummy 드라이버로 실행했다. G3 디렉터 승인도 대신하지 않는다.

## 2. 확인한 정상 동작

최종 통합 실행은 **23.2초, 검사 37건 중 통과 34·실패 3**이었다. 실패 3건은 원본 아이템 줍기·빈 가방 물약 사용·미니맵 적 표시다. 이 카운트와 별도로 엔진 오류 7건(사망 시그널 중복 연결), 비유한 벡터 경고 1,529건을 기록했다. GDScript `SCRIPT ERROR`는 0건이다. 경고가 집중된 실행이므로 정상 플레이 판정은 아니다. 도구의 `gdformat`·`gdlint` 검사는 통과했다.

| 항목 | 관찰 |

| 전체 GUT | 93개 스크립트, **856/856 통과**, 어서션 2,809, deprecated 8건 |
| 시작 지역·신규 적 필드 | 실제 씬 로드와 몬스터 스폰 확인 |
| 이동·회피 | D 0.6초 입력으로 약 31.65px 이동, Space 회피 시 충전 2→1 |

## 3. 발견 사항

### RT01 · P1 · 바닥 아이템을 감지하지 못해 F로 주울 수 없음

- **재현**: 시작 지역 플레이어 위치에 원본 월드 아이템 씬으로 하급 포션 1개 생성 → 근접 상태에서 F 입력 → 가방에 들어오지 않고 월드에 남는다.
- **근거**: [world_item.tscn](../../godot/scenes/items/world_item.tscn)은 `collision_mask`를 지정하지 않아 기본값 1이다. [player.tscn](../../godot/scenes/player/player.tscn)의 플레이어 `collision_layer`는 2다. 실행 중에도 mask=1, layer=2, 감지 body=0을 확인했다.
- **영향**: 물약·재료·장비 획득 및 아이템 줍기 튜토리얼을 막는다. 아이템 데이터 API를 직접 호출하는 테스트로는 발견되지 않는다.
- **대조 실험**: 테스트 아이템의 감지 마스크를 2로 바꾸고 감지 범위를 재진입한 뒤 같은 F 입력을 주면 감지 body=1, 인벤토리 연결=true가 되고, 아이템 제거·`POT-HP-1` 보유량 1을 확인했다. 원본 씬은 변경하지 않았다. 입력은 `_process` 직전에 주입해 `just_pressed`가 프레임 경계에서 사라지는 테스트 도구의 오차를 제거했다.
- **완료 기준**: 원본 월드 아이템이 플레이어를 감지하고 F 프롬프트·획득·월드 오브젝트 제거까지 연결될 것. 가방이 찬 경우에는 아이템이 유지되고 실패가 안내될 것.

### RT02 · P2 · 빈 가방에서도 5번 키로 회복

- **재현**: 포션 0개, HP 54/135에서 5번 입력 → HP **94.5/135**, `potion_used` 1회, 가방은 계속 비어 있다.
- **원인**: [player_controller.gd](../../godot/scripts/player/player_controller.gd)의 `_process_potion_input()`이 인벤토리를 거치지 않고 스탯 컴포넌트의 기본 30% 회복을 호출한다.
- **관계**: 기존 점검 A05를 실제 키 이벤트 경로까지 확인한 결과다. 소비 경제·포션 부족 난이도 관찰을 왜곡한다.
- **완료 기준**: 보유 포션 종류·수량 확인, 데이터 회복량 적용, 성공 시 1개 차감. 재고가 없으면 회복하지 않을 것.

### RT03 · P2 · 반복 명중 시 사망 시그널 중복 연결 오류

- **재현**: 신규 적 필드의 궁수로 같은 임프를 반복 사격하면 `Signal 'died' is already connected` 오류가 기록된다.
- **근거**: [player_attack_resolver.gd](../../godot/scripts/combat/player_attack_resolver.gd)의 `_on_attack_hit()` 88행은 매 타격마다 `died.connect(..., CONNECT_ONE_SHOT)`을 실행한다. 최초 연결은 적이 죽기 전까지 남아 있으므로 다음 명중에서 재연결을 시도한다.
- **영향**: 실제 전투 중 엔진 오류가 반복된다. 이번 실행에서 오류로 프로세스가 종료되지는 않았다.
- **완료 기준**: 살아 있는 동일 적을 여러 번 타격해도 오류가 없고, 사망 효과는 사망 시 한 번 발생할 것. 움직이는 적과 고정된 적을 모두 검사할 것.

### RT04 · P2 · 교전 중 미니맵 적 표시 없음

- **관찰**: 적과 교전해도 미니맵은 플레이어 화살표만 보인다. 몬스터 스폰 수가 양수인데 `monsters` 그룹 수는 0이다.
- **원인**: [minimap_display.gd](../../godot/scripts/ui/minimap_display.gd)는 해당 그룹에서만 적을 찾는다. 현재 스포너는 그룹에 등록하지 않는다. 공격 자동 조준에는 별도 트리 탐색 대체 경로가 있어 이 문제와 구분해야 한다.
- **범위**: 지형 미니맵과 NPC·퀘스트 표시는 기존 미구현 범위다. 이번 지적은 이미 존재하는 몬스터 표시의 연결 누락이다.
- **완료 기준**: 근처 적의 위치가 반영되고, 사망·재스폰 때 표시도 갱신될 것.

### RT05 · 조사 필요 · 타격 중 비유한 벡터 경고

궁수 교전 진단 실행에서 `Vector2 cannot be normalized, the elements must be finite` 경고가 반복됐다. 스택은 [imp_monster.gd](../../godot/scripts/ai/imp_monster.gd)의 `move_and_slide()` 호출 위치를 가리킨다. 히트스톱이 시간 배율을 0으로 만드는 구간과의 관련성은 조사 가설이며, 이번 테스트로 원인을 확정하지 않았다. 타격·경직·이동을 함께 실행하는 물리 프레임 단위 재현이 필요하다. 경고만으로 저장 데이터 손상이나 영구 좌표 오염을 주장하지 않는다.

## 4. 화면 관찰과 남은 범위

시작 화면, 캐릭터 정보, 스킬 목록, 부활 후 화면, 검투사 HUD, 궁수 교전 화면을 확인했다. 캐릭터·스킬 정보는 표시되지만 메뉴 상단 탭 글자가 본문보다 상당히 작다. 읽기 편한지는 실제 사용자의 화면 크기에서 추가 확인이 필요하다. 인벤토리·저널·지도·도감의 미완성 상태는 기존 범위이며, 탭이 열린다고 기능이 완성된 것은 아니다.

이번에는 보스 공략·정예 그로기·야간 전환·자연 재스폰 대기·NPC 대화·퀘스트 완주·장비 외형·게임패드·해상도별 UI 전체를 검사하지 않았다.

## 5. 재실행과 근거

저장소 루트에서 설치된 Godot 실행 파일을 사용한다.

```powershell
godot --headless --path godot -s addons/gut/gut_cmdln.gd -gdir=res://test -ginclude_subdirs -gexit
godot --path godot --rendering-method gl_compatibility --audio-driver Dummy --resolution 1920x1080 --script ../docs/qa/tools/runtime_playtest_2026_09_11.gd
```

스크립트 경로의 상대 해석이 다른 실행 환경에서는 `--script`에 저장소 내 해당 파일의 절대 경로를 준다. `-- --combat-only`를 덧붙이면 궁수 교전만 실행한다. 창과 커서를 사용하는 자동 검사이므로 실행 중 게임 창을 수동 조작하지 않는다. 실패한 검사가 있으면 종료 코드 1을 요청하며, 엔진 오류는 검사 카운트와 별개로 로그도 확인해야 한다. 120초 제한 초과 시 종료 코드 2를 요청한다.

로그·스크린샷은 로컬 QA 자료로 유지하고 커밋하지 않는다. 문서와 재실행 도구만 저장한다. **수정 우선순위는 RT01 아이템 회수 → RT02 물약 입력 → RT03 반복 타격 오류**다.
