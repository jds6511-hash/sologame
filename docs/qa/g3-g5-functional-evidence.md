# G3~G5 기능 증거와 리디자인 검수의 구분

- 의존: [G3 체크리스트](m3-gate-checklist.md), [저장 G4](../design/systems/save-load.md), [연속 플레이](yeoulmok-play-session-review-request.md)

## 현행 판단

미감·최종 캐릭터 비례·의상·무기 디자인은 **그래픽 리디자인 이후** 평가한다. 이 항목을 지금 완성시키려고 미세 조정을 반복하지 않는다. 그렇다고 기능 검사·동작 결함·게이트 판정을 모두 사람 플레이 대기로 남기지 않는다.

| 항목 | 확인한 것 | 남은 것 |
|---|---|---|
| 전사 좌우 손 교체 | player_visual_module.update가 side+왼쪽에 flip_h 적용. 몸/검 합성 시트 전체가 뒤집힘. 현 STYLE_GUIDE의 미러 허용 계약과 일치 | 디렉터가 지적한 어색함은 **미해결**. 손 좌표 오류가 아니며 좌우 전용 원화가 필요. 지금 코드에서 flip_h만 끄면 왼쪽 이동 때 오른쪽을 보므로 수정안으로 쓰지 않음 |
| 궁수 작은 활 | aim/attack/rollshot의 크기 인자6 고정. 손 접점·머리 보존 검사 통과. 검증 생성 PNG와 실제 배포 전투 시트3장 바이트 동일 | 몸 대비 비례·활 모양의 적정성은 리디자인 검수. 이 검사로 보기 좋다고 주장하지 않음 |
| 이상한 화살 | ArrowProjectile은 충돌 폭을 반올림한 두께, 그3배 길이의 단색 사각형 임시 그림. 방향은 launch에서 회전, 판정은 별도 Area2D | 화살촉/깃/몸체·활에서 나오는 시각 접점은 미완료. 표시를 교체할 때 판정 폭/사거리까지 같이 바꾸지 말 것 |

전사 손 일관성은 새 원화의 필수 조건으로 남기며, 이번 작업으로 고쳤다고 표시하지 않는다. 런타임 좌우 프레임 지원·좌우 원화 제작·대기/이동/공격 전환 검증을 함께 해야 한다. 현재 배포 시트에는 독립 왼쪽 프레임이 없다. 최종 비례 작업을 미뤄도 손-무기 분리·조준/발사 방향·판정 타이밍 오류는 별도로 즉시 처리한다.

## 게이트별 증거 상태

| 게이트 | 자동 기능 증거 | 승인/검증 공백 |
|---|---|---|
| G3 전투 | GUT의 검 휘두름 단계·궁수 조준/회피·화살 이동/관통/사거리·피해 계산, Python 무기 접점·궁수 전투 시트 검사 | 전사 손 교체 미해결, 전체 직업/실전 다수전 가독성·체감 미판정. 최종 미감은 리디자인 후 |
| G4 저장 | 파일/codec/세션 GUT + 실제로 걸은 위치를 저장하고 다른 프로세스에서 복원. 슬롯2 해시 보존·새 캐릭터 슬롯1 보존 | OS 키로 F6 조작·사용자 체감 승인 별도. 자동검증이 장비 미배선 등 기존 제한을 해소한 것은 아님 |
| G5 의뢰 | 의뢰 GUT + MQ05 보고/보상/지역 왕복·노베라 대화·재실행 보존 | MQ01~04는 여행 probe에서 fixture. 모든 의뢰를 처음부터 실제 처치/선택으로 수행한 종단 간 검증은 아님 |

**G3/G4/G5 전체 통과를 선언하지 않는다.** 미감 보류를 기능 검사의 보류로 확대하지 않으며, 자동 기능 PASS를 디렉터 승인으로 바꾸지도 않는다.

## 통합 재실행

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File docs/qa/tools/run_functional_gates.ps1
```

궁수 생성/배포4검사 → 무기 배치10검사 → 전체 GUT → 여행 cleanup/depart/return/reload/cleanup을 실행한다. 프로세스 종료 코드·SCRIPT ERROR·일반 ERROR·단계 PASS 마커를 함께 검사하며 하나라도 실패하면 중단한다. 단 GUT의 의도적 저장 I/O 실패는 정확한 `user://m4_test_<숫자>/file/child` 생성 오류와 ExpectedError 기록이 함께 있을 때만 제외한다. 외부 LPC 원본이 없어 Python 검사가 skip되면 통과시키지 않는다. 이전 결과 JSON은 시작 시 running으로 교체하고, 실패는 failed, 성공은 functional_evidence_pass로 기록한다. 출력은 ignored `docs/qa/screenshots/functional-gates/`다. 여행 cleanup은 전용 QA 폴더에만 적용된다.

이 실행기는 이미 구현된 검사를 묶으며 새로운 전투 실황이나 물리 키 조작을 대신하지 않는다. 성공 문구는 FUNCTIONAL_EVIDENCE_PASS이고 게이트 승인이 아니다. 공통 LPC 팔레트 검사에서 Pillow getdata 폐기 경고는 남아 있다. GUT assert 수는 기존 난수 시험으로 실행마다 다를 수 있다.

기존 `audit_player_grips.py`도 조회 과정에서 실행됐다. 이는 외부 LPC 손 추정치와 현재 수동 좌표의 차이를 출력하는 진단이며, 원본의 좌표 추정 불가 항목이 있다. 큰 차이 수치를 현재 PNG의 손 분리 결함이나 PASS로 단정하지 않는다. 실제 배포 PNG 대조와 명시 접점 검사를 기능 근거로 사용한다.

## 이번 실행 결과 (2026-09-29)

- Python 궁수 4/4, 무기 배치 10/10 통과. 전체 GUT 1,063/1,063, 119 scripts, 9,120 asserts, SCRIPT ERROR 없음.
- 여행 cleanup/depart 통과. return은 실제 도보 좌표 `(152.4334, 519.0394)` 도달 후 `recent_combat` 2회, `enemy_nearby` 18회로 20회 저장 재시도 소진. exit 1 / YEOULMOK_JOURNEY_FAIL. 통합 결과도 failed이며 reload는 실행하지 않았다.
- 이것은 직전 독립 검토의 성공 기록을 취소하지 않는다. 살아 있는 월드의 적 배회에 따라 안전 조건이 충족되지 않을 수 있음을 이번 실행에서 확인했다. 타이머를 조작하거나 적을 제거하거나 성공할 때까지 재실행하지 않았다. 어떤 개체가 반경에 들어왔는지는 이번 로그로 특정하지 않았다.
- 처음 통합 실행은 의도된 저장 I/O 음성 테스트의 ERROR 로그까지 실패로 분류했다. 위의 좁은 예외를 추가한 뒤 GUT가 통과했고, 이어지는 실제 여행 실패는 정상적으로 검출했다. PASS 마커 없는 오류가 성공으로 기록되지 않았다.
- 미감 보류와 별개로 저장 가능성·전사 손 교체는 미해결이다. 이번 변경은 제품 코드/그림 수정이 아니라 검증 실행기와 배포 그림 대조, 검수 범위 정리다.

## 변경 파일과 인계

- `godot/assets/tools/test_player_archer_art.py`: 검증 생성 결과와 배포된 궁수 전투 PNG 3장 대조 추가.
- `docs/qa/tools/run_functional_gates.ps1`: 기존 Python/GUT/여행 검사 통합, 실패 시 중단·결과 JSON 기록. 전체 통합 통과 주장은 하지 않는다.
- 본 문서: 사용자 관찰의 코드 원인, 자동 증거와 승인 구분, 실제 실패 결과 기록.
- `STYLE_GUIDE.md`, `m3-gate-checklist.md`: 최종 미감 검수 시점과 현행 미러의 한계 연결.
- 키트 README와 연속 플레이 검토서: 리뷰 통과, 루트 자식 전제, 리뷰어 관측 종료 경고 기록.
- `PROJECT_STATUS.md`, `HANDOFF.md`: 최신 결과와 남은 결함 연결. 기존 추적 스크린샷 9개는 변경/스테이징하지 않는다.

이번 진단만으로 작은 재리뷰 요청서는 만들지 않는다. 다음 구현 묶음은 저장 거부 원인 계측·기능 검증 공백과 전사 좌우 프레임 대응을 구분하여 다룬다. 미감 보류는 손 교체 해결을 승인한 것이 아니다.
