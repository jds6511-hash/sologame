## 이번 입력·메뉴 통합

`job_save_menu_probe.gd`가 제품 시작 지역에서 기존 Page Up 디버그 키로 Lv10/40을 준비한다. V 키 → 표시된 전직 카드 pressed 신호로 전사/궁수, 전사→검투사를 선택한다. 전직 함수·직업 ID·레벨 필드 직접 대입은 없다. **정상 사냥으로 전직 레벨에 도달한 증거는 아니다.**

기본 공격 홀드로 공격 상태 진입, 오른쪽 이동+회피 입력으로 대시·실제 위치 변화를 확인한다. 재사용 대기·안전 조건은 실제 14초를 기다리며 타이머를 수정하지 않는다. 이후 F6 키 이벤트 → 표시 저장 버튼 → 확인/취소 신호 → 제품 저장, ESC 닫기·일시정지 해제를 확인한다.

확인창은 headless에서 실제 클릭을 확인하지 못했다. 따라서 확인창을 숨기고 **confirmed/canceled 신호를 명시적으로 발생**시킨다. SaveSession API를 직접 호출하지 않지만 네이티브 팝업 자체의 입력 검증도 아니다. 일반 버튼도 텍스트·표시·활성 상태를 확인한 pressed 신호다. OS 키/마우스 검증으로 부르지 않는다.

직업별 별도 프로세스에서 F6 불러오기를 수행해 레벨·EXP·직업·잔여 스킬 포인트·회피 후 위치를 스냅샷과 비교한다. 새 캐릭터 취소 시 직업 유지, 실행 시 Lv1 모험가·일시정지 해제, 기존 슬롯 SHA-256 불변을 확인한다. 장비·강화·HP/MP·시간은 이 새 스냅샷 범위가 아니며 기존 저장 검사와 구분한다.

사망 신호는 전체 과정에서 감시하고, 마지막 검사 도달 플래그·종료 코드·PASS 마커·SCRIPT ERROR/ERROR/false 단언으로 실패를 거른다. 직업별 `user://job_save_menu_probe/<job>`만 사용한다.

- 미감 보류와 별개로 저장 가능성·전사 손 교체는 미해결이다. 이번 변경은 제품 코드/그림 수정이 아니라 검증 실행기와 배포 그림 대조, 검수 범위 정리다.
