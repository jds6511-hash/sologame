# M6 경제·장비 통합 설계 검토 요청

> 2026-09-28 검토 수신: M5 보완 통과, M6는 보완 후 착수 가능. [대응 기록](m6-economy-equipment-review-response.md)에 공급 공백·가격4종·무기 계열 계약을 반영했다. 이 요청서는 과거 검토 범위이며 다시 전달할 필요 없다. 현재 우선순위는 여울목 시각 시제품, 후속 M6 검토는 통합 구현 단위다.

- 날짜: 2026-09-28
- 담당: Codex
- 기준: `aa3c580` 이후 여울목 장 리뷰 보완 포함
- 변경 이력: 2026-09-28 다음 큰 구현 묶음의 가격·스탯·저장 경계 작성
- 대상: [M6 통합 설계안](../design/systems/m6-economy-equipment-loop.md)

여울목 구현은 통과했으며 [작은 보완 결과](m5-chapter-one-review-response.md)의 재승인을 요구하지 않는다. **이번에 검토할 것은 구매→판매→비교/장착→실제 전투→저장/재실행 전체 루프의 설계**다. M6 제품 변경은 아직 없다. 설계 검토 후 구현을 기능별 작은 리뷰로 분할하지 않고 통합한다.

중점 질문:

1. `ItemData.price` 의미 분리를 거래 목록으로 처리하면 재료4골드가0골드로 잘못 매입되는 문제와 비매품 판매 허용을 막는가?
2. 성장의 가상B급 제거·실제 장비 합성과 구버전 최대HP/MP 검증을 분리한 소유권이 맞는가? 치명타/속도 중복과 레벨업 회복의 재적용 경로가 빠지지 않았는가?
3. **V5 이관안**: 기존 소유품 보존, 부적합 장비 가방 이동, 포화 시 이관 전용overflow, 빈 슬롯C급 보정안의 비용/기존 플레이 영향이 적절한가? 현실 콘텐츠의 장비 공급 공백과 C급 하향은 제품 적용 전 차단 조건으로 남겼다.
4. 거래 확정 전 전체 검증/확정 후 신호·재진입 차단·pause 중재가 단일 캐릭터 거래에 충분한가? 계정 공유 창고 거래는 범위 밖이다.
5. 이 묶음의 자동 검증·실제 플레이·M5/M6/G4/G5 경계를 과장한 부분이 있는가?

코드 근거: `inventory_component.gd`의 null 배선/1회 base 캡처/equip 조건, `player_stat_growth.gd`의 가상 장비 포함 계산, `character_save_codec.gd`의 `unsupported_equipment_stat_binding`, `save_content_registry.gd`의 장비 없는 `max_stats`, `inventory_tab_stub.gd`의 임시UI, 소검/토끼 발/포션/목걸이 `.tres` 가격을 읽었다. 새 경제 코드 실행 결과로 주장하지 않는다.

보완·설계 커밋: `36a9724` (기준 `aa3c580`,13파일). 코드 변경은 M5 보완4파일이며 M6/V5 제품 구현은 없다. 직접 플레이/G4/G5·질주 힌트·2장 의뢰는 이월 유지.
