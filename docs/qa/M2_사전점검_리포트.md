### 1-3. 동렙(同Lv) 교차 검증 (설계 의도 재현 확인)

균열 점액 초과분의 원인을 확인하기 위해, `m2-monster-spec.md` 2장 표의 "플레이어 물공/방어" 값을 그대로 대입해 **플레이어도 몬스터와 동레벨**인 경우를 계산했다(기본 콤보만, 손계산·공식 재적용):

- Lv4 동렙(물공39) vs 들개 마수(방어2.0): TTK ≈ 4.08초
- Lv8 동렙(물공58) vs 균열 점액(방어4.0): TTK ≈ 4.08초

세 몬스터 모두 "동렙" 조건에서는 TTK가 약 4.08초로 균일하게 나와, `combat.md` 8-1장의 곡선 공식이 전 레벨 구간에서 균등한 TTK를 보장한다는 설계 의도가 실제 데이터로도 재현됨을 확인했다.

**결론**: 1-2절의 균열 점액(9.2초/8.19초) 초과는 데미지 공식이나 몬스터 스탯의 오류가 아니라 **Lv1 캐릭터가 자기보다 4레벨 높은 균열 점액(Lv8)과 조우한 비동렙 상황**이 원인이다. `m2-monster-spec.md` 2장이 이미 "동렙 전제 주의 — 저레벨 플레이어가 균열 점액을 만나면 TTK가 길어지는 것은 의도된 난이도 신호"라고 명시해 둔 그대로다.

### 1-4. 발견 사항 (참고)

1. **[참고] 균열 점액 비동렙 조우 시 TTK가 목표 상한(8초)을 근소 초과** — 설계 문서가 이미 "의도된 신호"로 명시한 항목이라 결함은 아니나, 시작 지역(여울목~노베라 들녘) 동선상 Lv1 캐릭터가 실제로 균열 점액과 조우하는 빈도·타이밍이 적절한지는 레벨 배치(`world-structure.md` 4장) 확인이 필요하다. G2-1 디렉터 플레이 세션에서 실제 체감 확인 권장.
2. **[참고] 동렙 기본 콤보 실측 TTK(≈4.08~4.32초)가 설계 목표치(5.0초)보다 다소 빠름** — 전사 2타 콤보의 평균 계수(1.25/타, 2타 합 2.5)가 `combat.md` 7장의 "기준 DPS = 공격력×1.7"(스킬 로테이션 포함 가정)보다 이미 높기 때문. 결함은 아니며 "스킬을 전혀 안 써도 목표 TTK 근방을 이미 달성하는 여유 마진"으로 해석되나, 스킬을 섞으면 TTK가 하한(3초)에 더 가까워지므로 G2-1 손맛 튜닝 시 systems-designer가 참고할 사항으로 기록한다.

## 3. QA-3 — 페이스 실측

### 3-1. 데이터 공백 확인 (주의)

작업 지시대로 "실제 경험치 지급 데이터"로 계산하려 했으나, **M2 코드베이스에 플레이어 경험치 누적·레벨업 시스템이 아직 구현되어 있지 않다.**

- `hud.gd`의 `set_exp_ratio()`, `player_status_panel.gd`의 `set_level_and_job()`은 표시용 setter만 존재하고, 실제 몬스터 처치 시 경험치를 누적하거나 레벨을 올리는 로직은 전체 코드베이스에 없음(grep 확인).
- `DropSystem`·`MonsterSpawner`·`PlayerStatsComponent` 어디에도 경험치 지급 호출이 없다.
- 이는 M2_PLAN.md 범위표(2-1·2-3장)에도 별도 태스크로 명시되지 않았던 항목으로, 버그가 아니라 **M2 범위에 경험치/레벨업 시스템 구현이 아예 포함되지 않았던 것**으로 판단된다(M2는 "Lv1 전사 고정 스탯" 기준 전투 손맛 검증에 집중).

### 3-2. 대안 계산 (QA-1 실측 TTK + 설계 수식 조합)

경험치 지급 데이터가 없어 "실측"은 불가능하지만, QA-1에서 실측한 동렙 TTK(≈4.08초)를 `growth.md` 5-3장의 사이클 가정에 대입해 참고용 추정치를 산출했다.

| 항목 | 설계 가정(growth.md 5-3) | 실측 대체값 |
|---|---|---|
| TTK | 5.0초 | 4.08초 (QA-1 동렙 실측) |
| 이동·루팅 오버헤드 | 7.0초 (실측 불가 — 이동/루팅 타이머 미구현) | 7.0초 그대로 사용(가정 유지) |
| 사냥 사이클 | 12.0초 | 11.08초 |
| 시간당 처치(환산) | 300마리 | 약 325마리 |
| Lv10 도달 누적 시간 | 1.8시간 (growth.md 5-2 표) | 약 1.66시간(≈99분), 비율 300/325≈0.923 적용 |

- 위 추정치는 이동·루팅 7초 가정을 실측하지 못한 채 그대로 가져온 것이므로 **신뢰도가 제한적**이다. 결론은 "실측 TTK만 놓고 보면 설계 목표(1.8시간)보다 약 8% 빠른 페이스"이나, 실제 이동 동선·루팅 UX(F 상호작용)까지 포함한 진짜 사이클 시간은 디렉터 플레이 세션 또는 별도 계측이 필요하다.
- 서브퀘스트 평균 13분 가정(`quest-structure.md` 9장)은 M2에 퀘스트 시스템 자체가 없어 측정 불가 — 그대로 이월.

**판정: 부분 측정.** 계산 자체는 수행했으나 원천 데이터(경험치 지급) 부재로 "실측 완료"라고 볼 수 없다. producer에게는 "경험치/레벨업 시스템이 M2 범위에 없어 QA-3을 완전히 수행할 수 없었다"는 사실과 위 추정치를 함께 전달 필요.

- 없음. 본 리포트는 이미 확정된 수치·범위를 실측/검증한 결과이며 방향 결정 사항을 포함하지 않는다. 단 3장(QA-3)의 "경험치/레벨업 시스템 M2 미구현"은 producer가 M2 범위 정의상 의도된 것인지 재확인해 후속 마일스톤(M3+) 계획에 반영할 필요가 있다(디렉터 결정이 아니라 producer 확인 사항).
