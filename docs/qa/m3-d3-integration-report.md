### 2-4. 무법자 guard 애니메이션 (지시 중점 ④) — **통과**

`_start_guard()` 이후 시간축 실측(0.05초 단위 프레임 진행):

| 시점 | state | 재생 애니 |
|---|---|---|
| `_start_guard()` 직후 | GUARD(3) | walk (직전 잔상 — `guard_enter_sec = 0.2` 대기 중이라 정상) |
| +0.35초 (가드 진입) | GUARD(3) | **guard** |
| +1.35초 (가드 지속) | GUARD(3) | **guard** |
| +1.95초 (가드 종료) | GUARD(3) | idle |

`outlaw.tscn`의 SpriteFrames가 `["attack", "death", "guard", "idle", "walk"]`를 보유하며, `_play_animation_or("guard", "idle")`가 **폴백이 아니라 guard를 재생한다.** 배선 의도대로 동작한다.

실행 화면(`C10_01_무법자_무리_교전.png`, `D03_03`)에서 무법자 3마리가 신규 스프라이트로 정상 렌더링되며, 후드·상반신·무기 실루엣이 배경과 분리돼 읽힌다.

단, 같은 스크립트를 쓰는 **노상강도·밀렵꾼에는 guard 프레임이 없다** → 비차단 이슈 #2 (3장).

### 2-5. 콘솔 오류·경고 (지시 중점 ⑤) — **통과**

| 실행 | 결과 |
|---|---|
| GUT 852테스트 | 오류 0 / 실패 0 |
| 시작 지역 헤드리스 장시간 구동 | 오류 0, 경고 0 |
| 검증 필드 `--capture` (전 구역 교전 16초) | 오류 0, 경고 0 |
| 검증 필드 `--capture-respawn` | 오류 0, 경고 0 |
| 통합 하네스(사망·부활·레벨업·전직 40회) | 게임 코드 기인 오류 0 |

- **시그널 인자 수 불일치 없음.** 골드 지급 경로(`gold_dropped` → `add_gold.unbind(1)`)는 시작 지역·검증 필드 양쪽 씬에서 동일하게 배선돼 있고(`eastern_frontier_starting_area.gd:50`, `m3_new_enemy_field.gd:83`), 전 세션에 걸쳐 인자 수 오류가 재발하지 않았다. 사망 골드 차감 경로(`death_penalty_applied(gold_lost: int)`)도 인자 1개로 정상 수신됨을 실측했다.
- **null 참조 없음.** `_apply_gold_penalty()`의 `get_node_or_null("Inventory")`는 두 월드 씬 모두에서 노드를 찾고, 못 찾는 경우(디버그 전투장 등)에도 조용히 return하여 사망 시퀀스가 계속 진행됨을 골드 0 케이스로 함께 확인했다.
- 종료 시 `ObjectDB instances were leaked` / `resources still in use` 메시지는 강제 종료 경로에서만 나오는 정리 순서 경고이며 M2부터 상시 관측되던 것이다. 신규 발생분 아님.

### 비차단

#### 비차단 #1 — 궁수 계통에 2차 전직 경로가 없다 (담당: systems-designer / **디렉터 결정 필요**)

**재현 절차**
1. 시작 지역 씬 실행
2. Page Up ×9 (또는 Shift+Page Up)로 Lv10 도달 → `[전직] Lv10 도달` 안내 확인
3. **F12(궁수)** 로 전직
4. Page Up ×30으로 Lv40 도달

**기대 동작** — Lv40에서 2차 전직 가능 안내가 뜨고 상위 계통 후보가 제시된다(jobs.md 1장, Lv40 2차 전직).
**실제 동작** — `transition_available = false`, `candidate_jobs() = []`. 아무 안내도 뜨지 않고 2차 전직을 실행할 수 없다.

**원인** — `player.tscn`의 `tier2_jobs = [job_def_gladiator]` 하나뿐이고, 검투사는 `required_job_id = &"warrior"`다. `data/jobs/`에 궁수 상위 계통 정의 파일이 없다(`job_def_archer.tres` / `job_def_gladiator.tres` / `job_def_warrior.tres` 3개뿐). `PlayerJobTransition.candidate_jobs()`가 빈 배열을 돌려주고 `_next_transition_level()`이 −1을 반환해 판정 자체가 중단된다.

**로그**
```
[디버그] 레벨 점프 → Lv40
[통과] Lv40 도달 Lv40
[실패] 궁수 Lv40 2차 전직 가능 available=false 후보=[]
```
대조군(전사 경로):
```
[전직] Lv40 도달 — 2차 전직이 가능합니다.
  F11 키 = 검투사 전직
[전직] 검투사 전직 완료 — 스킬 슬롯 개방·스킬 포인트 +2.
```

**차단으로 올리지 않은 이유** — 코드 결함이 아니라 데이터 미등록이며, 전사 경로로 2차 전직 관찰이 성립한다. 프레임워크 자체는 일반화돼 있어 `.tres` 하나만 추가되면 그대로 받는다.

**세션 운영 회피책** — Lv40 2차 전직(검투사)을 보려면 **Lv10에서 F11(전사)** 를 골라야 한다. 궁수는 G3-2(원거리 전투 작동) 관찰용으로 Lv10~ 구간에서 확인하고, 2차 전직 관찰은 전사 경로에서 진행한다.

**디렉터 결정 필요** — 궁수 2차 전직 직업을 M3 범위에 넣을지, M4로 미룰지. 현재 `docs/design/systems/`에는 전사 2차(검투사) 규격만 있다.

#### 비차단 #2 — 노상강도·밀렵꾼에 guard 프레임이 없어 idle로 폴백한다 (담당: pixel-artist)

**재현 절차**
1. 검증 필드(`m3_new_enemy_field.tscn`) 실행
2. A3 구역(노상강도) 또는 B1 구역(밀렵꾼)에서 정면으로 일반 공격을 넣어 가드 반응을 유발

**기대 동작** — 무법자와 같이 가드 자세 애니메이션이 재생된다.
**실제 동작** — 가드 자체는 발동하지만(피해 −60% 감쇄·1회 흘림 정상), 시각적으로는 idle 자세 그대로다.

**근거**
- 세 씬(`outlaw.tscn` / `highwayman.tscn` / `poacher.tscn`) 모두 `scripts/ai/outlaw_monster.gd`를 공유하고, `_on_guard_entered()`가 `_play_animation_or("guard", "idle")`을 호출한다.
- 세 스탯 파일(`outlaw_stats.tres` / `highwayman_stats.tres` / `poacher_stats.tres`) 모두 `guard_enter_sec`~`guard_cooldown_sec` 전 항목을 보유 → 가드는 세 종 모두 실제로 발동한다.
- SpriteFrames 실측:
  - `outlaw.tscn`: `["attack", "death", "guard", "idle", "walk"]` → +0.35초에 `guard` 재생 **확인**
  - `highwayman.tscn`: `["attack", "death", "idle", "walk"]` → `idle` 폴백
  - `poacher.tscn`: `["attack", "death", "idle", "walk"]` → `idle` 폴백

**게이트 영향** — G3-1 판정 축 ③(아트)에 부분 영향. 다만 O-1~O-7 관찰 항목에 노상강도·밀렵꾼 가드는 포함되지 않는다. 무법자 2프레임(`mob_outlaw_thug_guard.png`)과 같은 방식으로 확장 가능하다.

#### 비차단 #3 — 사망 시퀀스 중 통합 메뉴를 열면 연출이 정지하고, 암전이 메뉴를 덮는다 (담당: ui-dev / **디렉터 결정 필요**)

**재현 절차**
1. 시작 지역 씬 실행
2. 몬스터에게 맞아 사망 (또는 HP를 0으로)
3. 사망 모션~암전 구간에서 ESC / I / Tab 등 통합 메뉴 키를 누른다

**기대 동작** — 사망 연출 중에는 메뉴가 열리지 않거나, 열려도 연출을 가리지 않는다.
**실제 동작(실측)**
```
사망 직후: phase=MOTION 암전alpha=0.00 입력잠금=true
메뉴 개방 직후: tree.paused=true 메뉴가시=true
메뉴 연 채 다수 프레임 경과: phase=MOTION (변화 없음) is_dead=true
  → 사망 시퀀스 완전 정지
메뉴 닫음: tree.paused=false
이후: phase=NONE is_dead=false 입력잠금=false HP=95.8
  → 복구 성공
```

**원인**
- `integrated_menu.gd:46` `process_mode = PROCESS_MODE_ALWAYS`, `:88` `get_tree().paused = true`.
- `PlayerDeathSequence`는 기본 process_mode(pausable)라 `_process()`가 멈춘다 → 단계 타이머가 정지.
- `IntegratedMenu._unhandled_input()`은 `is_input_locked`를 보지 않으므로 사망 중에도 메뉴가 열린다.
- 암전은 `BLACKOUT_CANVAS_LAYER = 20`, 통합 메뉴는 layer 10 → **암전 구간(alpha≈1)에 메뉴를 열면 메뉴가 검은 화면 아래 깔려 보이지 않는다.** 플레이어에게는 "게임이 멈췄다"로 보인다.

**차단으로 올리지 않은 이유** — 메뉴를 닫으면 시퀀스가 정확히 이어져 부활까지 완주한다(영구 정지 아님). 데이터 손상도 없다.

**디렉터 결정 필요** — 사망 중 메뉴 개방을 차단할지, 아니면 암전 레이어를 메뉴 아래로 내려 메뉴를 볼 수 있게 할지. `ux-foundation.md` 3장 S15(사망/게임 오버 오버레이)는 화면 등재만 돼 있고 규격이 없어 판단 근거가 없다.
