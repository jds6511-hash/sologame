# 뿔토끼 저장 차단·실패 안내·자동 저장 대기 통합 검토

- 최종 수정: 2026-09-29 / 담당: Codex
- 기준: `7cbf7c5` / 구현: `a740968` (13파일, 로컬 완료·원격 미푸시).
- 목적: 인지 밖 배회 토끼가 저장을 막는 문제를 제한적 종별 판정·제품 안내·세션 상태·회귀·화면 검증으로 연결한다.
- [이전 실패 기록](g3-g5-functional-evidence.md)의 귀환 저장 실패를 통과로 덮지 않는다. 전 종의 반경 축소나 G4 승인이 아니다.

> 독립 검토 수신(2026-09-29): `a740968` / 인계 `2da4494` 통과, 지적0건. GUT1069/1069·기능 게이트·화면3장 재현. 누적 시간 승계 설명은 지역 이동으로 한정했다. 재전달 필요 없음.

## 사용자 동작과 계약

1. 수동 저장이 `enemy_nearby`로 거부되면 가장 가까운 차단 개체의 이름·방향·거리(타일)를 표시한다. 메뉴를 닫고 거리를 벌리라는 행동을 안내한다. 알 수 없는 Node2D는 내부 노드명 대신 ‘주변 개체’로 표시한다.
2. 활성 슬롯의 180초가 지나면 안전 판정 사유를 `auto_wait_reason`에 유지한다. 이유가 바뀔 때만 신호를 내고 HUD에 짧은 대기 사유, 메뉴에 설명을 표시한다. 같은 이유로 매 프레임 알림을 반복하지 않는다.
3. 안전해지면 기존대로 다음 갱신에 저장한다. 수동 저장 성공도 대기 표시/타이머를 해제한다. 메뉴 일시정지 동안 시간은 진행하지 않는다. 대기 상태는 파일에 저장하지 않는다. 지역 이동 시에만 기존 누적 시간으로 재판정하며, F6 불러오기·새 캐릭터는 누적 시간0부터 시작한다.
4. 보스 조우·행동·쿨다운·5초 정적 및 검사 순서는 유지한다. **살아 있고 경직되지 않은 WANDER 뿔토끼가 인지48px 밖에 있을 때만** 기본160px 차단에서 제외한다. 인지 경계48px와 도주·휴식·박치기·경직/사망 잔존 상태는 기존160px 미만 차단을 유지한다. 다른 종/미지정 Node2D도 유지한다. 표시된 개체는 ‘현행 저장 차단 대상’이며 ‘현재 공격 중인 적’의 의미가 아니다.

## 정책 보완의 실측 근거

안내 구현 뒤 실제 도보 depart에서 저장 실패가 다시 발생했다. 로그23건이 모두 살아 있는 뿔토끼, `state=0(WANDER)`, 인지48px, 플레이어 거리 **86.0438~157.7419px**였다. 추적/공격이 아니라 인지 밖 배회로 차단되었다. 따라서 전체160px를 줄이거나 전투 상태 판정을 제거하지 않고 종별 공개 조회 API에 예외를 둔다. 저장 계층은 토끼의 사설 타이머/enum을 직접 읽지 않는다. 진단 로그 원본은 ignored 재실행 경로라 최종 실행으로 갱신됐으며 수치는 당시 로그를 읽어 집계한 관측값이다. 원래 귀환 실패 개체까지 소급 특정하지 않는다.

## 검증

- 최초 신규 테스트 2건은 미구현 상태에서 실패했다(기존18통과/신규2실패). 구현 뒤 둘 다 통과했고 경계/일시정지 테스트2건을 추가했다.
- 토끼 예외 테스트2건도 제품 수정 전 실패(기존22통과/신규2실패)를 확인했다. 구현 뒤 저장 세션 **24/24, 170 asserts**, 최종 전체 GUT **1,069/1,069 · 119 scripts · 9,171 asserts**. assert 수는 기존 난수 영향의 관측값이다.
- 기존 Python 궁수4/4·무기10/10 통과. 변경 GD8개 형식/린트 통과.
- 최종 여행 **cleanup→depart→return→reload→cleanup 5/5 PASS**, SCRIPT ERROR 없음, FUNCTIONAL_EVIDENCE_PASS. 실제 도보→저장→프로세스 복원 경로를 다시 통과했다. 반복 성공률이나 G4 승인을 의미하지 않는다.
- `SAVE_FEEDBACK_PREVIEW_PASS`, exit0. 세 화면 작성 및 완료 카운터 확인. 최종 로그 SCRIPT ERROR/ERROR 없음. 근접32px 토끼의 실제 이름/동쪽/2.0칸 안내와 자동 대기 화면 검증. 정지 UI fixture를 실제 교전으로 주장하지 않는다.
- 출력은 ignored `docs/qa/screenshots/save-feedback/`와 `functional-gates/`다. 추적 PNG/다른 작업자의 화면9개는 변경하지 않는다.
- 개발 중 진단 probe의 정적 타입/선행 preload가 오토로드 초기화 전 컴파일 오류를 일으켜, 런타임 load/읽기 검사로 수정했다. 화면 probe의 `res://..` 출력 경로 실패도 절대 경로 변환 후 재실행했다. 두 실패를 제품 결함으로 집계하지 않는다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File docs/qa/tools/run_functional_gates.ps1
godot --path godot --script ../docs/qa/tools/save_feedback_preview.gd
```

화면 probe는 월드를 정지하고 180초를 주입하며 수동 버튼 처리 함수를 직접 부른다. 실제 시간/사람 입력 검증이 아니다. 전용 `user://save_feedback_preview`가 비어 있지 않으면 파일을 건드리지 않고 실패한다. 성공 시 자신이 만든 QA 파일을 정리한다.

## 검토 질문과 제한

1. 예외가 뿔토끼의 인지 밖 평시 배회에만 제한되는가? 다른 적·인지 경계·조우 상태·보스 우선순위·만료된 자동 저장 재시도가 유지되는가?
2. 파일을 쓰기 전에 차단되고, 수동 성공/안전 상태 복귀 뒤 대기 표시가 정상 해제되는가? 매 프레임 신호를 반복하지 않는가?
3. 수동 안내가 실제 차단 반경/가장 가까운 개체와 일치하며, 메뉴 일시정지 중 기다리라고 오해하게 만들지 않는가?

계측 추가 후 첫 실행은 차단 없이 통과했으나, 다음 전체 실행에서 위23건을 얻었다. 인지 안 토끼/다른 적에 의해 저장이 거부될 가능성은 정상적으로 남는다. 장기 플레이 체감·OS 입력·전투 가독성·전사 손 교체·G3~G5 승인·미감/환경 제품 채택은 해결하지 않았다. 별도 소규모 리뷰를 여러 번 보내지 않고 이 사용자 기능 전체를 한 번에 검토한다.
