새 캐릭터로 대화 수락·실제 공격을 연결하자 `body_entered → attack_hit → take_damage → died → _spawn_item → add_child`에서 `Can't change this state while flushing queries` 엔진 오류가 발생했다. 기존 드롭 확률 단위 검사와 완료 fixture를 사용하는 여행 검증에서는 지나지 않았던 실제 물리 콜백이다.

`DropSystem`의 보상 판정과 `item_dropped` 신호 시점은 유지한다. 충돌 Area의 **인스턴스 생성과 월드 추가 모두** 메시지 큐로 넘긴다. 월드가 먼저 해제되면 예약 대상도 해제되고, 트리에서 빠졌거나 삭제 예약된 경우에는 추가하지 않는다. 새 월드를 검색해서 드롭을 옮기지 않는다. 드롭 확률·수량·골드 계산·퀘스트 신호·저장 형식은 바꾸지 않았다.

좌측 계약 리뷰의 잔상 주석은 flip_h가 아닌 방향을 근거로 정정했다. 잔상 동작과 PNG는 불변이다. 기존 원본 좌우 비교만으로 오른손 일관성을 보장할 수 없어, **전사 손 교체는 여전히 미해결**이며 전용 원화의 칼날/잔상 방향 검수를 남긴다.

## 자동 조작이 지나가는 경로

1. 실제 새 월드에서 접수원 근접 상호작용 → 표시된 모험가 패 버튼 → MQ02 수락 버튼.
2. 이동 액션과 마우스 조준·공격 홀드로 뿔토끼 2마리 처치 → `monster.died` 제품 배선으로 목표 진행 → 접수원 보고.
3. 같은 경로로 MQ03 수락 → 들개 2마리 실제 처치 → 귀환 보고.
4. MQ04 수락 → 충돌을 피해서 북쪽 조사 지점까지 도보 → interact 입력 → 보고.
5. MQ05 수락 → 관문지기 보고 → 제품 지역 전환 → 안전 조건을 실제로 기다려 슬롯1 저장.
6. 프로세스를 새로 띄워 불러오기 → 노베라/5개 완료 상태/레벨/현재 EXP/골드/공훈을 저장 직전 읽기 전용 스냅샷과 대조.

`journal.accept/complete/restore_state/record_event`, 피해량 직접 호출, HP/타이머/좌표/속도 대입, 몬스터 정지·강제 처치를 사용하지 않는다. UI는 표시 중인 버튼의 텍스트를 확인한 뒤 **pressed 신호를 직접 발생**시킨다. 실제 마우스 클릭·OS 키 전달 검증은 아니다.

저장/불러오기는 제품 `SaveSession.save_slot(1)` / `load_slot(1)`을 호출한다. F6 메뉴의 버튼 조작까지 검증한 것은 아니다. NPC 접근·수락·보고는 위의 실제 상호작용과 표시 버튼 경로를 사용한다.

QA 조작기는 충돌 마스크와 캡슐 모양으로 읽기 전용 격자를 만들고 AStar 경로를 따라 이동 액션을 보낸다. 몬스터 위치를 읽어 조준하므로 사람의 탐색·전투 실력이나 난이도 평가에 사용할 수 없다. `seed(20260929)`·`--fixed-fps 60` 시나리오이며, 렌더/물리 스케줄까지 결정적이라고 보장하지 않는다. **play/blocked는 렌더링이 필요하고 포인터를 움직인다.** headless에서는 마우스 위치가 전달되지 않아 해당 두 단계를 명시적으로 실패시킨다. 환경 키트는 설치하지 않는 제품 원본 월드 검증이다.

## 검증 이력과 제한

- 최초 드롭 회귀: 2개 중 1개 실패(즉시 생성되어 자식 수 2, 기대 1). 수정 후 실제 물리 콜백 검사까지 추가해 3/3·9 asserts 통과.
- 초기 조작기 시행착오: headless 조준 좌표 무반영, 들개 충돌 반경보다 작은 공격 시작 거리, 직선 귀환 경로의 장애물 충돌. 이는 조작기 한계이며 몬스터 난이도 결함으로 판정하지 않는다.
- 반복 실행에서 임의 x좌표 귀환 목표가 막힌 칸이 되는 경우와 고정 사냥 접근점이 살아 있는 적에게 막히는 경우도 실패했다. 귀환은 동문 경유점을 사용하고, 사냥터에서는 고정 지점 도달보다 추격·공격을 시작하도록 수정했다. 단일 통과를 모든 동적 배치의 성공 보장으로 해석하지 않는다.
- 초기 추격 시행에서 맵 폭을 넘는 좌표도 관측했다. 그 실행의 조작기/난수는 최종 시나리오와 다르고 원인은 특정하지 않았다. 맵 경계·출구 이탈을 안전하다고 주장하지 않으며 별도 재현 항목으로 남긴다.
- 첫 저장 복원 비교는 JSON float와 런타임 int를 포함한 Dictionary 비교 때문에 실패했다. 양쪽을 동일한 JSON 경계로 정규화한 뒤 같은 저장의 비교가 통과했다. 제품 저장 변환은 바꾸지 않았다.
- 전체 GUT 및 최종 6단계 결과는 아래 확정 기록에 기재한다.
- 결과와 로그는 ignored `docs/qa/screenshots/onboarding/`. 재실행은 추적 PNG/실제 `user://saves`를 건드리지 않는다. probe 전용 `user://yeoulmok_onboarding_probe`만 cleanup한다. 실패 시 후속 단계는 멈추고 해당 fixture를 남긴다.
- 공격 생략 음성 실행은 사냥 시간 초과로 실패해야 하고, 저장 없는 reload도 실패해야 한다. 제품 오류가 섞이면 종료 코드가 맞아도 실행기가 거부한다.
- 전사/궁수 전직·전투 가독성·드롭 줍기·장시간 균형·전용 좌측 원화·미감·G3~G5 승인은 별도 미검증이다. 이번 캐릭터는 기본 모험가다.

```powershell
powershell -ExecutionPolicy Bypass -File docs/qa/tools/run_yeoulmok_onboarding.ps1
godot --headless --path godot -s addons/gut/gut_cmdln.gd -gdir=res://test -ginclude_subdirs -gexit
```
