# M6 공급·거래·실착·V5·플레이 통합 후보 검토

- 날짜: 2026-09-30 / 담당: Codex
- 기준: `d53bd25` / 대상 커밋: 인계 상단 기록
- 변경 이력: `4c30841` 리뷰를 반영하고 M6를 하나의 통합 후보로 구현.
- 설계: [통합 계약](../design/systems/m6-economy-equipment-loop.md), [실행 계획](../design/systems/m6-implementation-plan.md)

## 이번 기능 묶음

노베라 보급상에 도보 접근 → F 거래창 → 구매/취소/확정 → 가방/8칸 장착·해제·비교 → 실제 공격·방어 스탯 → 판매 → V5 저장 → 별도 프로세스 복원 → 여울목 귀환을 연결했다. B로 어디서든 후보 가방을 열고 상인40px 안에서만 구매/판매한다. UiPauseArbiter를 공유하고 거래 확정 시 거리/골드/수량/공간을 다시 검사한다.

**기본 제품은 V4 그대로다.** 후보 월드/세션/codec/store만 V5를 사용하고 디렉터 실제 저장 경로는 거부한다. 기존 파일 계층에는 `economy_content_error`를 공유 차단 목록에 추가했다. 경제 정의 오류를 손상 저장으로 분류해 백업 복구·보존본 생성으로 우회하지 않는다. 기본 프로젝트 씬·장비 리소스·ItemData·배포 Manifest·곡선은 변경하지 않았다.

### 데이터·거래

- C급11티어 ×9종 =99개 공급(기존16개 유지, 신규83개). 같은 반지 두 칸은 동일ID 수량2다. 모험가/전사/궁수/검투사의 유효 Lv1~100 조합343개를 검사했다.
- JSON 명시 레코드를 ItemData로 만들며 가격/계열/공급 표를 함께 보관한다. 생성기만 ID 규칙을 사용하고 런타임 장착은 명시 계열 표를 조회한다. 기존 ID·원본 ItemData 수치를 바꾸지 않는다.
- 노베라 구매: C급Lv1/10, 하급 포션. 매입: 카탈로그에 명시한 C급/포션/초반 재료3종. 소검120/12, 포션300/30, 토끼 발4. B급 및 가격 미확정품은 거래 불가다. 전체 경제 품목 완료가 아니다.
- 복사본에서 검사 후 골드·가방을 함께 확정한다. 골드/수량 상한, 만석 교환, 보관 회수 실패는 원본 불변. 상태 확정 뒤 통지하며 재진입 저장/거래를 막는다.

### 실착·이관

- 가상 B급 공격/방어 기여를 제거하고 실제 장비를 합성한다. 반지/속도는 기존 Inventory getter 소비처를 유지해 중복 가산하지 않는다. 레벨업은 최종 최대치 증가분, 착탈/로드는 현재 HP/MP clamp만 수행한다.
- 정상 전직은 기존 무기를 가방에 보존할 수 있을 때만 허용하며 직업 지급 무기를 한 번 장착한다. 복원 때 재지급하지 않는다. 후보 DropSystem은 전체 C급 공급과 검투사 대검 계열을 사용한다.
- V1~V4는 기존 schema로 원본부터 검증한다. 복사본을 기존 EXP/V4 변환 후 V5로 정규화한다. 부적합 장비는 가방, 포화 때 이관 전용 overflow(최대8개)로 보존하고 빈 슬롯만 C급 보정한다. 원본 Dictionary 불변·V5 재입력 멱등을 검사했다.
- V5 구조/스킬/의뢰/계정 검증은 기존 검증기에 사본을 전달해 재사용하고, 원 HP/MP는 실착 최대치로 별도 검증한다. overflow는 사용·판매·장착 없이 가방 회수만 제공한다.

## 검증과 한계

최초 M6 테스트는 모델 미구현 preload 오류로 실행되지 않았다. 이를 제품 결함의 음성 재현이라고 주장하지 않는다.

| 최종 확인 | 결과 |
|---|---|
| 전체 GUT | 1095/1095, 125 scripts, 13414 asserts, 25.778초. SCRIPT ERROR/종료 누수 0, 기존 ExpectedError 저장 I/O 1건. 직전 실행13418은 난수에 따른 관측 차이 |
| M6 전용 GUT | 14/14, 4210 asserts. 공급·변환 343 레벨/직업 조합 포함 |
| 기존 온보딩 감시 | 5/5 PASS (`guards-20260930-144415-002`), 선행 실패 음성 마커 억제·대기 중 사망 감지 유지 |
| 경제 프로세스 | 최종 배치 cleanup→seed→reload→cleanup 4/4 PASS. 구매/취소/확정·장착/판매·가방/장비 저장 복원·귀환. 렌더 seed 포함 별도 4단계도 통과 |
| 통합 교전 배치 | **FAIL** (`20260930-144231`): MQ02/03 실제 처치 후 드롭 접근 도보 시간 초과. 배치 exit1, 이후 복원/정리 단계 미실행 |
| 형식/린트 | 변경 GD17개 통과, git diff --check 통과 |
| 생성기 | 재생성 전후 카탈로그 SHA-256 동일 |

**전투 후보의 반복 완주 관문은 미통과다.** 중간 후보 `20260930-142614`는 경제+교전 8/8로 완주·별도 프로세스 복원을 확인했지만, 이후 `143048`(줍기 도보), `143514`(토끼 사냥), 최종 `144231`(줍기 도보)은 실패했다. 서로 다른 코드 실행을 동일 후보의 성공률로 합치지 않는다. 최종 실패는 (501.9648,229.3549)에서 드롭 접근점 (532.1234,432.4304)으로 가려다 정체했고, 재탐색139/방어3이었다. 사냥 난이도나 제품 결함으로 원인을 확정하지 않았으며 조작기와 충돌·조준 경로의 추가 진단이 필요하다. 통과할 때까지 재실행해 최종 성공으로 대체하지 않는다.

후보 조작기에만 8px 경로 격자와 드롭 주변 8/12px의 통행 가능한 접근점 선택을 추가했다. 제품 좌표/충돌/아이템을 옮기지 않으며 원래 프롬프트·가방 증가 검사를 유지한다. 기존 조작기의 기본값은 16px와 드롭 중심 그대로다. 이 보완만으로 정체가 해소됐다고 주장하지 않는다. **현재 통합 검토는 기능·저장 경계 검토이며 기본 제품 채택은 보류한다.**

- 전 레벨 공급/이관·원본 불변·위조 장비/vitals·만석·파일 보호·네 직업 복원·전직 지급·레벨업·재진입·착탈 회복 방지 GUT.
- 경제 process probe: MQ01~05 완료와1000골드는 **준비 fixture**. 상인 접근은 실제 이동 액션, F 상호작용/선택/레이캐스트/pause 경로. 구매/취소/확정은 표시 버튼 pressed 신호, 장착/판매는 Economy API. OS 클릭 검증이 아니다. 경제 상태를 별도 프로세스에서 비교한다.
- 전투 probe: 기존 완료 fixture 없는 온보딩 흐름에 후보 월드·격리 저장 경로·위의 접근점/격자 확장을 적용했다. 정상 수락·실제 처치·줍기·보고·여행·저장/재실행을 시도하며 실제 포인터가 움직인다. 기존 세션 사망 감시/실패 종료를 유지한다. 완주 여부는 위 배치별 결과로 한정한다.
- 초기 후보 월드 스크립트 교체가 `map_id`를 초기화해 노베라 대신 시작 맵을 만들었다. 명시 지역 보존으로 수정했다. 또 입력 해제 직후 상호작용 시점과 관문 거리 조건을 조작기에서 지키도록 수정했다. 저장 성공 JSON의 `recovered: false`를 실행기가 실패 단언으로 오인한 탐색 배치는 실패 기록으로 보존하고 출력은 코드만 남기도록 수정했다.
- 343조합의 **공격력만으로 계산한 TTK비 상한1.30**, 방어력만의 피격비 상한1.10894. 실제 TTK/난이도/HP 보너스 포함 생존시간이 아니다. [측정 도구](tools/m6_balance_probe.gd)의6레벨·4직업 요약과 전수 최대치를 분리했다. C급 하향의 체감 승인·100시간 경제 균형은 남는다.

```powershell
python docs/qa/tools/generate_m6_catalog.py
powershell -ExecutionPolicy Bypass -File docs/qa/tools/run_m6_candidate.ps1 -Combat
# 수동 후보 실행: B 가방 / 노베라 보급상 F
godot --path godot --script ../docs/qa/tools/m6_candidate_probe.gd -- play
```

출력은 ignored `docs/qa/screenshots/m6/` 및 `m6-*.log/json/png`, 저장은 `user://m6_candidate_*`. 실제 플레이 폴더를 정리하지 않는다. 새 코드가 기존 V4 저장을 기본으로 덮어쓰지 않는다.

## 변경 파일 소유권

- `godot/scripts/economy/`: 공급/가격·변환·후보 월드/세션·실착·전직·드롭·장착 API·UI·상인.
- `godot/data/economy/m6_catalog.json`, `generate_m6_catalog.py`: 명시 공급·가격 산출물과 결정적 생성.
- `godot/scripts/save/save_validation_codes.gd`: 콘텐츠 오류의 파일 계층 차단.
- `godot/test/economy/` 두 파일: 순수 모델·실제 노드·파일·호환 검증.
- M6 process/전투/비교 probe와 실행기, 기존 onboarding probe의 월드 생성/격리 경로 확장점.
- 설계/계획, 이 검토서, G3~G5 증거, PROJECT_STATUS/HANDOFF/로드맵: 현재 범위와 승인 상태 동기화.

## Claude 통합 검토 질문

1. 원본 V1~V4 검증 → 보존 이관 → V5 실착 검증에서 기존 소유품/스킬/계정 보호가 약해지거나 콘텐츠 오류가 복구로 우회되는가?
2. 구매/판매/장착/전직/로드/레벨업이 같은 소유권·스탯 모델을 사용하며, 포화·재진입·반복 착탈·보관품 회수에서 유실/복제/회복 악용이 가능한가?
3. 후보 세션은 지역 교체/새 캐릭터/복원 뒤에도 격리되며, 기존 V4 기본 경로에 실착/V5가 새어 들어가는가?
4. process fixture·API·버튼 신호와 실제 온보딩 입력/처치 증거를 구분했는가? 후보 데이터 표현/상인 품목 범위·기존 가방 임시 탭 미교체·C급 체감 미승인 한계가 제품 채택 전에 충분히 명시됐는가?

G3 기능 부분 통과·체감 대기/진행 허용, G4 직접 저장 판정 미기록, G5 MQ01~05 기능 범위라는 구분을 유지한다. M6 후보 완주를 G3~G6 승인이나 V5 기본 배포 승인으로 바꾸지 않는다.
