## 리뷰 설명에서 구분한 부분

- V1에도 `progress.quests = {}`가 존재한다. “V1에 quests 키 자체가 없다”는 예시는 정확하지 않지만 교차 버전 검증 필요성은 유효하다.
- 같은 `SaveFileStore`의 다른 슬롯 저장만으로 원래 V1 슬롯이 보존본으로 이동하지는 않는다. 보존 루프는 쓰기 대상 주 파일/백업에 적용된다. 정상 V1을 잘못 거부할 위험 자체는 H1 보완으로 다룬다.
- 현재 월드도 초기 개체를 `_register_spawned_monsters()`로 소급 등록한다. 미래 QuestController가 신호만 구독하면 누락될 수 있다는 지적은 설계 위험으로 채택했으며, 현재 M4에서 퀘스트 처치 누락이 재현됐다는 의미는 아니다.
- `corrupt`는 현재 원본 보존 대상이 아니므로 H3 제안 코드를 그대로 쓰면 보존 정책이 약해진다. 지원 버전 불일치를 `invalid_data`로 정한 이유다.

## 리뷰어에게 재전달할 범위

이번 보완 커밋을 `9996700`과 비교해 계약 §3·4·6 및 실행 계획 단위 1·2를 확인해 주세요. 특히 V1 검증 분기/자동 저장 보류, 버전 불일치 보존 분류, 카탈로그 선행, 명시적 스포너 start, UI pause 중재가 각 지적을 닫는지 검토해 주세요. 코드 구현 검토는 아직 아닙니다.

회신은 지적 번호별 해소/잔여와 **단위 1 착수 가능 여부**로 요청합니다. 수정·커밋·푸시는 Codex가 담당합니다. M4 직접 이동 위치 복원·종료 경고·G4 승인 대기는 유지합니다.

## 변경 및 검증 기록

### b9b5599 재검토 수신 및 잔여 반영

Claude는 H1~H4와 M1~M3의 설계 보완을 해소로 판정했고 H5의 명시적 start 방향도 수용했다. V1 quests 필드, 대상 슬롯 보존 범위, 기존 소급 등록에 관한 최초 리뷰 설명을 정정했으며 `invalid_data` 보존 분류도 수용했다.

단위 2 잔여/참고 사항을 코드와 대조했다:

| 항목 | 처리 | 검증 예정 |
|---|---|---|
| 소급 등록과 신호 등록 중복 가능성 | 신호 연결 후 start로 전환할 때 `_register_spawned_monsters()` 호출·불필요한 함수와 기존 시점 주석 제거. 신호 단일 경로로 통일 | 초기 토끼 처치의 드랍/EXP/퀘스트 각 1회, 중복 연결 오류 0 |
| REACH/TALK 시점 | 접근만 하면 REACH, 대화 열기 성공 때 TALK로 분리 | 범위 밖 대화 성공을 가정하지 않고 접근 전후/대화 전후 counts 비교 |
| 교체 실패 pause 의미 | 불리언만이 아닌 기존 메뉴 표시·토큰 소유권 동시 복원, 성공은 이전 토큰 폐기 | 실패 후 메뉴 닫기로 재개, 이전 월드의 늦은 release 영향 없음 |

모두 계약 §7과 실행 계획 단위 2에 반영했다. 현재 게임 코드의 결함을 재현하거나 수정한 작업은 아니다. 이 문서 보완만으로 설계 리뷰 반복을 요청하지 않는다. **다음 리뷰 인계물은 단위 1 구현 커밋·검증 보고서**이며 M4/G4 이월 항목은 유지한다.

계약과 실행 계획에 정책·인터페이스·회귀 항목을 반영하고 리뷰 요청/현황/인수인계에 이 대응 문서를 연결했다. 문서 상대 링크 및 diff 공백 검사를 수행한다. 보완 커밋은 `git log --oneline -- docs/qa/m5-design-review-response.md`로 확인한다.
