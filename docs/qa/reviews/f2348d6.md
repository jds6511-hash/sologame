## 발견 사항

### 낮음 1. 2장 시작 체험의 준비 골드가 1장 실제 지급보다 적다
- 위치: [game_bootstrap.gd](../../../godot/scripts/world/game_bootstrap.gd) `preparation()` — 2장 준비 `gold = 560`.
- 1장 의뢰 골드 합계는 20 + 100 + 150 + 300 + 560 = **1,130**이다(100시간 예산 1장 의뢰 골드 풀과 일치). 560은 MQ-01-05 하나의 보상이다.
- 영향: 디렉터가 2장 체험에서 상점·장비 구매 체감을 볼 때 실제보다 570G 적게 시작한다. 1장 처치 골드도 빠져 있다.
- 권장: 최소 1,130으로 맞추거나, "의뢰 보상만 반영, 처치·판매 골드 제외"를 시작 화면 안내에 적는다.

### 낮음 2. 일반 ObjectDB 누수는 경고로만 남고 실패하지 않는다
- verify_all은 `ERROR:` 줄만 실패로 본다. `WARNING: N ObjectDB instances were leaked`는 `warnings`에만 기록된다.
- 이번 실행에서는 누수 종류가 모두 Ogg 4개 클래스라 문제없었다. 하지만 Ogg 외 객체가 새로 누수되면서 "resources still in use" ERROR 줄이 없으면 통과로 처리될 수 있다.
- 권장: `leaked_types`에 Ogg 4개 외 타입이 있으면 실패로 처리한다(verbose 로그가 있는 단계 기준).

### 참고 1. Ogg 종료 누수가 거의 모든 프로세스 단계에서 나온다
- 107단계 중 프로세스 단계 대부분이 `ObjectDB 4~14개 + resources 2~4개` 경고를 남긴다. 누수 종류는 모두 BGM의 Ogg 재생 객체다.
- 화이트리스트로 넘기기보다 `BgmManager.reset()`에서 재생기를 멈추고 스트림 참조를 비우는 쪽이 근본 해결이다. 해결하면 verify_all의 예외 규칙도 지울 수 있다.

### 참고 2. 콘텐츠 개정은 "추가만"이라는 규칙을 문서로 고정한다
- 현재 설계는 개정 번호가 낮은 저장을 최신 통합 목록으로 검증한다. 콘텐츠가 추가만 된다면 안전하다.
- 앞으로 기존 의뢰 ID의 목표 수·선행 조건·보상을 바꾸거나 지역·ID를 삭제하면, 옛 저장의 의미가 바뀐다.
- 권장: `content-integration-plan.md`나 `save-load.md`에 "기존 ID 변경·삭제는 개정 번호만으로 처리하지 않고, 형식 버전 또는 명시적 변환을 거친다"를 한 줄 적는다.
