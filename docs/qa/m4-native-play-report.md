## 발견 및 제한

1. **시작 지점에서도 저장 거부가 발생했다.** 새 캐릭터 생성 후 공격하지 않고 건물 앞에 정지한 상태에서 슬롯 2 저장이 `적에게서 떨어진 안전한 곳에서 저장하세요`로 거부됐다. 메뉴를 닫고 게임 시각 00:08→00:14 동안 기다린 뒤 같은 위치에서 재시도하니 성공했다. 화면에는 토끼형 개체가 보였지만 어느 개체가 차단했는지는 특정하지 않았다. `save_safety.gd`는 스포너의 모든 Node2D 자식을 거리 기준으로 검사한다. 안전 지역/개체 분류에 대한 후속 판단 근거이며, 이번 QA에서 기준은 바꾸지 않았다.
2. **조작 도구의 문자 키 전달 한계.** K 입력 로그는 `key=75 physical=4194313 device=16 menu_skill=false`였다. 프로젝트는 물리 키 코드를 사용한다. 따라서 이동·스킬 메뉴가 반응하지 않은 것을 게임 결함으로 확정하지 않는다. 입력 매핑을 QA 편의로 바꾸지 않았으며, 장비·강화 및 이동 위치 복원은 남겨둔다.
3. **종료 경고.** 재실행 후 로드·새 캐릭터를 거친 프로세스를 종료했을 때 `6 ObjectDB instances` 및 `2 resources still in use`가 출력됐다. 이번 UI/QA 런처 경로의 관측이며 기존 headless seed 16/4와 별개다. 원인·재현 범위는 미확정. 저장 유실은 관측하지 않았다.
4. 최초 1280×720 창 시도에서는 HUD가 잘리고 버튼 조작을 확인하지 못했다. 전체 화면에서 위 절차를 완료했다. 작은 창의 레이아웃과 좌표 전달 문제는 분리 진단이 필요하다.

## 2026-09-27 Claude 리뷰 대조

### 시작 지점 저장 거부의 구조적 근거

시작 좌표 `(152,504)`와 `eastern_frontier_starting_area.tscn`의 마커 기준 계산이다. 실제 배회 중 좌표 로그가 없으므로 당시 차단 개체를 확정하는 증거는 아니다.

| 뿔토끼 마커 | 좌표 | 시작점 거리 | 차단 반경 160px까지 여유 |
|---|---|---:|---:|
| C | (312,408) | 186.6px | 26.6px |
| A | (344,360) | 240.0px | 80.0px |
| B | (392,488) | 240.5px | 80.5px |

`rabbit_stats.tres`의 인지 범위는 3타일(48px), 배회 속도는 1.5타일/초(24px/초), 귀환 범위는 -1이다. C에서 **플레이어 쪽으로 직진한다면** 약 1.1초 후 차단 반경에 진입할 수 있다. 아무 방향으로 배회해도 1.1초 후 진입한다는 의미는 아니다. 저장 차단 거리는 인지 범위의 약 3.33배로, 인지·추적 여부와 독립적이다. 거부 후 00:08→00:14는 게임 내 6분 표시이며 실제 6분 대기가 아니다.

`save_safety.gd`는 스포너 자식의 Node2D 여부·거리만 검사하므로 사망 애니메이션 중인 개체도 포함할 수 있다. `monster_base.gd`는 사망 애니메이션 종료 후 제거한다. 최근 전투 5초 차단이 먼저 적용되지만 긴 사망 애니메이션에서는 별도 검토가 필요하다.

후속 판단 후보는 반경 조절, 인지 범위 연동, 추적/적대 상태 판정, 안전 구역이다. 아직 어느 정책도 채택하지 않았다.

### 자동 저장 관측의 해석

`save_session.gd::advance()`는 메뉴 일시정지를 제외한 180초 경과 후 안전 조건을 검사한다. 차단 중에는 누적 시간을 유지하고 매 갱신 재검사하므로, 정상 파일 조건에서 실제 저장은 **180초 이후 처음 안전해진 갱신**에 실행된다.

그러나 이번 259초는 저장 발생 시각이 아닌 완료 표시 관측 시각이다. **259−180=79초를 실제 지연으로 계산하거나 토끼 배회 때문이라고 확정할 수 없다.** 차단 사유별 시간 기록이 없으므로 타이머 드리프트도 배회 지연도 이번 기록으로 측정한 것은 아니다.

### 자동 검증과 남은 직접 확인

`save_session_process_probe.gd`의 seed는 `player.position += Vector2(8.0, 0.0)`으로 위치를 바꾼 뒤 저장한다. verify는 새 프로세스에서 복원된 플레이어를 다시 캡처해 기대 payload 전체와 비교한다. 따라서 “probe도 시작 좌표만 사용한다”는 리뷰 서술은 정정한다. 장비 8칸·동일 반지 2칸·스킬 강화/지출 역시 기존 probe 범위다. 이번 대조에서 probe를 재실행하지는 않았다.

남은 위치 확인은 **실제 이동 입력 → 다른 장소에서 F6 저장 → 종료/재실행 → 그 장소 복원**이다. 장비·강화는 자동 검증 완료와 네이티브 미확인을 구분한다. 종료 경고 6/2의 원인은 계속 미확정이며 디렉터 G4 승인은 유지 대기다.
