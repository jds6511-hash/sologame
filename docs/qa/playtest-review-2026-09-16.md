[구현 계약](../art/sword-sweep-contract.md), [실제 렌더 재생](evidence/2026-09-16/sword-sweep-runtime.gif). 최종 GUT **892/892**, 아트 검사 **17/17**, 월드 입력 **40/40**, 변경 GDScript 포맷·린트 통과. 최종 로그에서 SCRIPT ERROR/ERROR/WARNING 없음(GUT의 기존 API deprecated 알림 8건은 남음). 아래 `a0a89dd` 검토는 수정 전 기록이다. 최종 미적 품질·G3 승인 완료는 아니다. 의뢰 중심 성장은 [M5 구현용 설계](../design/quests/early-leveling-route.md)로 정리했으며 게임에 퀘스트를 구현한 것은 아니다.

## 판정

기능 검사는 통과했다. **전투 난이도·검 휘두르기 체감·G3 승인은 보류**한다. OS 입력 도구의 키/클릭이 게임에 반영되는 것을 확인하지 못했으므로 직접 수동 플레이 성공으로 기록하지 않는다. 아래는 게임 내부 입력 주입, 실제 렌더, 사용자 영상 프레임 관찰 및 수치 모델의 결과다.

| 범위 | 이번 확인 | 남은 확인 |
|---|---|---|
| 이동·전투·메뉴·상태 전환 | 기존 런타임 검사 40/40 | 실제 OS 입력으로 조작되는지, 일반 플레이 동선 |
| 손·무기 연결과 모션 | 렌더 4직업×3방향×5시점, 돌진 자세 9/9, 아트 도구 검사 14/14 | 검 연속 궤적, 전체 콤보·좌우 반전·복귀 동작의 육안 판정 |
| 피격·초반 성장 | 사용자 영상 12시점 확인, 최신 자원으로 성장 모델 재산출 | 최신 빌드의 자연 사냥·사망·Lv10 실측 시간 |

## 1. 기능 검사

`runtime_playtest_2026_09_11.gd`를 현재 빌드에서 실행했다. 23초, 실패 0건.

- D 이동 31.65px, 회피 충전 소비, 좌클릭 홀드 7회 공격, 1번 스킬 시전.
- 메뉴 6개 탭 전환, 메뉴 중 이동 정지, Esc 복귀.
- 빈 가방의 포션 사용 차단, 테스트용 포션 생성 후 줍기·회복·1개 소비·쿨다운 중 재고 보존.
- 피해 API로 사망 유도 후 입력/메뉴 차단, 시작 위치 부활, HP/MP 50% 회복, 골드 1,000→950.
- 디버그 레벨 점프로 전사·검투사·궁수 전직 검사. **자연 레벨업 시간 검사가 아니다.**
- 별도 적 필드에서 궁수를 임프와 48px 거리로 배치하고 화살 9회 명중 확인. 적 AI의 피해로 플레이어 HP 335→0, 자연 교전 보상은 XP 0/골드 0이었다.
- 이후 잔여 적을 피해 API로 처치해 XP 384/골드 128 배선을 확인했다. **실제 사냥 성공 기록에 포함하지 않는다.** 이 고정 교전은 회피·거리 조절을 하는 사람의 난이도 평가도 아니다.

실행 시 상대 `--log-file` 경로에 대한 로그 디렉터리 생성 오류가 있었다. 검사는 끝까지 수행되고 출력도 남았으나, 실행 전체가 오류 0건이었다고 표기하지 않는다. 재실행에는 절대 로그 경로를 사용한다.

## 2. 무기 시각 검토

[현재 공격 단계 렌더](evidence/2026-09-16/attack-phases.png)를 확인했다. 기본 1타의 정지 샘플이므로 전체 콤보/연속 재생의 승인 자료는 아니다.

- **검 — 추가 검증 필요**: 준비 시 위로 든 검에서 판정 시 아래로 향한 검으로 크게 바뀐다. 중간 궤적이 충분히 읽히는지는 이 샘플만으로 입증되지 않는다. 사용자의 “휘두르는 느낌이 없다”는 지적을 해결 완료로 닫지 않는다.
- **걷기 손잡이 — 제한 범위 통과**: 생성기의 방향별 18프레임 피부 손 접점·출력 검사 통과. 이는 좌표/픽셀 조건의 검증이며 모든 런타임 이동 전환의 시각적 자연스러움을 보장하지 않는다.
- **궁수 — 제한 범위 통과**: 조준→발사→회복의 활 크기 설정이 6으로 일정하고 관련 회귀 검사가 통과했다. 렌더 샘플에서도 급격한 크기 변화는 확인하지 못했다. 방향별 원근 차이와 모든 비전투 자세까지 같은 외형 크기라는 뜻은 아니다.
- 공용 질주/난입 강타 자세 검사 9/9 통과. 최종 캐릭터 비율·옷·머리·체중 이동 등의 미적 수정은 이번 범위에서 제외했다.

아트 도구 `test_player_walk_grips`, `test_weapon_placement`, `test_player_archer_art`: **14개 통과, skip 없음**. Pillow `getdata` 사용 중단 예정 경고 1건은 비차단이다.

## 3. 사용자 영상과 성장 속도

원본 `녹음 2026-09-14 213211.mp4`: **1920×1080, 30fps, 3,405프레임, 113.5초**. [메타데이터](evidence/2026-09-16/video-metadata.json), [시점별 화면](evidence/2026-09-16/video-contact.png).

영상의 정확한 게임 커밋은 알 수 없다. 파일명의 녹화일과 수치 조정일이 같아 수정 전후를 단정할 수 없으며, **최신 빌드 검증과 분리**한다. 연속 영상 전체의 프레임 단위 분석이 아니라 지정한 12시점의 관찰이다.

| 영상 시점 | 화면에서 확인한 상태 |
|---|---|
| 6초 / 10초 | Lv1 HP 135/135, 검은 들개 여러 마리와 접근·교전 |
| 16초 | Lv1 HP 49/135 |
| 48초 → 55초 → 60초 | Lv2 HP 89→56→2/155, 강/다리 주변 점액 교전 |
| 64초 | 시작 건물 위치, HP 78/155. 직전 빈사와 위치·HP 변화를 보면 사망 후 부활로 추정 |
| 72~88초 | 강 주변 들개 다수, 88초에는 Lv3 HP 44/175 |
| 110초 | Lv3 HP 0/175, 쓰러진 캐릭터 |

반복 빈사와 두 차례의 사망 정황은 초반 생존 부담 지적을 뒷받침한다. 다만 피격 원인·예고 인지 가능 시간·동시 공격 수는 정지 샘플만으로 확정할 수 없다. 바닥 사각 장식과 반복 무늬의 대비도 높아 작은 캐릭터와 경쟁한다.

현재 `m3_respawn_pace_calc.py`의 자원/공식으로 다시 계산했다. 처치 외 오버헤드 7초, 활동 비중 50%, 낮:밤 2:1, 퀘스트 보상 0 가정이다.

| 목표 | 효율 우선 정상 동선 모델의 누적 시간 |
|---|---:|
| Lv3 | 1.47분 |
| Lv5 | 7.68분 |
| Lv8 | 26.37분 |
| Lv10 | 51.05분 |

이 모델은 레벨 차 ±4 및 치사성 조건을 통과한 종 중 EXP/초가 높은 대상을 우선 배분한다. **가장 가까운 레벨의 단일 종만 고르는 모델은 Lv10까지 104.81분**이다. 따라서 “Lv10은 누구나 51분”이라고 안내하면 안 된다. 사망·회복·길찾기·공격 실패를 실제 행동으로 모사하지 않은 계산값이다.

추가 관찰: Lv9→10 필요 EXP는 6,014지만 Lv10→11은 17,393으로 2.89배다. 의도대로 Lv10 이후 기존 곡선으로 복귀한 결과다. 전직 후 사냥 효율 향상이 이 증가를 상쇄하는지 후속 실측이 필요하다.

## 다음 확인 순서

1. 최신 빌드 들개 1마리에서 예고→판정→후딜을 연속 녹화하고 회피 성공/실패 원인을 대조한다. 다음에 2마리 접근 상황을 비교한다.
2. 검의 걷기→1/2/3타→대기 전환을 같은 방향으로 이어 관찰한다. 손 이탈·갑작스러운 방향 전환·판정 불일치만 수정 후보로 삼는다.
3. 디버그 레벨 점프 없이 Lv3/5/10 도달 시간, 사망 수, 포션 소비, 사냥 종을 기록한다. 51분 모델과 단일 종 모델의 차이를 실제 플레이로 검증한다.

새 수치 하향이나 최종 캐릭터 리디자인은 이 보고서만으로 진행하지 않는다. M3 G3 승인 상태는 그대로다.
