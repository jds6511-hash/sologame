## 구현과 저장 경계

`godot/data/content/base.json`은 기존 1·2장 목록, `chapter_three.json`은 3장 의뢰 8건·NPC·표식·스폰·간선·레이아웃의 정본이다. 생성기가 `game_content.gd`와 3장 의뢰 리소스를 만든다. 장마다 월드·카탈로그·세션을 만들지 않는다. 기존 상수12개와 의뢰13개는 이전 커밋과 대조해 의미 불변을 확인했다.

제품 형식 V6를 유지하고 개정2를 추가했다. 구 V1~V5 원본 검증 → 변환 → 재검증 순서는 그대로이며 개정1 저장에 3장 완료 상태를 채우지 않는다. 미래 개정은 백업 우회 없이 거부한다. 기존 ID의 목표·선행·보상 변경/삭제는 개정 증가만으로 처리하지 않는다고 문서에 고정했다. 생성기는 현재 목록 정합성을 검사하며 과거 ID 동결 자체를 자동 보장하지는 않는다.

메인5/서브3, 보고 EXP33,811·골드36,660·공훈600을 현행 100시간 문서와 독립 대조한다. 생성 전 전체 입력 검증, 선행 사슬·source·표식·지역 실재, 출력 경로 검사, `--check` 무기록, 실패 시 무기록을 Python7개 검사로 확인했다.

방어 현장은 1024×640이며 기본 여울목 타일을 변경하지 않는다. 명시적 재개에서만 현재 KILL 목표의 `목표−완료−동일 source 생존수`를 생성하고 전체 생존 수를3으로 제한한다. 다음 무리도 다시 재개해야 한다. 사망·삭제 대기·재개 연타·다른 source·지역·완료 상태를 회귀 검사한다. 그림자 목격은 기존 대화·일시정지 소유권을 쓰고, 신분·복구권은03-05 완료에서만 파생한다. 영지/스토리 예약 저장 필드는 빈 객체다.

## 발견해서 수정한 제품 결함

1. Lv13 최대 HP `375.22499999999997`가 JSON 왕복에서 `375.22500000000002`로 올라가 파일 쓰기 후 `vitals` 검증에 실패했다. 제품 capture만 원래 값 이하의 왕복 가능한 수로 정규화한다. 최대치 검증과 동결 구 저장 규칙은 완화하지 않았다. 회귀 테스트의 실패 → 통과와 실제 완료 저장으로 확인했다.
2. 월드 교체 시 이전 TileMapLayer 충돌이 queue_free까지 한 프레임 남아 방어 현장 도착점 `(192,544)`를 `(192,530.0074)`로 밀었다. `process_mode=DISABLED`만으로 타일 충돌이 제거되지 않았다. 새 월드의 복원이 성공한 뒤에만 이전 월드를 트리에서 즉시 분리하고 지연 해제한다. 실패 롤백 경로는 유지한다. 실제 물리 프레임 테스트가 실패 → 통과했다.

## 검증 명령과 범위

최종 결과: `verify-all/20261002-232047-307/result.json` **114/114 PASS**, GUT **1,181/1,181 · 140 scripts · 14,370 asserts**, 실제 저장 원본6개 해시 불변. ERROR는 GUT 기존 ExpectedError와 verbose로 분류된 Ogg 종료 오류만 예외 처리됐고 SCRIPT ERROR는0이다. Ogg 경고를 남긴 단계는54개이며 새 일반 누수로 확대 해석하지 않는다. 누수 해소를 선언하지 않는다.

렌더 API `defense-api-render-final.log`는 **PRODUCT_DEFENSE_PASS**, false/ERROR/SCRIPT ERROR0이다. 그림자 대화·향사 캐릭터 화면을 직접 열어 확인했다. 시작 화면의 3장 준비 `PRODUCT_START_PREVIEW_PASS`, 재생성한 실행기 `--smoke` exit0. 변경 GD30개 gdformat/gdlint, Python7개 검사, 생성물 일치, PowerShell 구문과 git diff 검사가 통과했다. 증거 출력은 ignored `docs/qa/screenshots/`만 사용한다.

최초 렌더 실패는 잘못 선택한 QA 탭 번호와 월드 교체 잔류 충돌을 드러냈다. 초기 저장 실패는 위 HP 직렬화 결함이었다. 해당 탐색 로그를 지우지 않았으며 실패를 최종 통과 표본에 합치지 않았다. 전투 조작기 `-Combat`은 이번에 실행하지 않았다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File docs/qa/tools/verify_all.ps1
godot --path godot -s ../docs/qa/tools/product_defense_probe.gd -- seed
```

단일 검증에 콘텐츠 Python2단계와 3장 API5단계(cleanup → seed → reload_mid → reload → cleanup)를 추가했다. 실제 저장6개는 전후 SHA-256과 복사본 이관으로만 확인한다. 3장 API는 `user://product_defense_probe`, 시작 체험은 `user://product_chapter_preview`만 쓴다.

API는 2장 완료·42,828 EXP·골드·좌표·적에게 가하는 피해를 fixture로 준비한다. 플레이어 물리 입력도 차단한다. 수락·표식 상호작용·대화·방어 생성·실제 사망 신호·보상 보고·지역 교체·파일 저장·별도 프로세스 복원은 제품 경로다. 정상 공격/회피·도보 완주·OS 입력·실전 TTK 증거가 아니다. 중간 파일은 첫 무리 완료 후 상태, 완료 파일은 메인과 기준 서브 완료 상태다. 오류로 흐름이 끊기면 마지막 도달 검사와 실행기 로그 검사가 실패시킨다.

물리 검사는 실제 캡슐 오프셋과 `test_move`/공간 질의를 사용하고 충돌 경계의 양성 대조를 포함한다. 신규 양방향 관문·도착점, 현장 NPC·표식·재개점·스폰점 접근, 관문지기 의뢰 우선순위, 목격창 pause 획득/해제를 확인했다. 렌더는 정지 화면이며 최종 아트 승인이나 동적 가독성 판정이 아니다.
