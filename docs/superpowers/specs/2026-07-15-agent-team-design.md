# 2D RPG 게임 스튜디오 에이전트 팀 — 설계 문서

날짜: 2026-07-15
상태: 승인 대기

## 목적

Godot 4.x 기반 2D RPG를 개발하기 위해, 역할별로 특화된 서브에이전트 18개로 구성된 "가상 게임 스튜디오"를 구축한다. 사용자는 메인 Claude(오케스트레이터)에게만 지시하고, 메인 Claude가 적절한 에이전트를 골라 일을 분배하고 결과를 종합 보고한다.

## 프로젝트 제약

- 게임 텍스트와 모든 산출 문서는 **한국어 전용**
- **개인 프로젝트** — 배포/공유 없음 (빌드 파이프라인, 마케팅, 로컬라이제이션 불필요)
- **싱글플레이 전용** — 멀티플레이/서버/PvP/경매장/수익 모델 없음. 왕국 이벤트는 플레이 중에만 진행되는 싱글 콘텐츠
- 플랫폼: **PC(Windows) 전용**, 키보드(+마우스) 조작
- 버전 관리: git 사용, 원격 저장소 `https://github.com/jds6511-hash/sologame.git`

## 폴더 구조

```
Desktop\game\
├── .claude\agents\        ← 에이전트 18명 정의 (md 파일 18개)
├── CLAUDE.md              ← 프로젝트 규칙 (한국어 전용, Godot 경로, 스포일러 규칙 등)
├── docs\
│   ├── PROJECT_STATUS.md  ← producer가 관리하는 백로그/진행 상황
│   ├── design\            ← 기획 산출물 (GAME_CONCEPT.md, GDD, 시스템 기획서 등)
│   │   └── spoilers\      ← 반전 요소 등 스포일러 문서 (사용자 열람 금지 구역)
│   ├── art\               ← 스타일 가이드, 에셋 목록
│   └── qa\                ← 리뷰 결과, 알파테스트 리포트
└── godot\                 ← Godot 프로젝트 (scenes, scripts, assets)
```

## 협업 방식

- 에이전트끼리 직접 대화할 수 없으므로 **문서가 인수인계 수단**이다. 기획 에이전트가 `docs\design\`에 기획서를 쓰면, 개발 에이전트는 구현 전에 해당 기획서를 읽는다.
- 메인 Claude가 작업 크기에 따라 필요한 에이전트만 골라 호출한다. 매번 전 단계(기획→개발→QA)를 강제하지 않는다.
- 각 에이전트 정의 파일에는 역할, 전문지식, 작업 규칙, 산출물 위치, "산출물은 한국어로 작성" 공통 규칙을 명시한다.

## 운영 규칙 (CLAUDE.md에 명시)

- **git**: 작업 단위마다 커밋, 마일스톤 완료 시 원격(`github.com/jds6511-hash/sologame`)에 푸시. gdformat 등 일괄 포맷팅 전에는 반드시 커밋해 되돌릴 수 있게 한다.
- **문서 최신성**: 모든 기획 문서 상단에 최종 수정일 + 간단한 변경 이력(changelog)을 기록한다. 개발 에이전트는 작업 시작 전 참조 기획서의 변경 이력을 확인한다.
- **기획 문서 공통 템플릿**: 제목, 최종 수정일, 담당 에이전트, 의존 문서 링크를 머리말로 포함.
- **디렉터 승인 게이트**: 각 마일스톤(M1, M2, M3…) 완료 시 디렉터(사용자)가 직접 확인·승인해야 다음 단계로 넘어간다. 특히 M2(수직 슬라이스)는 디렉터가 직접 플레이하여 재미/난이도를 승인한다 — alpha-tester는 버그는 잡아도 재미는 판단할 수 없기 때문.
- **Godot 버전 고정**: 설치 시점에 확정된 마이너 버전(예: 4.5.x)을 CLAUDE.md에 기록하고, 애드온 설치 시 해당 버전 호환성을 확인한다.
- **GDScript 컨벤션**: 씬/스크립트 파일 배치와 네이밍 규칙을 CLAUDE.md에 정의하고 gdformat/gdlint로 강제한다.

## 스포일러 규칙 (반전 요소)

- 게임 스토리에는 반전 요소가 있어야 하며, **사용자는 직접 플레이할 때 처음 확인**해야 한다.
- narrative-designer가 반전을 설계해 `docs\design\spoilers\`에만 기록한다.
- 메인 Claude와 모든 에이전트는 사용자에게 반전 내용을 절대 언급하지 않는다. 진행 보고 시에도 "스토리 반전 구현 완료" 수준으로만 표현한다.
- 한계: 사용자가 해당 파일이나 게임 코드를 직접 열면 스포일러를 피할 수 없다. 폴더명으로 경고하는 것까지가 시스템이 할 수 있는 보호다.

## 알파테스터 작동 방식

- Godot 커맨드라인 실행(`--headless` 포함)으로 게임 구동, 콘솔 로그·에러 수집
- GUT 프레임워크로 자동 테스트 스크립트 작성·실행
- 스크린샷 캡처 후 이미지 분석으로 화면 상태 확인
- 결과를 `docs\qa\`에 플레이 리포트로 작성
- **리포트는 휘발성**: 리포트 내용은 관련 에이전트(수정 담당 개발자 등)에게 공유되어 반영하고, 지적 사항이 모두 처리되면 해당 리포트 파일은 삭제한다. `docs\qa\`에는 미해결 리포트만 남는다.
- 한계: 사람처럼 자유로운 실시간 조작은 불가. 자동 테스트 + 화면 확인 조합으로 동작. 버그·오작동은 잡을 수 있으나 "재미있는가"는 판단 불가 — 재미 판단은 디렉터 승인 게이트에서 수행

## 게임 기획 요구사항

사용자가 제공한 게임 요소는 `docs\design\GAME_CONCEPT.md`에 정리한다. 요약:

- 직업 10개(히든 2개 포함), 모험가로 시작 → 10레벨에 전직, 3차 전직까지
- 레벨업 시 스탯/스킬 성장, 세이브/로드
- 메인퀘스트 중심 + 수백 개 서브퀘스트, 예상 플레이 200시간
- 판타지 세계(인간/엘프/드워프), 왕국 중심의 도시–마을–부락 구조
- 명성 기반 계급 시스템: 명성 수치에 따라 부락→마을→도시를 하사받고, 규모에 따른 수입 + 영지 관리 콘텐츠
- 펫, 칭호(약 100개), 도감(아이템/몬스터/펫/칭호)
- 아이템: 레벨 제한 + S/A/B/C 등급제, 퀘스트/특정 몬스터 전용 특수무기
- 게임 내 시간: 현실 30분 = 게임 하루, 게임 한 달마다 랜덤 왕국 이벤트(결과에 따라 명성/골드)
- 스토리 반전 요소 (스포일러 규칙 적용)

## 개발 단계 (마일스톤)

200시간 분량은 매우 큰 규모이므로, 수직 슬라이스(작게 완성)부터 단계적으로 확장한다:

1. **M0 — 스튜디오 구축**: Godot/도구 설치, 에이전트 18명 생성, 폴더 구조, 동작 검증
2. **M1 — 기획 기반**: GDD(세계관, 직업/전투/경제 시스템 상세 설계), 아트 스타일 가이드
3. **M2 — 수직 슬라이스**: 마을 1개 + 필드 1개 + 전투 + 세이브 + 퀘스트 몇 개가 도는 최소 게임
4. **M3 이후 — 콘텐츠 확장**: 전직, 영지, 도감, 펫/칭호, 왕국 이벤트 등 시스템을 하나씩 추가

각 마일스톤은 별도의 스펙→계획→구현 사이클로 진행한다. 본 문서는 M0의 스펙이다.

## 검증 기준 (M0 완료 조건)

- Godot 실행 파일이 CLI에서 구동됨
- `.claude\agents\`에 18개 에이전트 파일 존재, 각각 역할/규칙/산출물 위치 명시
- 폴더 구조와 CLAUDE.md 생성 완료
- git 원격 저장소 연결 및 푸시 성공
- 에이전트 1명 이상 실제 호출 테스트 통과 (예: producer가 PROJECT_STATUS.md 초안 작성)
- 문서 인수인계 엔드투엔드 테스트: 기획 에이전트가 작성한 문서를 개발 에이전트가 읽고 정상 참조하는지 확인

## 지금 결정하지 않는 것 (M1로 이월)

전투 방식(실시간 vs 턴제), 세계관 세부(종족 관계, 톤, 마법 체계), 직업 목록/전직 구간, 퀘스트 유형/분기, 명성과 계급의 관계, 아이템 강화/제작, 펫·칭호 세부, 낮밤/계절, 콘텐츠 시간 배분 등 게임 내용에 관한 결정은 전부 M1(기획 기반)에서 담당 기획 에이전트가 안을 만들어 디렉터 승인을 받는다. 외부 검토에서 나온 질문 목록은 `docs\design\M1_QUESTIONS.md`에 보관하여 M1 기획의 입력으로 사용한다. 단, **전투 방식은 다른 모든 시스템의 전제**이므로 M1에서 가장 먼저 결정한다.
