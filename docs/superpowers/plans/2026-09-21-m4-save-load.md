## 상위 실행 계약

Claude 독립 검토 반영 후 상세 판단은 [저장·불러오기 계약](../../design/systems/save-load.md)을 따른다. 이 계획의 간략 표현과 충돌하면 해당 계약이 우선한다.

## 목표와 범위

현재 Godot 게임에서 저장→종료→재실행→슬롯 불러오기로 같은 캐릭터 진행을 복원한다. 계정 파일 1개와 캐릭터 슬롯 10개를 분리한다. 신규 직업·퀘스트·경제 구현은 포함하지 않는다.

- 파일은 `user://saves/`에 JSON으로 기록한다. 계정·캐릭터 각각 버전 1부터 시작한다.
- 저장 파일은 종류·버전·체크섬·JSON 본문을 포함한다. 임시 파일 기록·재검증 후 교체하며 이전 정상본은 `.bak`으로 보존한다. 실패 시 성공으로 표시하지 않는다.
- 손상된 본문은 백업을 읽고 복구 사용 사실을 알린다. 미지원 상위 버전은 되돌리거나 덮어쓰지 않는다. 기존 출시 저장 형식은 없으므로 버전 0 등을 임의 추측해 변환하지 않는다.
- 계정은 계정 ID·도감/업적/외형/본 콘텐츠 기록·유산·공용 창고 영역을 가진다. 현재는 튜토리얼 완료를 연결하고 나머지는 빈 영역으로 유지한다.
- 캐릭터는 ID·이름·플레이 시간·레벨/EXP·직업·스킬 강화/실제 지출·가방/장비/골드·HP/MP·맵/위치·게임 시간 및 향후 진행 영역을 가진다.
- 아이템/직업/스킬/맵 참조는 stable ID다. 표시명과 리소스 경로를 파일에 저장하지 않는다. 등록되지 않은 ID와 잘못된 수치는 거부하고 현재 진행은 그대로 둔다.
- 복원은 신규 월드에서 진행한다. 레벨업/전직 보상을 재지급하지 않고 직업→장비/스탯→스킬→HP/MP→UI 순서로 복원한다.
- 전투 순간 상태(투사체·공격 동작·적 HP·바닥 드롭)는 저장하지 않는다. 안전한 정지 상태에서만 저장하며 불러오면 필드를 다시 구성한다. 쿨다운 초기화 악용을 막기 위해 회복/스킬/대시 준비가 끝난 상태에서 저장한다.
- 저장 메뉴는 시작 지역에만 연결한다. 10개 슬롯의 저장/불러오기/새 캐릭터를 제공한다. 덮어쓰기와 현재 진행을 버리는 작업은 메뉴에서 명시 확인한다. 활성 슬롯에 3분 주기 안전 상태 자동 저장을 연결한다. 자동 불러오기는 하지 않는다.
- `project.godot`을 변경하지 않고 기존 시작 지역 루트에 세션 노드를 연결한다. 별도 개발 전투장은 영향받지 않는다.
