디렉터가 M2를 **"코어 실시간 전투 루프가 기술적으로 작동함"**으로 승인·종료했다(2026-07-27). 게이트 재정의의 배경: 수직 슬라이스(전사 1직업·몬스터 3종·시작 지역 1곳, 경험치/레벨업 미구현)로는 재미/난이도를 판정할 수 없다는 것은 수직 슬라이스의 정상적 한계이며, 재미/난이도의 실제 판정은 콘텐츠가 갖춰지는 M3로 이월한다. ### 9-5. 마일스톤 미배정 3건 — **계획 누락** (2026-08-20 신규 등재)

**경위 (문서 대조 근거)**

> **이 장은 확정 범위가 아니다.** M3는 디렉터가 4기둥을 직접 확정하는 절차를 거쳐 범위가 성립했다(10-2절, 2026-07-27). **M4도 같은 절차가 필요하다** — 아래는 producer 제안이며 **M3 게이트(G3) 판정 결과와 함께 디렉터가 확정**한다. 확정 전에는 어느 Phase도 착수하지 않는다.

**표기**: 리뷰는 M4-A/B/C 명칭을 제안했으나, M3에서 이미 Phase A~E 표기를 쓰고 있어 **기존 표기(M4 Phase A/B/C)로 통일**했다 — 명칭만 보류하고 3분할 구조 자체는 채택했다.

### 11-1. Phase 구조와 순서 근거

| Phase | 이름 | 한 줄 목표 | 담당(제안) | 9-5절 대응 |
|---|---|---|---|---|
| **A** | 영속성 | "게임을 끄고 다시 켜도 진행이 유지된다" | systems-dev | **N1** |
| **B** | 퀘스트 수직 슬라이스 | "NPC에게 임무를 받아 전투로 완료하고 보상을 받은 뒤 그 상태가 저장된다" | quest-designer + systems-dev + level-designer | **N2 · N3** |
| **C** | 아트 전환 | "M3에서 검증한 플레이 감각을 해치지 않고 목표 아트 방향으로 전환한다" | art-director + pixel-artist | — |

**순서 근거는 의존성이다.** ① A가 없으면 B의 완료 판정("저장된 상태가 유지된다")이 성립하지 않는다. ② C를 A·B와 같은 커밋 흐름에 섞으면 기능 버그와 아트 변경 영향을 구분할 수 없다. ③ M3까지의 질문이 "전투가 재미있는가"였다면 M4의 질문은 **"플레이할 수 있는가"**이고, 그 답의 직접 구성 요소는 A와 B다.

### 11-2. Phase A — 영속성 (세이브/로드)

**범위(제안)**: 세이브 스키마 · 최소 단일 저장 구조(또는 슬롯) · 로드 · 오토세이브 트리거 정의 · 플레이어 진행 · 인벤/장비 · 골드 · 직업·스킬 상태 · 최소 월드 상태.

**제약 — 채택 3 (리뷰 6.3절): 세이브 스키마는 stable content ID + 버전 필드를 전제로 설계한다.**

- **노드 경로·표시 이름을 저장 데이터 ID로 쓰지 않는다.** 식별자는 `player` · `item:<id>` · `quest:<id>` · `npc:<id>` · `world_flag:<id>` · `map:<id>` · `spawn:<id>` 형태의 **stable content ID**만 쓰고, scene/node 경로는 **런타임 매핑 계층**에 둔다.
- **버전 필드 없이 저장 포맷을 고정하지 않는다.** 버전 불일치 처리 정책이 있어야 한다.
- **채택 이유 — 우리 상황의 실제 위험이다.** M4에서 **세이브(Phase A)와 아트 전환(Phase C)이 같은 마일스톤에 겹친다.** 아트 전환은 씬 구조·스프라이트 배선을 광범위하게 건드리므로, 노드 경로를 저장 ID로 쓰면 **Phase C 진행 중에 Phase A의 세이브가 깨진다.**

**완료 조건(제안)**: 새 게임 → 플레이 → 저장 → 종료 → 재실행 → 동일 진행 복원 / 손상·누락 저장 파일에서 크래시 없음 / 버전 불일치 정책 존재 / 주요 저장 대상 자동 테스트 존재 / **기존 856 테스트 회귀 0건**(3장 실측 스냅샷 기준).

### 11-3. Phase B — 퀘스트 수직 슬라이스 (퀘스트 + NPC/대화)

**제약 — 채택 1 (리뷰 3.2절): 퀘스트 시스템을 고립 구현하지 않는다. 최소 NPC/대화와 한 덩어리로 관통시킨다.**

관통해야 하는 흐름: **NPC → 대화 → 퀘스트 제시 → 수락 → 목표 진행 → 완료 조건 → NPC 보고 → 보상 → 저장.**

- **채택 이유 — 우리 프로젝트에 이미 전례가 있다.** 온보딩이 퀘스트 부재로 `TutorialController` 세션 상태로 대체 구현됐고, 그것이 **이월 4건(9-1절 C1~C4)**이 됐다. 퀘스트만 따로 만들면 디버그 키 수락 · UI 버튼 시작 · 테스트 플래그 직접 변경 같은 임시 구현이 또 생기고, 나중에 NPC/대화를 붙이면서 흐름을 전부 뜯게 된다.
- **첫 퀘스트는 분기 없이 최소로.** 예: NPC A → 특정 몬스터 N마리 처치 → NPC A 복귀 → 골드/아이템 보상. **목적은 콘텐츠 품질이 아니라 계층 연결 검증**이다.
- **상점은 이 슬라이스에서 제외 가능**하다(11-5절로 분리). 마을은 NPC를 배치할 수 있는 최소 규모면 된다.
- 여기서 **9-1절 C1~C4(온보딩 이월 4건)를 함께 해소**한다 — C1이 퀘스트 시스템 도입에 종속돼 있기 때문이다(9-2절).
- 완료되면 **9-1절 A3(페이스 레버) 재판정 조건이 갖춰진다** — A3은 "퀘스트 시스템이 M3 범위 밖이라 검증 대상 부재"로 미룬 항목이다.

**완료 조건(제안)**: NPC 대화로만 수락 가능(디버그 경로로 수락되지 않음) / 목표 카운트 자동 진행 / 저장·재실행 후 진행 유지 / 완료 후 중복 보상 불가 / 퀘스트 상태에 따라 NPC 대화 분기 / 실패·엣지 테스트 존재.

### 11-4. Phase C — 아트 전환

**범위(제안)**: 롬스테드 기준 4축(프롭 밀도 · 팔레트 32→128 · 명암 4→5~6단 · 부분 아웃라인) + `Camera2D.zoom` 4→3. **착수 시점을 M3 게이트 후로 두는 것은 이미 디렉터 확정 사항**이다.

**제약 — 채택 2 (리뷰 3.3절): 기능 구현과 분리한 독립 workstream으로 운영하고, 대표 샘플부터 검증한다.**

- **스프라이트 284개를 한 번에 교체하지 않는다.** 대표 샘플 세트(지형 1세트 · 플레이어 1직업 · 근접 몬스터 1종 · 원거리 몬스터 1종 · 전투 FX 일부)를 먼저 검증한 뒤 환경/캐릭터/몬스터/FX 카테고리별로 확대한다.
- **기능 시스템 커밋과 아트 대량 교체 커밋을 섞지 않는다.** 섞으면 기능 버그인지 아트 영향인지 구분할 수 없고, 회귀 원인 추적이 막히며, 플레이 비교 기준이 흔들린다.
- 샘플 게이트에서 볼 것: 가독성 · 명암 · 줌 · 충돌 박스 체감 · 공격 거리 체감 · 픽셀 밀도.
- **`Camera2D.zoom` 4→3은 G3 이후에만.** 한 줄 변경이지만 G3-1 판정 기준을 흔든다(10-4절).
- **게이트 전 최소 수정은 Phase C가 아니다.** 지형 명도 폭 101 → ≤15 축소는 **M3 게이트 직전 작업**이다(`interim-review-2026-08-20.md` 7장 1번).

### 11-6. 디렉터 확정 필요 사항 (M4 착수 전)

1. **M4 범위 확정** — Phase A/B/C 3개를 한 마일스톤에 모두 넣을지, 잘라낼지. **3개 전부는 M3보다 크다.** Phase C는 독립 workstream이라 A·B와 기간이 겹쳐도 커밋 분리만 지키면 되지만, **무엇을 줄일지는 디렉터 판단**이다.
2. **9-5절 N1·N2·N3의 마일스톤 배정 승인** — 위 Phase 대응(N1→A, N2·N3→B)을 그대로 확정할지.
3. **세이브 슬롯 정책** — 단일 저장인지 슬롯 다수인지. 플레이 경험에 직접 영향을 주므로 Phase A 설계 전에 필요하다.
4. **Phase B 첫 퀘스트의 서사 위치** — 검증용 최소 퀘스트로 둘지, 메인 스토리 MQ-01/02를 그대로 쓸지.
5. **G4 게이트 판정 대상** — 무엇을 직접 플레이해 승인할지. 범위 확정 시 함께 정한다.

- **마일스톤 완료 조건에는 항상 디렉터 승인이 포함된다** — M4도 예외 없다(1장 마일스톤 이력 · 5-1절).
