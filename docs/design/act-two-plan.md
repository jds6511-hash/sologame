# 2막(4~9장) 전체 개발 계획

> 구현 담당: 계획 통과 후 `superpowers:executing-plans`로 아래 기능 묶음을 순서대로 실행한다. 내부 작업·커밋은 나눌 수 있으나 외부 검토는 기능 묶음 단위로 한다.

- 작성: 2026-10-03 / Codex. 상태: **전체 계획 독립 검토 요청 전**. 4장·M8 제품 구현은 아직 시작하지 않았다.
- 목표: 1막 기본 게임에 왕국 순회, 영지 운영, 2차 전직, 남작 하사와 발크렌 방어전을 연결한다.
- 구조: 현재 공통 제품 월드·세션과 통합 콘텐츠 목록을 유지한다. 장별 표를 생성기로 만들고 공통 기능만 확장한다. 장마다 후보 월드·저장 검증기 상속 사슬을 만들지 않는다.
- 기술: Godot 4.7.1/GDScript, JSON 콘텐츠 표, Python 생성기, PowerShell `verify_all`.
- 디렉터 지시: **이 전체 계획을 한 번 검토받고 통과하면 4장부터 순차 구현**한다. 새 시스템 묶음만 상세 설계 검토를 유지한다. 체감 판정은 **6장 끝과 9장 끝**에 모은다. 계획 작성은 M8 단독 선행 구현 지시를 대체한다.

## 1. 기준과 범위

수치는 [100시간 예산](100-hour-progression-budget.md)의 장별 수·시간·골드·공훈과 [EXP 여유 계약](100-hour-exp-margin.md)을 함께 적용한다. 후자가 EXP 지급 시점·증액·합격선에서 우선한다. [공개 서사](story.md), [지역 구조](levels/world-structure.md), [직업](systems/jobs.md), [영지](systems/reputation-territory.md)는 지역·행동·승급 계약의 근거다. 이 문서들의 옛 200/250시간, 옛 장별 보상·레벨 표를 현행 예산에 섞지 않는다.

2막은 기준 누적 **5~53시간(48시간)**, 메인 **30건**, 기준 서브 **60건**이다. 추가 서브 **16건**은 9장 완료 뒤 별도 보완으로 남기며 아래 기본 보상·시간에 더하지 않는다. 새 아트 리디자인, 상점 세부 미감, 펫, 3차 전직, 백작·도시 하사와 10~12장 콘텐츠는 이번 범위 밖이다. 임시 그래픽을 쓸 때도 공격 예고와 상호작용 표시는 구현한다.

현재 제품은 V6/콘텐츠 개정 2이며 1막은 기본 반영·체감 확인을 마쳤다. 2막 진입에 1막 재완주를 요구하지 않는다. 기존 저장은 실제 달성 상태를 유지하며 새 장을 완료로 채우거나 레벨을 계획값에 맞춰 올리지 않는다.

## 2. 장별 콘텐츠 범위

레벨 구간은 **증액 전 예산의 진입~종료 참고값**이다. 실제 몬스터 밴드·전투 수와 누적 EXP를 구현할 때 대조한다. 특히 7장 증액 후 종료 레벨은 이 표와 달라질 수 있다. 레벨 숫자를 지역 잠금에 그대로 추가하지 않는다.

지역별 서브는 해당 장의 조사·주민 생활·보급을 보강한다. 기준 60건은 현재 지원하는 모든 직업에서 수락·완료할 수 있게 만든다. 직업·선택 분기로 배타적인 의뢰는 기준 풀에 넣지 않는다. 메인 ID는 `MQ-04-01~04`, `MQ-05-01~05`, `MQ-06-01~05`, `MQ-07-01~06`, `MQ-08-01~05`, `MQ-09-01~05`로 예약하고 실제 장 제작 시 등록한다. 아직 없는 ID를 현재 저장 검증기에 미리 허용하지 않는다.

몬스터 명칭·권역은 지역 구조의 패밀리 골격을 따른다. 다음처럼 제작 범위를 구분한다.

- 멧돼지·표범·늑대·사냥개는 추격/돌진/근접, 허수아비·도마뱀전사·코볼트·오우거는 근접/예고 강타, 정령·독버섯은 투사체/장판 등 기존 행동을 조합하되 종별 사거리·예고·취소·피격 반격을 데이터로 구별한다. 이름과 HP만 바꾼 것을 새 전투 패턴으로 보고하지 않는다.
- 하피·박쥐의 비행은 시각 표현과 접근 패턴부터 구현한다. 지형·외곽벽을 무시하는 새 이동 규칙은 자동 도입하지 않는다. 가고일의 주야 전환과 망령의 야간 전용 출현은 선택 변형으로 남기며 필수 의뢰에 시간 대기를 강제하지 않는다.
- 가시덩굴 고정 공격, 트렌트의 넓은 예고, 골렘의 느린 강타는 공통 행동 확장으로 처리한다. 지휘·단계 전환·전장 목표가 필요한 군후는 **9장 전에 별도 새 시스템 설계**로 검토한다. NPC 동료는 장면·지원 효과부터 연결하고 자유 동행 파티 AI까지 암묵적으로 확장하지 않는다.
- 정예·보스 EXP는 아래 처치 풀에 포함한다. 종수·스폰 수 자체가 그 풀을 지급했다는 증거는 아니다.

## 3. 100시간 예산 대조

### EXP: 기초 풀과 확정 증액 분리

서브 보고는 `roundi(보고×0.4)`, 메인 보고는 나머지다. 표의 모든 값은 고정 지급 예산이며 수령 레벨에 따라 재평가하지 않는다.

| 장 | 기초 메인 보고 | 기준 서브 보고 합 | 처치 풀 | 추가 필수 보고 | 최종 장 EXP |
|---|---:|---:|---:|---:|---:|
| 4 | 119,011 | 79,340 | 85,008 | 0 | 283,359 |
| 5 | 246,398 | 164,265 | 175,998 | 0 | 586,661 |
| 6 | 566,607 | 377,738 | 404,719 | 0 | 1,349,064 |
| 7 | 1,317,896 | 878,598 | 941,354 | **500,000** | **3,637,848** |
| 8 | 2,036,662 | 1,357,775 | 1,454,758 | 0 | 4,849,195 |
| 9 | 3,870,011 | 2,580,008 | 2,764,294 | 0 | 9,214,313 |
| 합계 | 8,156,585 | 5,437,724 | 5,826,131 | 500,000 | **19,920,440** |

S7은 `MQ-07-01` 첫 필수 조사 보고에 배정한다. 기존 메인 풀에서 **500,000을 앞당기고 신규 500,000을 더해 1,000,000**을 지급한다. 나머지 메인 5건의 보고 EXP 합은 **817,896**이다. 7장 메인 최종 합은 1,817,896이며 앞당긴 몫을 뒤에서 다시 주지 않는다. 첫 보고에는 Lv40·2차 전직·선택 종족 서브 완료를 요구하지 않는다. G40은 이 보고 직후 판정한다.

정본 산술의 G40 누적 요구는 **2,532,500**, 기준 공급 3,323,530, 보수적 B 공급 3,054,443이다. 이는 예산 공급을 실제 콘텐츠가 지급한다는 조건부 수치다. 1막에서 실제 처치 EXP가 예산보다 적었던 문제를 이 숫자로 덮지 않는다. 4장 착수 때 기존 1막 완료 저장 표본의 실제 누적치를 기록하고, 장마다 처치 레벨차·보고 지급 순서·서브 생략 경로를 계산한다. 부족하면 해당 장의 처치/보고 배분·목표 동선을 정본과 함께 명시적으로 조정한다. 자동 레벨 보정·무료 EXP 주입·의무 반복 사냥으로 통과시키지 않는다. G80/G95는 3막 범위이며 이번 통과를 주장하지 않는다.

### 골드·공훈

골드는 `g(L)=roundi(2×L^1.5)`, 메인 합 `300g`, 기준 서브 **각** `30g`다. 영지·사냥·판매 수입은 의뢰 풀 밖이며 필수 구매력의 전제로 삼지 않는다.

| 7 | 44 / 584 | 175,200 | 17,520 / 13 | 402,960 | 1,400 / 700 | 3,200 / 4,600 |

진입 공급은 **이전 장까지**의 기준 서브 포함 값이다. 해당 장 보상을 선반영하지 않는다. 기준 서브 공훈 20% 손실 시 R4~R9 공급은 1,160/1,860/2,920/4,300/6,260/7,280으로 요구를 넘는다. 이것은 의뢰 건수 20%나 모든 서브 생략을 보장하는 말이 아니다. 영지 투자를 공훈 관문의 선행으로 만들지 않는다.

메인 골드를 마지막 보고에 몰지 않는다. 각 장 장비 구매·회복·이동·재시도 전에 지급되는 현금과 현물을 실제 거래 가격으로 대조한다. 2차 지급 무기는 의뢰 골드와 별도 현물로 장부에 기록하며 반복 전직/불러오기로 복제되지 않아야 한다.

전직 시련은 메인30/서브60의 수에 몰래 넣지 않는다. 별도 분류로 등록하고 상세 설계에서 정본 전직 보상·기초 풀과의 관계를 확정한다. **G40을 넘기 위해 전직 후 받는 시련 보상을 미리 더하는 것은 금지**한다. 현재 미지원 8계열과 3차 전직은 이 묶음에 자동 포함하지 않는다.

M8 상세 설계는 기존 ‘현장 조작/원격 조회’, 금고 7게임일 상한, 최소 30게임일 회수, 고정 영지 기준 단가를 검산한다. 시설 중 아직 없는 펫·도감 시스템 효과는 작동하는 것으로 표시하지 않는다. 오프라인 시계·휴식 스킵·메뉴 일시정지로 수입이 늘어나는지, 미수령 상한 이후 적립과 불러오기 중복을 명시한다. 영지 수입을 아래 의뢰 공훈 합계에 섞지 않는다.

## 5. 지역·데이터·저장 구현 계약

도시는 NPC·상점·문장원·보고 동선, 필드는 시야·사거리·서식지·귀환 시간에 맞춰 크기를 정한다. 예를 들어 거점은 1,024×768부터, 큰 도시는 구역을 나누고, 필드는 1,280×768 이상에서 동선으로 조정하며 실내는 더 작게 둔다. 이는 초기 배치 기준일 뿐 모든 지역을 같은 크기로 고정하는 규칙이 아니다. 각 지역은 자기 bounds·카메라·외곽벽과 관문별 도착점을 가진다.

오란세 내부는 독립 성역이다. 몬스터·왕국 영지 징수·워프 게이트를 넣지 않고 순례길로 진입한다. 그곳의 증언은 의뢰 진행이며 왕국 공훈은 브란텔 보고에서 지급한다. 아르셀은 기록/학술 공간, 항구는 부두/창고, 수림은 통행/조사 구역으로 기능과 길찾기를 구별한다. 그래픽 리디자인 전에도 도시 이름만 다른 동일 맵을 만들지 않는다.

주요 변경 위치와 책임:

| 위치 | 책임 |
|---|---|
| `godot/data/content/chapter_four.json` ~ `chapter_nine.json` (신규) | 의뢰·예산·NPC·표식·스폰·지역·간선의 장별 입력 표. 실제 장 구현 시 추가 |
| `tools/generate_chapter_content.py` | 통합 생성과 예산/선행/source/지역 연결 검사 확장. 생성물 수동 편집 금지 |
| `godot/scripts/content/game_content.gd`, `game_catalog.gd` | 통합 정의와 조회. 진행/선택 상태는 저널에 유지 |
| `game_layout.gd`, `game_spawner.gd`, `game_site.gd`, `game_navigation.gd` | 데이터 기반 지역 템플릿·배치·목표·지역간 안내. 장 전용 세션 사슬 금지 |
| `godot/scripts/world/product_world.gd`와 공통 제품 세션 | 월드 교체·설치·저장 연결. 상인 확정 거리 검사 재사용 |
| 새 `godot/scripts/territory/` 및 전직/보스 공통 모듈 | 실제 새 시스템만 분리. 상세 설계에서 상태와 원자적 변경 경계를 고정 |
| `docs/qa/tools/verify_all.ps1`와 기존 GUT/세션 검사 | 새 경로를 기존 단일 명령에 추가. 장마다 별도 최상위 실행기를 늘리지 않음 |

콘텐츠 추가만이면 **content_revision만 증가**한다. 영지 금고/시설 등 저장 구조가 처음 생기는 M8에서만 제품 형식 변경을 검토한다(제품 V7 예상, 과거 후보 V7과 다름). 2차 직업·새 목표 저장이 기존 구조에 들어가면 형식을 다시 올리지 않는다. 상세 설계에서 불가피한 구조 변경이 확인된 경우에만 버전을 올린다.

원본은 해당 버전 동결 규칙으로 검증한 뒤 이관하고, 현재 통합 목록으로 재검증한다. 미래 `content_revision`은 `unsupported_content`로 거부하며 백업 우회 금지, 미지 ID·선행·지역 잠금·공훈 합계를 유지한다. 실제 저장을 자동으로 덮어쓰지 않으며 QA 복사본으로 이관을 확인한다. 새 영지는 실제 하사 완료에서 초기화하고 이전 금고·시설을 지우지 않는다.

## 6. 실행·검증·검토 순서

- [ ] **P0 전체 계획:** 이 문서 하나를 독립 검토한다. 통과 전 4장/M8 제품 코드를 시작하지 않는다. 반격 `a08a715` 등 이전 결과 파일도 정해진 시점에 확인한다.
- [ ] **P1 4장/M8:** 상세 시스템 계약 → 필요한 실패 회귀 검사 → 공통 기능·장 표·런타임·UI·저장 구현 → 생성/단일 검증 → 기능 묶음 커밋·통합 구현 검토. 임시 화면만 만든 뒤 검토로 끊지 않는다.
- [ ] **P2 5장**, **P3 6장:** 각 장을 수락→동선→전투/조사→보고→중간/완료 복원까지 연결한다. 같은 틀의 장별 설계 문서는 다시 검토받지 않는다.
- [ ] **P4 6장 끝:** 4~6장 기능 검증·성장/경제 장부를 모아 중간 체감 요청을 한 번 한다. 아래 체감 항목만 요청한다.
- [ ] **P5 7장/2차**, **P6 8장/남작**, **P7 9장/방어전:** 위 도입 순서에 따라 통합한다. 계획 통과 후의 일반 구현 검토 대기 동안에는 다음 승인된 장의 작업을 진행한다. 새 시스템 상세 설계에서 미결인 계약은 구현 완료로 간주하지 않는다.
- [ ] **P8 9장 끝:** 기본 게임에서 2막 기능·저장 경로를 닫고 최종 체감과 추가 서브16건의 후속 우선순위를 정리한다. 3막은 자동 착수하지 않는다.

장별 종료 조건은 생성기 결정성, 예산 합·선행 DAG·source/표식 실재·왕복 간선, 전체 GUT, 변경 API 세션의 중간/완료 저장 복원, 미래/미지 데이터 거부, 실제 저장 해시 불변이다. 제품은 기본 실행에 합치고 개발 중인 장만 격리 준비 상태를 제공한다. 준비 상태는 QA 경로만 쓰며 정상 완주 증거와 구분한다.

자동 전투는 `verify_all -Combat` 참고 옵션이고 채택의 새 관문으로 만들지 않는다. 실행한다면 시작 전에 3회를 고정하고 모두 기록한다. 도구 문제만 보완하는 별도 묶음을 반복하지 않는다. 제품 오류는 우선 수정하고 원인 불명은 미검증으로 남긴다. 낮음/참고는 다음 제품 묶음에 함께 넣는다.

반격 `a08a715` 독립 검토는 통과했다(최종 코드 114/114 재현). 참고 2건인 궁수의 사거리 우위를 이용한 거리 유지 사냥, 스폰 16타일 경계에서 재피격에 따른 귀환/추격 반복은 2막 신규 적의 추격·예고·배치와 함께 확인한다. 이 참고만으로 1막을 다시 체험하도록 요청하지 않는다.

처치 EXP 실측은 몬스터별 레벨·개체 수·레벨차 배율·정예/보스·보고/선택/반복 지급을 분리한다. 기본 장부와 서브 생략 A/B를 나란히 기록하고 전직 전에 쓸 수 있는 보상만 계산한다. 합계가 맞아도 실제 지급·플레이 시간이 맞았다고 보고하지 않는다.

## 7. 디렉터 체감 판정 두 번

| 시점 | 한 번에 볼 항목 | 반복 요청하지 않을 항목 |
|---|---|---|
| **6장 끝** | 왕도/항구/학술도시/수림의 구별과 길찾기, 이동 거리, 영지 수입·투자의 이해도, 지원 두 계열의 전투 부담·성장·장비 구매력 | 매 장 저장/불러오기·의뢰 재완주·상점 회귀 |
| **9장 끝** | 2차 전직 차이, 남작/두 영지 운영의 의미, 군후 예고와 방어전 재시도 부담, 2막 흐름·성장·길찾기 | 1막 재완주와 이미 확인한 동일 조작 |

각각 약 30분의 대표 구간·준비 상태를 한 쪽 체크리스트로 제공한다. 저장/기능 검증은 Codex와 독립 검토가 맡는다. 체감 판정 대기만으로 영향 없는 다음 작업을 막지 않으며 지적된 범위만 보완한다. 이 표는 최종 아트 승인이나 실제 48시간 분량 검증을 대신하지 않는다.

## 8. 계획 검증 기록

문서 전용 변경이다. 장별 EXP·골드·공훈·건수·시간을 현행 정본과 산술 대조한다. 제품 코드·콘텐츠·저장·실행기는 수정하지 않는다. 전체 GUT를 다시 실행한 것으로 기록하지 않는다. 정본 예산 검증 명령과 실제 결과는 독립 검토 요청서에 기록한다.

변경 이력: 2026-10-03 디렉터 지시에 따라 2막 전체 계획과 검토 선행 조건, 6/9장 체감 판정, 시스템 도입 순서를 작성.
