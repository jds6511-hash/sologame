## 1. 현재 위치

- **M0** 스튜디오 구축, **M1** 기획 기반, **M2** 코어 전투 수직 슬라이스는 완료됐다.
- **M3**의 구현 Phase A~D와 게이트 선결 조건은 완료됐다. 현재 남은 관문은 대표 직업 전투 자세·전용 동작 확인을 포함한 **G3 디렉터 플레이 승인**이다.
- G3 승인 전에는 M4 구현으로 넘어가지 않는다. G3에서 나온 결함은 해당 전투·아트 범위에서 수정한 뒤 다시 확인한다.
- G3 승인 직후 첫 신규 시스템은 **M4 Save/Load**다. 신규 직업, 신규 몬스터, 대규모 지역 확장은 M4~M8의 RPG 기반 루프보다 앞서지 않는다.

## 3. 핵심 의존 관계

```text
M3 전투·성장 기준선 승인
  → M4 Save/Load
  → M5 NPC·Dialog·Quest
  → M6 Shop·경제·장비
  → M7 동부 변경 완성
  → M8 명성·계급·영지
  → M9 직업 확장
  → M10 왕국 월드 확장
  → M11 수집·메타
  → M12 3차 전직·히든 직업
  → M13 후반 세계
  → M14 최종전·엔딩
  → M15 목표 콘텐츠량 충족
  → M16 최종 QA
```

이 순서는 콘텐츠 수를 줄이기 위한 것이 아니다. 뒤에서 수백 개로 늘어날 데이터를 앞 단계의 안정된 구조 위에 올리기 위한 제작 순서다.

## 4. M4 — Save/Load

최소 저장 스키마는 다음 범주를 처음부터 수용한다.

| 범주 | 저장 대상 |
|---|---|
| Player | 레벨, EXP, 직업, 스킬, HP/MP, 위치 |
| Inventory | 아이템, 장비, 골드 |
| World | 현재 맵, 발견 지역, 월드 플래그, 게임 시간 |
| Progress | 퀘스트 상태, 명성, 영지, 스토리 플래그 |
| Account | 계정 버전, 클리어·도감·업적·외형·유산·공용 창고·본 콘텐츠 기록 |
| Character | 캐릭터 버전·ID, 플레이 시간과 아래 Player/Inventory/World/Progress 소유권 |

- 저장 키는 노드 경로나 표시명이 아닌 **stable content ID**를 사용한다.
- 저장 형식은 처음부터 `AccountSave` 1개와 캐릭터 슬롯 10개의 `CharacterSave`로 나누고 각각 독립 버전을 둔다.
- 세부 소유권과 손상 격리 규칙은 [개척자의 유산](systems/pioneer-legacy.md) 3장을 따른다.
- 누락·손상·구버전 데이터의 처리 정책과 자동 테스트를 함께 만든다.
- 완료 조건은 **새 게임→플레이→저장→종료→재실행→동일 진행 복원**이다.

## 5. M5 — NPC·대화·퀘스트

최소 수직 슬라이스는 다음 흐름 전체를 통과한다.

```text
NPC 접근 → 대화 → 퀘스트 제안 → 수락 → 목표 수행
→ NPC 복귀 → 완료 → 보상 → 저장·재실행 후 상태 유지
```

- `QuestData`와 플레이어별 `QuestState`를 분리한다.
- 목표 유형은 `TALK`, `KILL`, `COLLECT`, `REACH`, `DELIVER`, `ESCORT`, `INTERACT`를 데이터로 표현할 수 있어야 한다.
- 첫 구현은 [플레이 경험 구체화](PLAY_EXPERIENCE_PROPOSAL.md)의 여울목 퀘스트 흐름을 사용한다.
- 480개 퀘스트를 개별 코드로 만들지 않는다. 같은 실행 계층에 데이터와 대사·목표·보상을 추가하는 구조를 완료 조건으로 삼는다.

## 6. M6~M8 — 첫 RPG 완성 구간

### M6 경제·장비

- 구매, 판매, 장비 비교, 8슬롯 장착, 직업 제한, 스마트 드랍, 골드 흐름을 하나의 루프로 연결한다.
- 장비 교체가 실제 전투 스탯과 저장 데이터에 반영되는지 검증한다.

### M7 동부 변경

- 노베라, 여울목, 잿골, 초반 필드, 폐허, 던전, 균열 지역을 NPC·상점·퀘스트·보상까지 한 묶음으로 완성한다.
- 완료 게이트는 뉴게임부터 3장 여울목 하사까지 디버그 조작 없이 진행하는 것이다.

### M8 명성·계급·영지

- 퀘스트·토벌의 공훈이 문장원 공훈부의 명성으로 기록된다. M11 왕국 이벤트가 같은 명성 입력 계약을 사용할 수 있도록 확장 지점을 둔다.
- 명성 조건과 승급 퀘스트를 모두 충족해야 향사·남작으로 오른다.
- 여울목 부락→잿골 마을의 통치·복구·수입·투자 루프를 구현한다. 카엘론 백작 단계는 M10 월드와 M14 스토리 진행에 맞춰 완성한다.

## 7. M9~M14 — 확장과 종결

- **M9**: 전사, 기사, 도적, 궁수, 마법사, 소환사, 창술사, 격투가의 기본 공격·회피·보조 공격·고유 자원·핵심 스킬을 직업별로 구분한다. M3에서 이월된 궁수 2차 계통을 이 단계 첫 작업에 포함한다.
- **M10**: 동부→중부→남부→북부→서부 순으로 확장한다. 지역 하나를 도시·주변 정주지·필드·던전·NPC·퀘스트·몬스터·음악 단위로 완료한 뒤 다음 지역으로 간다.
- **M11**: 몬스터 도감→아이템 도감→칭호→펫 순으로 연결하고, 계정 도감·업적·외형·계정 칭호·공용 창고·유산 UI를 구현한다. 펫은 전투 참여와 저장·도감이 모두 준비된 뒤 넣는다.
- **M12**: 왕도 브란텔의 3차 전직과 룬각인사·감응자 해금 퀘스트를 구현한다.
- **M13**: 균열→악마→심연→숨결의 진실→창천 순으로 후반 정보를 공개한다. 오란세는 왕국 명성과 다른 공덕 질서를 플레이로 보여준다.
- **M14**: 메인 12장, 종족 연합 전쟁, 총군후 보스전, 최종 통치 방침과 에필로그를 완성한다. 엔딩 완료 시 클리어 스냅샷을 계정 유산 회랑에 기록하고 다음 캐릭터의 계승을 활성화한다.

## 8. M15~M16 — 분량 완성과 출시 품질

- **M15**에서 서브퀘스트 약 480개, 펫 확정 목표량, 칭호 약 100개, 특수무기, 왕국 이벤트, 반복 콘텐츠, 도시별 퀘스트 라인과 후반 던전을 채운다. 개척자의 유산 1~10회차 보상과 10직업 완주 업적도 이 단계에서 완성한다.
- **M16**에서는 신규 기능을 늘리지 않고 버그, 밸런스, 전투 감각, 이동 동선, 로딩, FPS, UI, 튜토리얼, 저장 안정성을 조정한다.

## 9. 횡단 작업과 공통 규칙

- **아트**: G3까지는 현행 LPC 몸·직접 작화 무기·28×36·EDG32·zoom 4를 유지하고 기능적 모션 결함만 고친다. 이후 [아트 제작·전환 파이프라인](../art/art-pipeline-candidates.md)에 따라 여울목 지형 1세트·플레이어 1직업·몬스터 2종·FX 일부의 대표 샘플을 검수한 뒤 확대한다. 기능 커밋과 대량 아트 교체 커밋을 분리한다.
- **데이터 확장성**: 새 기능은 "10개가 아니라 500개가 되어도 같은 구조로 관리 가능한가"를 검토한다.
- **테스트**: 각 마일스톤은 기존 회귀 테스트와 해당 기능의 실패·복구 경로를 함께 검증한다.
- **승인 게이트**: 구현과 자동 테스트가 끝나도 디렉터가 해당 마일스톤의 실제 플레이를 승인해야 다음 단계로 넘어간다.
- **상세 계획**: 이 문서는 상위 순서만 정한다. 실제 구현 전에는 저장, 퀘스트, 경제처럼 시스템별 별도 실행 계획을 작성한다.

## 10. 바로 다음 작업 순서

1. M3 대표 전사·궁수 및 검투사 전용 동작을 실제 교전에서 확인한다.
2. `docs/qa/m3-gate-checklist.md`의 G3-1~G3-4를 실행하고 디렉터 판정을 기록한다.
3. G3에서 발견된 결함만 수정하고 회귀 검증한다.
4. G3 승인 후 M4 Save/Load 상세 설계와 테스트 계획을 작성한다.
5. M4를 통과한 뒤 M5 여울목 첫 퀘스트 수직 슬라이스를 구현한다.
