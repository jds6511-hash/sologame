## 0. 구현 전제 — 퀘스트 시스템은 NPC/대화와 함께 수직 슬라이스로 구현한다

**규정**: 퀘스트 시스템은 **최소 NPC/대화 수직 슬라이스와 함께 구현한다. 퀘스트 시스템만 고립 구현하지 않는다.** (디렉터 검수 확정 2026-08-20 — 재논의 불요)

본 절은 콘텐츠 설계가 아니라 **구현 순서에 대한 제약**이다. 1장 이하의 퀘스트 콘텐츠 설계(총량·유형·단계·보상)는 본 절과 무관하게 그대로 유효하다.

### 0-1. 근거

1. **고립 구현은 임시 진입로를 낳는다** — 디버그 키로 수락, UI 버튼으로 퀘스트 시작, 테스트용 글로벌 플래그 직접 변경. 나중에 NPC/대화를 붙이면서 그 흐름을 다시 뜯게 된다.
2. **우리 프로젝트에 이미 그 전례가 있다** — 온보딩 튜토리얼의 대체 구현(0-3절). 같은 실수를 반복할 자리다.
3. **현재 코드베이스에 퀘스트·NPC·대화 구현은 0줄이다** — `godot\scripts`·`godot\scenes` 전체에 해당 키워드 파일 없음(2026-08-20 실측). 기존 구현에 맞출 제약이 없으므로, 전제를 지금 확정하는 것이 가장 싸다.

### 0-2. 최소 수직 슬라이스 (채택)

```
NPC → 대화 → 퀘스트 제안 → 수락 → 목표 진행 → 완료 조건 → NPC 보고 → 보상 → 세이브
```

- **첫 퀘스트는 분기 금지.** 예: NPC A → 특정 몬스터 N마리 처치 → NPC A 복귀 → 골드/아이템 보상. 프리미티브로는 `TALK → KILL → TALK` — 2-2절 토벌 유형의 표준 단계 패턴 그대로다(새 프리미티브 불필요).
- **상점은 이 슬라이스에서 제외 가능.**
- 핵심은 콘텐츠 품질이 아니라 **계층 전체가 end-to-end로 연결되는지 검증**이다. 슬라이스용 퀘스트는 본 문서의 정식 퀘스트 목록에 등재하지 않아도 된다.
- **세이브 연동 대상**: 수락·진행·완료·보상 수령 상태. 세이브/로드 시스템 자체는 **선행 Phase**에서 만든다(본 슬라이스의 선행 조건).

### 0-3. 이 규정의 발생 원인 — 온보딩 대체 구현 전례 (C1)

온보딩 튜토리얼(`docs\art\ux\onboarding.md` 3장 6단계)은 M2 시점에 퀘스트 시스템이 없어, 문서가 트리거로 지정한 "MQ-01 자동 수령"·"MQ-02 수령 + 서식지 진입"을 **대체 조건으로 근사**해 구현됐다 — `godot\scripts\ui\tutorial_controller.gd`(`TutorialController`). 진행 플래그(`tutorial_done`)도 세이브가 없어 **노드의 세션 내 상태**로만 존재한다(스크립트 머리 주석에 사유 명시).

그 결과가 `PROJECT_STATUS.md` 9-1절 C그룹 이월 4건이며, 그중 **C1 = "퀘스트 연동 트리거 정식 구현"**이다. 즉 **C1이 본 절 규정의 발생 원인**이다. 나중 담당은 이 제약을 과한 요구로 읽지 말 것 — 이미 한 번 치른 비용을 두 번 치르지 않기 위한 규정이다.

- 슬라이스가 완성되면 `TutorialController`의 대체 조건은 정식 퀘스트 트리거로 교체되어야 한다(= C1 해소). 이 교체를 **슬라이스 완료의 부수 검증 항목**으로 둔다.
- 3-2절의 `MQ-01-01`~`MQ-01-05`는 온보딩과 트리거를 공유하므로, 정식 구현 시 온보딩 6단계 대응(3-2절 말미)을 함께 재확인한다.

### 0-4. 기존 서술과의 정합

- **`MQ-01-01`의 "뉴게임 시작 시 자동 수령"(3-2절)은 그대로 유지한다** — 게임 시작 퀘스트로서 정당한 설계다. 단 자동 수령은 NPC 발주 경로가 아니므로 **슬라이스의 end-to-end 검증 경로로 쓰지 않는다.** 검증에는 NPC 발주 → 수락 → 보고 → 보상이 온전히 도는 퀘스트를 쓴다(`MQ-01-02` 계열의 `TALK → KILL → TALK` 구조가 요건을 그대로 만족).
- **게시판 발주(4장 반복 퀘스트의 "조합 게시판")는 1차 슬라이스 범위 밖**이다. 발주 주체가 NPC가 아닌 상호작용 오브젝트라 별도 진입 경로이며, NPC 경로가 검증된 뒤에 얹는다.
- 그 밖에 본 문서에 "NPC 없이 퀘스트를 수락한다"고 가정한 서술은 없다. 2-3절 스키마의 `발주 NPC`가 전 퀘스트 필수 필드이므로 구조적으로도 본 규정과 정합한다.

## 1. 총량 설계 — "수백 개"의 근거 숫자

`growth.md` 5장 곡선에서 역산한 퀘스트 물량의 뼈대. 모든 경험치는 **"동렙 몹 환산 마리분"** 단위로 다룬다 (레벨과 무관하게 유효한 상대 단위).

| 항목 | 값 | 산출 근거 |
|---|---:|---|
| 1→100 총 필요 경험치 | 54,450마리분 | `growth.md` 5-1 (11L 누적) |
| 퀘스트가 담당할 몫 (45%) | 약 24,500마리분 | `growth.md` 5-3 |

| **서브퀘스트 몫** | **약 20,400마리분** | 잔여분 |
| **서브퀘스트 설계 목표** | **약 480건** (450~500) | 20,400 ÷ 평균 45마리분/건 |

- 레벨당 필요 서브퀘 수 = 0.45 × 11L ÷ 45 ≈ **0.11L건** → Lv40 부근 4~5건/레벨, Lv70 부근 7~8건/레벨. `growth.md`의 "레벨당 평균 4~8건" 가이드와 일치함을 확인.
- **구간별 공급 목표** (설계 시 이 분포를 지킬 것):

| 레벨 구간 | 서브퀘 공급 목표 | 주 공급처 |
|---|---:|---|
| 1~9 (모험가) | 약 12건 | 여울목 부락·노베라 초입 (메인이 성장 주도) |
| 10~39 | 약 70건 | 동부 변경 + 초기 방문 도시 1차 묶음 |
| 40~79 | 약 240건 | 도시 순회(2막) 9개 도시 묶음 + 마을·부락 + 종족·인물 라인 |
| 80~99 | 약 160건 | 도시 **후속 묶음**(2부) + 엔드게임 균열 소탕 + 반복·이벤트 보충 |

- **도시 서브 묶음의 2부제**: 각 도시의 묶음(도시당 20~40건, `story.md` 5장)을 "첫 방문 시 개방되는 1차 묶음(15~25건)" + "3막 진입 후 개방되는 후속 묶음(5~15건)"으로 나눈다. 2막에서 물량이 소진되고 3막(Lv80+)에 서브가 고갈되는 문제를 구조적으로 방지한다.
- 서브퀘 480건의 수납처 배분 (제안): 도시급 허브 9개 묶음 270 (**왕국 도시 8 + 성도 오란세** — worldview 6.4 재편 "왕도 1 + 도시 8 + 독립 성역 1" 기준. 오란세 묶음은 순례·교단 결로 재정향, 5장) + 왕도 브란텔 20 + 마을·부락(동부 변경 중심) 100 + 종족 서사 라인 2종 24 + 인물(동료·조연) 라인 20 + 필드·던전 발견형 46 = **480**.

## 2. 퀘스트 유형 분류와 비중 — 양산 체계

### 2-1. 목표 프리미티브 (9종)

수백 건 양산의 핵심: 모든 퀘스트 단계(목표)는 아래 9개 프리미티브의 조합으로만 만든다. systems-dev는 이 9종만 구현하면 전 퀘스트를 데이터로 찍어낼 수 있다 (데이터 주도 — JSON/Resource 기반 구현 전제).

| 프리미티브 | 정의 | 파라미터 |
|---|---|---|
| KILL | 대상 몬스터 N마리 처치 | 몬스터 ID, 수량, (선택) 지역 한정 |
| COLLECT | 아이템 N개 획득 | 아이템 ID, 수량, 출처(드랍/채집 노드) |

## 6. 명성 퀘스트 — 명성 보상 규칙 골격

### 6-1. 원칙: "명성 = 문장원이 심사하는 공훈" (worldview 5.3)

명성은 인기가 아니라 **국가 공인 실적**이다. 따라서 **공적 보고가 성립하는 유형만** 명성을 준다.

| 유형 | 명성 | 근거 |
|---|---|---|
| 토벌, 호위·구조, 탐사·조사(균열 관련), SURVIVE(방어전) | **지급** | 조합·영주·관청이 문장원에 보고하는 공적 |
| 메인퀘스트, 승급 의식, 왕국 이벤트 | **지급 (대량)** | 왕국 차원의 공훈 |
| 채집·조달, 전달·심부름, 사적 서사 퀘스트 | **0 또는 미미** | 사적 의뢰 — 공훈부 기재 대상 아님 |

- 이 구분 자체가 플레이 가이드가 된다: 명성이 급하면 토벌·조사·이벤트를 하라.

### 6-2. 명성 지급 수치 (확정 — `reputation-territory.md` 1-2 규격)

명성 절대 스케일은 `reputation-territory.md`에서 확정됐다. 서브퀘 명성은 규모 비율 **1:2:4**로 통일하고, 각 출처의 확정 수치를 그대로 따른다 (퀘스트별 실수치 배정은 quest-designer 소관이되 본 규격 밖 보상은 reputation 개정 후에만 허용).

| 출처 | 확정 명성 (명성 지급 유형에만) |
|---|---|
| 서브퀘 소형 / 표준 / 대형 | **10 / 20 / 40 (비율 1:2:4)** |
| 메인퀘스트 장 완료 | 장별 100~1,000 (`reputation-territory.md` 2-2 표) |
| 왕국 이벤트 1건 성공 | 100~300 (대 300 / 중 200 / 소 100 계열) |
| 반복 퀘스트 (일일 / 주간) | **5 / 30** (총 기여 상한 관리 — 반복 노가다만으로 승급 불가) |
| 보스·정예·균열/심연 군단 소탕 토벌 | reputation 1-2 규격 (최초 처치 보스 30/거점 50, 정예 5, 반복 소탕 10~20) |

- 원천별 총 공급 비중의 확정본은 `reputation-territory.md` 1-3 표(메인 30% / 서브 36% / 이벤트 17% / 토벌 9% / 반복 6% / 영지 2%)를 따른다. 본 문서 구 버전의 비중 목표(서브 35/메인 45/…)는 토벌·영지 원천이 빠져 있어 폐기하고 reputation 1-3으로 대체한다.

### 6-3. 명성 하락 — 미도입 확정 (`reputation-territory.md` 1-4)

- **명성은 오르기만 한다. 오점(명성 하락) 시스템은 도입하지 않는다** (디렉터 확정 2026-07-16). 퀘스트 실패·포기·이벤트 미참여는 "보상 없음"일 뿐 차감이 아니다.
- worldview 5.3의 "오점" 개념은 **서사 텍스트(대사·공훈부 묘사)로만** 살리고 수치에는 반영하지 않는다. 구 버전의 CHOICE 오점 차감 규칙은 삭제한다.
