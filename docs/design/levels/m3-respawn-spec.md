## 2. 재스폰 규칙 — 3안 비교와 선택 근거

### 2-1. 무엇을 만족해야 하는가

| # | 요구 | 출처 |
|---|---|---|
| R1 | Lv1→Lv10을 정상 플레이로 도달 가능하게 (목표 ≈ 1.8h) | Phase D 3-5, growth.md 5-2 |
| R2 | **사냥 사이클 12초 = 시간당 300마리 환산** 전제를 성립시킬 것 — 재스폰 대기가 사이클의 네 번째 항이 되어서는 안 된다 | growth.md 5-3 |
| R3 | 한 자리 무한 사냥·고레벨 양학이 새 지름길이 되지 않게 | Phase D 3-6 |
| R4 | 진입 스톨(M2 tech-artist 프로파일링: FPS 1~4) 재발 금지 | monster_spawner.gd 헤더 |
| R5 | 야간 전용 종의 스폰·소멸 흐름을 건드리지 않을 것 | m3-monster-spec 7-1 |
| R6 | 드랍·처치 EXP 배선 유지 | m3-new-enemy-placement 6-3 |

### 2-2. 방식 3안

| 안 | 규칙 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| **① 시간 기반** (처치 후 T초 뒤 같은 자리) | 개체/마커가 죽으면 타이머 → 만료 시 스폰 | 구현 최소. 공급률이 `개체 수 ÷ T`로 **닫힌 식**이라 페이스를 문서로 검산할 수 있다(R1·R2에 직접 대응) | 플레이어 **눈앞에서 팝인**. 인지 범위 안에서 되살아나면 즉시 어그로가 붙어 "부당한 피격"이 된다 | 골격으로 채택 |
| **② 플레이어 거리 기반** (D타일 밖으로 나가면 즉시 스폰) | 거리만 조건 | 팝인 없음, 연출이 자연스럽다 | **페이스가 이동 습관에 전적으로 종속**된다 — 두 마커를 왕복하면 사실상 즉시 재스폰이라 R2의 12초 전제가 무의미해지고, 반대로 한자리에 머물면 영구 공백이 된다. 문서로 검산 불가(Phase D 신뢰도 C) | 단독 미채택 |
| **③ 하이브리드 = ① + ②** | 쿨다운 만료 **그리고** 플레이어가 게이트 밖일 때 스폰 | 쿨다운이 **공급 상한**을, 게이트가 **연출·공정성**을 각각 담당해 두 축을 독립 튜닝할 수 있다. 페이스는 ①의 닫힌 식으로 계산 가능 | 마커 위에 계속 앉아 있으면 재스폰이 무한 지연된다 | **채택** |

③의 단점(무한 지연)은 **취소가 아니라 지연**으로 구현해 완화했다 — 게이트에 걸린 슬롯은 쿨다운이 이미 만료된 상태로 대기하므로, 플레이어가 게이트를 벗어나는 **다음 틱(≤1초)에 즉시** 스폰된다. 게이트 반경도 인지 범위 + 1타일(4~8타일)로 작아, 전투 중 자연스러운 이동만으로 해제된다.

### 2-3. 왜 "개체 단위"가 아니라 "마커(무리) 단위"인가

| 근거 | 설명 |
|---|---|
| **정예 캠프 규격** | `m3-monster-spec.md` 7-4는 포효 임프장에 **포효 버프 대상 아군이 반드시 동반**되어야 한다고 규정한다. 개체 단위 리필이면 "임프장만 되살아난 캠프"·"호위만 되살아난 캠프"가 생겨 지휘관 셋업이 깨진다. 마커 단위면 캠프가 항상 통째로 복원된다 |
| **무리 어그로 정합** | `pack_id`는 마커 단위로 부여된다(`m3-new-enemy-placement.md` 6-1). 재스폰 단위를 마커에 맞추면 `PackAggroCoordinator`의 공격 토큰 2가 항상 온전한 무리에 대해 작동한다 |
| **순환 강제(R3)** | 개체 단위 리필은 마커 하나가 절대 비지 않아 "제자리에서 30초마다 1마리씩" 사냥이 성립한다. 마커 단위면 무리를 정리한 뒤 **다른 마커로 이동**해야 하므로 growth.md 5-3의 오버헤드(이동·루팅)가 실제로 발생한다 |
| **성취감** | "무리를 쓸어 냈다"가 상태로 남는다(마커가 비어 있는 것이 보인다). 개체 리필은 청소한 느낌이 나지 않는다 |

부작용으로 **부분 처치 후 이탈**이 가능하다(3마리 중 2마리만 죽이고 떠나면 1마리가 계속 남고 재스폰도 없다). 이는 플레이어에게 불리한 방향이므로 억제 장치를 해치지 않는다.

### 2-4. 쿨다운 값의 근거

| 값 | 근거 |
|---|---|
| 일반 **30초** | 재스폰을 **페이스 브레이크로 쓰지 않는다**는 판단. growth.md 5-3의 오버헤드 7초는 "이동·루팅"이고 재스폰 대기는 그 안에 없다(R2) — 즉 페이스는 TTK와 마커 간 거리가 결정해야 하며, 재스폰은 "공급이 끊기지 않을 만큼" 짧으면 된다. 시작 지역 마커 밀도에서 30초는 전 종 합계 **1,320마리/시간**을 공급해 growth.md 전제(300마리/시간)의 **4.4배**이므로, 정상 동선에서 병목은 재스폰이 아니라 플레이어 사냥 속도가 된다(4-2장 실측: 7초 오버헤드 페이스 기여 +1.2%). 반대로 30초보다 짧게 하면 "죽자마자 다시 서 있는" 연출이 되어 마커 단위 청소감이 사라진다 |
| 정예 **180초** | 정예 캠프를 **양학 억제 장치로 전용**했다. Phase D 3-6장은 포효 임프장 캠핑이 동렙 일반 사냥의 2.1~3.7배 효율이라고 실측했는데, 이 배수는 쿨다운을 0으로 본 값이다. 180초를 넣으면 실측 TTK 24.51초와 합해 사이클 204.5초가 되어 **10.69 EXP/초(Lv11) / 9.39(Lv16)** 로 떨어지고, 동렙 일반 사냥(29.73 / 28.87)보다 **낮아진다**. 즉 경험치 규칙(레벨 차 표)을 건드리지 않고 배치 레버만으로 정예 양학을 제거했다 |
| 판정 주기 **1초** | 쿨다운이 30초 단위이므로 1초 해상도로 충분하다. 매 프레임 판정할 이유가 없다(R4) |
| 게이트 여유 **+1타일** | 인지 범위 경계에 정확히 스폰되면 그 프레임에 어그로가 붙는다. 1타일을 더해 "재스폰된 개체가 플레이어를 인지하지 않은 상태로 등장"을 보장한다. 종별 실효 게이트: 뿔토끼 4.0 / 균열 점액 5.0 / 들개·무법자·노상강도·임프장 6.0 / 숲거미·임프 6.0~7.0 / 밀렵꾼 8.0타일 |

## 3. 구현 규격 (`godot\scripts\world\monster_spawner.gd`)

### 3-1. 슬롯 모델

```
마커 1개  =  RespawnSlot 1개
            ├─ kind            SOLO / RING_PACK / IMP_LORD_CAMP
            ├─ scene, spawn_position, marker_name
            ├─ pack_size_range, pack_prefix   (RING_PACK 전용)
            ├─ delay_sec       30.0 (일반) / 180.0 (정예 캠프)
            ├─ gate_tiles      첫 스폰 시 = max(서식종 인지 범위) + 1.0
            ├─ alive[]         현재 생존 개체 (died 시그널로 갱신)
            ├─ awaiting_respawn / remaining_sec
```

상태 전이:

```
      [스폰됨]  alive = N > 0, awaiting_respawn = false
          │  개체 died → alive.erase()
          ▼
   alive == 0 ?  ── 아니오 ──▶ [스폰됨] 유지  (부분 처치로는 재스폰 없음)
          │ 예
          ▼
      [쿨다운]  awaiting_respawn = true, remaining_sec = delay_sec
          │  매 틱(1초) remaining_sec -= 1.0
          ▼
   remaining_sec <= 0 ?  ── 아니오 ──▶ [쿨다운] 유지
          │ 예
          ▼
   거리 게이트 통과?  ── 아니오 ──▶ [쿨다운 만료·대기]  (다음 틱 재확인 = 지연)
          │ 예
          ▼
   이 틱에 이미 1마커 스폰?  ── 예 ──▶ [쿨다운 만료·대기]  (다음 틱 = 프레임 분산)
          │ 아니오
          ▼
      [스폰됨]  무리 크기·산개 각도·pack_id 재생성
```

### 3-2. 성능 처리 (R4)

| 장치 | 내용 |
|---|---|
| 판정 주기 | `_process`가 델타를 누적해 **1초마다 한 번만** `advance_respawn_tick()`을 호출한다. 슬롯이 없으면 즉시 반환 |
| 틱당 상한 | `MAX_RESPAWNS_PER_TICK = 1` — 쿨다운이 동시에 만료돼도 **초당 1마커**로 자동 분산된다. 마커 하나의 최대 개체 수는 4마리(전 종 무리 상한)이므로 한 틱의 최대 부하가 초기 스폰의 마커 1개분과 동일하다(= M2에서 이미 스톨 없음이 확인된 단위) |
| 실측 | 검증 필드에서 **전 8마커를 한 프레임에 동시 재스폰**시킨 최악 조건(220틱 일괄 처리, 몬스터 0 → 18마리)이 **3.70 ms**에 끝나고 FPS는 **144 유지**. 실제 게임 경로는 이보다 8배 이상 분산된다 |

### 3-3. 야간 전용 종과의 관계 (R5)

- 그림자 숲거미는 **슬롯을 만들지 않는다**. `GameClock.night_started`에 스폰하고 `day_started`에 `queue_free()`하는 기존 흐름을 그대로 유지했다(코드 무변경).
- 낮 소멸은 `died`를 발신하지 않으므로 쿨다운 트리거와 애초에 만나지 않는다. 회귀 테스트가 "낮에 정예 쿨다운(180초)만큼 시간이 흘러도 야간 종이 재스폰되지 않음"을 보증한다.
- **처치된 야간 종은 그 밤 안에 돌아오지 않는다** — 밤마다 1회 스폰이 spec 7-1의 규격이며, "밤에만 나오는 희귀종을 그 밤에 몇 마리 잡았는가"가 그대로 남는 편이 야간 연출에 맞는다는 판단이다. 주간 종(숲거미 등)은 밤에도 정상 재스폰되므로 야간 사냥터의 공급은 유지된다(회귀 테스트로 확인).
- **후속 레버**: 야간 종 공급을 늘릴 필요가 생기면 "야간 종 전용 슬롯 + 새벽에 쿨다운 강제 취소"가 다음 단계다. 현재는 EXP 기여가 미미해(모델에서 아예 제외해도 페이스가 목표 범위) 도입하지 않았다.

### 3-4. 드랍 · 처치 EXP 재등록 (R6) — 확인 결과

```
재스폰 → _populate_slot() → _spawn_ring()/_spawn_monster()
                              └─ monster_spawned.emit(monster)     ← 첫 스폰과 동일 경로
                                   └─ 월드 루트 _register_monster()
                                        ├─ BgmManager.register_monster        (정예 전투 곡)
                                        ├─ MonsterDropRegistry.table_for()
                                        ├─ DropSystem.register_monster        (골드·재료·포션·장비)
                                        └─ PlayerProgression.register_monster (처치 EXP)
```

- 재스폰은 **첫 스폰과 완전히 같은 `_spawn_monster()`를 통과**하므로 `monster_spawned`가 그대로 발신되고, 시작 지역 씬·검증 필드 씬 둘 다 이 시그널을 구독하므로 자동 재등록된다.
- **누수 없음을 확인**: `DropSystem.register_monster`·`PlayerProgression.register_monster`·`BgmManager.register_monster`는 전역 목록에 담지 않고 **그 몬스터의 `died`/`took_damage` 시그널에만 연결**한다. 개체가 `queue_free`되면 연결도 함께 사라지므로, 재스폰이 반복돼도 등록이 누적되지 않는다.
- 회귀 테스트가 "재스폰된 개체도 `monster_spawned`를 타고 `MonsterDropRegistry.table_for()`가 표를 돌려준다"를 보증한다.
- 실제 렌더 검증에서 필드 몬스터 전멸 → 플레이어가 **Lv1 → Lv6**으로 상승했다(처치 EXP가 실제 지급됨을 확인).

## 4. 페이스 검산 — Lv1 → Lv10 도달 가능성

### 4-1. 판정 기준이 바뀐다

Phase D 3-5장은 **재스폰이 없다**는 전제로 빌드 전체 EXP를 **유한 재고**로 계산했다(10,688 = Lv10 요구 41,359의 25.8% → 도달 불가). 재스폰이 들어오면 EXP는 재고가 아니라 **공급률**이 되므로 판정 질문도 바뀐다: *"총량이 충분한가"* → *"공급률이 플레이어 사냥 속도를 가로막는가"*.

### 4-2. 시작 지역 공급률 (마커 실측 × 쿨다운)

| 종 | Lv | 마커 | 마커당 | 개체 수 | 쿨다운 | 공급(마리/시간) |
|---|---:|---:|---:|---:|---:|---:|
| 뿔토끼 | 1 | 3 | 1.0 | 3.0 | 30s | 360 |
| 들개 마수 | 4 | 2 | 1.5 | 3.0 | 30s | 360 |
| 균열 점액 | 8 | 2 | 1.0 | 2.0 | 30s | 240 |
| 숲거미 | 10 | 3 | 1.0 | 3.0 | 30s | 360 |
| **합계** | | **10** | | **11.0** | | **1,320** |

(그림자 숲거미 야간 마커 2개는 슬롯 대상이 아니라 **모델에서 제외** — 있으면 더 빨라질 뿐이므로 보수적이다.)

- growth.md 5-3 전제(300마리/시간)의 **4.4배**. 즉 정상 동선에서 재스폰은 병목이 아니다.
- **재스폰 공급 상한의 페이스 기여**(상한 제거 시와 비교): 정상 동선 **+1.2%**(오버헤드 7s) / **+9.2%**(오버헤드 3s). 7초 설계 가정에서는 R2 충족 — 재스폰 대기가 사냥 사이클의 네 번째 항이 되지 않았다.
- **사냥 사이클 환산**: Lv1 13.31초 / Lv5 12.11초 / Lv8 11.78초(오버헤드 7s, 정상 동선) → growth.md 5-3의 **12초 전제와 일치**한다.

### 4-3. Lv1 → Lv10 도달 시간 (h)

사냥 대상 선택 모델 3종으로 상·하한을 감쌌다(Phase D 1-1 신뢰도 **B 모델 계산**). 전제는 Phase D와 동일(활동 비율 50%, 주간 2/3·야간 1/3, 동렙 B급 기준선, 치사성 게이트 = 허용 피격 4대 이상).

| 모델 | 정의 | 오버헤드 7s·퀘스트 0% | 3s·퀘스트 0% | 7s·퀘스트 45% |
|---|---|---:|---:|---:|
| **정상 동선 ← 대표값** | 레벨 차 보정이 1.00인 종만(d = −4~+4). 게임 자신의 레벨 차 표로 "양학도 저레벨 재방문도 아닌" 구간을 정의 | **1.891h** | **1.350h** | 1.040h |
| Phase D 배치종 동선 | \|d\|가 최소인 **단일 종**만 | 3.881h | 3.857h | 2.135h |
| 탐욕 최적 동선 | 치사성 게이트만 통과하면 EXP/초 최대(= 양학 허용 상한) | 1.661h | 1.145h | 0.913h |

- **M3 빌드의 실제 조건은 "퀘스트 0%"** 열이다 — 퀘스트 시스템이 M3 범위 밖이라(`M3_PLAN.md` 1-4) 경험치 100%를 사냥으로 벌어야 한다. growth.md 5-2의 1.8h는 **퀘스트가 45%를 대신하는 완성형 전제**이므로, 목표와 직접 비교할 값은 "퀘스트 0% + 재스폰"이다.
- **결론: 정상 동선 1.89h(오버헤드 7s) ~ 1.35h(오버헤드 3s)** — 초반 체력 완화만으로는 이동·루팅 시간이 지배적이라 기존 1.93~1.40h에서 소폭만 줄었다. 첫 전직 목표 시간을 더 줄이려면 경험치 곡선 또는 퀘스트 보상을 별도로 조정해야 한다.
- 배치종 동선(단일 종)이 3.88h로 크게 느린 것은 **Lv7~9 구간에서 균열 점액 마커 2개(240마리/시간)만 사냥한다는 제약** 때문이다. 실제로는 같은 개울 북쪽에 숲거미 3마커가 함께 있어 플레이어가 둘을 섞어 사냥하므로 이 값은 하한 쪽 인공물이다. 다만 4-4장의 병목은 실재한다.
- **오버헤드는 여전히 최대 불확실 요인**이다(Phase D 3-4 핵심 발견 E와 동일 구조). 재스폰은 그 불확실성을 줄이지 않는다 — 다만 재스폰 부재라는 **확정적 차단 요인**은 제거했다.

### 4-4. 알려진 공급 병목 — 균열 점액 마커 2개 (배치 레버, 미조정)

| 플레이어 Lv | 병목 | 손실(오버헤드 7s) | 손실(3s) |
|---:|---|---:|---:|
| 4~5 | 균열 점액 240마리/시간 상한 (마커 2개) | 13.5~15.5% | 27.6~29.7% |
| 6~9 | 숲거미 360마리/시간 상한 (마커 3개) | 0% | 1.0~2.5% |

- Lv4~5에서 손실이 큰 이유: 그 구간의 `|d| ≤ 4` 후보가 들개(Lv4)와 점액(Lv8)뿐인데 점액 EXP가 훨씬 높아 플레이어가 점액을 선호하고, 점액 마커는 2개뿐이다.
- **조정하지 않았다**: ① 전체 페이스가 이미 목표(1.8h)를 감싸고 있어 손실을 메울 필요가 없다 ② 균열 굴 어귀의 점액 2마커는 "저레벨 구간의 위험 신호" 연출을 위한 **의도적 소수 배치**이며(`eastern-frontier-start-map.md` 5장 각주), 늘리면 Lv1~4 동선의 즉사 위험이 커진다 ③ 배치 변경은 MQ-01-04 동선(REACH 9.9타일 / INTERACT 8.1타일 여유)과 재검증이 필요하다.
- 필요해질 경우의 레버는 순서대로 **① 점액 쿨다운만 30 → 20초 ② 균열 굴 어귀에 점액 마커 1개 추가(퀘스트 지점 6타일 밖) ③ 균열 외곽 지역 씬 신설**이다. ①은 마커 배치를 건드리지 않아 가장 싸다.

## 8. 디렉터 결정 필요

- **없음** — 본 작업은 Phase D가 지적한 차단 요인의 해소이며, 확정된 규격(growth.md 5-3 페이스 전제, m3-monster-spec 무리 구성·야간 전용) 안에서 배치 레버만 사용했다. 게임 방향을 바꾸는 결정은 포함하지 않는다.

**개발 협의 사항 (디렉터 결정 아님)**

1. **골드 드랍이 전혀 지급되지 않는다 — 기존 버그, 소관 외라 손대지 않음.** `DropSystem`의 `signal gold_dropped(amount: int, world_position: Vector2)`(2인자)를 두 월드 루트가 `InventoryComponent.add_gold(amount: int)`(1인자)에 직접 연결한다(`eastern_frontier_starting_area.gd:47`, `m3_new_enemy_field.gd:59`). 몬스터가 죽을 때마다 `ERROR: Error calling from signal 'gold_dropped' to callable: 'add_gold': Method expected 1 argument(s), but called with 2.`가 발생하고 **골드가 인벤토리에 들어가지 않는다**. HEAD(`2cdb14f`)에도 존재하는 선행 버그이며, 재스폰 렌더 검증에서 처치가 발생하자 드러났다(이전에는 월드 씬에서 몬스터를 죽이는 검증이 없었다). 수정은 `_drop_system.gold_dropped.connect(_inventory.add_gold.unbind(1))` 한 줄이지만, `scripts/items` 소관자가 "월드 루트에서 unbind" vs "`add_gold`에 위치 인자 추가" 중 어디를 고칠지 결정해야 하므로 **보고만 한다**. G3-1에서 상점·경제 체감을 보려면 선행 수정이 필요하다.
2. **`m3_new_enemy_field.gd`에 재스폰 캡처 모드(`--capture-respawn`)를 추가**했다. 검증 필드는 정식 지역 씬 완성 시 폐기 예정(`m3-new-enemy-placement.md` 9장 2번)이므로 이 코드도 함께 사라진다.
