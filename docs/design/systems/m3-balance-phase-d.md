## 1. 측정 방법과 신뢰도 등급

### 1-1. 신뢰도 3등급

| 등급 | 정의 | 본 문서 표기 |
|---|---|---|
| **A. 구현 실측** | `.tres`/`.gd`에서 직접 읽은 값, 또는 그 값만으로 결정되는 산술 결과. 전제가 없다 | 표에 별도 표시 없음(기본) |
| **B. 모델 계산** | A + 명시된 행동 전제(사냥 대상 선택·오버헤드·퀘스트 비중·주야 비율 등)를 조합한 결과 | 표 제목에 전제를 병기 |
| **C. 계산 불가** | 현 빌드에서 측정할 수 없거나, 플레이어 행동에 전적으로 의존하는 값 | **"계산 불가"**로 명시 + 9장 G3-1 이관 |

### 1-2. 측정 방법

실플레이 1.8시간을 돌릴 수 없고, 후술하듯 **현 빌드는 재스폰이 없어 Lv10 도달 자체가 불가능**하므로(3-5장), 구현체의 값을 직접 읽어 계산하는 방식을 택했다. 스크립트(`docs\qa\tools\m3_phase_d_balance_calc.py`)는 다음을 수행한다.

1. `data/progression/*.tres`에서 REQ/EXP 곡선 계수·레벨 차 배율표·스탯 성장 공식·직업 배분을 파싱.
2. `scripts/progression/stat_growth_calculator.gd`의 순수 함수를 그대로 재현해 레벨별 플레이어 공격력·HP·방어력을 산출.
3. `data/player/*_basic_combo.tres`의 단계별 계수·선딜/판정/후딜을 합산해 **계수/초**를 산출(콤보 데이터가 기본값에 의존하는 대검 1타는 `warrior_attack_step.gd` 기본값으로 보정).
4. `data/monsters/*.tres`(HP/공격/방어) + `data/drops/*.tres`(몬스터 레벨·등급)로 TTK·EXP·피격 예산을 계산.
5. `scripts/player/player_controller.gd`의 `_resolve_move_speed_px()` 분기를 그대로 재현해 이동 속도 조합을 산출.
6. `scenes/world/*.tscn`의 스폰 마커 좌표와 `scripts/world/monster_spawner.gd`의 무리 크기로 빌드 내 몬스터 개체 수·EXP 재고를 산출.

**모델 검증(캘리브레이션)**: 스크립트로 `growth.md` 5-3 유도식(환산 처치 495 / 사냥 300마리·시간 / 퀘스트 45% / 활동 비율 50%)을 재현하면 **Lv10 도달 1.815h**가 나와 `growth.md` 5-2 표기값 **1.8h와 일치**한다. 이후 표는 이 유도식에서 **TTK·EXP·레벨 차·주야간만 구현 실측치로 대체**한 것이다 — 즉 모델 자체가 아니라 입력값만 바뀌었으므로 편차를 그대로 "구현이 설계에서 벗어난 정도"로 읽을 수 있다.

### 1-3. 트리 상태 (측정 시점)

## 2. D-1 — 공격 중 이동 45% 밸런스 재검증

### 2-1. 문제 재정의

`combat.md` 5-1·8-2는 피격 예산(잡몹 10대 / 보스 4대)을 **"정지 스윙 = 피격 감수"** 전제로 역산했다. QoL④(공격 중 이동, 계수 0.45)는 캐이던스를 바꾸지 않으므로 TTK·HP 곡선은 불변이지만, **실제 피격 수를 줄여 설계보다 쉬워질 여지**가 재검증 트리거로 남았다.

측정 결과 이 문제는 세 개의 서로 다른 질문으로 분해되며, 그중 둘만 계산 가능하다.

| 질문 | 신뢰도 | 답 |
|---|---|---|
| ① 피격 예산 **수치 자체**가 무너졌는가 | A 구현 실측 | **아니다** — 2-4장, 전 10종 9.91~10.30대 |
| ② 공격 중 이동으로 **실제로 흘릴 수 있는 패턴**이 무엇인가 | A 구현 실측 | 근접 스윙 1종에 국한 — 2-3장 |
| ③ 그래서 **실제 피격 수가 몇 대 줄어드는가** | **C 계산 불가** | 플레이어 행동에 전적으로 의존 → 9장 G3-1 |

### 2-2. 이동 속도 실측 (구현 실측 — 둔화 조합 포함)

`player_controller.gd::_resolve_move_speed_px()` 구현을 그대로 재현했다. 걷기 절대값은 `player_movement_data.gd`가 `combat.md` 4장의 대시 3수치(3타일 / 0.35초 / 2.6배속)에서 역산한 값이다.

```
speed = walk × (1 − slow_pct)
if aim_multiplier < 1.0:  return speed × aim_multiplier      # 조준이 0.45를 "대체"
if is_attacking:          return speed × 0.45
return speed
```

| 상태 | tiles/s | 기본 대비 | 근거 |
|---|---:|---:|---|
| 기본 걷기 | **3.297** | 100% | `(16×3 / 0.35) / 2.6` px/s → 타일 환산 |
| 공격 중 (×0.45) | **1.484** | 45% | `ATTACK_MOVE_SPEED_MULTIPLIER = 0.45` |
| 거미줄 둔화 (−40%) | **1.978** | 60% | `web_slow_pct 0.4`, 지속 2.0초 (야간 아종 3.0초) |
| **둔화 + 공격 중** | **0.890** | **27%** | 둔화는 **곱연산**이라 0.45와 중첩 — 신규 수치 |
| 궁수 조준 (×0.4) | **1.319** | 40% | `aim_move_speed_multiplier 0.4` |
| **둔화 + 조준** | **0.791** | **24%** | 조준은 0.45를 대체하지만 둔화는 그 위에 곱해진다 |
| 회피 대시 | **8.571** | 260% | **둔화·공격 중 모두 면제**(무적 이동기) |

**참조 — 몬스터 전투 이동속도**: 들개 마수 4.2 / 무법자·노상강도 4.0 / 숲거미·밀렵꾼 3.6 / 임프 3.4 tiles/s. 무법자 돌진은 8.0 tiles/s.

> **핵심 발견 A — 공격 중 이동으로는 "도망"이 성립하지 않는다.** 공격 중 1.484 tiles/s는 **모든 근접 몬스터의 추격 속도(3.4~4.2)보다 느리다**. 즉 QoL④가 주는 이득은 "거리를 벌려 도주"가 아니라 **"제자리에서 정지한 예고 판정에서 한 걸음 빠지기"** 하나뿐이며, 그것이 2-3장의 검산 대상이다.
>
> **핵심 발견 B — 둔화×공격 중 = 기본의 27%(0.890 tiles/s).** M2 검증 시점에 없던 조합이다. 둔화×조준(궁수)은 **24%**로 더 낮다. 두 값은 어느 문서에도 없으므로 8장에서 `combat.md`에 명시하도록 지시한다.

### 2-3. 패턴별 판정 이탈 검산 (구현 실측)

**공통 조건(구현 확인)**: 근접 몬스터는 스윙 상태 진입 시 `velocity = Vector2.ZERO`로 **위치를 고정**하고, 히트박스는 몬스터 중심의 원(반경 = 사거리)이며 ACTIVE 구간에만 `monitoring = true`가 된다. 숲거미 도약은 **예고 시작 시점의 플레이어 위치**를 착지점으로 고정(`_resolve_land_point()`)하고, 무법자 돌진은 예고 시작 시점에 방향을 고정한다(`_on_charge_telegraph_started()`). 따라서 "예고 개시 후 확보되는 시간 안에 판정 원을 벗어날 수 있는가"가 순수 기하 문제로 환원된다. 플레이어 캡슐 반경 **0.375타일**(6px, `player.tscn`)을 필요 이탈 거리에 가산했다.

### 2-5. 판정 — 0.45 유지, 레버 3개 전부 미채택

**판정: 이동 계수 `ATTACK_MOVE_SPEED_MULTIPLIER = 0.45`를 유지한다. `combat.md` 3-1장의 조정 레버 3개를 모두 채택하지 않는다.**

| 레버 | 미채택 근거 |
|---|---|
| ① 이동 계수 0.45 → 0.3 | **완화 경로를 닫지 못하면서 둔화 조합만 파괴한다.** 0.3이면 1.0 tiles/s → 근접 스윙 경계 이탈(필요 0.375 / 0.5초)에 0.494타일로 **여전히 성공**한다. 즉 유일하게 남은 완화 경로(2-3장 1행)는 그대로 열려 있다. 반면 둔화 조합은 0.6×0.3 = 0.18 → **0.593 tiles/s(기본의 18%)**로 사실상 정지가 되어, 손맛만 잃고 난이도는 그대로다. |
| ② 페이즈 한정 (ACTIVE 이동 금지) | **실효가 거의 없고 스터터만 생긴다.** 소검 ACTIVE는 0.07~0.10초, 대검은 0.10~0.15초로 총 모션의 20% 미만이다. 총 이동거리 감소가 약 15%에 불과한 반면, 스윙 도중 이동이 끊겼다 이어지는 감각은 QoL 도입 목적(반응성)을 직접 훼손한다. |
| ③ 몬스터 공격력 상향(피격 예산 8~9대 재역산) | **애초 필요가 없다.** 2-4장에서 예산이 유지됨을 확인했고, `combat.md` 3-1도 이 레버를 "우선순위 최하"로 규정했다. 채택하면 몬스터 `.tres` 10개 + 8-2 곡선 전 구간 재산출이 발생한다. |

**유지 판단의 실체적 근거 3건**

1. **피격 예산 수치가 무너지지 않았다** (2-4장, 전 10종 9.91~10.30대).
2. **완화 경로가 M3 콘텐츠에 의해 이미 좁혀졌다** (2-3장): 도약·돌진은 공격 중 이동으로 흘릴 수 없고, 남은 근접 스윙 1종도 "사거리 경계에 정확히 서 있을 때"로 한정된다. 소검 리치 1.5타일 = 잡몹 스윙 사거리와 동률이므로(`m3-adventurer-basic-combo.md` 2장), 넉백(경량 0.3 / 표준 0.2타일)에 밀린 몹을 다시 따라 들어가는 플레이가 강제되어 경계에 머무는 시간이 짧다.
3. **완화를 실현하려면 대가를 낸다.** 예고에 반응해 후퇴하면 그 사이 소검 콤보는 리치(1.5타일)를 벗어나 헛돈다. 근접 스윙 1사이클(예고 0.5 + 판정 0.12 + 후딜 0.3 = 0.92초) 동안 이탈·복귀하면 소검 약 0.8사이클(계수 1.84, 뿔토끼 HP의 약 21%)이 사라진다. **"실피해 1대(HP의 약 10%)를 아끼려 TTK를 20% 늘리는" 교환**이므로 순이득이 작고, 늘어난 TTK가 다시 노출 시간을 늘려 상쇄한다.

**계산 불가로 남기는 것**: "그래서 디렉터가 플레이했을 때 실제로 몇 대 맞는가"는 회피 숙련도에 전적으로 의존하므로 **계산 불가**다. `combat.md` 5-1의 "10대"는 **치사성 캘리브레이션**(몇 대 맞으면 죽는가)이지 기대 피격 수가 아니다 — 들개 3마리 무리전만 해도 공격 토큰 2마리 기준 12.3초 동안 약 22회의 스윙이 발생하므로, 애초에 "대부분 회피한다"가 설계 전제다. 이동 계수는 그 회피의 **천장**을 바꾸며, 천장의 적정성은 문서로 판정할 수 없다 → 9장 G3-1 관찰 항목 #1.

- **M2 QA-3의 추정치는 구현 실측으로 확인됐다.** 같은 모델(설계 곡선)로 계산하면 1.622h(−10.6%)로, QA-3의 1.66h(−8%)와 **2.3% 차이**다. 차이는 야간 블렌드(QA-3 미반영)와 정확한 TTK(4.08 → 4.06~4.14) 때문이다. → **QA-3은 신뢰도 제한 표기를 붙일 만했으나 값 자체는 옳았다.**
- **−10.6%의 원인은 캐이던스 1.23배(플래그 1)다.** 설계는 TTK 5.0초 + 오버헤드 7초 = 사이클 12초를 가정했으나, 구현 실측 TTK는 4.06~4.14초라 사이클이 11.1초가 된다. 즉 D-2의 편차와 플래그 1은 **같은 원인의 두 표현**이며, 플래그 1을 조정하면 D-2 편차는 자동으로 해소된다.
- **두 모델이 목표를 사이에 두고 갈린다**(−10.6% ~ +6.5%). 배치종 동선이 오히려 느린 것은 위의 "낮은 레벨 몹과 싸운다" 효과 때문이다. **목표 1.8h가 두 모델 사이에 있다는 것이 D-2의 핵심 결과**다.

## 6. 이월 플래그 3 — 뿔토끼 HP 220 vs 서술 불일치

### 6-1. 실측 (구현 실측)

|---|---|---|---:|---:|

### 6-2. 추가 발견 — 걸어서는 붙잡을 수조차 없다

`rabbit_monster.gd` 상태머신을 실측했다.

- 도주 중 플레이어가 근접 사거리(1.5타일) 안으로 들어오면 박치기 1회(예고 0.4초, 그 동안 정지) → 다시 도주.

> **따라서 뿔토끼의 실제 벽시계 처치 시간은 데미지 기준 TTK 4.21초보다 상당히 길고, 율속 요인은 HP가 아니라 대시 충전(2회·4초/충전)이다.** 정확한 벽시계 값은 대시 사용 판단과 지형(구석 몰이 여부)에 의존하므로 **계산 불가**이며, "즉시 처치" 서술과 어긋나는 **두 번째, 더 큰 이유**다.

## 7. 정예 그로기 게이지 재검산 (난입 강타 `groggy_gain_ratio`)

### 7-1. 구현 확인 (ai-dev 확정치)

- 게이지 최대 = `effective_max_hp() × groggy_gauge_hp_ratio(0.25)`.
- 일반 타격 축적 = `take_damage()`에서 **최종 피해량 1:1**(`add_groggy(final_amount)`).
- 그로기 지속 `groggy_duration_sec = 3.0`, 종료 시 게이지 0 초기화.
- 그로기 중 슈퍼아머 붕괴(`_ignores_stagger()`가 `is_groggy()`면 false → 경직·넉백 정상 적용).
- **`add_groggy()`는 `is_groggy()`면 즉시 반환** → **그로기 중에는 게이지가 전혀 축적되지 않는다.** ai-dev 검산에 없던 구현 사실이며, 아래 모델의 핵심 항이다.
- 난입 강타: `groggy_gain_ratio 0.25`(= 게이지 최대치의 25%), 쿨다운 11초.

### 7-2. 모델 (레벨 무관 — HP 비율만으로 결정)

`H` = 정예 유효 최대 HP, `D` = 플레이어 지속 DPS, `T = H/D` = 정예 TTK. 게이지 최대 `G = 0.25H`, 난입 강타 1회 = `0.25G = 0.0625H`(DPS 시간 환산 **1.875초분** — ai-dev의 "약 1.9초분"과 일치).

```
N × 0.25H = D × (T − 3.0N) + (캐스트 수) × ratio × 0.25H
                 └─ 그로기 3초 × N회 동안은 축적되지 않는다
```

`H`로 나누고 `D = H/T`를 대입하면 **`H`와 `T`가 소거되어 레벨·야간 배율과 무관**해진다(게이지 최대치가 HP 비례이므로). 캐스트 수 = `floor(T/11) + 1`.

### 7-3. 재검산 결과

| 정예 TTK 전제 | `groggy_gain_ratio` | 캐스트 | **그로기 횟수** | 무방비 시간 | **무방비 비중** |
|---|---:|---:|---:|---:|---:|
| 설계 명목 30초 | 0.00 (난입 없음) | 0 | 2.86회 | 8.6초 | 28.6% |
| 설계 명목 30초 | 0.20 | 3 | 3.29회 | 9.9초 | 32.9% |
| **설계 명목 30초** | **0.25 (현행)** | 3 | **3.39회** | **10.2초** | **33.9%** |
| 구현 실측 24.5초 | 0.00 | 0 | 2.68회 | 8.1초 | 32.9% |
| 구현 실측 24.5초 | 0.20 | 3 | 3.09회 | 9.3초 | 37.8% |
| **구현 실측 24.5초** | **0.25 (현행)** | 3 | **3.19회** | **9.6초** | **39.0%** |

> **ai-dev 검산의 "전투당 3회 → 4~5회"는 과대 평가다. 실제는 2.86회 → 3.39회(+0.53회)다.** ai-dev는 1.9초 단축을 **매 사이클**에 적용했으나, 난입 강타 쿨다운 11초가 그로기 사이클(약 8.6초)보다 길어 **모든 사이클에 캐스트를 넣을 수 없다**. 전투 전체로 보면 3캐스트 × 1.875초 = 5.6초분이며, 이는 일반 타격이 대는 총 축적량의 약 19%다.

### 7-4. `groggy_gain_ratio` 0.20 하향이 무의미한 이유

0.25 → 0.20은 무방비 비중을 **33.9% → 32.9%(1.0pp)**밖에 줄이지 않는다. 게이지 축적의 **81%가 일반 타격**이므로 난입 강타 비율은 지배 항이 아니다. 실제 유효 레버는 **`groggy_gauge_hp_ratio`(게이지 최대치 비율)**다:

| `groggy_gauge_hp_ratio` | 그로기 횟수 | 무방비 시간 | 무방비 비중 |
|---:|---:|---:|---:|
| **0.25 (현행)** | 3.39회 | 10.2초 | **33.9%** |
| 0.30 | 3.06회 | 9.2초 | **30.6%** |
| 0.35 | 2.81회 | 8.4초 | 28.1% |

### 7-5. 판정 — `groggy_gain_ratio` 0.25 유지, `groggy_gauge_hp_ratio` 0.25도 유지

**판정: 두 비율 모두 현행 유지. 조정하지 않는다.**

1. **초과 폭이 3.9pp다** (33.9% vs 설계 의도 "무방비 비중 최대 30%"). ai-dey 우려대로 4~5회(40%+)였다면 조정이 필요했겠지만, 실제는 그 절반 이하다.
2. **초과의 주된 원인은 난입 강타가 아니라 플래그 1이다.** 난입 강타를 완전히 제거해도 명목 기준 28.6%로 겨우 30% 아래고, **실측 TTK 24.5초 기준으로는 난입 없이도 32.9%**다. 즉 분모(정예 TTK)가 캐이던스 1.23배로 짧아진 것이 주범이다. 플래그 1을 수용하기로 했으므로(4장) 그로기도 같은 축에서 수용해야 일관되며, **플래그 1의 예약 레버를 나중에 당기면 그로기 비중은 39.0% → 33.9%로 자동 하강**한다.
3. **M3 플레이 범위에서 이 조합은 재현 불가하다.** 난입 강타는 검투사(2차 전직 **Lv40**) 스킬이고, 구현된 유일한 정예는 **포효 임프장 Lv16**이다. Lv40 검투사가 Lv16 정예를 만나면 레벨 차 d = −24(경험치 ×0.10)이고 TTK는 약 9.9초로 줄어 검산 전제(30초) 자체가 무너진다. **Lv40대 정예는 미구현**이므로 G3-1에서 관찰할 수 없고, **문서 확정만 가능한 항목**이다(9장 구분).
4. `m3-warrior-tier2-skills.md` 4-2의 후속 검산 요구("난입 강타 1회 = 일반 타격 몇 회분")에 대한 답: **1.875초분의 지속 화력 = 명목 정예전(30초) 화력의 6.25%**. 같은 문서가 참고 산정에서 예상한 "약 5타분"(최대치를 일반 타격 20회분으로 가정)과 비교하면, 실제 최대치는 일반 타격 **약 12회분**(30초 ÷ 2.5초/타 기준)이고 난입 강타는 **약 3타분**이다. "대량 축적"이라는 서술의 하한은 지킨다.

- 그 외 **디렉터 결정 필요 없음.** D-1·D-2·플래그 3건·그로기는 모두 확정된 규격 안에서의 판정이며 게임 방향을 바꾸지 않는다. 9-2장의 O-1~O-7은 결정 요청이 아니라 **플레이 관찰 항목**이다.
