- 근거: [첫 구간](m7-novera-first-loop.md), [100시간 예산](../100-hour-progression-budget.md), [공개 서사](../story.md), [의뢰 구조](../quests/quest-structure.md). 구250시간 보상표는 사용하지 않는다.

## 1. 하나의 플레이 묶음

MQ02-04 보고 이후 조합에서 균열 탐사 수락 → 외곽에서 던전 진입 → 탐사·교전·유물 조사 → 귀환 보고 → 가레스의 장 마무리 보고까지 구현한다. 함께 할 수 있는 기본 서브2건, 목표 지도, 반복 방문, 중간 저장 복원을 포함한다. 세부 UI/완성 아트, 3장 방어전과 영지 하사·경영은 포함하지 않는다.

기존 외곽에 표식만 추가하는 안보다 별도 던전을 선택한다. 탐사 공간과 필드의 동선을 구분하며, 기존 저장 위치의 지형은 보존한다. 일회용 던전은 재방문 계약과 맞지 않아 선택하지 않는다. 이번 묶음으로 메인6건과 기본 서브2건이 연결되지만 추가 선택 서브1건 및 장 전체 시간·성장 균형은 완료로 선언하지 않는다.

## 2. 의뢰·보상 배정안

수치는 신규 제안이며 다음 구현의 데이터 계약이다. 기존 MQ02-01~04 보상은 유지한다. 모든 보상은 최종 보고 때 한 번만 지급한다.

| ID / 가칭 | 수락 조건 / 순서 있는 목표 | 보고 EXP | 골드 | 공훈 |
|---|---|---:|---:|---:|
| MQ-02-05 균열 안쪽의 기록 | 02-04 완료 / 조합 수락 → 던전 조사실 REACH → 전용 서식지 점액3 KILL → 유물 INTERACT → 접수원 보고 | 3,000 | 8,000 | 0 |
| MQ-02-06 신참의 귀환 | 02-05 완료 / 접수원 수락 → 가레스 TALK → 가레스 최종 보고 | 3,977 | 8,650 | 500 |
| SQ-NOV-001 돌아오는 길 | 02-04 완료 / 전용 귀환 기록표식2곳 INTERACT → 거점 접수원 보고 | 7,000 | 1,890 | 0 |
| SQ-NOV-002 남겨진 측량 기록 | 02-04 완료 / 던전 입구실·조사실 기록2곳 INTERACT → 거점 접수원 보고 | 7,651 | 1,890 | 0 |

서브는 메인의 선행 조건이 아니며 순서와 수행 여부를 플레이어가 선택한다. 유물·측량 기록은 판매 가능한 가방 아이템 대신 의뢰 목표 진행으로 표현한다. 가방이 꽉 차도 조사 가능하고, 확률 드롭을 요구하지 않는다. 가레스 대화는 공개 서사의 회수·보고까지만 다루며 유물의 정체나 반전은 쓰지 않는다. 기존 원화/상호작용 UI를 재사용한다.

예산 검산:

SQ-NOV-001의 표식 ID는 `novera_return_record_a`, `novera_return_record_b`이며 source는 각각 ID 뒤 `_site`를 붙인다. 둘 다 새 INTERACT 표식이다. 기존 물가/정찰 REACH 표식은 바꾸지 않는다. 상인은 거래 전용이며 보고는 접수원이다. MQ06은 기존 accept_npc_id로 접수원 수락과 가레스 보고를 구별한다.

- 메인 보고: 기존15,000 +3,000 +3,977 = **21,977**.
- 서브 보고: 7,000 +7,651 = **14,651**. 전체 보고 **36,628**, 기초 처치 풀 **15,697**은 별도다.
- 메인 골드: 기존2,250 +8,000 +8,650 = **18,900**. 서브3,780을 합쳐 의뢰 골드 **22,680**. 처치·판매 수입은 이 합계에 넣지 않는다.
- 장 완료 공훈: 기존 누적100 +500 = **600**. R3 요구500을 충족하지만 향사 임명·영지 하사를 자동 실행하지 않는다.

메인 골드를 후반에 배정한 것만으로 전직 직후 구매력을 보장하지 않는다. 기존 첫4건2,250과 실제 판매/포션 지출을 별도 장부로 측정하며 부족하면 지급 시점 재배분을 제안한다. EXP 여유안은 이미 공급 제작 계약으로 채택됐고 추가량은 S7/S11/S12에 배정돼 있다. 2장에 일괄10%를 다시 더하는 규칙이 아니므로 이번 2장 기초 풀은 그대로다.

기본 서브2건에 보고 풀을 모두 배정한다. 추가 선택 서브1건을 구현할 때 이 풀에 보상을 더 얹지 않는다. 현재 배정을 재분배하는 별도 예산 변경이 필요하며, 여기서는 그 의뢰를 만들지 않는다. 메인만으로 Lv12를 보장하지 않는다. 처치 풀15,697은 공급 목표이지 이번 점액3마리의 지급량이 아니다. 기존 외곽의 들개Lv4·점액Lv8 및 새 던전 처치의 실제 레벨차 EXP를 로그로 합산하고 목표와 차이를 보고한다. 차이를 숨기기 위한 자동 EXP 보충·레벨 주입·무한 사냥 조건은 넣지 않는다.

## 3. 던전·왕복·재방문

`novera_rift`는 제안 크기64×40타일(1024×640)이다. 기존 거점64×48, 외곽80×48과 달리 입구실→조사실→유물실의 짧은 탐사에 맞춘다. 통행 폭은 최소3타일, 입구 도착 구역은 적 스폰과 분리한다. 새 원화나 새 AI 대신 기존 타일과 점액을 재사용한다. 이번에는 별도 보스 시스템을 추가하지 않는다.

외곽의 기존 균열 조사 표식은 유지하고 근처에 별도 던전 관문을 둔다. 관문 후보는(1168,272), 외곽 귀환 후보는(1120,320)이다. 던전 서쪽 출구 후보(96,320), 도착 후보(144,320). 모두 설계 좌표이며 실제 캡슐 오프셋·지형·기존 표식·적 인지/사격 범위로 재측정해 구현에서 확정한다. 관문과 도착점은40px 초과로 떨어뜨린다. 기존6개 간선을 유지하고 왕복2개를 추가한다.

던전 입장은 MQ02-04 완료를 요구한다. 메인 수락 전에도 입장·서브 조사는 가능하지만 미수락 메인 목표는 진행하지 않는다. 전직은 권장 안내이며 입장 조건이 아니다. 귀환은 완료/교전 여부로 잠그지 않으며 현재 지역 이동의 사망·입력 잠금·재진입 보호만 유지한다.

점액3개는 별도 source로 등록한다. 다른 필드 처치로 목표를 채우지 않는다. 재방문 시 몬스터는 다시 생성할 수 있지만 의뢰 completed/보고 보상은 되돌리지 않는다. 조사 표식은 현재 목표일 때만 F를 소비한다. 중간 저장은 의뢰 counts를 복원하고 적 배치/개체 HP는 기존 월드 재생성 규칙을 따른다. 적이 살아났다는 이유로 완료 카운트를 빼거나 보상을 다시 지급하지 않는다.

지도는 다른 지역 목표에 현재 지역의 출구를, 던전에서는 방/표식을 표시한다. 완료 후 미구현 3장 관문을 표시하지 않고 ‘2장 메인 완료, 후속 이야기 준비 중’으로 안내한다. 서브 미완료 목표는 계속 선택할 수 있다.

## 4. 저장 경계

V6의 허용 의뢰/지역 의미를 보존하기 위해 **별도 V7 확장 카탈로그·지역 목록과 후보 세션**을 둔다. V6 검증기가 참조하는 M7 목록에 새 ID를 직접 추가하지 않는다. V1~V6 원본 규칙 검증 → 기존 이관 → V7 표기 및 V7 재검증 순서다. V6→V7은 기존 위치·EXP·골드·장비·의뢰 상태를 보존하며 새 상태를 완료로 채우지 않는다. 입력 사본 불변·V7 재입력 멱등을 검사한다.

새 던전 저장은 MQ02-04 완료를 요구한다. MQ02-05/06 선행과 기본 서브의 수락 조건도 저장 검증에 반영한다. 별도 story_flags/territory 필드를 열지 않는다. V7 파일은 구 실행기가 거부하고 백업으로 우회하지 않는다. 후보 경로는 `user://m7_closure_candidate_*`로 한정해 V6 실제 슬롯과도 분리한다. 이전 슬롯 읽기 대조는 복사본으로만 하며 사용자 원본을 덮어쓰지 않는다.

기본 채택은 **M6/V5 → M7/V6 → 이번 V7** 순서다. 새 후보 개발이나 장 보상 설계가 이전 전투 관문을 승인하지 않는다.

## 5. 구현·검증 종료 기준

카탈로그/의뢰 데이터, 던전/관문/스폰, NPC/지도, V7 저장·실행기를 하나의 제품 검토로 전달한다. 기존 GUT 전체와 변경 저장/퀘스트 경로를 검사하고 구 V5/V6의 신규 ID 거부를 포함한다. 부분 진행·ready·completed 저장과 보고 반복·가방 만석을 확인한다.

직전 리뷰의 조작기 보완을 이 구현에 포함한다. 첫 구간의 내부240초는600초로, 실행기의300초 감시는660초로 함께 조정한다. 사냥도 실제 충돌형 기반 경로 재계산을 사용한다. PowerShell 실행기는 UTF-8 BOM으로 저장한다. 시간 증가가 완주를 보장한다고 가정하지 않는다.

확장 완주 검사는 첫 구간부터 후반 메인·서브·던전 왕복·장 보고·별도 프로세스 복원까지 대상으로 한다. 길이가 늘어난 확장 검사는 시작 전 내부900초/외부960초,3회로 고정한다. 실행 중 제한을 늘리거나 성공 표본만 선택하지 않는다. fixture로 생략한 구간이 있으면 별도 검증으로 기록한다. 사망/정체/시간 초과는 실패로 남기고 제품 원인이 불명확하면 미검증으로 둔다. QA 안정화만으로 또 별도 묶음을 만들지 않는다.

검토 시점의 종료 결과는 기능/저장 검증, 실제 처치·보고 EXP 및 소요 시간, 실패 로그다. 미감·직업별 난이도·Lv12 성장 목표 실현·기본 채택을 자동 통과로 확대하지 않는다.
