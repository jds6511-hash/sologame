# M6 기본 실행 반영·M7 후속 정리 계획

- 2026-09-30 / Codex. 의존: [M6 설계](m6-economy-equipment-loop.md), [승인·완주 기록](../../qa/m6-m7-adoption-evidence.md).
- 변경 이력: M6 승인 뒤 기본 실행/V5 이관과 M7 검토 참고 사항을 하나의 제품 묶음으로 구현.
- 실행: subagent-driven-development 스킬로 독립적인 M7 정리를 분담하며 기본 실행·저장 통합은 주 작업자가 담당한다. 기존 사용자 실행 경로를 유지하기 위해 현재 작업 폴더에서 명시 파일만 수정한다. 타인 PNG9개를 건드리지 않는다.

## 목표·설계

기본 게임 실행과 새 게임을 M6 경제/장착 런타임·V5 저장으로 연결한다. 기존 V1~V4는 동결된 검증기로 원본 검증 후 메모리 이관하고, 정상 저장할 때 V5를 기록한다. 기존 슬롯을 시작만으로 재작성하거나 후보 파일을 정식 저장으로 복사하지 않는다. M7/V6·V7은 격리 후보로 유지한다.

공통 경제 런타임을 재사용하는 제품 환경을 추가하고, 후보의 저장 경로 허용 조건과 안내 표시를 좁은 확장점으로 분리한다. 기본 실행은 `user://saves`, 테스트는 명시한 전용 경로만 사용한다. V4 검증기·기존 테스트용 씬을 전역적으로 V5로 바꾸지 않는다.

외곽 BGM은 실제 map_id에 맞는 필드 곡을 사용한다. V7 의뢰 선택은 카탈로그 정의 밖의 세션 UI 상태로 옮기고, 대화·추적·지도·지역 이동에서 같은 선택을 읽게 한다. 저장 형식과 완료 진행은 바꾸지 않는다. EXP42,828/Lv11 관측은 기록만 하고 보상·몬스터 수치를 임의 증액하지 않는다.

## 작업·검증

- [x] 기본 환경/실행기/V5: 제품 환경·부트 씬 추가, 기존 후보 격리 불변. GUT에서 기본 시작/월드 교체/미래 버전 거부·구버전 검증 경계를 검사한다.
- [x] 저장 프로세스: 전용 fixture V4 파일 준비 → V5 메모리 로드(원본 파일 불변) → 명시 저장 → 별도 프로세스 재로드. 원본 백업·보상/장비 중복 없음·V6/V7 거부 확인. 사용자 저장 파일은 열거나 수정하지 않는다.
- [x] M7 UI/BGM: 기존 실패를 먼저 재현하고 선택 상태의 월드 격리·대화/지도 정합성·지역별 BGM을 검사한다.
- [x] 통합: 전체 GUT, 기존 경제/API 세션, 변경 저장 프로세스, 기본 실행기 smoke/렌더, GD 형식/린트. 전투/저장 변경 범위를 보고 필요한 고정3회 배치를 실행하며 실패 표본을 제거하지 않는다.
- [x] 한 쪽 통합 검토서·진행/실행 안내 갱신, 명시 경로 커밋. 원격 반영 여부는 별도 기록.

## 검토 초점

구버전 원본 검증 우회, 로드만으로 파일 덮어쓰기, 후보 저장 경로 침범, 월드 교체 시 V4 복귀, UI 선택이 정의/진행 검증을 오염시키는 경우를 우선 확인한다. M6 승인과 이번 배선 검토, M7/V7 미채택을 구분한다.
