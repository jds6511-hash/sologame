# MQ-01-04 — 균열 어귀 조사 구현 계약

- 최종 수정일: 2026-09-28
- 담당: Codex (설계·구현 통합)
- 상태: 기존 M5 후속 의뢰 설계, 구현 전 독립 검토 대상. G4/G5 미판정 유지.
- 의존: [퀘스트 정본](../quests/quest-structure.md), [초반 성장](../quests/early-leveling-route.md), [시작 맵](../levels/eastern-frontier-start-map.md), [MQ03 이월 지적](../../qa/m5-third-quest-review-response.md), [저장 계약](save-load.md)

## 1. 한 묶음의 결과

들개 의뢰를 보고한 플레이어가 접수원에게 탐사 의뢰를 수락하고, 기존 균열 굴 어귀에 도달한 뒤 표식을 F로 조사하고 돌아와 명시적으로 보고한다. 도달만으로 조사를 완료하거나 보상을 자동 지급하지 않는다. 신규 적·던전·상점·명성 시스템은 추가하지 않는다. 기존 M5 범위 안에서 INTERACT와 복수 목표 표시를 완성한다.

| 항목 | 계약 |
|---|---|
| ID / 제목 | `MQ-01-04` / 옛 균열의 숨소리 |
| 선행 / 수락·보고 | `MQ-01-03` completed / `yeoulmok_receptionist` |
| 목표 순서 | REACH `yeoulmok_old_rift_entrance` 1회 → INTERACT `yeoulmok_rift_mark` 1회 |
| 두 목표 출처 | `yeoulmok_old_rift_site` (신규 stable ID) |
| 보고 EXP | 1,040, 초반 성장 정본 고정값 |
| 보고 골드 | 300 = 권장 Lv3의 `roundi(2×3^1.5)=10` × 30마리분 |
| 기타 보상 | 없음. 기존01~03 보상 불변 |
| 완료 뒤 | 다음 여울목 출발 의뢰는 아직 제공되지 않음을 안내. MQ05 자동 생성·수락 없음 |

누적 보고 EXP는 1,930, 골드는 570이다. 처치 EXP/드랍은 별도이며 도달 레벨을 강제하지 않는다. S7/S11/S12 추가 EXP는 이번 의뢰와 무관하다.

## 2. 현행 코드와 차이

- `QuestData.definition_error()`는 REACH/TALK/KILL만 지원한다. INTERACT를 추가하고 실행기가 없는 나머지 유형은 계속 거부한다.
- `QuestJournal.record_event()`는 첫 미완료 목표만 검사하고 매칭 실패여도 그 자리에서 break한다. 이 순서 계약을 유지한다. 조사를 먼저 호출해도 counts `[0,1]`이 되면 안 된다.
- `QuestPresentation._view()`는 단일 문구와 `counts[0]`를 읽는다. 숫자만 바꾸지 않고 해당 목표의 이름·위치도 함께 선택해야 한다.
- `QuestNpc`는 단일 NPC용 메타와 HUD 프롬프트를 직접 쓴다. 새 표식이 같은 메타를 매 프레임 덮으면 NPC/줍기 우선순위가 깨지므로 동일 패턴을 복제하지 않는다.
- `Markers/QuestPoints/REACH_균열굴어귀_MQ0104`, `INTERACT_균열표식_MQ0104`는 이미 Marker2D다. 표식은 `(184,72)`이며 현재 마커 자체에는 표시·조사 동작이 없다. 생성 스크립트로 맵 전체를 재생성하지 않는다.

## 3. 도달과 조사

시작 월드의 기존 `_setup_quest_ui`와 같은 캐릭터 QuestController에 조사 지점을 연결한다. 노드 이름으로 저장 목표를 추론하지 않고 위 stable ID를 export/상수로 명시한다.

- REACH는 어귀 마커 반경 32px에서 현재 캐릭터의 생존·월드 소속을 확인해 기록한다. 벽 너머 도달을 막도록 월드 충돌 레이어 1의 시야선도 검사한다. 수락 전 이벤트는 Journal에서 무시된다. 해당 위치에서 로드/수락한 경우 다음 갱신에 도달을 인식한다.
- INTERACT는 표식 반경 40px와 동일 시야선 검사, 생존·입력 잠금·피격 경직·공격·스킬·대시·pause 조건을 적용한다. MQ04 active이며 첫 목표 완료, 조사 목표 미완료일 때만 후보가 된다.
- 실제 F 입력 시 후보 조건을 다시 확인하고 `record_event("INTERACT", target, source, 0)`를 보낸다. 키 반복을 무시한다. Journal의 목표 상한과 순서 검사로 연타 중복을 막는다. KILL 전용 token 장부는 재사용하지 않는다.
- 완료 직후 추적창은 접수원 보고로 바뀌고 조사 프롬프트는 사라진다. 표식은 간단한 독자적인 월드 표식/라벨로 위치를 식별할 수 있게 하되 충돌·몬스터 배치를 변경하지 않는다.
- 조사 순간 게임을 정지시키거나 자동 저장하지 않는다. 피격 직후·전투 중 상태가 위 조건을 통과하는지 기존 NPC와 같은 기준으로 판단한다. 주변 슬라임을 의뢰 필수 처치로 추가하지 않는다.

## 4. 상호작용 우선순위 — 필요한 만큼의 공통화

월드에 로컬 상호작용 조정 노드 하나를 둔다. 전역 Autoload/새 입력 액션을 만들지 않는다. NPC와 표식은 후보 여부·거리·프롬프트·실행 메서드를 제공하고 조정 노드가 한 대상만 고른다.

선택 순서는 **가능한 NPC → 가능한 조사 지점 → 기존 아이템 줍기**다. 같은 종류에서는 가까운 대상, 동률이면 stable ID 순서로 고정한다. NPC/표식이 없는 경우 기존 아이템 동작을 유지한다. F 처리와 화면 프롬프트가 반드시 같은 선택 결과를 쓴다. 선택 노드만 `_unhandled_input`에서 F를 소비하며 NPC/표식별 중복 입력 처리는 제거한다.

`npc_interaction_available` 기존 소비자(WorldItem·TutorialController)는 조사에도 적용되는 `world_interaction_available` 공통 판정으로 함께 전환한다. 이 메타의 작성자는 조정 노드 한 곳이며 선택/해제/pause/대상 삭제/월드 종료 때 해제한다. 기존 이름을 새 노드가 별도로 덮어쓰지 않는다. 튜토리얼의 공격 안내와 아이템 프롬프트 모두 동일 판정으로 억제한다. 독립 NPC 테스트 씬도 공통 조정 경로로 검증한다.

프롬프트 정리 시 다른 UI 소유자의 프롬프트까지 무조건 숨기지 않도록 소유권을 분리한다. 메타만 바꾸고 화면은 남기는 MQ02 당시 회귀를 반복하지 않는다.

## 5. 정의·표시 검증 (MQ03 이월 2건 포함)

`QuestData`에 목표별 `objective_labels: Array[String]`, `objective_location_hints: Array[String]`를 추가하고 01~04 정의를 함께 갱신한다. 기존 단일 필드는 호출처를 전수 제거한 뒤 폐기한다. 저장 payload에는 이 표시 데이터가 없으므로 counts 형식은 바뀌지 않는다.

`title`, `offer_text`, 목표별 label은 trim 후 빈 문자열이면 콘텐츠 오류다. 두 표시 배열 길이는 objective_counts와 일치해야 한다. 목표별 위치도 공백을 거부하되 기존 패 지급 의뢰 MQ01의 접수원 REACH/TALK만 빈 위치를 허용한다. `grants_adventurer_pass` 하나만으로 임의 신규 의뢰의 위치 검증을 우회시키지 않는다.

공통 순수 표시 함수가 첫 미완료 목표의 **종류·이름·위치·현재 수·필요 수**를 함께 반환한다. Journal과 별도의 진행 상태를 저장하지 않는다. Tracker와 Dialog가 같은 projection을 사용한다. MQ01의 패 수령/대화 문구와 완료 시 보고 표시를 유지한다.

카탈로그 전체 정의 검증과 `quest_content_error` 차단을 그대로 적용한다. 아직 수락하지 않은 MQ04 정의가 잘못돼도 읽기·쓰기 모두 차단하고 정상 저장을 손상본으로 보존/백업 승격하지 않는다.

## 6. 저장과 수명

배포 CharacterSave V3 / AccountSave V1 유지. 기존 V1/V2는 원본 Legacy 검증→C1 변환→재검증 경로 유지. 기존 저장에 MQ04가 없으면 미수락으로 남고 03 완료 조건만으로 제안한다. 기존 보상 재지급 없음.

MQ04는 `[0,0]` active, `[1,0]` active, `[1,1]` ready/completed로 저장한다. `[0,1]`은 기존 순서 검증으로 거부한다. 도달/조사 여부는 counts만 사용하며 월드 노드에 별도 영속 플래그를 만들지 않는다. 로드한 ready는 재조사가 필요 없고, completed는 다시 보상받지 않는다.

구 카탈로그가 MQ04 저장을 읽는 다운그레이드는 지원하지 않는다. 기존 파일 계층의 invalid_data 원문 보존을 실제 과거 3의뢰 카탈로그 fixture로 검사한다. V3 숫자가 같다고 구 빌드 호환을 보장하지 않는다.

## 7. 구현·검증 묶음

정의/복수 목표 표시·상호작용 조정/월드 표식·보고/저장 재실행을 **하나의 구현 리뷰**로 전달한다. 작은 변경마다 별도 리뷰 요청을 만들지 않는다.

1. Resource 검증: 공백 문구, 배열 불일치, MQ01 위치 예외, 미수락 MQ04 콘텐츠 오류의 저장 차단/파일 해시 불변.
2. Journal/표시: 선행 거부, 수락 전/틀린 출처/조사 선행 무시, `[0,0]→[1,0]→[1,1]`, 첫 미완료 이름·위치 변경, 기존01~03 표시 회귀.
3. 실제 월드: 위치·시야선·거리 경계·행동 잠금, NPC/표식/아이템 중첩에서 선택·프롬프트·F 소비 일치. 키 echo·표식 삭제·pause 해제·월드 교체에 메타/입력 잔류 없음. 단순 Journal 직접 호출과 실제 입력 배선 검증을 구분한다.
4. 보상: 실제 Controller 보고로 1040 EXP/300골드 정확히 한 번, 잘못된 NPC/연타/재로드 중복 0. 보상 전후 레벨·EXP·골드를 비교한다.
5. 별도 프로세스: 기존 V2/V3 세 의뢰 저장, MQ04 두 active 상태·ready·completed 재실행, 원본 슬롯 해시 보호, 조사 이후 표식 재생성해도 재지급 없음. 기존 C1 변환 probe 유지.
6. 전체 GUT·변경 GD 형식/린트·월드 UI 렌더. 실제 조작·처치 시간·안전한 조사 동선·G4/G5는 자동 통과로 치환하지 않는다.

예상 변경: quests의 Data/Catalog/Presentation, `mq_01_01~04.tres`, NPC/시작 월드/UI 프롬프트 소비자, 새 조사 지점·상호작용 조정 노드, quests/world/save 테스트. Journal/Schema는 기존 순서 계약을 우선 재사용하며 필요한 변경만 한다. 전투·저장 안전 반경·맵 타일·슬라임 스탯은 범위 밖이다.
