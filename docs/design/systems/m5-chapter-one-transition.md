# M5 여울목 장 마무리와 노베라 입구 이동

- 최종 수정일: 2026-09-28
- 담당: Codex
- 근거: [로드맵](../DEVELOPMENT_ROADMAP.md), [의뢰 정본](../quests/quest-structure.md), [초반 성장](../quests/early-leveling-route.md)
- 변경 이력: 2026-09-28 — 디렉터의 진행 구간 단위 구현 지시를 반영.

## 한 묶음의 완료 범위

MQ04 보고 → 접수원 MQ05 명시 수락 → 부락 관문 도달·관문지기 배웅 → 명시 보상 수령(EXP1800/골드560/공훈100) → 노베라 입구로 이동 → 입구 탐색·여울목 귀환 → 저장·종료·재실행 후 지역/위치/의뢰/공훈/장비 유지.

노베라 입구는 기존 타일셋으로 만드는 별도 작은 통행 구역이다. 노베라 읍 전체·2장 의뢰·상점·추가 사냥/보상은 이번 완료 주장에 포함하지 않는다. 2장 개시와 첫 장 완료는 MQ05 완료로 판정하며 그 뒤 콘텐츠 미구현 안내를 명확히 한다.

## 데이터·실행 계약

- MQ05 목표: REACH와 TALK 모두 `yeoulmok_gatewarden`(출처 빈 문자열). 수락 NPC는 기존 접수원, 보고 NPC는 관문지기다. 다른 NPC 보고·미수락 이동·중복 보고는 보상 불가.
- 수락/보고 NPC를 별도 데이터로 구분한다. 접수원은 수행 중 보고 NPC로 안내하고 보상은 지정 보고 NPC에서만 받는다.
- 공훈은 현행 제공 의뢰의 완료 상태에서 합산하며 저장에도 같은 총량을 기록한다. 이번에는 MQ05 100만 공급한다. 나중 토벌/영지 공훈 확장은 별도 계약이다.
- CharacterSave V4: V1/V2 Legacy 원본 검증→C1 변환→V4, V3 C1 원본 검증→EXP 불변 V4. V1~3은 기존 단일 맵/공훈0 계약을 유지한다. V4 공훈과 완료 의뢰가 불일치하거나 MQ05 완료 없이 노베라 입구인 저장은 거부한다. 과거 파일은 명시 저장 전 쓰지 않으며 이전 버전 로드 후 자동 저장 보류는 유지한다.
- 지역 레지스트리가 ID→씬·범위·도착점을 소유한다. 로드/이동은 목표 맵의 범위를 검사한다. 새 캐릭터는 항상 여울목. 지역 이동은 현재 캐릭터 snapshot을 새 월드에 복원하며 계정/캐릭터 ID·슬롯·시각·플레이시간·이전 버전 보류를 유지한다. 실패하면 기존 월드·pause 소유권을 복원한다.
- 보상과 이동을 구분한다. 배웅 보고 후 이동이 차단되면 지급 완료 상태를 유지하고 재대화의 이동 버튼으로 재시도한다. 이동 자체에 추가 보상/자동 저장은 없다.
- 이동은 관문 NPC 근처에서만 가능하며 사망/보스/최근 전투/일시 효과·행동을 검사한다. 저장의 반경160px 규칙은 변경하지 않는다. 이동은 비적대 배회 몬스터까지 모두 차단하는 고정 저장 반경을 쓰지 않는다.

## 저널 리뷰 보완

전체 메뉴 불투명 배경과 상위 저장 배지 숨김으로 겹침을 막는다. 렌더의 기본 출력은 추적하지 않는 screenshots 경로로 옮겨 정본 PNG를 덮어쓰지 않는다. 기본 상태 필터는 의미에 맞게 '미완료'로 표기한다. 숨겨진 UI 재생성 최적화는 서브 의뢰 확장 때 처리한다. 현재5건이며 표시 질의의 즉시성 계약을 이번 지역 전환과 함께 바꾸지 않는다.

## 검증

검증 결과와 재현 명령은 [통합 검토](../../qa/m5-chapter-one-review-request.md)에 기록한다. 좌표 주입·선행 의뢰 합성 상태·대화 API를 사용한 자동 검증이며 실제 도보 조작/G4/G5를 대신하지 않는다. 월드 교체 실패 복구는 기존 공통 경로의 회귀 검사이고 새 지역 부팅 실패를 별도 주입했다고 주장하지 않는다.
