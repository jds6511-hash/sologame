## 1. 목적과 선택

노베라에서 급보 수락 → 여울목으로 귀환 → 주민 대피와 방어 → 현장 조사 → 문장원 심사 → 향사 임명과 여울목 복구권/통치 책임 확인까지 연결한다. 플레이어가 첫 장의 장소를 지키고 자기 영지를 얻었다는 변화를 만든다. 공훈500은 자격이며 자동 임명이 아니다.

접근 비교: 기존 여울목 타일을 직접 파괴하면 구 저장 좌표·NPC·온보딩이 함께 바뀐다. 대사만으로 전투를 생략하면 방어전 플레이가 없다. **기존 여울목에서 진입하는 별도 방어 현장**을 선택한다. 방어 현장의 피해는 장식이고 기본 여울목 타일/충돌은 유지한다. 완료 뒤 기본 여울목에 복구권 안내 NPC와 영지 현황만 추가한다. 전면 파괴/복구 아트는 후속이다.

범위: 메인5건·기준 서브3건, 방어 현장1개, 순차 전투, 지도·NPC, 하사 표시, 제품 V6/개정2 저장까지 한 묶음. 추가 서브1건, 4장, 영지 투자/수입/시간 생산, 남작·백작, 새 직업, 대규모 아트는 제외한다. M8의 경영 기능을 완료로 선언하지 않는다.

M6와 2장은 제품 V6에 기본 반영됐고 `f2348d6` 독립 검토를 통과했다. 3장은 같은 월드·카탈로그·세션에 표와 생성기로 추가한다. 체감은 1막 종료 후 한 번 확인한다.

## 2. 진입·의뢰·보상

현행 100시간 예산 머리말과 §2~5를 우선한다. 3장은 **메인5·기준 서브3·추가1**, 보고33,811/처치14,490 EXP, 골드36,660, 메인 공훈400/서브200이다. 옛 quest-structure의 메인6·구250h 보상을 혼용하지 않는다. EXP 여유 증액은 S7/S11/S12이므로 3장에 임의10%를 더하지 않는다.

진입은 MQ-02-06 completed + 실제 Journal 공훈≥500이다. Lv12는 권장치이고 새 하드 잠금이 아니다. 기존 V7 표본은 Lv11이므로 Lv11 기본 C장비·두 전직 및 모험가로 접근 가능한지 구현 때 확인한다. 자동 레벨 보정·반복 사냥 의무를 넣지 않는다.

## 3. 현장·왕복·전투

지역 ID `yeoulmok_defense`, 제안 크기64×40타일(1024×640). 기본 여울목48×36보다 넓고, 북쪽 방어선·중앙 대피로·남쪽 안전 집결지를 구분한다. 최종 타일/관문 좌표는 실제 캡슐·NPC 이름표·적 사격 반경으로 검증한 뒤 확정한다. 맵별 BOUNDS를 사용하고 전체 지역 크기를 고정하지 않는다.

간선은 기본 여울목의 전용 현장 안내인→방어 현장 남쪽 집결지, 현장 출구→여울목 기존 안전 공간이다. 출입구와 도착점은 상호작용40px 밖에 두고, 기존 노베라 왕복 간선을 수정하지 않는다. 입장은03-01 완료부터, 귀환은 항상 허용한다. 스킬/포션 대기를 새 이동 제한으로 넣지 않는다. 임명 후에도 기록/서브 때문에 현장을 재방문할 수 있다.

전투는 기존 AI/피격·드롭·몬스터 등록을 재사용한다. 03-03의 두 무리는 **각각 동종3마리**로 구성하고 source `yeoulmok_defense_wave_1/2`를 분리한다. 동시 최대3마리, 앞 무리 완료 후 명시적인 다음 방어선 상호작용으로 뒤 무리를 시작한다. 타이머 생존/주민 HP/영구 실패는 이번에 도입하지 않는다. 03-04 정예는 별도 source이며 새 보스 시스템 대신 기존 공격 예고가 있는 AI와 전용 데이터로 구성한다. 레벨·HP·공격 수치는 기존 전투 공식으로 작성하고 Lv11~13 장비별 피해/TTK를 구현 검토서에 기록한다.

진행 정본은 Journal의 순서 있는 KILL 목표 counts다. 재진입/로드 때 현재 목표에서 **남은 수량만** 생성하며 완료 무리를 재생성하지 않는다. 서로 다른 몬스터를 섞지 않아 count만으로 어떤 적이 남는지 모호하지 않게 한다. 스폰 관리자는 월드당 하나이고 개체당 처치 이벤트는 한 번만 보낸다. 다른 무리/필드 개체의 source로 진행하지 않는다. 숨긴 몬스터·HP·EXP 주입으로 완주를 만들지 않는다.

현장에 들어온 것만으로 전투를 시작하지 않는다. 재진입/로드에서도 집결지의 방어 재개 상호작용 후 잔여 개체를 생성한다. 시작 여부는 세션 상태, 처치 진척은 Journal 상태로 나눈다. 시작 버튼 연타/중복 노드가 같은 무리를 두 번 만들지 않으며 ready/completed에서는 생성하지 않는다.

사망/귀환은 이미 기록된 목표 counts를 임의 초기화하지 않는다. 다시 들어오면 미처치 수량만 생성한다. 저장은 기존 안전 조건으로 판단해 전투 중 자동 체크포인트를 만들지 않는다. 이전 파일을 다시 로드하면 EXP·드롭·목표가 같은 스냅샷으로 함께 돌아간다. 안전 집결지에서 중간 저장→재시작→잔여 무리·보고 단회 지급을 검사한다.

## 4. 향사와 첫 영지의 표현

MQ-03-05 수락/최종 보고에서 공훈≥500을 재검사한다. 보고 확정은 기존 보상 트랜잭션으로 한 번만 수행한다. 완료된05가 **향사 임명·여울목 복구권 부여의 단일 근거**다. 별도 돈/아이템 지급이나 두 번째 하사 버튼을 두지 않는다.

이번 단계의 작위·영지 현황은 Journal 완료에서 파생하는 읽기 전용 표시다. 캐릭터 화면에 향사, 여울목 안내 NPC에 ‘복구권과 통치 책임을 부여받음 / 경영 기능 준비 중’을 보여준다. 완료 전에는 자격 충족과 임명을 구분한다. `progress.territory`/`story_flags` 예약 필드는 **계속 빈 객체**로 유지한다. M8에서 실제 투자·시설 상태가 생길 때 명시적 버전 이관으로 해당 필드를 연다. 같은 사실을 의뢰·작위·영지 세 곳에 저장해 불일치를 만들지 않는다.

## 5. 제품 V6/콘텐츠 개정2·구 저장 계약

V1~V5 원본을 동결된 기존 규칙으로 검증한 뒤 제품 V6/개정2로 변환·재검증한다. 제품 V6/개정1은 기존 의뢰 ID 의미를 그대로 유지하며 불러온다. 새 의뢰를 completed로 채우지 않고 공훈만 보고 향사로 만들지 않는다. 기존 위치·직업·아이템·보상 기록을 유지한다. 과거 QA 후보 V6/V7은 호환 대상이 아니다.

현장 저장은03-01 completed를 요구한다. 의뢰 선행·counts·공훈 합계를 검증하고03-01은02-06 완료/공훈500,05 completed는 선행 및 최종 자격과 양립해야 한다. 구 형식에 새 지역/의뢰를 섞거나 예약 territory를 넣은 파일은 거부한다. 미래 콘텐츠 개정·콘텐츠 정의 오류를 백업 복구로 우회하지 않는다.

3장 API 검사는 `user://product_defense_probe`, 시작 체험은 `user://product_chapter_preview`만 쓴다. `verify_all`은 실제 저장 원본을 해시·복사로만 읽고 이관 검사는 QA 복사본에서 한다. 새 후보 버전이나 후보 세션은 만들지 않는다.

## 6. 구현·검증 묶음

1. 의뢰 데이터8건·지역/표식·NPC·지도/추적·전투 스폰/재진입을 함께 구현한다.
2. 하사 파생 표시와 제품 V6/개정2·중간/완료 저장·단일 실행기를 연결한다. BGM 종료 잔존의 재현과 해제 경로도 확인한다.
3. GUT: 출입 잠금/귀환, source 분리, 동시 수량/잔여 재생성, 중복 보고, 서브 생략 하사, 공훈만으로 미임명, 구버전 거부와 이관/파일 격리.
4. API fixture: 2장 완료 준비→현장 중간/완료 별도 프로세스 복원. 정상 입력 검사에서는 3장 상태·HP·적·피해·보상 주입 금지. 전체 시작 전 고정3회, 실패 포함 집계. 자동 조작기 보완만을 별도 기능 묶음으로 확장하지 않는다.
5. 새 실행기는 2장 완료 준비로 시작해 이전 장 재완주를 요구하지 않는다. 체감/미감 판정은 큰 마일스톤에서 모아서 받으며 매 커밋 직접 테스트를 요구하지 않는다.

검증 결과와 한계는 구현 검토서에 기록한다. API fixture 완주와 사람의 정상 입력·난이도 판정은 구분하며, 이 문서를 체감 승인으로 읽지 않는다.

변경 이력(2026-10-02): 디렉터의 구조 통합 이후 저장·후보 계약을 실제 제품 V6/개정2로 교체. 승인된 의뢰 수치와 범위는 유지.
