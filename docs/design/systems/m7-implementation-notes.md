# M7 첫 구간 구현 기록

- 2026-09-30 / Codex. 근거: [승인 설계](m7-novera-first-loop.md).
- 변경 이력: 지도·NPC·의뢰·V6 저장 통합 구현의 실제 범위와 검증 경계를 기록.

## 연결 구조

기본 V4와 M6 V5의 지역/의뢰 목록은 그대로다. M7만 별도 Catalog/Regions/Schema/Codec/Store/Session을 사용한다. 공통 코드에는 카탈로그 순서·NPC 이름, 지역 검증, 여행 도착점의 주입 지점을 둔다. 원본 V1~V5는 기존 M6 검증기로 먼저 검사하며 V6 재입력은 깊은 사본을 반환한다.

**보존 범위 정정:** V5→V6는 버전 외 게임 상태를 보존한다. V1~V4→V6는 이미 승인된 M6의 V5 변환(부적합 장비 가방/overflow 회수·빈 슬롯 starter·후보 최대치 clamp)을 먼저 적용한다. M7이 이 규칙을 없애거나 과거 장비를 그대로 V5에서 허용하는 것은 아니다. 원본 Dictionary/파일은 바꾸지 않는다.

지도는 기존 타일을 쓰는 기능용 구성이다. 거점64×48, 외곽80×48이며 카메라·지도·외곽벽은 지역 BOUNDS를 따른다. 새 미술·음악을 제작하지 않았고 기존 노베라 씬 기반 배경음을 유지한다. 기본 제품 채택은 M6/V5 조건을 먼저 판단한 뒤 M7/V6를 판단한다.

들개·점액 정의/보상은 기존 리소스 그대로다. 들개는 개체별 pack ID로 분리한다. 같은 줄 최소 간격은224/224/192px이다. 표식은 물가(352,272), 균열(1120,272), 정찰(272,128). 물가 표식과 가장 가까운 점액은 약125px, 균열 표식은144px다. 스폰 기준의 간격이며 배회/유인된 적까지 안전함을 보장하지 않는다.

개체 해제 뒤30초, 플레이어가 스폰에서160px 밖이면 같은 슬롯에서 재스폰한다. 실제 개체는 기존 MonsterSpawner 아래에 있어 저장 금지·안내·드롭·경험치 경로에서 빠지지 않는다. 신규 슬롯 관리자는 위치/상태를 임의 복원하지 않는다.

상인은 기존 입구(216,440)와 거점(416,416)을 유지한다. UI와 확정 거래는 같은 월드의 활성·삭제 대기 아님 상인을 실제 위치/반경으로 조회한다. UI 선택 후 상인이 이동/비활성화되면 거래 확정에서도 다시 거부한다.

## 검증 구분

- GUT: 원본 버전 거부, 후보 이관, 예산·목표 순서·재보고, 지역 범위·실제 캡슐·상인·저장 안전. 목표 이벤트를 직접 발신하는 단위 검사는 실제 처치 증거가 아니다.
- `m7_candidate_probe.gd`: 1장/목표 완료와 위치를 fixture로 준비하고 실제 Session의 일곱 방향 교체·거래·V6 파일·별도 프로세스 복원을 검사한다. 게임 시계의 복원 후 경과는 동등 스냅샷에서 제외한다.
- `m7_combat_probe.gd`: 1장 완료/누적3820 EXP만 준비한 뒤 기존 액션 이동·공격·대화 버튼 조작기를 사용한다. 마우스 포인터가 움직인다. 2장 완료/HP/피해/좌표를 주입하지 않는다. 고정240초 제한에서 실패도 기록한다.
- 새 게임 전체 시간, 사람 길 찾기·미감·난이도, 네이티브 클릭, 기본 제품 채택은 별도 판정이다.

최종 결과(2026-09-30): 구현 대상 `8622db2`, GUT1130/1130·129 scripts·13,700 asserts, 기존 M6 경제4/4·M7 세션4/4·렌더·실행파일 smoke 통과. 입력 전투는 표식 보완 전 동일 코드 고정3회 모두 전체240초 시간 초과(0/3), 최종 코드 전투 재실행 없음. 실제 MQ02-01·02 완료와03 조사점 접근까지 확인했고04 완주/전직 UI는 미검증이다. API/fixture 검증으로 이를 대신 통과 처리하지 않는다. 내부 검토의 표식 줍기 독점은 조건부 선택으로 수정하고 회귀 테스트로 닫았다.
