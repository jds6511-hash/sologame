## 2. 경험치 곡선 시트 (Lv1~20 + 밴드)

### 2-1. 수식 (growth.md 5-1 그대로)

```
필요 경험치   REQ(L) = round(55 × L^2.5)     (L → L+1, 유효 범위 L = 1..99)
몬스터 경험치 EXP(L) = round(5 × L^1.5)      (동렙 일반 몬스터)
정예 배율 ×6 / 보스 배율 ×40                  (HP·골드 배율과 동일)
환산 처치 수 = REQ(L) / EXP(L) = 11 × L       (레벨당 동렙 몹 처치 수, 정비례)
```

- `REQ(L)`은 **L=1..99**에만 쓴다(Lv100은 만렙, 다음 레벨 없음). `REQ(100)`은 곡선 참고값일 뿐 레벨업에 사용하지 않는다.
- 반올림 안전성: `L^2.5`·`L^1.5`는 정수 L에서 소수부가 정확히 `.5`가 되는 경우가 없어(무리수), GDScript `round()`(half-away)와 원표 산출(Python `round()`, half-even)이 **전 구간 일치**한다(재현 확인). 따라서 `REQ(L)=round(55*pow(L,2.5))`를 GDScript로 그대로 구현하면 아래 표와 정확히 같다.

## 3. 레벨업 트리거 규칙 (B-1)

### 3-1. 경험치 획득 → 누적

- 플레이어 상태: `current_level: int`, `current_exp: int`(현재 레벨 내 누적치, 0 ≤ current_exp < REQ(current_level)).
- **경험치는 정수**로 관리한다(REQ·EXP 모두 `round()` 결과 정수). float 누적 불필요.
- 몹 처치 시 획득량:

```
gain = round( EXP_base × mult_grade × mult_leveldiff × mult_night )
  EXP_base     : 동렙 몹 EXP(4장 몬스터 스펙이 종별로 지정, 곡선 기준 = round(5×MobLevel^1.5))
  mult_grade   : 일반 1.0 / 정예 6.0 / 보스 40.0
  mult_leveldiff : 4장 레벨 차 보정 배율 (몹레벨 − 플레이어레벨 기준)
  mult_night   : 야간 1.20 / 주간 1.00 (보스는 야간 배율 제외 — combat.md 2-3)
```

- **구현 규약**: 반올림은 **최종 1회만**(`round(모든 배율 곱)`). 중간 단계마다 반올림하면 누적 오차가 생긴다. 정수 0 방지: `gain = max(1, round(...))` (레벨 차 10%로 눌려도 최소 1 보장 — 완만 하향 취지, 4장).
- 퀘스트 경험치는 별도 경로로 `add_exp(amount)`에 직접 투입(레벨 차·배율 미적용). growth.md 5-3의 "퀘스트 45%"는 이 경로. (퀘스트는 M3 범위 밖이나 인터페이스는 열어 둔다.)

### 3-2. 레벨업 판정 (다중 레벨업 지원)

```
func add_exp(amount: int) -> void:
    current_exp += amount
    while current_level < MAX_LEVEL and current_exp >= REQ(current_level):
        current_exp -= REQ(current_level)   # 초과분 이월
        current_level += 1
        _on_level_up(current_level)         # 스탯 재계산 + 스킬 포인트 +1
    if current_level >= MAX_LEVEL:
        current_exp = 0                      # 만렙: 초과 EXP 폐기, 바 만충 표시
```

- **초과 EXP 이월**: 레벨업 시 `current_exp -= REQ(이전 레벨)` 하고 나머지를 다음 레벨로 이월. `while` 루프로 한 번의 획득이 여러 레벨을 올릴 수 있다(초반 대량 퀘스트 보상 대응).
- **만렙(100) 처리**: 더 이상 레벨업 없음, `current_exp = 0`으로 고정해 경험치 바 만충 표시(초과분 폐기). ※ growth.md에 만렙 초과 EXP 규정 없음 → 폐기안 채택(8-3 플래그).
- **스탯 재계산 시점**: `_on_level_up`에서 `(current_level, job)` 순수 함수로 `CombatantStats`를 통째로 다시 채운다(5장). 현재 HP/MP 비율 유지 정책은 아래.
  - 최대 HP/MP 증가분 처리 권장: **레벨업 시 증가한 최대치만큼 현재값도 가산**(`current_hp += ΔmaxHP`)해, 전투 중 레벨업이 "즉시 약간 회복"으로 체감되게 한다(성장 보상감). 전체 회복은 아님. — 구현 규약(밸런스 무영향, 연출 목적).

### 3-3. 전직 임계(Lv10/40/80) 교차 처리

- 스탯을 `(레벨, 직업)` 순수 함수로 재계산하므로 **다중 레벨업이 Lv10을 건너뛰어도 스탯 정합은 자동**이다(전직 완료 후 함수의 job 인자만 바뀌면 소급 반영).
- 전직 UI 트리거 타이밍(레벨업 루프를 Lv10에서 일시정지할지, 계속 올리고 나중에 직업 선택 시 소급할지)은 **B-5(전직 처리)와 협의**한다. 설계 권장: 루프는 멈추지 않되 Lv10 도달 시 "전직 가능" 플래그를 세우고, 직업 미선택 동안은 모험가 배분으로 계산 → 전직 완료 순간 재계산. (8-2 플래그)

## 4. 레벨 차 경험치 보정 (growth.md 5-4)

`d = 몬스터 레벨 − 플레이어 레벨`

| d 범위 | +5 이상 | +4 ~ −4 | −5 | −6 | −7 | −8 | −9 | −10 이하 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 경험치 배율 | 1.20 | 1.00 | 0.85 | 0.70 | 0.55 | 0.40 | 0.25 | 0.10 |

- 구현: `d`를 clamp해 룩업. `d >= 5 → 1.20`; `-4 <= d <= 4 → 1.00`; `d = -5..-9 → {0.85,0.70,0.55,0.40,0.25}`; `d <= -10 → 0.10`.
- 스텝 구조: 상향은 +5에서 1.20 상한으로 한 번에, 하향은 −5부터 레벨당 −0.15씩(−9까지), −10 이하는 0.10 바닥.
- **경제 정합**: `economy-foundation.md` 5-4가 "이 표를 골드에도 동일 적용"으로 확정 → EXP와 골드가 동일 레벨 차 배율을 공유한다. **전제 불일치 없음**(economy 머리말 확인 완료). 본 배율표를 공용 데이터(`LevelDiffCurve`)로 두고 EXP·골드 계산이 함께 참조하도록 구현하면 이중 관리가 없다.

## 5. 스탯 자동 성장 — 순수 함수 정의 (B-2)

### 5-1. 1차 스탯 (레벨, 직업 → 힘/민첩/지력/체력)

```
stat_x(level, job) = 8.0
                   + min(level - 1, 9) × 1.5                 # 모험가 구간(1~10 균등)
                   + max(level - 10, 0) × job.growth_x        # 직업 구간(11~)
```

- `job.growth_x`: growth.md 2-1 배분표(합 6.0). 모험가는 4스탯 모두 1.5. 전사 힘2.5/민첩1.0/지력0.5/체력2.0. 궁수 힘1.0/민첩2.6/지력0.9/체력1.5. (전 직업표는 growth.md 2-1.)
- 초기값 8/8/8/8(Lv1). 함수는 idempotent — 세이브에 스탯을 저장할 필요 없이 `(level, job)`만 저장하면 복원 가능.

### 5-2. 파생 스탯 (growth.md 1-2 — 공식 그대로)

| 파생 | 공식 | 스탯 기여분(progression 계산) | 장비 기여분(item system) |
|---|---|---|---|
| 최대 HP | `50 + 체력×10 + 레벨×5` | 전부 progression | — |
| 최대 MP | `30 + 지력×5 + 레벨×2` | 전부 progression | — |
| 공격력 | `무기 공격력 + 주스탯×2` | `주스탯×2` | 장착 무기 `attack_power` |
| 방어력 | `방어구 방어 합 + 체력×1` | `체력×1` | 장착 방어구 합 |
| 치명타% | `min(5 + 민첩×0.05, 40)` | 전부 progression | (장신구 옵션 가산 가능) |

- **책임 분리**: progression은 "스탯 기여분"만 계산해 `CombatantStats`에 넣고, 무기/방어구 기여는 장비 시스템(IT, M3 범위 밖이나 기존 `.tres` 장비 존재)이 더한다. 공격력/방어력 최종값 = progression 기여 + 장비 기여.
  - **[배선 확정, 2026-07-27]** 이 책임 분리의 M3 실제 배선(gear_* 처리·InventoryComponent 배선 여부·Post-M3 이관)은 B-2 이중 계산 충돌 해소로 **`m3-gear-growth-wiring.md`에서 확정**됐다. 요지: M3에선 성장 계층이 B급 기준선을 계속 공급하고 InventoryComponent를 공유 CombatantStats에서 분리(gear_* 유지), 완전 분리(gear_*→0 + 인벤토리 장비 공급)는 Post-M3. 검산표(2-3·growth.md 2-2)는 "동렙 B급 장비 착용" 상태임이 확정(순수 성장 아님).
- 2-3장 검산표는 "동렙 B급 장비 장착" 상태의 합산 결과다. **B-2 GUT는 스탯 기여분**(주스탯×2, 체력×1, HP/MP/치명타 전체)을 검증하고, 장비까지 합친 최종값은 특정 테스트 장비(`warrior_lv1_combatant_stats.tres` 등)로 확인.
- 주스탯 결정: `job.main_stat`(전사=힘, 궁수=민첩). growth.md 1-1 "공격 기여 스탯은 무기 계열이 결정 = 직업이 결정".
- 치명타 상한 40%·치명 배율 150%는 `combat.md` 6장, 기존 `DamageCalculator`/`DamageFormulaData`가 이미 보유 — 재구현 불필요, 민첩 값만 갱신되면 됨.

### 5-3. 순수 함수 채택 근거

- growth.md 2-1: "스탯 = 초기 + 모험가 9레벨분 + 직업 (L−10)레벨분 → 재서임 시에도 소급 계산이 단순." 이 문장이 곧 5-1 함수다.
- 누적 가산 방식 대비 이점: ① 부동소수 오차 없음(직접 계산) ② 세이브에 `level`·`job`만 저장 ③ 다중 레벨업·전직 소급이 자동 ④ GUT에서 임의 레벨을 단발 검증 가능.

## 6. 스킬 포인트 경제 (B-3, growth.md 6장)

### 6-1. 포인트 지급

| 원천 | 지급 | 누적(만렙) |
|---|---|---|
| 레벨업 | 레벨당 +1 (Lv2~100) | 99 |
| 전직 보너스 | 전직 1회당 +2 (Lv10/40/80, 3회) | +6 |
| **합계** | — | **105** |

- 순수 함수: `earned_points(level, transitions_done) = (level - 1) + 2 × transitions_done`.
- M3 구간(Lv1~20, 1차 전직 1회): 예) Lv15 전직 완료 시 = 14 + 2 = **16 포인트**.
- `available_points = earned_points − spent_points`. `spent_points`는 스킬별 강화에 쓴 합.

### 6-2. 스킬 강화 비용·계수

| 스킬 종류 | 레벨 범위 | 각 단계 비용 | 풀업 총비용 | 강화당 계수 |
|---|---|---|---|---|
| 일반 스킬 | 1~5 | Lv2:1, Lv3:1, Lv4:2, Lv5:4 | 8 | +8%/레벨 |
| 궁극기 | 1~3 | Lv2:3, Lv3:3 | 6 | +8%/레벨 |

- 습득은 전직 시 자동(스킬 레벨 1). 포인트는 **강화(레벨 업)에만** 사용.
- 계수 적용: `effective_coefficient = base_coefficient × (1 + 0.08 × (skill_level − 1))`.
  - 예: 강타 base 1.3(m2-warrior-skills), Lv3 → 1.3 × (1 + 0.08×2) = 1.3 × 1.16 = 1.508.
  - `base_coefficient`는 스킬 리소스(`WarriorSkillData.damage_coefficient` 등)의 기존 필드값 = "스킬 레벨 1" 기준값이다. 런타임에 스킬 레벨을 곱해 최종 계수를 산출(원본 리소스 값은 불변).
  - 차지 강타(CHARGE)는 `charge_min/max_coefficient` 두 값 모두에 동일 배율 적용.
  - 버프·힐 스킬(계수 없음)은 효과 수치(회복%·버프%·지속)에 `×(1+0.08×(lv-1))`를 적용 — 계수와 동일 상승률로 통일(구현 규약).
- **총 105 < 풀업 118**: 만렙에도 전 스킬 풀업 불가 = 빌드 선택(growth.md 6장). M3 구간에선 포인트가 넉넉하므로 이 제약은 후반 밸런스 사안 — M3 구현은 비용/계수 규칙만 정확히.

### 6-3. 스킬 상태 저장

- 스킬별 현재 레벨을 `Dictionary { skill_id: int(1~max) }`로 관리. `available_points` 검사 후 차감·레벨 증가.
- 초기화(리스펙)는 상시 유료(`jobs.md` 7장) — M3 범위 밖, 인터페이스만 열어 둠.

- HUD: `hud.gd`/`player_status_panel.gd`에 `set_level_and_job(level, job)` setter가 이미 존재(M2 표시 stub) → B-4에서 실제 값 연결. 경험치 바는 `(current_exp, REQ(current_level))`을 넘김.

## 8. 확인 필요 / 구현 규약 플래그

### 8-1. [확인 필요·경미] 표시 반올림 방식

- growth.md 2-2 검산표는 **half-to-even(Python `round`)**으로 산출됨(예: Lv1 방어력 14.5 → 표시 14, Lv40 힘 96.5 → 96). GDScript `round()`는 **half-away**라 같은 값이 15/97로 표시됨.
- **밸런스 영향 없음**: 내부는 float 유지(14.5)이고 데미지 공식은 float를 그대로 쓴다(`DamageCalculator`). 오직 HUD 숫자 표기만 다르다.
- 조치: 내부 float 유지 원칙 확정. HUD 표기 반올림 방식은 구현 시 하나로 통일하면 되며(권장: GDScript 기본 `round`=half-away, 코드베이스 일관), 이 경우 2-3장 괄호 표시값과 최대 1 차이날 수 있음을 문서에 남김. **디렉터 결정 불요**(표기 취향 문제). 기존 `warrior_lv1_combatant_stats.tres`의 `defense=14.0`은 progression 전환 시 float 14.5로 대체됨을 명시.

### 8-2. [B-5 협의] 전직 임계 다중 레벨업 처리

- 3-3장: 다중 레벨업이 Lv10을 건너뛸 때 전직 UI 트리거/일시정지 정책은 B-5(전직 처리) 소관. 본 문서 권장안(루프 계속 + 전직 가능 플래그 + 선택 시 소급 재계산)을 B-5에서 확정.

### 8-3. [구현 규약·확정] growth.md 미규정 항목

본 문서에서 systems-designer 권한으로 확정한 구현 규약(밸런스 무영향 또는 취지 부합):
1. 만렙 초과 EXP = 폐기, 경험치 바 만충 표시(3-2).
2. 획득 EXP 반올림 = 모든 배율 곱 후 **최종 1회** `round`, `max(1, …)` 하한(3-1).
3. 레벨업 시 늘어난 최대 HP/MP만큼 현재값 가산(전체 회복 아님, 3-2) — 성장 체감 연출.
4. 버프·힐 스킬의 스킬 레벨 상승 효과 = 계수와 동일 `+8%/레벨`(6-2).

이 4건이 디렉터 방향성을 바꾸는 사안이 아니라고 판단해 확정 처리했다. 반대 의견 시 조정 가능.

### 8-4. [정합 확인 완료] 경제 교차

- 몹 EXP 공식(`5×L^1.5`)·정예/보스 배율(×6/×40)·레벨 차 배율표가 `economy-foundation.md` 골드 설계와 **동일 전제 공유**(economy 머리말 "전제 불일치 없음", 1장·5-4). 레벨 차 배율은 EXP·골드 공용 리소스(7-2) 권장. **충돌 없음.**
