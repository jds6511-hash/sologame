## 1. 결정이 필요한 이유

전투 방식은 직업 스킬 설계, 몬스터 행동 패턴, 맵 구조, UI, 조작 체계, 밸런스 공식 등 **거의 모든 후속 기획의 전제**입니다. 이 결정 없이는 직업 10개 스킬 목록도, 몬스터 도감 수치도 확정할 수 없습니다.

## 2. A안: 실시간 액션 전투

### 2-1. 핵심 루프 (플레이어가 실제로 하는 행동)

필드에서 몬스터와 심리스(끊김 없이) 전투. 별도 전투 화면 전환 없음.

```
이동으로 거리 조절 → 기본 공격(마우스) → 스킬 쿨다운 확인 →
몬스터 공격 모션 보고 회피(대시) → 스킬 콤보 → 처치 → 루팅
```

- 초 단위 판단: 위치 선정, 회피 타이밍, 스킬 순서.
- 잡몹 1마리 처치 목표 시간: 3~8초. 보스: 2~5분 (패턴 학습형).
- 다수 몬스터 동시 교전이 기본 (2~5마리 무리).

### 2-2. 스킬 사용 방식

- **쿨다운 + 자원(MP) 이중 제한.** 슬롯 6~8개 (키보드 1~4, Q, E, R + 궁극기).
- 스킬 유형: 즉발 / 차징(홀드) / 설치(장판) / 이동기(대시·돌진) / 버프·힐.
- 회피(스페이스 대시)는 전 직업 공통, 무적 프레임 0.2~0.3초.
- 캐스팅 스킬은 이동 시 취소 → "서서 쏘느냐, 움직여 피하느냐"가 핵심 긴장.

### 2-3. 직업 10개 · 3차 전직과의 궁합

- 직업 차이가 **조작감 차이**로 직결됨: 근접(짧은 리치·높은 기동), 원거리(카이팅), 마법(캐스팅 관리), 소환/보조(펫·소환수 지휘) 등으로 손맛이 뚜렷하게 갈림.
- 전직은 "새 스킬 + 기존 스킬 강화 + 신규 메커니즘(예: 2차에서 콤보 게이지 추가)"으로 표현 가능 → 전직 체감이 큼.
- **리스크**: 10개 직업 × 3차 전직의 스킬을 전부 "액션으로 재미있게" 만들려면 직업당 애니메이션·이펙트·히트박스 작업량이 큼. 히든 직업 2개 포함 시 액션 개발 비용이 직업 수에 거의 선형으로 증가.

### 2-4. 펫 전투 참여 방식

- 펫은 **자동 전투 동반자(AI)**: 플레이어를 따라다니며 자동 타겟팅으로 보조 공격/버프/아이템 줍기.
- 플레이어가 직접 조작하지 않음 (조작 부담 한계). 명령은 "공격 우선/대기/귀환" 3단계 정도.
- 펫 AI(추적, 타겟 선정, 충돌 회피)가 별도 구현 비용.

### 2-5. 조작 (키보드+마우스)

| 입력 | 기능 |
|---|---|
| WASD | 이동 |
| 마우스 좌클릭 | 기본 공격 (마우스 방향 조준) |
| 마우스 우클릭 | 보조 공격 / 가드 (직업별) |
| 1~4, Q, E | 스킬 |
| R | 궁극기 |
| Space | 회피(대시) |
| Tab / F | 타겟 고정 / 상호작용 |

- 조준·회피·스킬을 동시에 요구 → 조작 숙련도가 난이도에 직접 반영. 액션이 서툰 플레이어에게 진입 장벽.

### 2-6. Godot 구현 난이도와 리스크

- 난이도: **높음.**
- 필요 요소: 히트박스/허트박스(Area2D) 프레임 단위 관리, 몬스터 종별 AI 상태머신(추적/공격/경직/사망), 넉백·경직·무적 프레임, 애니메이션-판정 동기화, 다수 유닛 충돌 처리.
- **최대 리스크는 코드가 아니라 "손맛"**: 타격감(히트스톱, 화면 흔들림, 이펙트, 사운드)이 없으면 액션은 밋밋해짐 → vfx/audio/애니메이션 품질 의존도가 매우 높음. 2D 액션의 재미는 튜닝 반복(수십 회 플레이테스트)에서 나오며, 이 반복 비용이 M2 일정의 주요 변수.
- 몬스터 도감을 채울 수십 종의 몬스터마다 **개별 행동 패턴**을 만들어야 도감 수집이 의미 있어짐 → 몬스터당 비용 높음.

## 3. B안: 턴제 전투

### 3-1. 핵심 루프 (플레이어가 실제로 하는 행동)

필드에서 몬스터 심볼과 접촉하면 전투 화면으로 전환 (심볼 인카운터, 랜덤 인카운터 아님).

```
전투 개시 → 턴 순서 확인(속도 스탯 기반) → 내 턴: 공격/스킬/아이템/방어/도주 선택 →
적 행동 관전 → 약점 속성·상태이상·자원 관리로 최적 수 계산 → 승리 → 결과 화면(경험치/드랍)
```

- 판단 단위가 "턴": 반사신경 대신 **수읽기와 자원 관리**가 실력.
- 잡몹 전투 1회 목표 시간: 20~40초. 보스: 5~10분 (기믹 페이즈형).
- 편성 개념 도입 가능: 플레이어 + 펫(+ 추후 동료 NPC)의 소규모 파티 턴제.

### 3-2. 스킬 사용 방식

- **MP + 일부 스킬 턴 쿨다운.** 메뉴에서 선택 → 대상 지정 → 발동.
- 스킬 유형: 단일기/전체기/속성 공격(약점 시스템)/상태이상(중독·기절·화상)/버프·디버프/힐.
- 깊이는 **속성 상성 + 상태이상 + 턴 순서 조작**(속도 버프로 턴 앞당기기)에서 나옴.
- 스킬 수가 많아도 메뉴에 추가하면 되므로, 직업당 스킬 수 확장이 저렴함.

### 3-3. 직업 10개 · 3차 전직과의 궁합

- 직업 차이가 **역할과 수싸움 스타일 차이**로 표현됨: 탱커(도발·피해 감소), 딜러(속성/치명타), 힐러·버퍼, 상태이상 특화, 소환 특화 등. 싱글플레이지만 펫·동료와의 편성 시너지로 역할군이 성립.
- 전직은 스킬 트리 확장 + 신규 자원(예: 3차에서 오버드라이브 게이지)으로 표현 → 수치·데이터 중심이라 **10개 직업 확장 비용이 낮음**. 히든 직업도 스킬 세트 교체로 구현 가능.
- **리스크**: 애니메이션이 단순하면 직업 간 "체감" 차이가 스탯 창 차이로만 느껴질 수 있음 → 스킬 연출 최소 품질은 필요.

### 3-4. 펫 전투 참여 방식

- 펫이 **파티원 슬롯**을 차지하는 정식 전투원: 자기 턴을 가지며 플레이어가 직접 명령(또는 자동 모드).
- 펫 육성·수집(도감)이 전투력과 직결 → 수집 콘텐츠와 시너지가 가장 큰 구조.
- 구현은 "플레이어와 같은 전투 유닛 클래스 재사용"이라 추가 비용 낮음.

### 3-5. 조작 (키보드+마우스)

| 입력 | 기능 |
|---|---|
| WASD / 화살표 | 필드 이동, 메뉴 커서 |
| 마우스 좌클릭 / Enter | 명령 선택·대상 지정 |
| ESC / 우클릭 | 뒤로 |
| 단축키 1~8 | 자주 쓰는 스킬 바로 선택 (숙련자용) |
| Space | 메시지/연출 스킵, 전투 배속(2x) 토글 |

- 반사신경 불요 → 진입 장벽 낮음, 장시간 플레이에 피로 적음.

### 3-6. Godot 구현 난이도와 리스크

- 난이도: **중간(낮은 편).**
- 필요 요소: 전투 상태머신(턴 큐), 명령 UI, 데미지 공식, 전투 화면 전환. 모두 데이터 주도(리소스/JSON) 설계가 쉬워 **밸런스 수치를 코드 수정 없이 조정 가능** — 전투 밸런스 최종 책임자(본인) 입장에서 튜닝 파이프라인이 가장 안전함.
- 몬스터 추가 = 스탯 + 스킬 목록 + 스프라이트 1~2장 + AI 가중치 테이블 → **도감용 몬스터 다수 양산에 최적.**
- **최대 리스크는 반복 피로**: 수백 개 서브퀘스트를 도는 200시간 동안 전투 화면 전환과 턴 진행이 늘어지면 지루함이 액션보다 빨리 옴. **완화책 필수**: 전투 배속·연출 스킵, 약한 몬스터 즉시 처치(오버킬 판정 시 전투 화면 생략), 심볼 회피 가능, 자동 전투(잡몹 한정).

## 4. C안 (절충): 실시간 이동 + 쿨다운 스킬 (논타겟 최소화 하이브리드)

A안의 축소판. 심리스 필드 전투는 유지하되, 액션 요소를 줄여 구현 리스크를 낮춘 안.

- 조준은 **자동 타겟팅**(가장 가까운/지정 대상), 회피는 이동으로만 (무적 프레임 대시 없음).
- 기본 공격 자동 반복 + 쿨다운 스킬 4~6개 수동 사용. 몬스터 패턴은 "장판 예고 후 공격" 중심 → 히트박스 정밀도 요구가 낮음.
- 펫은 A안과 동일한 자동 동반자.
- 구현 난이도: A와 B의 중간. 타격감 요구치는 A보다 낮지만 여전히 존재.
- **주의**: "액션의 손맛"과 "턴제의 수읽기" 둘 다 옅어질 수 있음 — 어중간해질 위험이 이 안의 본질적 리스크. A안이 매력적이지만 구현 리스크가 걱정될 때의 보험으로만 추천.

## 5. 확정 조건과의 궁합 평가

| 확정 조건 | A안 실시간 액션 | B안 턴제 | C안 하이브리드 |
|---|---|---|---|
| **200시간 플레이** | 조작 재미로 버티려면 후반까지 새 패턴 공급 필요 → 콘텐츠 제작 부담 큼 | 빌드·편성·수집으로 시간을 채우기 좋음. 단 배속/스킵 없으면 피로 급증 | A에 준하나 요구치 낮음 |
| **수백 개 서브퀘스트 (반복 전투 피로)** | 잡몹전이 빠름(3~8초) → 반복 토벌 퀘스트에 유리 | 전투 진입/이탈 오버헤드 존재 → **배속·전투 생략 시스템이 사실상 필수 전제** | 잡몹전 빠름, A와 동급 |
| **명성·영지 시스템** | 직접 연관 낮음(중립). 영지 침공 방어전을 액션 웨이브전으로 만들면 시너지 | 중립. 영지 방어를 편성 중심 전투로 표현 가능 | 중립 |
| **도감 수집 (몬스터 다수)** | 몬스터당 행동 패턴 제작비 높음 → 종 수 확보가 병목 | **몬스터 양산 비용 최저** → 도감 볼륨 확보에 최적 | 중간 (패턴 단순화로 A보다 저렴) |
| **게임 내 시간 (30분=1일)** | 심리스라 시간 흐름과 자연 연동 (밤 몬스터 등) | 전투 중 시간 정지 규칙 필요(전투 화면 분리) — 규칙만 정하면 문제없음 | A와 동일 |
| **펫 시스템** | 자동 동반자 (존재감 보통) | **파티원으로 승격 → 펫 수집·육성의 가치 최대** | 자동 동반자 |
| **직업 10개·3차 전직** | 조작 체감 최고, 제작비 최고 | 확장 비용 최저, 체감은 연출 품질에 의존 | 중간 |

| 실패 시나리오 | 타격감 미달로 "밋밋한 액션" | 스킵 미비로 "지루한 노가다" | 둘 다 어중간 |

## 7. 추천안

**추천: B안 (턴제) — 단, "배속·전투 생략·자동 전투" 3종 피로 완화책을 확정 조건으로 묶어서.**

근거 (이 프로젝트의 확정 조건 기준):

1. **볼륨형 게임이다.** 200시간·서브퀘 수백 개·도감·펫·칭호 100개는 "콘텐츠 양산 단가"가 승부처. 턴제는 몬스터·직업·스킬 추가가 데이터 작업이라 소규모 개발로 이 볼륨을 실제로 채울 수 있는 유일한 안에 가깝다. 실시간 액션은 같은 볼륨을 채우려면 종당 패턴·애니메이션·타격감 비용이 수 배로 든다.
2. **수집 콘텐츠와의 시너지.** 펫이 파티원이 되는 순간 펫 수집=전투력이 되어 도감·펫 시스템이 코어 루프에 편입된다. 이는 A안에서는 얻기 어려운 구조적 이점.
3. **밸런스 책임 관점.** 전투 밸런스 수치의 최종 책임자로서, 턴제는 결과가 수식으로 재현 가능해 HP/데미지/성장 곡선을 문서와 자동 테스트(GUT)로 검증할 수 있다. 실시간은 히트박스·플레이어 숙련도가 변수라 수치 검증이 훨씬 어렵다.
4. **리스크 프로파일.** A안의 실패 요인(타격감)은 아트·사운드·튜닝 총력전이 필요하고 실패 시 회복이 어렵다. B안의 실패 요인(반복 피로)은 배속/전투 생략/자동 전투라는 **알려진 해법**이 있어 설계로 통제 가능하다.

단, 디렉터가 **"직접 조작하는 손맛"을 이 게임의 핵심 재미로 원한다면 그 가치는 턴제로 대체 불가**하므로 A안(일정·아트 투자 증가 수용) 또는 C안(손맛 일부 포기하고 리스크 절감)을 선택해야 한다. 이것은 재미의 방향에 대한 취향 결정이므로 수치로 정당화할 수 없다.

### 디렉터 결정 필요

- [ ] **전투 방식 선택: A / B / C** (게임 전체 방향 결정 사항)
- [ ] B안 선택 시: 피로 완화 3종(배속, 약몹 전투 생략, 잡몹 자동 전투)을 확정 사양으로 승인
- [ ] A/C안 선택 시: M2 일정에 타격감 튜닝 반복 기간 추가 승인 (producer와 일정 재협의)
