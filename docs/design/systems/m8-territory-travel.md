# M8 영지 운영·워프·남작 확장 계약

- 최종 수정: 2026-10-03 / Codex / 상태: `1207aeb` 설계 통과. 4장 통합 구현·검증 진행.
- 의존: [2막 계획](../act-two-plan.md), [영지 정본](reputation-territory.md), [100시간 예산](../100-hour-progression-budget.md).
- 범위: 4장과 함께 여울목 운영·도시 워프를 구현한다. 8장의 잿골 하사는 같은 모델 확장으로 준비하며 지금 완료 상태를 지급하지 않는다. 아래 세부 수치는 구현용 제안이며 기존 정본과 다른 부분은 명시한다.

## 1. 플레이 흐름

MQ-03-05 완료자는 여울목 관리인에게 F로 관리 화면을 연다. 요약에는 금고/상한, 하루 조수입·유지비·순수입, 시설 2칸, 다음 주문까지 남은 시간을 표시한다. 수령·건설·개발·납품은 현장에서만 가능하며 원격 영지 화면은 조회 전용이다. 창은 기존 UiPauseArbiter를 사용한다. 저장 안전 조건은 완화하지 않는다.

첫 시설은 시장 또는 공방을 고른다. 시장은 주문 주기 단축, 공방은 기존 경제 모델의 C급 장비·포션 상인을 설치한다. 다음 시설로 다른 하나를 지을 수 있다. 아직 없는 방벽 이벤트·펫·도감 효과는 비활성 메뉴로 늘어놓지 않는다. 여관과 나머지 시설은 해당 시스템 도입 묶음에서 확장한다. 투자를 하지 않아도 메인 의뢰·지역 이동은 진행할 수 있다.

## 2. 회계와 시간

현재 GameClock의 날짜는 디버그 시간 이동도 받으므로 금고 정산의 정본으로 쓰지 않는다. 세션의 **실제로 흐른 시뮬레이션 시간**을 정수 밀리초로 저장하고 하루=1,800,000ms로 정산한다. 일시정지·종료·디버그 날짜 변경·휴식 스킵에는 적립하지 않는다. 지역 교체로 타이머를 초기화하지 않는다. 소수 delta 잔여는 누적하여 매 프레임 버림 오차를 피한다.

부락 g(10)=63, 번영도 P(0~100)에서 일 순수입은 `floor(63×(3+P/50))`다. 조수입 `63×4×(1+P/200)`에서 유지비63을 뺀 결과를 마지막에 한 번 내린다. P0=189G, P35=233G, P100=315G. 유지비를 플레이어 가방 골드에서 따로 차감하지 않는다.

정산은 완료된 하루마다 그날 시작에 고정한 요율을 적용한다. 건설/번영 증가가 이미 경과한 시간을 소급 증액하지 않도록 다음 날부터 새 요율을 쓴다. 금고 상한은 현재 대표 요율의 7일치이며 상한에서 신규 유입만 멈춘다. 기존 금고를 잘라내지 않는다. 수령은 금고→보유 골드를 하나의 원자적 변경으로 처리하고 오버플로·사망·현장 이탈을 다시 검사한다.

## 3. 시설·개발·주문

초기 제안 비용은 부락 고정 단가63을 사용한다. 플레이어 레벨로 비용을 올리지 않는다.

| 항목 | 비용 | 번영 | 일수입 증가 상한 | 30일 회수 하한 |
|---|---:|---:|---:|---:|
| 시장 | 12,600 (200마리분) | +20 | 26G | 780G |
| 공방 | 18,900 (300마리분) | +15 | 19G | 570G |
| 개발 투자 1~5단계 | 단계당 25,200 (400마리분) | 없음 | 0G | 0G |

총 선택 소비 수용량은 157,500G=2,500마리분이다. **개발 투자는 번영·추가 수입을 만들지 않는 영지 외형 복구 단계**로 제안한다. 길/관리소/울타리/광장/기념물 정비를 눈에 보이게 반영하며 단계별 설명과 확인을 둔다. 효과 없는 수치 소비로 구현하지 않는다. 100h 구매력에서 매우 큰 선택 소비이므로 4장에 완성을 요구하지 않는다. 이 비용표는 최소 회수 기간 조건을 넘지만 재미·유용성이 검증된 것은 아니다.

주문은 기존 재료 ID의 확정 수량 납품부터 구현한다. 기본 7일, 시장 보유 시3.5일마다 한 칸을 갱신하며 시장 건설 시 기존 마감은 앞당기지 않고 다음 주문부터 적용한다. 발급 시 주문 ID·재료·수량·보상·마감을 고정한다. 시간 만료 뒤 미수행은 페널티 없이 교체하며 여러 미수행 주문을 쌓지 않는다. 보상은 부락 20g=1,260G와 번영+2(주문 기여 상한25, 전체100 이내), 공훈·EXP 없음. 재료 판매가 합이 보상을 넘는 주문을 발급하지 않는다. 납품은 가방 차감·골드·번영·완료 상태를 함께 확정한다. 연타·재접속 중복 수령은 실패해야 한다.

## 4. 워프와 귀환

왕국 도시 첫 방문 때 영구 개방한다. 4장 최초 연결은 노베라·그란시아·브란텔이며 후속 도시는 해당 장에서 등록한다. 오란세·실비엔·카른두름에는 게이트를 만들지 않는다. 일반 필드/던전은 목적지가 될 수 없다. 월드맵에서 개방 도시를 고르고 목적지·금액을 확인해 이동한다. 향사 영지에서는 같은 도시로 출발할 수 있다.

도시별 고정 권장 레벨과 간선 비용 표를 사용한다. 거리 등급은 인접25, 중거리40, 횡단60마리분이고 `ceil(등급×g(목적지 Lv)×인장 할인율)`을 최종 요금으로 한다. 현재 세 도시는 인접25/횡단60을 쓰며 목적지 기준 레벨은 노베라10·그란시아18·브란텔22다. 할인은 정본대로 공훈 구간500부터0.9, 5,500부터0.7, 7,500부터0이다. 영지 하사/신분 표시는 여전히 의식 완료에서 파생하며 할인과 구분한다. 비용표는 콘텐츠로 검증하며 소지금 부족·미개방·잠긴 지역이면 차감 없이 거부한다. 출발 위치를 읽어 거리 등급을 계산하고 임의 목적지 값을 받지 않는다.

무료 귀환 인장은 하사 영지로 이동하며 쿨다운은 실제 진행 시간900초다. 8장부터 소유 영지를 선택한다. 기존 지역 이동 정책대로 전투 대기 시간을 새로 요구하지 않는다. 사망·입력 잠금·다른 창 소유권은 확인하고 성공한 월드 교체에서만 골드/쿨다운을 확정한다. 실패하면 이전 상태 그대로다. 이전 월드 삭제 후 이전 노드를 호출하지 않는다.

기존 저장에 방문 기록이 없으면 현재 저장 지역 도시와, MQ-01-05 완료로 실제 방문이 입증된 노베라를 초기 개방한다. 다른 완료 의뢰로 모든 도시 방문을 추측하지 않는다. 여울목 소유자는 귀환을 사용할 수 있으므로 방문 목록이 비어도 갇히지 않는다. 유료 정기선은 7장 하프나 연결 때 같은 이동 트랜잭션을 쓰되 승선 현장·정액·칭호 할인 없음으로 별도 정의한다.

## 5. 남작 확장

8장 의식 완료 후 잿골을 대표 영지로 삼는다. 마을 g(50)=707, 일 순수입 `floor(707×(6+P/25))`, 최대7,070G이며 여울목 수입을 더하지 않는다. 여울목 미수령 금고는 잿골 대표 금고에 정확히 한 번 이전하고 여울목의 이후 정산을 중단한다. 이전 금고가 신규 상한을 넘더라도 보존하고 추가 적립만 멈춘다.

여울목 시설·개발 상태와 방문 접점은 유지한다. 잿골 시설 슬롯4·번영은 별도이며 여울목 시설 효과를 중복 가산하지 않는다. 대표 금고는 소유 영지 현장에서 수령할 수 있게 하고 화면에 회계 귀속을 표시한다. 하사 이전·이후 저장 복원에서 소유권/대표/이전 상태의 모순을 거부한다. 구체적인 마을 비용은8장 경제 장부에서 확정하며 지금 부락 비용을 자동 레벨 배율로 복제하지 않는다.

## 6. 저장·구현 경계

영지와 방문 상태의 구조 변경으로 **제품 V7**을 한 번 도입한다(옛 QA 후보 V7과 다른 형식). 제품 V6 검증기를 개정2 목록과 함께 동결하고 V1~V6 원본 검증→변환→현재 재검증 순서를 지킨다. 버전 표기만 바꿔 새 영지 필드를 구 검증에서 통과시키지 않는다. V7에서는 영지·여행 데이터를 먼저 별도 검증하고 나머지 구조/의뢰/지역 검증을 공통화한다.

`progress.territory`에는 소유 영지별 시설/개발/번영·대표 회계(금고/날짜 잔여/고정 요율)·주문을, 별도 여행 상태에는 개방 도시 ID·귀환 남은 시간을 둔다. 정확한 필드 제한·숫자 상한을 스키마에 선언한다. 미지 ID·중복 시설·슬롯 초과·미하사 소유·미래 개정·음수·비정수 카운터를 거부한다. 새 콘텐츠만 추가할 때는 content_revision만 올린다.

M8 순수 모델(정산/명령/검증), 세션 런타임, 현장 UI, 이동 트랜잭션을 책임별로 분리한다. 경제 구매는 기존 EconomyRuntime을 재사용하고 상인 추가는 유효한 현장 노드를 등록한다. 소유권과 방문 상태는 공유 카탈로그에 쓰지 않는다. 시간은 한 세션에 한 번만 진행하며 월드마다 런타임을 중복 설치하지 않는다.

## 7. 구현·검증 묶음

4장 진입 공훈800과 MQ-03-05 완료를 검사한다. 준비 부족 시 남은 3장 서브 위치를 안내하며 점수를 자동 지급하지 않는다. 영지 건설·워프 요금 지출은 의뢰 선행으로 요구하지 않는다. 첫 두 보고를 왕도 도착 전 배치해 이동/구매 현금을 먼저 확보한다. 무상 도보 경로는 항상 남긴다.

1. 이 새 시스템 계약을 한 번 검토한다. 4장 콘텐츠 표·지도·의뢰는 같은 제품 구조에서 준비하되 미결 시스템 계약을 확정 구현으로 간주하지 않는다.
2. 모델 경계 검사부터 만든다: 하루 전후, 상한, 시장 건설 직전 만료, 중복 납품, 건설 요율 다음 날 적용, 금고 이전1회, 비용/거리 재검사, 이동 실패 롤백.
3. 원본 V4/V5/V6 QA 복사본→V7 저장→별도 프로세스 복원, 미래 개정 거부와 실제 저장 해시 보존을 verify_all에 넣는다.
4. 관리→수령→건설→납품→도시 개방→유료 워프→무료 귀환→저장 복원을 API 세션으로 연결한다. 시간 경계 준비 fixture와 실제 입력 증거를 구분한다.
5. 4장 메인4·서브5·지역·신규 적·보고·저장까지 완성한 뒤 구현 통합 검토한다. 디렉터 재완주 요청은6장 끝에 모은다.
