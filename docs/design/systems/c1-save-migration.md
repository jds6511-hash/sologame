- 2026-09-27, 코드 대조 `a7606fa`. **설계 검토 단계, 구현/제품 적용 없음.**
- [저장 정본](save-load.md) · [C1 후보](../100-hour-progression-budget.md) · [공급 목표](../100-hour-exp-margin.md) · [검토 요청](../../qa/c1-save-migration-review-request.md).
- 적용 전제: C1 제품 곡선 승인 및 명시적 의뢰 보상/지급 순서 계약. 이 문서가 이를 승인하지 않는다.

## 1. 버전과 규칙 소유권

캐릭터 **V3=C1 규칙**을 제안한다. V1/V2는 현재 배포된 구 곡선(55×L^2.5, L<10만0.45), V3는 C1을 쓴다. 계정 버전1 유지. 기존 엄격 필드 검증을 보존하며 불필요한 필드는 추가하지 않는다. 이후 곡선 변경으로 V3의 의미를 덮어쓰지 않는다.

구/신 규칙은 저장 계층의 읽기 전용 정의로 보관한다. 구 규칙 검증에서 배포용 `level_curve.tres`를 다시 읽지 않는다.1~99 REQ와 만렙100·전직/포인트 규칙을 fixture에 고정하고 엔진과 전 구간 대조한다. 지원 범위는 V1/V2로 실제 배포된 규칙이며0.45 도입 전 파일을 같은 버전이라고 추정 변환하지 않는다.

## 2. 원본 검증→변환→새 규칙 재검증

1. `SaveFileStore._read/_version_error`: 봉투/본문 버전 일치·크기·checksum·지원 버전 검사 유지. 캐릭터 읽기 허용1/2/3, 미래 버전 차단 유지.
2. `CharacterSaveCodec.bind_store` callback→`SaveSchema.character_error`: **본문 버전별 규칙**으로 계정 연결·예약 필드·의뢰·플레이어 검증. 주/백업 모두 같은 경로다.
3. `player_error`는 선택된 REQ/max_level을 사용한다. 전직 관문/스킬은 이번에 바꾸지 않지만 `skills_error`까지 선택 규칙을 일관되게 전달한다. 레벨 기반 HP/MP 산식은 유지한다.
4. `prepare_loaded`: 원본 검증→`CharacterSaveMigrations.upgrade` 복사 변환→V3 재검증. 직접 codec 호출도 store 검증을 가정하지 않는다.

콘텐츠 오류는 전용 차단 코드로 유지한다. 구 EXP 오류를 비율 변환으로 정상화하지 않는다. 미완 거래·다른 계정·미지원 ID도 기존 보호를 유지한다.

## 3. 변환 정책

**레벨과 레벨 내 진행 비율을 보존**한다. 직업/스킬 포인트·실지출/HP·MP/장비/골드/위치/시계/의뢰 상태는 복사하며 레벨업·전직·보상 이벤트를 발생시키지 않는다.

- 레벨1~99: `new_exp = floor(old_exp × new_req / old_req)`. 양수64비트 정수 나눗셈으로 계산한다. 원본 `0 <= exp < old_req` 검증 후이므로 결과도 `new_exp < new_req`다.
- 만렙100은 유효 EXP0 유지. 구/신REQ가 같은1~10은 EXP도 정확히 보존한다.
- 정수화 오차는 신곡선1 EXP 미만이다. 대량 clamp/초기화와 구별해 명시한다. 누적 절대 EXP 보존으로 레벨·포인트를 바꾸는 정책은 채택하지 않는다.
- V1의 의뢰 예약 규칙을 검증한 뒤 기존 V1→V2 흐름과 연결해V3로 올린다. 입력 Dictionary 불변, V3 재입력은 멱등이다.
- 검증된 EXP×REQ가64비트 범위 내인지 확인한다. 규칙 누락/범위 오류는 실패로 반환하고 변환본을 쓰지 않는다.

## 4. 세션·파일 쓰기

현재 `save_session.gd`의 `migration_pending = source_version == 1`을 **원본 버전 < 현재 캐릭터 버전**으로 일반화한다. 원본 버전은 변환 전에 보관한다. V1/V2를 메모리상V3로 로드해도 자동 저장은 보류하고, 안전 조건을 만족한 명시적 수동 저장 성공 후에만 해제한다. 실패·취소·로드 후 종료는 해제하지 않는다.

`capture`와 store `VERSIONS.character`의 출력은3, `SUPPORTED.character`는1/2/3으로 맞춘다. **C1 런타임이 적용되지 않은 빌드에서V3를 쓰지 않는다.** 승인 전에는 후보 규칙·임시 폴더 fixture로만 검증한다. 제품은 런타임 곡선과 저장 규칙을 함께 전환한다.

읽기는 원본을 다시 쓰지 않는다. 첫 수동 저장은 기존 회전/보존 규칙을 따르며 실패 시 원본 보호를 확인한다. 구 빌드는V3 주 파일을 기존 미지원 버전 정책으로 차단하며 자동 다운그레이드는 제공하지 않는다. 계정→캐릭터 쓰기의 기존 비원자성은 이번에 해결됐다고 주장하지 않는다.

## 5. 의뢰 보상 경계

현재01~03 ID·목표·보상은 유지한다. V1/V2 변환 중 미래 S7/S11/S12 보상을 소급 지급하지 않는다. V3는 곡선 버전이지 미구현 보상을 받았다는 증거가 아니다. 앞으로 기존 의뢰를 바꿀 때는 active/ready/completed별 지급/콘텐츠 버전 계약을 별도로 정한다. 현재 counts/선행 검증 및 명성0·영지/스토리 빈 예약 필드는 유지한다.
