## 목표와 전달 단위

노베라 입구 상인에게 접근 → 전리품 판매 → 포션/직업에 맞는 장비 구매 → 기존 장비와 비교 →8슬롯 장착 → 여울목 전투에서 실제 효과 확인 → 왕복·저장·재실행 유지. 상점만 먼저 붙여 별도 리뷰를 요구하지 않고 UI·거래·전투 스탯·호환을 모두 연결해 한 번에 구현 검토를 받는다. 내부 커밋은 분리할 수 있다.

지원 직업은 현재 구현된 모험가·전사·궁수·검투사다. 미래10직업을 구현했다고 주장하지 않는다. 기존 노베라 입구를 거점으로 사용하며 도시 전체/새 의뢰/영지/강화·제작·내구도는 이 묶음에 추가하지 않는다. 기존 스킬 투자와 장비 강화는 다른 개념이며 스킬 투자 저장은 유지한다.

## 거래와 UI 계약

- 새 ShopCatalog는 stable item ID·buy_price·sell_price·판매 허용 여부를 명시한다. ItemData.price/acquisition 문자열에서 구매 가능 여부를 추정하지 않는다. 모든 목록ID는 기존 SaveContentRegistry와 대조하고 중복/음수/미등록 정의를 초기화 오류로 처리한다.
- 기존 price는 C급 정가, 이미10%인 판매가, B급 명장 정가, 미정/비매의4종이다. 같은 C급Lv1 소검120과 대검12도 의미가 다르고 B급 방어구는 판매가인 반면 상위 B급 무기는 명장 정가다. 초기 거래 목록을 작성할 때 acquisition의 명시적인 `판매가 N골드`와 sell_price를 교차 검사한다. 이는 데이터 이관용 검증이며 런타임 가격 파서가 아니다. 표현 미검출을 통과 근거로 삼지 않고 각 등록ID의 정본 출처·구매/판매 여부·가격을 별도 검산표로 확인한다. 가격 미확정품은 허용 플래그로 거래를 막고 금액에 음수 sentinel을 쓰지 않는다.
- 예: 소검120 구매/12 판매, 토끼 발 구매 불가/4 판매, 하급 포션300 구매/30 판매. price=-1인 장비는 경제 정본에서 가격을 확정해 목록에 넣기 전에는 거래 불가로 표시한다. 구매가보다 비싼 판매가 금지. 가격 계산은 정수이며 장비 정가10%는 내림, 명시 재료가는 재차10% 하지 않는다.
- 초기 상인은 C급 장비·포션의 등록 목록만 판매, 재료/잉여 장비를 매입한다. 명장 전용B급 판매를 일반 상점에 섞지 않는다. 재고는 무제한(상인 재고 저장 없음), 수량은 양의 정수와 보유 골드·수량·2^31−1 범위로 제한한다.
- 거래는 동기 함수 안에서 가격/소유 수량/가방 포화/골드 상한을 전부 검사하고 성공 때만 함께 변경한다. 실패는 양쪽 불변. 신호는 상태 확정 뒤 발신하며 거래 중 재진입을 잠근다. 거래 중 저장·이동을 거부한다. 프레임 중단/프로세스 종료 시 마지막 저장으로 돌아가며 거래마다 디스크 자동 기록을 약속하지 않는다.
- 장착 중 아이템은 직접 판매하지 않고 해제한 뒤 판매한다. 같은ID 여러 개와 반지2칸을 수량으로 다룬다. 판매/교체 확인 버튼은 클릭 시 선택ID·수량·가격을 다시 검증한다. 가방 포화 상태에서 교체품 유실 금지.
- WorldInteraction 우선순위와 UiPauseArbiter를 사용한다. 상점·저널·저장·대화가 pause를 서로 해제하지 못하게 한다. 거래 창에서는 이동/전투 입력을 억제하고 Esc로 복귀한다. 메뉴 최종 미술은 별도다.

## 전투 스탯과 장비 조건

성장 계산은 순수 base를 만들고 실제 장비 합성 함수가 최종값을 산출한다. UI 비교와 저장의 최대 HP/MP 검사도 같은 순수 합성 함수를 사용한다. 공유 CombatantStats의 현재값에 반복 가산하지 않는다. 이전 순수 base 위에 새 장비만 합성하며 레벨업·전직·장착·해제·로드 경로가 같은 계산을 탄다.

ItemData에 명시적인 weapon_family(NONE/SWORD/GREATSWORD/BOW)를 추가하고 현행 무기 전부에 채운다. 직업별 허용 계열은 공용 규칙의 명시 매핑으로 관리하며 item_id 문자열을 파싱하지 않는다. 일반 무기는 NONE/미지원 계열을 거부하고 비무기는 NONE만 허용한다. SPECIAL_WEAPON은 별도 지원 규칙 없이는 장착 대상으로 열지 않는다. 모든 지원 직업의 매핑 존재·모든 등록 무기의 계열 유효성을 초기화와 테스트에서 확인한다. level_limit은 기존 필드를 재사용한다. 실제 장착 제한 활성화는 V5 이관·새 스키마 적용과 동시에 수행하고 V1~V4 원본 검증에는 소급하지 않는다.

무기 공격/4부위 방어·목걸이 최대HP%·반지 치명타·신발 이동속도·공격속도 소비처를 각각 확인한다. 이미 별도 getter를 쓰는 치명타/속도를 CombatantStats에도 중복 가산하지 않는다. 전투 동작 중 장비 교체는 차단한다. 레벨업 회복은 새/구 최종 최대치의 증가량만, 장비 교체는 현재HP/MP를 새 최대치 이하로 clamp하며 반복 착탈로 회복하지 않는다.

새 캐릭터는 가상B급 제거와 동시에 명시 C급 시작 장비를 지급한다. 기존 캐릭터의 빈 슬롯 보정/장비 제한 이관은 아래 저장 결정과 함께 적용한다. 시작 C급 전환이 초반 피격 부담을 악화시키면 수치 변경을 숨기지 않고 기존B급 기준선·C급실착·무장해제의 피해/TTK를 비교한다.

## 후속 저장 버전과 이관안 — 구현 전 리뷰 핵심

후속 버전은 **V5 후보**다. 곡선은 C1 그대로, 공훈은 V4 완료 의뢰 합계 계약 그대로다. 장비 스탯/조건의 의미 변경을 V4에 소급하지 않는다.

1. 원본 버전의 직업/EXP/스킬/장비/vitals를 먼저 검증한다. 기존 registry.max_stats를 새 합성식으로 무조건 교체하면 정상 V1~V4가 거부되므로 구 모델을 고정해 남긴다.
2. 정상 구 저장을 복사해 EXP 기존 변환을 적용하고 장비를 정규화한다. 소유 아이템은 삭제/판매하지 않는다. 새 장착 제한에 안 맞는 기존 장비는 가방으로 옮긴다. 가방 포화 시 V5 `inventory.overflow`(이관 전용 보관, 사용·장착·판매 불가, 가방으로 회수만 가능)에 보존하는 안을 권고한다. 한 번 이관 시 최대8칸이며 새 게임/일반 플레이에서 추가 생성하지 않는다. 이 필드는 새 검증·UI·복원·재실행을 함께 구현해야 한다.
3. 가상B급 기준선의 제거를 무보상 하향으로 숨기지 않는다. **보유품 유지 + 빈 슬롯에 직업/레벨에 맞는 C급 기본품 보정**을 권고한다. 적용 대상·item ID 목록은 구현 전 데이터 표로 확정하고 manifest에 등록한다. 현행 리소스가 부족한 레벨/부위는 출시 차단 항목이지 임의 가까운 아이템으로 대체할 사유가 아니다. 보정은 버전 변환에서1회뿐이며 재로드/왕복으로 재지급하지 않는다.
4. 기존HP/MP는 새 최대치 이하로 clamp하고 회복은 하지 않는다. 새 스키마는 장비 합성 최대치·직업/레벨 조건·보관 수량을 검증한다. 정상 변환 후 수동 저장까지 원본 파일 보호/자동 저장 보류를 유지한다.
5. 후보V5 검증→변환→재검증→실제 파일·세션→제품 전환을 하나의 검토 묶음으로 실행한다. 리뷰 전에 V5 파일을 기본 출력하도록 먼저 배포하지 않는다.

이관C급 선택은 전투력 보존 보장이 아니다. Lv1/10/20/40/80/100 및 지원4직업에서 구 가상B/소유장비/보정C의 차이를 표로 제시하고, 범위를 벗어난 하향이나 장비 공급 공백이 있으면 제품 전환을 보류한다. 이 정책·overflow 도입은 아래 검토에서 먼저 확정해야 한다.

### 공급 공백과 지원 범위 — 리뷰 후 보완

현행 장비는 C16종/B16종이다. C급 액세서리가 없고 몸통은Lv1뿐이며 다리/머리/신발은Lv10, 활은Lv30, 대검은Lv40이 끝이다. 소검은Lv1뿐이다. 따라서 현재 데이터만으로 전 레벨 C급 보정을 완료할 수 없다.

**기존 전 레벨 지원 계약을 유지한다(리뷰 선택지 b).** 콘텐츠 진행량을 근거로 정상 고레벨 저장을 부재로 간주하거나 Lv10 초과를 거부하지 않는다. 반복 사냥과 이미 지원하는 고레벨 저장/검증이 있기 때문이다. migration_pending은 변환된 상태의 수동 저장 대기를 뜻하며, 미지원 스탯 모델을 플레이 가능한 상태로 만드는 장치로 사용하지 않는다. 공백이 남으면 V5 제품 전환 전체를 보류하고 기존 V4 런타임을 유지한다.

구현 묶음에 **C급 공급 데이터 보충**을 포함한다. 기존 경제 정본의 티어 규격으로 무기3계열·방어구4부위·반지·목걸이의 명시 리소스와 stable ID를 준비한다. 부족분의 ID/레벨 제한/수치/가격/출처 표를 먼저 확정하고 기존 ID의 의미를 바꾸지 않는다. 이관용 보정 목록과 상점 판매 목록은 분리하며 고레벨 보정품을 노베라 초반 상점에 모두 판매하지 않는다. 동렙 가상B를 가장 가까운 저레벨 C로 치환해도 안전하다고 가정하지 않는다.

완료 조건은 Lv1~100의 **각 유효 직업/레벨 조합**에서 정규화 후 빈8슬롯을 채울 수 있고 모든 지급품이 장착 조건을 만족하는 것이다. 전직 조건상 불가능한 조합은 지급 시험 대신 원본 거부 시험으로 확인한다. 티어 경계 전후도 검사하고 기존의6레벨 표는 전투력 비교 요약으로만 쓴다. 반지2개는 동일ID 수량2로 다룬다. 이 계약은 데이터·전투력 검증 완료 전 V5 배포 승인이나 C급 하향의 체감 승인을 뜻하지 않는다.

## 구현 계획과 완료 증거

1. **데이터·거래·장착 공통층**: 거래 목록/가격 검산, 가방·골드 원자 변경, 장착 제한, 스마트 드랍의4직업 무기 매핑. UI 단독으로 먼저 배포하지 않는다.
2. **스탯·영속성**: 순수 합성·Lv1초기화·레벨업/전직, 구버전 고정 검증과 V5 후보 변환, 장비/보관 복원, 새게임·전직 지급1회.
3. **실제 루프**: 노베라 상인·인벤토리/비교/8칸·장비 소비처·여울목 왕복, 구매→장착→실제 공격/피격→판매→저장→종료→재실행. 실패/취소/가방 포화/다른 슬롯 불변까지 검증하고 한 문서로 검토 요청.

자동 검사: 네 직업·반지2칸·교체/해제·레벨업/전직 재계산·HP 착탈 악용·수량/골드 상한·잘못된ID/가격·재진입·정상 구 저장 이관·위조V5 거부·변환 멱등·V5재로드·계정/다른 슬롯 원본 해시. 수동 판정: 구매 안내/비교 가독성·직업 제한 설명·전투 체감·초반 생존 부담. G4/G5는 이 작업의 자동 통과로 닫지 않는다.

100시간 골드 예산과 기존250시간 경제표는 혼용하지 않는다. 개별 가격은 정본 규격을 사용하지만 전체 소비/소득 균형은100시간 공급과 다시 계산한다. 이번 설계만으로 전체 경제 균형 또는 M6 완료를 주장하지 않는다.
