# 상점·가방·장비 분리와 공통 글꼴

- 날짜: 2026-09-30 / 담당: Codex
- 후속 요청(2026-09-30): 상점/가방 아이템 hover에 이름·종류·효과·착용 조건과 해당 슬롯 비교를 표시한다. 설명 열람은 선택·구매·장착을 실행하지 않는다. 포션 자체의 재사용 대기는 유지하며 메뉴 조작 대기 제거와 구분한다.
- 향후 상품 정책(디렉터 지시): 전직 이후 구매 목록은 해당 직업의 장비와 공용 방어구/장신구/포션/재료로 한정한다. 레벨 미달인 같은 직업 장비의 선구매는 허용하고, 이미 보유한 다른 직업 물품은 가방/판매에서 숨기지 않는다. 직업 변경 시 목록을 다시 계산한다. 이번에는 정책 기록이며 상품 필터 제품 적용은 후속이다. 아래 다른 직업 무기 구매 허용은 현행 구현의 설명이다.
- 장착/장비 후속 권고(선택 대기): 캐릭터 장비 슬롯과 가방을 한 화면에 놓고 더블클릭 장착, 슬롯 클릭으로 해당 부위 교체 후보를 표시한다. 반지는 선택한 슬롯을 명시해 임의 교체하지 않는다. 드래그 방식은 대안이며 아직 적용하지 않는다. 상점은 이 화면과 계속 분리한다.
- 변경 이력(디렉터 확정): ESC는 계속하기·저장/불러오기·설정·종료로 한정한다. B 가방, C 캐릭터/장비, K 스킬, J 의뢰, M 지도를 분리한다. 아래 ‘B와 ESC의 가방 통일’ 제안은 폐기했다. 진입 구조 승인과 제품 구현 완료는 별개다.
- 상태: 2026-09-30 디렉터 적용 지시에 따라 **상점·가방·장비는 M6 후보에, ESC 분리는 공통 메뉴에 구현했다**. 저장 V5의 기본 제품 채택은 별도다. 원래 설계 이력의 미구현 표현은 이 구현 상태가 대체한다.
- 변경 이력(구현): 세로 상품 목록·아이콘/종류 아이콘·6열 가방·고정 거래 영역·반지 비교/부위 교체·단일 구매/착용·판매 확인·거래 대기 분리·ESC/저장 복귀를 적용했다. 분류는 펼침 선택, 정렬은 기본순/역순 버튼이다. 기존 전용 아이콘이 없는 품목은 코드로 그린 종류 아이콘을 쓰며 새 원화로 주장하지 않는다. 가격/저장 형식은 불변이다. 설정의 음량/그래픽 세부 기능과 기본 V4 인벤토리 자리 구현은 이 M6 묶음에 포함하지 않는다.
- 의존: [경제 UI 구현](../../../godot/scripts/economy/economy_panel.gd), [거래 모델](../../../godot/scripts/economy/economy_candidate.gd), [현재 구현 검토](../../qa/m6-shop-usability-review-request.md).
- 변경 이력(후속): 실제 상점 캡처를 대조해 상품 목록·상세 비교·고정 거래 영역·구매/판매 확인 정책을 재설계했다. 아래 새 설계와 충돌하는 기존 상점 설명은 새 설계가 우선한다. 구현 완료 기록은 아니다.
- 장착·해제는 골드 비용이나 행동/재사용 대기를 요구하지 않는다. 저장 안전 판정과 분리하며 직업·레벨·소유·가방 공간, 사망·입력 잠금·거래 재진입 보호는 유지한다. 구매/판매/보관품 회수도 저장용 대기에서 분리했으며 거리·소유·공간·재진입 검증은 유지한다.
- 변경 이력: 디렉터의 화면 역할 분리·무료 한글 폰트 적용 지시를 반영한다. 이전 동시 배치안을 대체한다.

## 상점 재설계안

목표는 처음 연 사람이 상품의 용도·착용 가능 여부·거래 수량·실제 금액을 읽고 거래를 끝내는 것이다. 현재 캡처는 텍스트 카드 4열의 시각적 비중이 같고, 선택 탭과 구매 버튼이 비활성처럼 보여 구분이 약하다. 창 분리만으로 이 문제를 해결했다고 보지 않는다.

### 화면 구성

상인 앞 F로 열고 제목은 실제 상인 이름으로 표시한다. 상단 오른쪽에는 보유 골드와 닫기만 둔다. 뒤의 HUD는 어둡게 처리하고 입력을 차단한다. 상점에서 가방/장비 화면으로 이어지는 탭은 두지 않는다. 닫은 뒤 B로 가방을 연다.

```text
노베라 보급상                              내 골드 1,000 G   [닫기]
[ 구매 ] [ 판매 ]
[전체] [회복약] [무기] [방어구] [장신구]           [검색]
┌ 상품 목록 ─────────────────┬ 선택한 상품 ─────────────────┐
│ 아이콘  하급 회복 포션       │ 큰 아이콘  하급 회복 포션       │
│ HP 100 회복       300 G/개 │ HP 100 회복 · 보유 0개          │
│                           │ 사용: 창을 닫고 퀵슬롯 [5]       │
│ 아이콘  무기 이름           │                               │
│ 전사 · Lv10       단가     │ 장비 선택 시 이 자리에           │
│                           │ 현재 착용품 ↔ 상품 비교           │
│ 목록만 스크롤               ├───────────────────────────────┤
│                           │ 수량 [−] [ 2 ] [+] [최대]       │
│                           │ 합계 600 G · 구매 후 400 G       │
│                           │ [ 2개 구매 · 600 G ]            │
└───────────────────────────┴───────────────────────────────┘
```

실제 1280×720 화면 기준 창은 약 1120×600, 좌우 비율 55:45를 출발점으로 잡는다. 좌표 고정보다 컨테이너로 여백/최소 크기를 보장한다. 본문은 실제 표시 기준 18px 이상, 거래 버튼 높이는 44px 이상으로 시작해 게임 렌더에서 확인한다. 기존 1920×1080 논리 좌표를 쓰면 표시 배율을 환산한다. 목록과 긴 상세 설명만 스크롤하고 거래 버튼은 항상 보인다.

### 상품 목록과 비교

- 4열 텍스트 카드를 세로 상품 행으로 바꾼다. 각 행은 아이콘·이름·핵심 효과 또는 부위·단가를 보여준다. 아이콘이 아직 없으면 종류별 구분 아이콘과 이름을 사용하고, 완성 아이템 원화처럼 표시하지 않는다.
- 선택은 테두리와 배경, 키보드 포커스는 별도 윤곽으로 구분한다. 구매/판매의 활성 탭은 밝은 배경과 밑줄을 함께 사용한다. 색만으로 상태를 구분하지 않는다.
- 첫 진입에는 상품을 자동 선택하지 않고 ‘왼쪽에서 상품을 선택하세요’를 표시한다. 상품 변경 시 수량은 1로 초기화한다. 초기 목록은 회복약→현재 착용 가능한 장비→그 외 장비 순으로, 같은 묶음에서는 요구 레벨·이름순으로 고정한다. 능력치만으로 ‘추천/최고’라고 단정하지 않는다.
- 사용 불가능한 상품을 숨기지 않는다. ‘전사 전용’, ‘Lv10 필요’처럼 목록과 상세에 이유를 표시한다. **착용 불가와 구매 불가를 구분**해 미리 구매하는 것은 허용한다.
- 장비 상세는 이름/부위/등급/조건, 현재 착용품과 상품의 수치, 교체 예상 증감 순서다. 현재 직업으로 착용할 수 없으면 유효한 능력치 상승처럼 표시하지 않는다. 반지는 비교 기준 ‘반지 1/반지 2’를 선택하며 실제 교체는 하지 않는다.
- 내부 아이템 ID와 데이터용 숫자 접미사는 표시하지 않는다. 필요한 레벨은 이름 대신 ‘요구 Lv10’ 필드에 쓴다. 서로 다른 상품은 의미 있는 표시 이름 또는 등급/레벨 부제로 식별한다. 저장 ID는 보존한다.

### 구매·판매 흐름

구매: 상품 선택 → 수량 → **‘2개 구매 · 600 G’** 한 번으로 확정한다. 중간의 일반적인 ‘확정’ 단계를 없앤다. Enter는 입력창 편집 중 거래를 실행하지 않고 거래 버튼에 포커스가 있을 때만 동작한다. 수량은 직접 입력/±/최대, 기본 1이며 장비도 복수 구매 가능하다. 최대는 실제 골드·가방 합치기/공간·모델 상한으로 계산한다. 0개만 가능하면 숫자를 0으로 보여 주고 구매를 비활성화하며 이유를 함께 표시한다.

성공하면 ‘하급 회복 포션 2개를 가방에 넣었습니다 · −600 G’를 거래 영역 근처에 3초 표시한다. 보유 골드·보유 수량·가방 칸을 즉시 갱신하고 목록 위치/선택은 유지한다. 수량은 1로 되돌려 같은 묶음의 우발적 반복 구매를 줄인다. 더블클릭/키 반복은 한 확정으로만 처리하고 성공 후 버튼을 다시 누르기 전까지 재거래하지 않는다.

판매: 탭 제목 아래 ‘내가 가진 판매 가능한 물건’을 명시한다. 가방 소지품만 표시하고 착용품·판매 금지품은 제외한다. 수량과 받을 골드를 보여 주고 **‘2개 판매 · N G’**를 누르면 물건 이름/수량/금액이 적힌 작은 확인창을 연다. 버튼은 ‘취소’와 ‘2개 판매’이며 기본 포커스는 취소다. 전체 일괄 판매는 추가하지 않는다. 마지막 수량 판매로 행이 사라지면 선택을 비우며 다음 물건이 자동으로 판매 대상이 되지 않는다.

거래 시점에 실제 소유·골드·수량·가방 공간·상인 거리를 다시 검사하며 사본 검증→확정의 기존 단일 모델을 유지한다. 버튼 비활성만으로 검증을 대신하지 않는다. 오류는 거래 영역에 ‘120 G 부족합니다’, ‘새 물건을 넣을 가방 1칸이 필요합니다’처럼 원인을 표시한다. 기존 더미 안내문은 제거한다.

**거래도 저장 대기에서 분리했다.** 상인과 대화해 창을 연 뒤 대시/스킬/포션 재사용 대기 때문에 구매·판매가 거부되지 않게 한다. 사망·입력 잠금·거리·재진입·계정/데이터 보호는 유지한다. 창을 열 수 있는지와 일시정지 소유권은 기존 상호작용 규칙을 따른다. 저장 조건 변경을 뜻하지 않는다. 충전 중 거래와 원격 거래 거부를 회귀 검사한다.

### 구현 묶음과 완료 기준

상품 행/분류/비교, 구매 수량/단일 확정, 판매 확인, 거래 대기 분리, 실패/성공 안내를 한 기능 묶음으로 구현한다. 가격·드롭·세이브 버전·환경 아트는 범위에 넣지 않는다. 가방/장비의 개별 화면을 상점에 다시 합치지 않는다.

검증은 포션 복수 구매→가방 증가, 착용 불가 장비 선구매→가방에서 착용 거부, 반지 비교 대상 선택, 판매 취소/전량 판매, 골드 부족/가방 만석, 충전 중 거래, 사망/원격 거래 차단, 중복 입력, 저장 후 별도 프로세스 복원을 다룬다. 화면에서는 활성 탭·키보드 포커스·스크롤 중 고정 거래 버튼·1280×720 글자 잘림·버튼 전체 클릭 영역을 확인한다. 실행한 검증과 한계는 통합 검토서에 기록한다.

## 가방·장비 재설계안 — 후속 요청

- 변경 이력(2026-09-30): ESC 메뉴 가독성 피드백과 함께 가방/장비의 정보 배치·사용 동작·진입 경로를 설계했다. 이 절은 아래 기존 계약보다 우선하며 M6 후보에 구현했다.

### 진입과 공통 동작

**ESC에는 가방·캐릭터·스킬·의뢰·지도 탭을 두지 않는다.** 플레이 화면에서 B는 가방, C는 캐릭터/장비, K는 스킬, J는 의뢰, M은 지도를 바로 연다. 캐릭터 화면에는 ‘장비 관리’를 두고, 가방의 ‘장비 보기’도 같은 장비 화면으로 연결한다. 캐릭터는 성장/능력치 열람, 장비는 착용 변경을 담당한다. 별도 장비 단축키는 추가하지 않는다. 기존 I 인벤토리와 B 도감 배선은 이 구조로 교체하고, I는 가방의 보조키로 유지한다. 도감의 새 단축키/진입점은 후속 도감 구현에서 결정하며 B를 중복 사용하지 않는다.

### ESC — 게임 관리 전용

중앙의 간결한 세로 메뉴에 아래 네 버튼만 표시한다. 첫 포커스는 ‘계속하기’다. 뒤의 HUD·의뢰 추적·후보 안내는 가려지고 입력도 전달되지 않는다.

```text
        일시정지
       [계속하기]
    [저장 / 불러오기]
         [설정]
       [게임 종료]
```

- 계속하기 또는 ESC: 메뉴를 닫고 플레이로 복귀한다.
- 저장/불러오기: 기존 슬롯 화면으로 전환한다. 저장·불러오기·새 캐릭터 확인과 저장 안전 조건은 그대로 유지한다. F6 직접 진입도 유지한다. ESC에서 들어온 슬롯 화면을 닫으면 ESC 메뉴로, F6 직접 진입이면 플레이로 돌아간다.
- 설정: 별도 설정 화면으로 전환하며 뒤로/ESC로 일시정지 메뉴에 돌아온다. 아직 구현하지 않은 음량·그래픽 기능을 완료된 것처럼 표시하지 않는다.
- 게임 종료: 저장되지 않은 진행이 사라진다는 확인창을 띄운다. 기본 선택은 ‘취소’, 취소하면 ESC 메뉴를 유지한다. 자동 저장 성공 없이 저장됐다고 안내하지 않는다.
- 가방/스킬 등 다른 창에서 ESC를 누르면 그 창의 확인 취소 또는 닫기만 수행하고 같은 입력으로 일시정지 메뉴를 열지 않는다. 플레이로 복귀한 뒤 다시 ESC를 눌러야 일시정지 메뉴가 열린다.
- B/C/K/J/M 화면에서는 같은 단축키 재입력으로 닫고, 다른 단축키는 검색/수량 입력에 포커스가 없을 때 해당 화면으로 전환한다. 상점·대화·ESC와 그 하위 확인창에서는 다른 기능 단축키로 우회 전환하지 않는다. 먼저 닫거나 뒤로 간다.
- 화면 교체·뒤로 가기 동안 pause 소유권을 연속 유지한다. 사망 연출/입력 잠금 보호와 확인창 우선 입력 소비를 보존한다. 종료 버튼은 거래·장비 화면에 복제하지 않는다.

상점은 구매/판매만 담당하고 가방·장비에서 판매 버튼을 제공하지 않는다. 화면 전환 시 기존 창을 닫고 pause 소유권을 새 화면으로 넘기되 월드가 한 프레임 움직이지 않게 한다. 확인창이 없으면 ESC는 열린 화면을 닫고 플레이로 복귀한다. 장비의 ‘가방으로’는 선택과 스크롤을 보존해 돌아간다. ESC로 가방을 닫자마자 설정이 열리는 이중 입력은 금지한다.

### 가방 — 찾고, 확인하고, 장착하기

```text
가방                               12 / 30칸   1,000 G   [장비 보기] [닫기]
[전체] [장비] [회복약] [재료] [검색]                       [정렬]
┌ 6열 × 5행 아이템 칸 ────────────────┬ 선택한 물건 ───────────────────┐
│ 아이콘/짧은 이름/수량               │ 이름 · 부위 · 등급              │
│ 선택 테두리 · 빈 칸은 빈 배경       │ 용도 / 요구 레벨 / 직업          │
│                                   │ 현재 착용품과 차이               │
│                                   │ 불가 시 정확한 이유              │
│                                   │ [무기에 장착]                   │
└───────────────────────────────────┴────────────────────────────────┘
```

- 왼쪽은 보유 물건, 오른쪽은 선택 상세와 해당 물건의 실행 버튼만 둔다. 30칸은 현행 가방 제한이며 아이템 수량 합계가 아니다. 수량은 아이콘 오른쪽 아래, 이름은 칸 아래 1줄로 표시하고 상세에서 전체 이름을 읽는다. 아이콘만 보고 종류를 추측하게 하지 않는다.
- 필터/정렬은 표시 순서만 바꾸고 실제 가방 데이터를 재배열하지 않는다. 기본 정렬은 종류→요구 레벨→이름. 검색/필터에 가려진 선택은 해제하고, 빈 결과는 ‘일치하는 물건이 없습니다’와 필터 초기화를 보여준다.
- 장비는 상세의 ‘무기에 장착’ 등 구체적인 버튼 한 번으로 장착한다. 이미 착용한 물건은 가방 목록에 중복 표시하지 않는다. 현재 착용품은 정상 교환 규칙으로 가방에 돌아오며, 공간 부족이면 변화 없이 이유를 보여준다. 장비 종류별 직업/레벨 조건과 사망/잠금 보호는 유지한다. 골드나 재사용 대기 비용은 없다.
- 반지를 가방에서 장착하면 반지1/반지2의 현재 물건과 비교를 나란히 보여 주고 바꿀 칸을 명시 선택한다. 빈 칸이 있어도 다른 반지를 자동 해제하지 않는다.
- 회복약은 회복량·보유 수량·현재 퀵슬롯 [5] 사용 안내를 표시한다. 현행 입력/일시정지 계약을 우회하는 ‘즉시 사용’ 버튼은 이번에 추가하지 않는다. 재료는 용도만 보여 주며 의미 없는 사용/장착 버튼을 만들지 않는다.
- 넘친 보관품은 일반 가방 칸 밖의 ‘보관 대기 N건’ 펼침 영역에서 개별 회수한다. 가격/판매 기능과 섞지 않고 가방 공간 부족 이유를 표시한다. 정체불명 ‘overflow’ 문자열은 노출하지 않는다.
- 드래그, 더블클릭 장착, 일괄 버리기는 이번 범위에서 제외한다. 한 번 클릭은 선택만, 명시 버튼만 상태를 바꿔 오작동을 줄인다.

### 장비 — 현재 상태와 바꿀 물건을 함께 보기

```text
장비                         Lv10 전사                  [가방으로] [닫기]
┌ 현재 착용 ────────────────────────┬ 선택한 부위: 무기 ─────────────┐
│          [모자]                   │ 현재 무기 이름 / 주요 능력치     │
│ [무기]   캐릭터   [목걸이]         │ [해제하여 가방으로]              │
│          [갑옷]                   │ 교체 가능한 가방 무기 목록        │
│ [반지1]  [하의]   [반지2]          │ 후보 선택 → 실제 변경 후 비교      │
│          [신발]                   │ [이 무기로 교체]                 │
│ 공격력 / 방어력 / 최대HP / 최대MP  │                                 │
└─────────────────────────────────┴─────────────────────────────────┘
```

- 여덟 칸 모두 부위 이름을 항상 표시한다. 빈 칸도 ‘무기 없음’처럼 읽을 수 있어야 한다. 캐릭터 그림이 슬롯이나 글자를 덮지 않게 고정 영역 안에 둔다. 새 장비 원화 미공급 상태에서는 캐릭터 그림이 실제 착용 외형까지 바뀐다고 주장하지 않는다.
- 부위를 고르면 오른쪽에 현재 물건과 **같은 부위의 가방 후보만** 표시한다. 후보를 골라도 화면 전체를 바꾸지 않고 현재 물건/후보/실제 교체 예상치/교체 버튼을 한 자리에 유지한다. 후보가 없으면 ‘가방에 교체할 무기가 없습니다’를 표시한다.
- 비교는 기본 수치와 추가 옵션을 구분한다. 공격력·방어력만으로 무조건 더 좋다고 표시하지 않고, 증감은 숫자와 +/− 기호로 보여준다. 현재 직업/레벨에 맞지 않는 후보는 이유를 표시하고 교체를 막는다.
- 교체는 실제 모델 검증 후 한 번 확정한다. 이전 물건의 가방 회수, 두 반지의 독립성, 최대HP/MP 변경 시 현재치가 회복되지 않는 규칙을 유지한다. 갱신은 캐릭터 능력치 화면에도 반영한다.
- 성공 후 선택 부위를 유지하고 ‘무기를 교체했습니다’를 잠깐 표시한다. 해제/교체 실패 시 착용·가방·골드 어느 것도 바꾸지 않는다.

### 구현 시 확인할 기준

B/I 가방의 동일 화면·데이터, ESC의 기능 탭 제거, ESC→저장/설정→뒤로 복귀와 F6 직접 진입의 복귀 차이, 장비↔가방 이동 시 pause 유지/중복 창 없음, 물건 선택과 사용 구분, 반지 칸 선택, 빈 후보, 만석 교체와 해제, 회수 실패, 능력치 갱신, 쿨다운 중 착용, 사망/잠금 거부, 실제 저장/프로세스 복원을 한 묶음으로 확인한다. 상품/가방/장비 화면이 같은 공통 글자 크기·선택 표시·오류 위치를 사용하도록 한다. 상점 재설계와 함께 M6 후보에 적용했으며 기본 V4 제품 채택과 구분한다.

## 기존 가방·장비·폰트 계약

가방은 B로 열며 보유품 격자·분류/검색·수량·물건 설명을 제공한다. 장비를 선택하면 장착할 수 있다. 포션은 퀵슬롯 사용 안내를 제공하며 일시정지 중 즉시 사용 기능을 새로 만들지 않는다. 구매/판매 버튼과 상인 상품은 없다. ‘장비 보기’로 장비 화면을 연다.

장비 화면에는 캐릭터 주위 8슬롯과 실제 적용 공격력·방어력·최대 HP/MP를 표시한다. 슬롯 선택 시 해당 부위 가방 장비만 교체 후보로 보이며 현재 장비 해제와 후보 장착을 제공한다. 반지 두 칸은 독립 선택한다. 장착 조건·가방 공간·상태 확정은 기존 EconomyRuntime을 따른다. ‘가방으로’로 복귀한다. 상점에서 장비 관리로 우회하지 않는다.

공통: 창 전환은 pending을 취소하며 pause 소유권을 유지한다. ESC는 확인 취소 후 창 닫기다. 원격 거래·착용품 직접 판매·슬롯 혼동을 회귀 검사한다. 저장 형식·아이템 가격·전투 수치는 변경하지 않는다.

글꼴은 Pretendard v1.3.9 Regular(본문·HUD·이름표), SemiBold(제목)로 통일한다. SIL OFL 원문을 폰트와 함께 보관하고 출처·해시를 README에 기록한다. 전역 기본 글꼴도 지정해 명시 폰트가 없는 대화/확인창을 포함한다. 월드 이름표에는 선형 필터와 MSDF 글꼴을 사용해 낮은 해상도의 글자 확대를 피한다. 스프라이트/타일의 최근접 필터는 유지한다. 게임 전체 글꼴 변경 지시에 필요한 project.godot 변경은 gui/theme/custom_font 한 키로 한정하고 diff를 대조한다.
