# M7 첫 묶음 — 노베라 거점·외곽 의뢰·첫 전직 연결

- 작성: 2026-09-30 / Codex. 상태: **통합 설계 검토안, 제품 미구현**.
- 근거: [로드맵 §6](../DEVELOPMENT_ROADMAP.md), [Lv6→10 연결 A~D](../quests/early-leveling-route.md), [100시간 예산](../100-hour-progression-budget.md).
- 디렉터 지시: 다음 큰 기능 묶음 진행. 세부 상점/가방/장비 디자인은 보류한다. M6의 UI·경제 기능 검토 통과와 기본 제품 채택은 별개다.

## 1. 플레이 결과와 범위

여울목 MQ01~05 완료 → 기존 노베라 입구 → 조합 앞 거점 → 외곽의 길목/물가/균열 흔적 의뢰 → 조합 보고로 Lv10 → 기존 V 전직 화면 안내 → 왕복·저장·별도 프로세스 복원까지 연결한다. 새 게임부터 디버그 레벨 주입 없이 첫 전직에 도달하는 것이 기능 목표다. 기존 C급 경제 후보를 그대로 사용해 전리품 판매/포션 구매/장비 교체도 가능하게 한다.

첫 전달물은 지역2개·의뢰4개·NPC·다중 관문·목표 안내·호환 저장을 하나로 구현한 묶음이다. NPC 한 명이나 퀘스트 한 건마다 검토하지 않는다. 이는 **M7 전체 완료가 아니다**. 2장 후반 2개 메인, 서브, 폐허/던전과 3장 여울목 하사까지는 후속 콘텐츠이며 기존 M7 게이트를 축소하지 않는다. 영지 수입/통치(M8), 새 직업/새 몬스터, BGM, 완성 아트는 이번 범위 밖이다.

비교: 기존 노베라 입구를 도시로 확대하면 과거 저장 좌표의 지형 의미가 바뀐다. 기존 입구에 의뢰만 더하면 거점/사냥터의 역할 구분이 없다. **기존 입구 유지 + 별도 거점/필드**를 선택한다. 상세 미감 대신 기존 타일과 명확한 통행 구역으로 기능을 먼저 확인한다.

## 2. 지역·관문·접근 계약

아래 크기/좌표는 설계안이며 실제 캡슐 경로 검사 후 구현에서 확정한다. 타일은16px. 크기는 공통 규격이 아니며 역할과 동선에 따라 다르다.

| 지역 ID | 크기 | 역할/주요 위치 |
|---|---|---|
| `novera_gate` | 기존48×36,768×576 유지 | 기존 여울목 왕복·상인·도착점 보존. 동쪽 (688,440)에 거점행 관문 추가 |
| `novera_commons` | 64×48,1024×768 | 서문(96,384), 도착(128,384), 조합 접수원(480,320), 전직 안내인(544,320), 보급상(416,416), 동문(928,384) |
| `novera_outskirts` | 80×48,1280×768 | 서문(96,384), 도착(144,384), 남쪽 들개 길목, 중부 물가, 북동쪽 균열 흔적. 보고 NPC는 거점에 둔다 |

양방향 연결: 여울목↔기존 입구↔거점↔외곽. 기존 `ARRIVALS[map_id]` 하나로 여러 출입구를 처리하지 않는다. **출발 관문 ID→도착 지역/도착 위치/도착 관문 ID**를 명시한 간선 표를 둔다. 거점의 서쪽에서 들어올 때(128,384), 외곽에서 돌아올 때(880,384)를 구별한다. 거점에서 기존 입구로 돌아오는 도착점은 **(640,440)**으로 제안한다. 동쪽 관문(688,440)과48px로40px 밖이다. 리뷰가 제안한(656,440)은32px라 범위 밖 조건을 충족하지 않는다. (640,440)의 캡슐 통행 검증은 구현 시 수행하며 통과를 미리 주장하지 않는다. 외곽 귀환과 기존 입구→여울목 귀환도 보존한다. 가까운 관문 F 대화에서 목적지를 명확히 보여주며 플레이어 임의 목적지/좌표를 신뢰하지 않는다.

새 지역 진입은 MQ01~05 완료를 요구한다. 이동에 전투5초/포션/대시 재사용 대기를 재도입하지 않는다. 사망·입력 잠금·처리 중 재진입 거부는 유지한다. 도착점에 관문 즉시 재발동이 없도록 상호작용 입력을 다시 요구한다. 모든 지역은 자기 BOUNDS로 카메라·외곽벽·저장 위치를 검증한다. 새 지역 진입 실패 때 현재 월드/슬롯을 보존한다.

거점에는 적을 배치하지 않는다. 외곽의 도착점·NPC 동선은 최초 인지 및 지속 공격 범위 밖으로 분리한다. 기존 들개/점액 정의는 재사용하되 의뢰별 서식지 source ID를 분리한다. 각 토벌은 한 마리씩 접근할 수 있게 배치하고, 정확한 스폰 좌표·최소 간격·재스폰 위치는 구현의 지형/캡슐 검사와 함께 기록한다. 의뢰 표식은 물/충돌 셀에 두지 않는다. 안전 구역이라는 이름만으로 유인된 적/투사체까지 차단했다고 주장하지 않는다.

## 3. 의뢰와 예산

현재 `godot/data/quests`는 MQ01~05뿐이다. 기존 A~D에 다음 ID를 제안하며 기존 ID의 목표 수/보상을 바꾸지 않는다. 수락은 명시 버튼, 순서대로 목표 처리, 최종 보고 한 번만 보상 지급한다. 발주/보고는 `novera_receptionist`; 가레스의 향후 본편 역할과 혼동하지 않도록 현장 접수원으로 둔다.

| ID / 제목(가칭) | 선행 | 순서 있는 목표 | 보고 EXP | 골드 제안 |
|---|---|---|---:|---:|
| MQ-02-01 길목을 여는 일 | MQ-01-05 | 외곽 길목 들개3 처치 | 2,000 | 300 |
| MQ-02-02 물가의 통행로 | 02-01 | 물가 점액3 처치 → 통행 표식 REACH | 3,000 | 450 |
| MQ-02-03 남겨진 균열 흔적 | 02-02 | 북동부 점액4 처치 → 흔적 INTERACT | 4,500 | 600 |
| MQ-02-04 다음 길을 고르다 | 02-03 | 외곽 정찰점 REACH → 거점 전직 안내인 TALK → 접수원 보고 | 5,500 | 900 |

A~D 보고 EXP 합계15,000은 이미 잡힌 예산의 **배정**이며 추가 보너스가 아니다. 1장 최소3,820 +15,000 =18,820, Lv10 누적18,612보다208 높다. 새 토벌10마리 EXP는 이 하한에 포함하지 않는다. 첫 장4마리와 합쳐 필수 토벌14마리다. D 완료에 전직 또는 Lv10을 선행 요구하지 않는다. D 보고로 Lv10이 열리므로 전직을 먼저 요구하면 순환 의존이다. 전직 자체는 기존 V UI/직업 조건을 사용하며 자동 전직·무기 이중 지급 없음.

2장 기초 풀52,325는 보고36,628+처치15,697이다. 보고의 메인60%를 roundi하면21,977, 서브 잔여14,651이다. A~D15,000을 배정하면 **남은 메인2건 보고6,977**이다. 골드2,250은 2장 **의뢰 골드 풀**22,680에서 차감해20,430을 후반 메인/서브 의뢰에 남긴다. 처치·판매 수입은 이 의뢰 풀과 별도로 계산하며 중복 배정하지 않는다. 후반 골드 분포와 소비처는 아직 실측하지 않았으므로 장 전체 균형 입증이 아니다. 공훈은 이번4건0, **100시간 예산 §3의 2장 메인 공훈500**은 장 마무리까지 유보한다. 장 완료 시1장100+2장500=600으로 R3 요구500을20% 여유로 충족시키는 것이 현행 의도다. ‘R3 조기 개방 방지’는 이번4건에 선지급하지 않는다는 뜻이며 장 완료 후 자격까지 막는다는 뜻이 아니다. 명성·영지 문서 §2-2의150과 R3 공급680은 머리말이 구분한 이전250시간 기준이다. 추가 필수 아이템 보상은0이며 기존 첫 포션2개/상인/정상 드롭을 유지한다.

후반 골드 검산 항목: 기존 메인 장 하한150마리분×g(10)=63을 유지하는 경우 장 메인 합계9,450, 뒤2건 최소7,200이 필요하다. 잔여 의뢰 풀20,430 안에서 배분하고 서브 몫과 중복 계산하지 않는다. 실제 배정은 후반 설계에서 확정하며 이번4건 보상으로2장 전체 경제를 검증하지 않는다.

단순 토벌3/3/4만으로 2장 전체 EXP52,325나Lv12를 달성한다고 주장하지 않는다. 뒤2건/서브/처치 예산은 후속 설계 대상이다. 기존30~45분 첫 전직 시간도 실측 전에는 가설이다. 확률 드롭 획득을 필수 메인 완료 조건으로 넣지 않는다.

## 4. 목표 안내·대화·전직

새 레이아웃에 전용 NPC ID와 목표 ID를 등록한다. 지명/표식/목표 안내 문구는 같은 위치를 가리킨다. 접수원은 다음 수락 가능 의뢰·현재 진행·보고 가능 상태에 맞게 말한다. 새 대화 시스템이나 선택 분기는 만들지 않는다.

현재 `quest_navigation.gd`는 현 월드에 목표가 없으면 빈 결과가 될 수 있고, 모든 의뢰 완료 뒤 MQ05 관문 안내로 돌아간다. 이 하드코딩을 지역/관문 그래프 조회로 바꾼다. 목적지가 다른 지역이면 **현재 지역에서 나갈 관문과 목적지 이름**을 표시한다. KILL은 살아 있는 적의 실시간 좌표 대신 서식지 범위/마커를 표시한다. 다음 수락/보고 지점도 같은 조회를 사용한다. MQ02-04 완료 후에는 현재 미구현인 02-05를 수락 가능처럼 안내하지 않고 ‘이번 구간 완료·전직/정비 가능’을 표시한다.

장착 방식·아이템 상세 레이아웃은 현행 유지. 직업별 상점 상품 제한은 별도 기록된 향후 정책이며 이 콘텐츠 묶음에 몰래 적용하지 않는다. 포션 재사용 대기는 그대로다.

상인은 기존 입구(216,440)를 유지하고 거점(416,416)에 추가한다. 현재 EconomyRuntime.act와 EconomyPanel.trading의 novera_gate/좌표 고정을 제거한다. 월드에 등록한 유효 상인 노드의 실제 global_position/거래 반경을 같은 조회 함수로 읽고, 같은 월드의 가장 가까운 유효 상인이 반경 안일 때만 거래한다. 다른 월드·삭제 대기·비활성 상인을 제외하고 구매/판매 확정 시 다시 검사한다. UI에서만 허용하거나 map_id만 맞으면 원격 거래를 허용하는 방식은 금지한다. 반경/좌표 이동·복수 상인·거리 밖·월드 교체를 회귀 검사한다.

## 5. 저장·후보 격리

현재 V4는 지역2개/의뢰5개를 사용하고 M6 V5는 실착 장비를 추가했다. 새 지역/의뢰를 기존 전역 카탈로그에 무조건 넣으면 구 버전 검증도 함께 넓어진다. 이를 피하기 위해 **M7 후보 V6**를 제안한다. 기본 실행 V4·M6 실행 V5는 유지하고 `user://m7_candidate_*`만 새 후보 실행기에 허용한다. M6 채택 승인을 우회하는 기본 배포가 아니다.

버전마다 허용 지역/의뢰와 필드 검증을 명시 선택한다. V1~V5 원본 검증(각 버전의 기존 지역/의뢰/장비 규칙) → V6 변환 → V6 재검증 순서. 구 데이터에 새 의뢰를 completed로 채우거나 보상을 선지급하지 않는다. 새 의뢰 상태 부재는 미수락이다. 기존 map_id/좌표/장비/골드/계정/슬롯 식별자는 보존한다. 기존 저장 폴더를 직접 이관하지 않는다. 이전 후보/기본 실행은 V6를 unsupported_version으로 거부하고 백업으로 우회하지 않는다.

V6도 position은 실제 저장 위치이고 arrival은 여행 직후에만 적용한다. 신규 지역/의뢰 잠금의 전제 MQ01~05 완료를 저장 검증에도 적용한다. 예약 story_flags/territory/discovered_regions는 이번에 열지 않는다. 사망/중간 진행/ready/completed의 각 상태, 지역 교체 및 메뉴 저장에서 같은 카탈로그를 전달한다. 후보 월드에 맞는 catalog/registry를 Journal·Schema·Navigation 모두가 사용하도록 주입하며 검증기 인스턴스에 마지막 버전을 남기지 않는다.

채택 순서: M7 후보 구현의 독립 검토와 기본 제품 채택을 구분한다. 기본 제품 반영 판단에서는 **M6/V5 채택 조건을 먼저 판정한 다음 M7/V6을 판정**한다. M6 전투1/3 미달 상태를 V6의 존재로 닫지 않는다. 후보 개발 자체는 기존 승인 범위에서 가능하다.

이관 때문에 버전별 기존 규칙 동결이 먼저 필요하다. 현재 QuestCatalog/RegionRegistry를 무작정 수정해서 V4/V5가 새 콘텐츠를 유효로 받아들이는 구현은 금지한다. 직전 full_precision 저장 수정도 V6에 그대로 사용한다. HP 상한 오차를 허용치로 덮지 않는다.

## 6. 구현과 검증 계획

1. 버전별 콘텐츠 규칙/카탈로그 전달과 V6 후보 저장·이관을 먼저 연결한다. 구 규칙 검증 실패·위조V5 새 지역·V6 새 지역·백업 버전 조합·원본 불변·멱등을 기존 저장 테스트에 추가한다.
2. 지역 그래프/출입구별 도착점·새 두 맵·NPC/스폰/표식을 연결한다. 기존2개 지역의 좌표/크기는 유지한다. 경로 검사는 플레이어 실제 충돌형 오프셋까지 반영한다.
3. 의뢰4개·대화·보고·다른 지역 목표 안내·전직 안내·경제 후보와의 수명을 연결한다. 레벨/완료 상태 주입 없이 진행할 수 있어야 한다.
