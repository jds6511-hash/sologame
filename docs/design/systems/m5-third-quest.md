# M5 후속 단위 — 무리들의 그림자

- 날짜: 2026-09-27. 코드 대조 기준 `234cc33`.
- 상태: Claude `bfb4f85` 설계 리뷰 **착수 가능**, 코드 구현·자동 검증 완료/구현 리뷰 대기. [보고서](../../qa/m5-third-quest-report.md). G4/G5 직접 플레이 승인을 대신하지 않는다.
- 근거: [전체 로드맵 §5](../DEVELOPMENT_ROADMAP.md), [퀘스트 구조 §3-2](../quests/quest-structure.md), [초반 성장](../quests/early-leveling-route.md), [시작 맵](../levels/eastern-frontier-start-map.md), [첫 슬라이스 계약](npc-dialog-quest.md).

## 목표와 범위

토끼몰이를 보고한 플레이어가 같은 접수원에게 다음 의뢰를 명시적으로 수락하고, 기존 동부 들녘의 들개 마수 2마리를 처치해 보고한다. 완료한 02 뒤에 다음 행동을 안내하고 기존 보상·저장 경계를 재사용한다. 신규 몬스터·맵·난이도 조정 없이 MQ-01-03 한 건을 잇는다. MQ-01-04의 INTERACT, 05의 명성/장 전환, Lv6~10 연결 의뢰는 별도 후속 단위로 남기며 전체 M5 범위를 축소하지 않는다. M6 착수나 M5 완료로 기록하지 않는다.

토벌 적의 실제 레벨과 보상 산정 권장 레벨은 다르다. 현재 적 밸런스를 바꾸거나 Lv4 몬스터 기준으로 의뢰 골드를 다시 늘리지 않는다. 첫 세 의뢰 보고 EXP 합계는 890, 골드는 270이며 실제 사냥 EXP/드랍은 별도다.

## 현재 코드와 필요한 연결

- QuestCatalog는 FIRST/SECOND Resource만 등록한다. 세 번째 정의를 등록하되 기존 ID·정의의 목표 수와 보상은 바꾸지 않는다.
- MonsterSpawner는 현재 토끼만 `content_id`/`spawn_source_id`를 부여한다. `WOLF_SCENE`에도 `feral_dog`를 부여하고, export `wolf_spawn_source_id`를 추가한다. 시작 지역에서만 `yeoulmok_dog_habitat`를 설정한다. 다른 테스트 월드는 기본 빈 출처를 유지한다.
- `_spawn_monster`에서 add_child 및 monster_spawned 발신 **전에** 메타를 넣는다. `_populate_slot`이 초기/재스폰 공통으로 호출하는 경로이므로 재스폰도 동일하게 적용한다. 노드 표시명이나 pack_id 접두사로 퀘스트 대상을 판정하지 않는다.
- 시작 지역의 `_on_monster_spawned`는 이미 메타를 받아 died→Journal을 한 번 연결한다. 새 의뢰별 별도 사망 콜백을 추가하지 않는다. 다른 지역/토끼/수락 전 처치/중복 token은 집계하지 않는다.
- QuestDialog/QuestTracker는 현재 01/02 분기와 고정 보상 문구를 갖는다. 이번에는 아래 공통 표시 선택 규칙을 도입해 세 번째 분기를 계속 복제하는 일을 피한다.

## 대화·추적 표시 선택 제안

명시적 카탈로그 표시 순서 `[01, 02, 03]`에서 해당 NPC의 첫 미완료 의뢰를 선택한다. active/ready가 있으면 그것을 먼저 표시하고, 없으면 선행 completed인 미수락 의뢰를 제안한다. 존재하지만 선행을 충족하지 않는 의뢰를 임의 수락시키지 않는다. Dictionary 순회 순서를 계약으로 사용하지 않는다.

QuestData에 표시용 제안문·진행 위치 설명을 추가하고 제목/보상은 기존 수치 필드에서 읽는다. UI 선택은 `accept/report + quest_id`로 Controller/Journal에 전달한다. 기존 01 패 수령 문구·01의 접근→대화 순서·Esc 무보상·성공 후 닫기·pause 소유권은 보존한다. UI에 없는 임의 ID/다른 NPC의 액션은 실행하지 않는다. Controller 보고 검증이 최종 권한이며 표시 함수가 보상이나 진행을 변경하지 않는다.

02 완료 후: `접수원에게 무리들의 그림자 수락 [F]` → `들개 마수 0/2 · 토끼 서식지 북동쪽` → `접수원에게 보고 [F]`. 기존 1~2마리 무리/어그로 공유를 그대로 두고 한 번에 모두 상대하라는 문구를 쓰지 않는다. 03 완료 뒤에는 `균열 조사 의뢰 준비 중`으로 실제 미구현 상태를 알린다. 자동 수락·자동 보고·새 의뢰를 위한 디버그 선행 완료는 없다.

## 저장 호환성

V2의 `{state, counts}` 형식은 유지한다. 기존 V2에서 03 항목이 없어도 정상이며 02 completed면 미수락 제안으로 시작한다. 03을 자동 삽입하거나 기존 보상을 재지급하지 않는다. active 1/2·ready 2/2·completed를 저장/재실행한다. 같은 계정의 다른 슬롯은 영향을 받지 않는다.

버전 상승 없이 콘텐츠만 추가한다(Claude 설계 검토 착수 가능). 이전 빌드는 의뢰 3개가 정의 수 2개를 넘어 먼저 `quest_fields`로 거부하며, 파일 계층은 이를 `invalid_data`로 분류한다. `unknown_quest` 분기에 도달한다고 가정하지 않는다. **이전 빌드로의 다운그레이드 복원을 지원한다고 주장하지 않는다.** 읽기 거부/백업 폴백과 이후 쓰기 시 invalid_data 원문 보존 경로를 구분해 회귀 테스트로 확인한다. 진단 순서 변경 제안은 기존 빌드 동작을 바꾸지 않으므로 이번에는 보류한다.

## 구현·검증 단위

1. 정의/표시 선택: 세 번째 Resource·Catalog 표시 순서·표시 문구, 공통 선택 함수 및 선행/NPC/존재하지 않는 ID 테스트. 기존 두 의뢰의 선택·문구·보상 의미가 유지되는지 확인.
2. 런타임: 들개 stable ID/출처를 최초·재스폰 경로에 연결, 실제 died 시그널로 1마리당 목표·경험치·드랍 각각 한 번. 다른 출처·수락 전·중복 사망은 0회. 스폰 수·AI·공격 수치를 변경하지 않는다.
3. UI/보상: 02 완료부터 명시적 03 수락/보고까지 연결. 490 EXP·150골드, 재보고/재로드 중복 지급 0, 잘못된 NPC/액션 거부, 대화/pause/줍기 우선 회귀.
4. 영속성: 기존 두 의뢰 V2 로드·03 세 상태 재실행·슬롯 보호 및 이전 Catalog로 읽을 때 원본 보호. 기존 7단계 probe 유지.
5. 전체 GUT·변경 파일 형식/린트·실제 렌더 UI 검증. 변경 파일/명령/한계/구현 해시를 보고서와 Claude 코드 검토 요청에 기록한다. 실제 플레이 불가 항목은 통과로 바꾸지 않는다.

예상 파일: `data/quests/mq_01_03.tres`, 기존 01/02 표시 필드, `quest_data.gd`, `quest_catalog.gd`, 필요 시 순수 표시 선택 helper, `quest_dialog.gd`, `quest_tracker.gd`, `monster_spawner.gd`, 시작 지역의 source 설정, 관련 quests/world/save 테스트. SaveSession의 저장 안전 기준·보상 원자성·계정 소유권을 바꾸지 않는다.
