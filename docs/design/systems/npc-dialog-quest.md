## 1. 목표와 이번 구현 범위

새 캐릭터가 여울목 접수원에게 모험가 패를 받고, 토끼몰이를 명시적으로 수락해 뿔토끼 2마리를 잡고 돌아와 보상을 받는다. 수락·처치·보고 상태와 보상이 종료/재실행 후 함께 복원돼야 한다. 목표는 반복 사냥 대신 의뢰가 다음 행동과 성장을 안내하는 첫 플레이 흐름이다.

첫 슬라이스는 MQ-01-01과 MQ-01-02다. 선행 의뢰를 디버그 완료 처리해 토끼몰이를 여는 방식은 정식 경로로 인정하지 않는다. MQ-01-03~05 및 Lv6~10 연결 의뢰는 이후 콘텐츠 단위로 확장한다. 최종 NPC 아트, 상점, 지역 확장, 전투 수치 조정은 이번 단위 밖이다. 전체 M5 범위를 축소한 것이 아니다.

| 의뢰 | 시작/목표 | 보고 보상 |
|---|---|---|
| MQ-01-01 | 새 캐릭터 자동 수락 → 접수원에게 접근·대화 | 75 EXP, 20골드, 모험가 패 |
| MQ-01-02 | 01 완료 후 NPC 제안·명시적 수락 → 서식지 뿔토끼 2마리 → NPC 보고 | 325 EXP, 100골드, POT-HP-1 ×2 |

모험가 패는 판매·장착 불가능한 서사 소유 상태다. MQ-01-01 완료로 소유를 도출하고 대화/퀘스트 화면에 표시한다. 이번에는 일반 가방 아이템이나 별도 계정 플래그로 중복 저장하지 않는다. 명성 보상은 이 두 건에 추가하지 않는다.

## 3. 데이터와 상태 소유권

QuestData는 Godot Resource로 ID, 선행 의뢰, 발주/보고 NPC ID, 목표 배열, 보상, 대사 키를 가진다. QuestState는 캐릭터마다 별도 Dictionary로 보유한다. 공유 Resource에 진행도를 쓰지 않는다. 처음부터 480건을 코드 분기로 늘리지 않는다.

첫 안정 ID: NPC `yeoulmok_receptionist`, 몬스터 `horned_rabbit`, 지역 `yeoulmok_rabbit_habitat`. 지역 판정은 뿔토끼 스폰 그룹의 출처로 고정하므로 이후 이동 거리와 무관하게 같은 출처로 센다. 노드 이름·번역 이름·instance ID를 저장 ID로 쓰지 않는다. instance ID는 현 월드의 중복 사망 이벤트 방지에만 사용하고 월드 종료 시 폐기한다.

상태는 `active → ready → completed`. 미수락은 항목 부재, 제안 가능 여부는 선행 완료로 도출한다. 저장 항목은 `{state, counts}`로 고정한다. counts는 목표 데이터 순서에 대응하는 정수 배열이며 수량을 넘지 않는다. ready는 모든 목표 충족, completed는 보상 지급 완료다. 수락 전 처치 소급 없음, 다른 종류/서식지 처치 제외, 사망으로 진행 초기화 없음, 포기·반복 수락은 첫 슬라이스에서 제공하지 않는다.

QuestJournal은 상태 전이·내보내기/복원 검증만 소유한다. 월드의 QuestController가 NPC·처치 이벤트와 보상 컴포넌트를 연결한다. SaveSession은 파일 저장과 월드 교체를 계속 소유한다. 계정으로 퀘스트 진행을 옮기지 않는다.

QuestData·QuestCatalog·첫 두 의뢰 Resource는 **단위 1**에서 함께 만든다. 검증기와 실행기는 같은 카탈로그를 사용하며 ID/목표/선행 상수표를 중복 작성하지 않는다. `QuestStateSchema.validate(quests, catalog)`는 카탈로그를 명시적으로 받는다. 01의 counts는 `[REACH 접수원=1, TALK 접수원=1]`, 02는 `[KILL 뿔토끼=2]`에 대응한다. 02의 수락·보고 대화는 목표 배열에 넣지 않고 상태 전이로 처리한다. 01은 40px 이내 유효 접근에서 REACH, 대화 열기 성공 시 TALK를 기록하며, 각 단계가 앞 목표 충족 후 진행된다.

TALK/KILL/REACH를 첫 슬라이스에서 실행한다. 2026-09-28 후속 [MQ04](m5-fourth-quest.md)에서 INTERACT를 추가했다. COLLECT/DELIVER/ESCORT/SURVIVE/CHOICE는 기존 9종 목표 계약에 남기되, 미구현 유형을 만난 실행기는 명시적 오류로 거부한다. 빈 성공 처리로 출시하지 않는다.

## 4. 상호작용·대화

- 살아 있고 행동 가능한 플레이어와 40px 이내의 접수원 중 가장 가까운 1명만 F 프롬프트를 표시한다. 벽 너머 상호작용은 충돌 조회로 배제한다.
- 다른 메뉴가 열렸거나 일시정지 중이면 대화를 열지 않는다. 대화가 소유한 일시정지만 닫을 때 해제한다. F6/통합 메뉴와 겹쳐 열지 않는다.
- 01 대화는 열린 시점에 TALK를 기록하고, 명시적 `모험가 패 받기` 선택에서 ready를 평가해 report한다. ESC로 닫으면 ready는 유지하고 보상은 지급하지 않는다. 다음 대화에서 다시 수령할 수 있다.
- 첫 대화 → 패 수령 → 토끼몰이 설명/수락 또는 나중에 → 진행 확인 → 보고/보상 → 후속 의뢰 안내 상태로 표시한다. 보상과 레벨업 알림은 대화 종료 후 순서대로 표시한다.
- 대화 중에는 월드와 자동 저장 시간이 정지한다. 닫기/ESC는 미선택 수락·보고를 실행하지 않는다. 클릭 연타·키 반복도 한 번의 전이만 만든다.
- 추적 문구는 `접수원과 대화` → `뿔토끼 처치 0/2` → `접수원에게 보고`로 전환한다. 기존 온보딩은 유지하되 새 추적 문구와 상호작용 프롬프트를 동시에 덮어쓰지 않게 우선순위를 정한다.

단위 2에서는 NPC 대화 대상이 있으면 F 줍기와 온보딩 공격 프롬프트보다 대화를 우선한다. 줍기는 NPC 범위 밖에서 수행한다. 기존 전직 선택창도 이미 pause 상태이면 열지 않아 세 UI의 소유권을 침범하지 않는다. 접수원은 기존 마커에서 런타임 생성하며 전사 LPC 외형을 임시 재사용한다. 최종 NPC 아트는 별도 단계다.

일시정지는 새 Autoload 대신 **월드 소유 UiPauseArbiter 1개**로 중재한다. `acquire(owner: Node) -> bool`은 다른 소유자 또는 외부 pause가 있으면 실패하고, 성공할 때만 pause를 건다. `release(owner: Node) -> void`는 자기 소유자만 해제한다. IntegratedMenu·SaveMenu·QuestDialog 모두 경유하고 직접 pause 토글/다른 메뉴 process_mode 비활성화 우회는 제거한다. 소유자 종료 시 자기 토큰만 반납하며 중복 반납은 무효다. 월드 교체는 기존 메뉴 토큰을 먼저 반납한 후 SaveSession이 전환용 pause를 잡고 이전 pause 상태를 복원한다. 이전 월드의 늦은 종료가 새 월드 pause를 풀지 않아야 한다. 기존 비메뉴 pause 중에는 세 UI 모두 열리지 않는다.

## 5. 보상과 저장의 일관성

보고는 QuestController의 한 동기 호출로 처리한다. ready·보고 NPC·보상 ID·가방 여유·수치 상한을 먼저 확인하고, 실패하면 어떤 보상도 주지 않고 ready를 유지한다. 30칸이 차도 기존 포션 묶음에 합산 가능하면 성공한다. 가방이 차서 실패하면 비우고 다시 보고하도록 안내한다. 보상을 바닥에 버리지 않는다.

검증 후 재진입 잠금을 건 채 가방·골드·EXP와 completed를 같은 프레임에 반영한다. 해당 구간에 await/파일 저장을 넣지 않는다. 보상 적용 중 신호에서 재보고/저장 요청이 들어와도 거부하며, 완료 후 신호를 발신한다. 실패 가능한 항목 지급을 EXP/골드 지급보다 먼저 수행하고 실패 시 상태를 보존한다. 기존 가방 API를 무시한 직접 배열 쓰기는 피한다.

저장은 완료 상태와 보상을 같은 캐릭터 payload에 캡처한다. 저장 전 종료하면 마지막 저장 시점의 진행·보상이 함께 되돌아가는 기존 정책을 따른다. 보고마다 강제 저장하거나 계정 보상 장부를 추가하지 않는다. 저장 실패 시 성공 표시를 하지 않으며 현재 세션 보상은 유지하고 재저장을 안내한다.

## 6. M4 호환성과 검증

새 퀘스트 payload를 구 M4가 정상 파일로 오해하지 않도록 **캐릭터 봉투 버전과 character_save_version을 2로 올리고 계정은 1을 유지**한다. V1 파일을 읽는 지원은 유지한다. 파일 계층은 허용 버전/체크섬뿐 아니라 기존처럼 등록된 payload 검증기도 호출한다. `bind_store`의 검증기는 payload 버전으로 V1/V2를 분기해 지원 버전을 모두 받는다. V1의 기존 예약 필드 제약도 유지한다. 검증된 V1만 codec의 순수 마이그레이션 함수로 변환하고 변환 결과를 V2 스키마로 다시 검증한다. 파일 계층은 마이그레이션하지 않는다.

봉투와 해당 payload 버전은 숫자 정수이고 일치해야 한다. 지원하지 않는 봉투/본문 버전은 `unsupported_version`으로 거부하고, 지원 버전끼리 불일치하거나 본문 버전 필드가 잘못되면 `invalid_data`로 거부한다. 이 선택은 `corrupt`와 달리 저장 시 원본 보존을 보장하기 위한 것이다. 쓰기에서도 출력 봉투 버전과 본문을 교차 검사한다. 캐릭터 1/2·2/1, 계정 불일치, 미래 버전 및 정상 1/1·2/2를 테스트한다. 검증기 Callable의 기존 Dictionary 입력 계약은 유지한다.

읽기만으로 원본을 다시 쓰지 않는다. **V1 로드 직후 `migration_pending` 세션 상태로 자동 저장을 보류**하고 `이전 버전 저장을 불러왔습니다. 확인 후 수동 저장이 필요합니다`를 표시한다. 180초가 지나도 어떤 슬롯에도 자동 쓰기하지 않는다. 수동 저장이 성공한 뒤에만 보류를 해제하고 자동 저장 타이머를 0으로 시작한다. 실패/취소 시 보류와 원본을 유지한다. 다른 슬롯으로 수동 저장하면 그 V2 슬롯만 활성화하고 원래 V1 슬롯은 그대로 둔다. 새 캐릭터/다른 슬롯 로드에서는 보류 상태를 해당 데이터로 다시 결정하며 파일에 저장하지 않는다. 기존 recovered 보호는 별도로 유지한다. 최초 같은 슬롯 수동 저장은 정상 V1 백업을 유지한다. 미지원 미래 버전·손상·백업 보존 계약은 그대로다.

V1 빈 quests는 미진행으로 이관한다. 단위 1 마이그레이션은 `{}`를 유지하며, MQ-01-01의 새 실행 상태 생성·자동 수락은 **단위 2 Journal 초기화**에서 수행한다. 기존 레벨·장비·골드·계정 연결·튜토리얼을 초기화하지 않는다. MQ01 진행 흔적이 없는 기존 캐릭터에 임의 보상을 주지 않는다. V2에서 퀘스트 ID·상태·counts 길이·범위·선행 조건을 검증하고 알 수 없는 콘텐츠는 보존 가능한 검증 실패로 처리한다. story_flags/territory/reputation의 미구현 예약 제약은 그대로 유지한다.

정적 콘텐츠 오류와 저장 진행도 오류는 구분한다. 카탈로그 생성 시 수락 여부와 무관하게 모든 정의의 목표·보상 수치·아이템 ID를 검사하고 잘못된 의뢰 ID와 이유를 보고한다. 저장 검증에서도 콘텐츠가 유효한지 확인하며, 실패하면 `quest_content_error`로 중단한다. 이 오류는 백업 복구·원본 보존본 이동·덮어쓰기로 우회하지 않고 메뉴에 게임 데이터 확인 안내를 표시한다. NPC ID의 레지스트리 대조는 단위 2의 NPC 연결 때 추가한다.

퀘스트 데이터 복원은 몬스터 이벤트·대화 입력을 받기 전에 끝낸다. 새 캐릭터와 다른 슬롯은 별도 상태 객체를 갖는다. 실패한 복원이 이전 월드를 파괴하거나 완료 보상을 다시 주지 않아야 한다.

이를 위해 MonsterSpawner의 `_ready()`는 참조/난수 준비만 수행하고 스폰은 하지 않는다. 월드가 Journal 복원 → Controller/드랍/처치 신호 연결 → `start()` → 초기 토끼 등록 후 온보딩 시작 순으로 호출한다. `start() -> void`는 중복 호출에 안전하며 최초 토끼는 동기 생성, 나머지 종의 프레임 분산·밤 스폰은 기존 방식을 유지한다. 시작 전 재스폰 틱과 낮/밤 스폰도 실행하지 않는다. 비동기 생성 중 월드가 종료되면 후속 생성하지 않는다. 시작 지역 외 `m3_new_enemy_field`와 스포너 직접 생성 테스트도 명시적으로 start해야 한다. 로드 직후 최초 토끼·이후 재스폰 모두 처치가 집계되어야 한다.

## 7. G5 첫 슬라이스 통과 기준

### 단위 2 구현 시 보존할 추가 불변식

- 신호 연결 → start 순서에서는 초기 토끼도 신호로 등록된다. `eastern_frontier_starting_area.gd`의 `_register_spawned_monsters()` 호출과 불필요해진 함수·“시점이 겹치지 않는다” 주석을 제거한다. 초기/분산/야간/재스폰 모두 `_on_monster_spawned` 한 경로로 드랍·경험치·퀘스트를 등록한다. 중복 연결 오류 로그가 없고 한 번의 사망이 각 시스템에 한 번만 반영되는지 검증한다. 기존 M4에서 이중 지급이 확인됐다는 의미는 아니다.
- 01의 REACH는 유효 접근 순간, TALK는 대화 열기 성공 순간에 별도로 기록한다. F가 가능한 시점에는 REACH가 충족되므로 “범위 밖에서 F 대화 성공”을 테스트 전제로 만들지 않는다. 접근만 한 상태에서 TALK가 0인지 확인한다.
- 월드 교체 실패 복원은 **메뉴 표시 상태와 pause 토큰 소유권을 함께 복원**하는 의미다. 전환 전 소유자를 보관하고, 실패 시 이전 월드의 동일 메뉴에 토큰을 재부여한 뒤 전환 pause를 해제한다. 메뉴가 열린 상태에서 월드가 잠시라도 돌지 않게 한다. 성공 시 이전 토큰은 폐기하고 새 월드는 열린 메뉴 없이 시작한다. 이전 월드의 늦은 release가 새 월드를 변경하지 못해야 한다. 이 규칙은 §4의 “이전 pause 상태 복원”을 구체화한다.

### 플레이 검증

1. 디버그 선행 완료 없이 새 게임에서 01 대화·보상 후 02 NPC 수락까지 가능.
2. 수락 전/다른 대상/중복 사망은 0회 반영, 올바른 2회는 ready. 자동 완료·자동 보상 없음.
3. 실제 보고로 정확히 325 EXP·100골드·포션 2개. 연타·재대화·로드 후 재보고로 추가 지급 0건.
4. active(1/2), ready(2/2), completed 각각 종료/재실행 복원. 가방 만석 실패 후 재시도도 검증.
5. V1 슬롯 호환, 미래 버전 보호, 슬롯 독립성, M4 저장 안전 기준 유지.
6. F/마우스/ESC·메뉴 간 전환·사망/월드 교체에 입력 잠금 잔류 없음. 대화 시간이 자동 저장 간격에 포함되지 않음.
7. 자동 검증과 실제 창 실행 결과를 별도로 기록하고 디렉터 플레이 판정을 받는다. 첫 슬라이스 통과를 전체 M5·Lv10 성장 검증 완료로 쓰지 않는다.

## 8. 선택 근거

월드마다 임시 카운터를 붙이는 방식은 NPC·저장 흐름에서 분리되므로 제외했다. 전역 Autoload 하나에 계정·퀘스트·대화를 모두 넣는 방식은 슬롯 간 상태 유출과 테스트 결합을 키우므로 선택하지 않았다. 기존 월드/캐릭터 소유 구조에 Resource 정의와 캐릭터별 Journal을 붙이는 방식을 사용한다.
