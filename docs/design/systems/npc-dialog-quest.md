# M5 — NPC·대화·첫 의뢰 구현 계약

- 날짜: 2026-09-27. 기준 코드: `dcbda4d`.
- 상태: 다음 단계 진행 지시에 따른 구현 설계. 구현·G5 통과 기록이 아니다.
- 담당: Codex 구현·통합, Claude 독립 검토.
- 정본: [개발 로드맵](../DEVELOPMENT_ROADMAP.md), [퀘스트 구조](../quests/quest-structure.md), [초반 성장](../quests/early-leveling-route.md), [저장 계약](save-load.md).
- M4 직접 이동 후 위치 복원·종료 경고 원인은 별도 추적한다. 다음 단계 진행 지시를 G4 합격으로 기록하지 않는다.

## 1. 목표와 이번 구현 범위

새 캐릭터가 여울목 접수원에게 모험가 패를 받고, 토끼몰이를 명시적으로 수락해 뿔토끼 2마리를 잡고 돌아와 보상을 받는다. 수락·처치·보고 상태와 보상이 종료/재실행 후 함께 복원돼야 한다. 목표는 반복 사냥 대신 의뢰가 다음 행동과 성장을 안내하는 첫 플레이 흐름이다.

첫 슬라이스는 MQ-01-01과 MQ-01-02다. 선행 의뢰를 디버그 완료 처리해 토끼몰이를 여는 방식은 정식 경로로 인정하지 않는다. MQ-01-03~05 및 Lv6~10 연결 의뢰는 이후 콘텐츠 단위로 확장한다. 최종 NPC 아트, 상점, 지역 확장, 전투 수치 조정은 이번 단위 밖이다. 전체 M5 범위를 축소한 것이 아니다.

| 의뢰 | 시작/목표 | 보고 보상 |
|---|---|---|
| MQ-01-01 | 새 캐릭터 자동 수락 → 접수원에게 접근·대화 | 75 EXP, 20골드, 모험가 패 |
| MQ-01-02 | 01 완료 후 NPC 제안·명시적 수락 → 서식지 뿔토끼 2마리 → NPC 보고 | 325 EXP, 100골드, POT-HP-1 ×2 |

모험가 패는 판매·장착 불가능한 서사 소유 상태다. MQ-01-01 완료로 소유를 도출하고 대화/퀘스트 화면에 표시한다. 이번에는 일반 가방 아이템이나 별도 계정 플래그로 중복 저장하지 않는다. 명성 보상은 이 두 건에 추가하지 않는다.

## 3. 데이터와 상태 소유권

QuestData는 Godot Resource로 ID, 선행 의뢰, 발주/보고 NPC ID, 목표 배열, 보상, 대사 키를 가진다. QuestState는 캐릭터마다 별도 Dictionary로 보유한다. 공유 Resource에 진행도를 쓰지 않는다. 처음부터 480건을 코드 분기로 늘리지 않는다.

첫 안정 ID: NPC `yeoulmok_receptionist`, 몬스터 `horned_rabbit`, 지역 `yeoulmok_rabbit_habitat`. 지역 판정은 뿔토끼 스폰 그룹의 출처를 사용해 개체에 전달한다. 배회로 좌표가 조금 바뀌어도 같은 서식지 출처로 센다. 노드 이름·번역 이름·instance ID를 저장 ID로 쓰지 않는다. instance ID는 현 월드의 중복 사망 이벤트 방지에만 사용하고 월드 종료 시 폐기한다.

상태는 `active → ready → completed`. 미수락은 항목 부재, 제안 가능 여부는 선행 완료로 도출한다. 저장 항목은 `{state, counts}`로 고정한다. counts는 목표 데이터 순서에 대응하는 정수 배열이며 수량을 넘지 않는다. ready는 모든 목표 충족, completed는 보상 지급 완료다. 수락 전 처치 소급 없음, 다른 종류/서식지 처치 제외, 사망으로 진행 초기화 없음, 포기·반복 수락은 첫 슬라이스에서 제공하지 않는다.

QuestJournal은 상태 전이·내보내기/복원 검증만 소유한다. 월드의 QuestController가 NPC·처치 이벤트와 보상 컴포넌트를 연결한다. SaveSession은 파일 저장과 월드 교체를 계속 소유한다. 계정으로 퀘스트 진행을 옮기지 않는다.

TALK/KILL/REACH를 첫 슬라이스에서 실행한다. COLLECT/DELIVER/ESCORT/INTERACT/SURVIVE/CHOICE는 기존 9종 목표 계약에 남기되, 미구현 유형을 만난 실행기는 명시적 오류로 거부한다. 빈 성공 처리로 출시하지 않는다.

## 4. 상호작용·대화

- 살아 있고 행동 가능한 플레이어와 40px 이내의 접수원 중 가장 가까운 1명만 F 프롬프트를 표시한다. 벽 너머 상호작용은 충돌 조회로 배제한다.
- 다른 메뉴가 열렸거나 일시정지 중이면 대화를 열지 않는다. 대화가 소유한 일시정지만 닫을 때 해제한다. F6/통합 메뉴와 겹쳐 열지 않는다.
- 첫 대화 → 패 수령 → 토끼몰이 설명/수락 또는 나중에 → 진행 확인 → 보고/보상 → 후속 의뢰 안내 상태로 표시한다. 보상과 레벨업 알림은 대화 종료 후 순서대로 표시한다.
- 대화 중에는 월드와 자동 저장 시간이 정지한다. 닫기/ESC는 미선택 수락·보고를 실행하지 않는다. 클릭 연타·키 반복도 한 번의 전이만 만든다.
- 추적 문구는 `접수원과 대화` → `뿔토끼 처치 0/2` → `접수원에게 보고`로 전환한다. 기존 온보딩은 유지하되 새 추적 문구와 상호작용 프롬프트를 동시에 덮어쓰지 않게 우선순위를 정한다.

## 5. 보상과 저장의 일관성

보고는 QuestController의 한 동기 호출로 처리한다. ready·보고 NPC·보상 ID·가방 여유·수치 상한을 먼저 확인하고, 실패하면 어떤 보상도 주지 않고 ready를 유지한다. 30칸이 차도 기존 포션 묶음에 합산 가능하면 성공한다. 가방이 차서 실패하면 비우고 다시 보고하도록 안내한다. 보상을 바닥에 버리지 않는다.

검증 후 재진입 잠금을 건 채 가방·골드·EXP와 completed를 같은 프레임에 반영한다. 해당 구간에 await/파일 저장을 넣지 않는다. 보상 적용 중 신호에서 재보고/저장 요청이 들어와도 거부하며, 완료 후 신호를 발신한다. 실패 가능한 항목 지급을 EXP/골드 지급보다 먼저 수행하고 실패 시 상태를 보존한다. 기존 가방 API를 무시한 직접 배열 쓰기는 피한다.

저장은 완료 상태와 보상을 같은 캐릭터 payload에 캡처한다. 저장 전 종료하면 마지막 저장 시점의 진행·보상이 함께 되돌아가는 기존 정책을 따른다. 보고마다 강제 저장하거나 계정 보상 장부를 추가하지 않는다. 저장 실패 시 성공 표시를 하지 않으며 현재 세션 보상은 유지하고 재저장을 안내한다.

## 6. M4 호환성과 검증

새 퀘스트 payload를 구 M4가 정상 파일로 오해하지 않도록 **캐릭터 봉투 버전과 character_save_version을 2로 올리고 계정은 1을 유지**한다. V1 파일을 읽는 지원은 유지한다. 파일 계층은 허용 버전/체크섬을 검사하고, 순수 마이그레이션 함수가 검증된 V1을 메모리에서 V2로 변환한다. 읽기만으로 원본을 다시 쓰지 않는다. 첫 명시적 저장에서 V2를 기록하고 기존 정상 파일 백업을 유지한다. 미지원 미래 버전·손상·백업 보존 계약은 그대로다.

V1 빈 quests는 미진행으로 이관하고 MQ-01-01을 새 실행 상태로 시작한다. 기존 레벨·장비·골드·계정 연결·튜토리얼을 초기화하지 않는다. MQ01 진행 흔적이 없는 기존 캐릭터에 임의 보상을 주지 않는다. V2에서 퀘스트 ID·상태·counts 길이·범위·선행 조건을 검증하고 알 수 없는 콘텐츠는 보존 가능한 검증 실패로 처리한다. story_flags/territory/reputation의 미구현 예약 제약은 그대로 유지한다.

퀘스트 데이터 복원은 몬스터 이벤트·대화 입력을 받기 전에 끝낸다. 새 캐릭터와 다른 슬롯은 별도 상태 객체를 갖는다. 실패한 복원이 이전 월드를 파괴하거나 완료 보상을 다시 주지 않아야 한다.

## 7. G5 첫 슬라이스 통과 기준

1. 디버그 선행 완료 없이 새 게임에서 01 대화·보상 후 02 NPC 수락까지 가능.
2. 수락 전/다른 대상/중복 사망은 0회 반영, 올바른 2회는 ready. 자동 완료·자동 보상 없음.
3. 실제 보고로 정확히 325 EXP·100골드·포션 2개. 연타·재대화·로드 후 재보고로 추가 지급 0건.
4. active(1/2), ready(2/2), completed 각각 종료/재실행 복원. 가방 만석 실패 후 재시도도 검증.
5. V1 슬롯 호환, 미래 버전 보호, 슬롯 독립성, M4 저장 안전 기준 유지.
6. F/마우스/ESC·메뉴 간 전환·사망/월드 교체에 입력 잠금 잔류 없음. 대화 시간이 자동 저장 간격에 포함되지 않음.
7. 자동 검증과 실제 창 실행 결과를 별도로 기록하고 디렉터 플레이 판정을 받는다. 첫 슬라이스 통과를 전체 M5·Lv10 성장 검증 완료로 쓰지 않는다.

## 8. 선택 근거

월드마다 임시 카운터를 붙이는 방식은 NPC·저장 흐름에서 분리되므로 제외했다. 전역 Autoload 하나에 계정·퀘스트·대화를 모두 넣는 방식은 슬롯 간 상태 유출과 테스트 결합을 키우므로 선택하지 않았다. 기존 월드/캐릭터 소유 구조에 Resource 정의와 캐릭터별 Journal을 붙이는 방식을 사용한다.
