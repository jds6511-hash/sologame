## 0. 목표와 게이트 요약

**목표**: 전사 1직업 + 몬스터 3종으로 "손맛 기준선"을 만들고, 디렉터가 직접 플레이하여 재미/난이도를 승인한다.

**M2 게이트 (4건, 모두 충족해야 M2 완료)**:

| # | 게이트 항목 | 근거 |
|---|---|---|
| G2-1 | **디렉터 직접 플레이 승인** — 손맛 기준선(재미/난이도) | 마일스톤 공통 규칙(CLAUDE.md), `combat.md` 9-1 "기준선 선확정 → 확산" 전략 |
| G2-2 | **픽셀 스케일(16px 타일·x4 줌)·EDG32 팔레트 실화면 최종 확인** | `STYLE_GUIDE.md` 9장, PROJECT_STATUS D-20 — "M2가 마지막 변경 기회" |
| G2-3 | **HitFeedback 타격 피드백 모듈 약/중/강 3프리셋 승인** | `combat.md` 5-3·9-1장 — 승인된 값이 이후 전 직업·몬스터 확산의 기준 프리셋이 됨 |
| G2-4 | **주야간 사이클 체감 확인** — 하루 30분(낮 20:밤 10) 비율이 플레이 체감상 적절한지. 짧다고 판정되면 비율 변경 + 연동 수치(왕국 이벤트 주기·영지 수입) 일괄 재산정 | 디렉터 문의(2026-07-16) — 시간 비율은 체감 수치이므로 실플레이로 판정 |

세 게이트는 **같은 디렉터 플레이 세션**에서 함께 확인하는 것을 권장한다(반복 호출 비용 절감). 승인 전까지 M2는 종료되지 않으며, 반려 시 손맛 튜닝만 반복하고 나머지 시스템 확산은 보류한다(`combat-options.md` 9장 "A안 선택 시 튜닝 반복 기간" 조건 이행).

### 1-2. 신규 포함 — 튜토리얼/온보딩 설계

`M1_QUESTIONS.md` 8절의 미답변 항목("튜토리얼/온보딩") — world-structure·quest-structure에 "튜토리얼 겸용" 배치 언급만 있고 온보딩 설계 자체가 없었다. M2에서 **첫 10분 경험**으로 정식 설계·프로토타입 제작한다(3장 UI-3·UI-4 태스크). 무대는 이미 확정된 메인 1장 `MQ-01~05`(여울목 부락, Lv1~4, `quest-structure.md` 3장 1행)를 그대로 쓴다 — 신규 지역·퀘스트 신설이 아니라 **기존 1장 진행에 조작 학습 곡선을 설계로 얹는 작업**이다.

### 1-3. 명시적 제외 — 캐릭터 커스터마이징

**캐릭터 커스터마이징은 M2 범위에서 제외한다.** `GAME_CONCEPT.md` 변경 이력 2026-07-16에 "캐릭터 커스터마이징 미도입(고정 외형, 외형 변화는 장비 교체로 표현) 확정"으로 기록되어 있다 — M1_QUESTIONS 8절의 또 다른 미답변 항목이 이번 G-2 승인과 함께 해소된 것으로, 본 문서 6-1절에서 M1_QUESTIONS.md 갱신을 함께 처리한다. 전사 스프라이트(3장 AR-1)는 고정 외형 1종만 제작하면 되므로 M2 아트 물량에 영향 없음.

### 1-4. 범위 제외 재확인 (PROJECT_STATUS 8장 그대로 승계)

명성·영지·퀘스트(개별 목록)·펫·칭호·도감·워프·주야간 시스템은 M2 범위 밖 — 전투 손맛 검증에 집중한다. **단 드랍·골드 공식은 전투 검증에 필요하므로 포함**(2장 IT-2). 천상계 콘텐츠는 여전히 M3+ 백로그이며 M2와 무관하다.

## 3. 의존 순서 (단계별, 단계 내부는 병렬 가능)

```
Phase 0 (설계 선행 — 병렬)
  CB-0 · CB-0b (systems-designer)   UI-3 (ux-designer+quest-designer)   MP-2 (tech-artist)

Phase 1 (에셋·데이터 제작 — Phase0 완료물 활용, 병렬)
  MP-1 타일셋            AR-1 전사 스프라이트         IT-1 스타터 아이템 데이터
  AR-2 몬스터 스프라이트(← CB-0)   AR-3 아이콘(← CB-0b, IT-1)

Phase 2 (코어 시스템 구현 — Phase0 완료 후, 병렬)
  CB-1 → CB-2, CB-4, CB-5 (컨트롤러 선행)
  CB-6 몬스터 행동 블록 (← CB-0)
  CB-3 데미지 공식 (독립 구현 가능)
  IT-3 인벤토리 (← IT-1)

Phase 3 (통합 — Phase1·2 완료 후, 병렬)
  CB-7 HitFeedback 코드 (← CB-3, CB-4)      CB-8 HitFeedback 셰이더 (← MP-2, CB-7과 병행)
  CB-9 디버그 전투장 (← CB-1, CB-2, CB-3, CB-6)
  MP-3 맵 씬 구성 (← MP-1, MP-2) → MP-4 몬스터 스폰 배치 (← MP-3, CB-6, AR-2)
  AR-4 타격 이펙트 (← CB-7)                  SD-1 전투 SFX (← CB-7)   SD-2 BGM (독립)
  UI-1 HUD (← CB-2, CB-5)                    UI-2 통합 메뉴 골격 (← IT-3)

Phase 4 (마무리 통합)
  IT-2 드랍/골드 공식 구현 (← CB-6, IT-1)
  UI-4 튜토리얼 구현 (← UI-3, MP-3, UI-1)

Phase 5 (검증 — 전체 통합 후)
  QA-1 (← CB-3, CB-6)   QA-2 (← IT-2)   QA-3 (← 전체 플레이 가능 상태)   QA-4 (← QA-1·2·3)

Phase 6 (게이트)
  G2-1 디렉터 플레이 승인 · G2-2 D-20 확인 · G2-3 HitFeedback 프리셋 승인 (← QA-4 통과 후 동일 세션)
```

- **병렬 가능 구간**: Phase 1의 pixel-artist 작업(MP-1·AR-1·AR-2·AR-3)과 Phase 2의 gameplay-dev/ai-dev 코드 작업은 서로 의존하지 않으므로 완전 병렬 진행 가능. Phase 3의 tech-artist(CB-8)와 gameplay-dev(CB-7)도 셰이더/코드 분업으로 병렬.
- **병목 지점**: CB-0(몬스터 스펙)과 CB-0b(스킬 세트)가 각각 AR-2/AR-3, CB-6, CB-2의 공통 선행 태스크이므로 Phase 0에서 최우선 완료해야 한다. 지연 시 이후 전 태스크가 순연된다.

## 4. 참고 — 페이스 실측 결과의 반영처

QA-3 실측 결과는 `growth.md` 5-3장의 3개 레버(퀘스트 경험치 비중·REQ 계수·사냥 사이클) 및 `quest-structure.md` 9장의 배분 추정치 조정에만 사용한다. 두 문서 모두 "M2 실측 후 조정"을 이미 지정 레버로 못박아 두었으므로, M2 종료 후 producer가 조정 필요 여부를 취합해 담당 에이전트(systems-designer/quest-designer)에게 전달한다(PROJECT_STATUS 9장 백로그로 등재).
